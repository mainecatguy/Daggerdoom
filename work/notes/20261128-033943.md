## What Daggerfall Unity uses a governing attribute for

**One thing: the character sheet.** `GetPrimaryStat` has a single caller, `TextProvider.GetSkillSummary`
(`Assets/Scripts/Utility/TextProvider.cs:502`), which prints the abbreviation (STR, AGI, ...) next to the skill in the
sheet's skill lists. Searched: every `.cs` file under `Assets` for `GetPrimaryStat` / `PrimaryStat`.

**It applies no learning-speed multiplier.** Every path that changes how fast a skill rises, and its inputs:

| Path | Inputs |
|---|---|
| Uses needed per point, `FormulaHelper.CalculateSkillUsesForAdvancement` | skill value, per-skill multiplier, class multiplier, character level |
| `PlayerEntity.RaiseSkills` | the above, uses tallied, Reflexes setting |
| `PlayerEntity.TallySkill` | the amount only |
| Training, `DaggerfallGuildServiceTraining.TrainSkill` and quest `TrainPc` | random 10-20 x per-skill multiplier |
| Doomerfall use gain and buying, `DoomerfallSkillXp` | damage dealt; the uses formula with multiplier 2 |

None reads an attribute. So there is no multiplier to put on top of Doomerfall's rates, and **the gun skills already
behave exactly like Daggerfall's skills**: the attribute is shown on the sheet and nothing else, under both Skill XP
and use-based gain.

The owner's caveat expects "whatever multiplier it did before". In Daggerfall Unity that is none. I did not invent one
(that would be new game design). I did not check the original 1996 executable. Raised as a question.

Not related to this table: the attribute damage bonuses (Strength and Agility gun damage) are separate decided rules
keyed by weapon type, not by `GetPrimaryStat`. They are unchanged.
