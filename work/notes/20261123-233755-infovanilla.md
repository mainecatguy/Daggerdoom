# Info mode like vanilla Daggerfall

Goal: Doom's Info control behaves like Info mode in Daggerfall (Daggerfall Unity's `PlayerActivate.cs` is the reference).
Owner's decision: Info on a building door shows the name and also enters; messages appear centered like Daggerfall's HUD text.
Earlier work: `work/notes/20261123-225143-info.md` (merged as `b457f4c`).

## Plan

1. Read `PlayerActivate.cs` again for what Info does differently from Grab. Result: one click runs every activation
   on the hit object in order. Info differs from Grab in only four places: a building shows its name (and closed
   hours), a static NPC says "You see NAME." instead of talking, quest resources are not triggered, and a corpse says
   "You see a dead NAME." Everything else, including static doors (`ActivateStaticDoor` has no mode check), action
   doors, action records (levers), ladders, bookshelves, loot and mobile townspeople, is the same as Grab.
2. So in Doom: Info = the Info message for its target, then Use's door handling. Keep Use's item and container route as it is.
3. Draw Daggerfall's text as Daggerfall Unity draws it (`PopupText.cs`, `DaggerfallHUD.cs`).
4. Test with the existing harness (`tools/info_mode`), now pressing Info (not the Use test hook) at the store door.

## What changed

- `UZDoom/src/dd_info.cpp`: after the NPC/monster check fails, Info sends the building request as before and then
  acts as Use on lines and location doors (`UseAsGrab`): `P_UseTraverse` plus sector use actions, without Doom's
  "oof" sound (Daggerfall's Info on a plain wall is silent), and `DDTreadmill_PressDoor()` for town, interior and
  dungeon doors. The building request goes out first, so Daggerfall names the building before the door event arrives.
  Walking townspeople (`DFTownsperson`) now stop the Info ray and do nothing, instead of letting it name the building behind them.
- `UZDoom/src/playsim/dd_treadmill.cpp/.h`: `DDTreadmill_PressDoor()`, one press of Use on a location door on the next
  tic (it expires after one tic, so a press on a map without town doors does not linger).
- Text: Doom no longer prints Info text on its top-left message line (it still goes to the log with `PRINT_LOG`).
  The engine passes it to the Doomerfall mod as a UI console event (`dfhud_top:` / `dfhud_mid:`), and
  `mods/doomerfall/src/zscript/Doomerfall.zs` draws it in Daggerfall's 320x200 layout: HUD rows centered from row 4,
  each held one second then scrolled up, at most 7 rows with the same catch-up speed-up; mid-screen text centered at
  row 146 for 1.5 seconds. Daggerfall's text colour (243,239,44) with its shadow colour (93,77,12) one pixel down-right.
- No bridge change. No Daggerfall change.

## Differences from vanilla (Daggerfall Unity's PlayerActivate)

| Difference | State |
|---|---|
| Info on a building door did not enter | Fixed: name first, then it enters. This also covers interior exits and dungeon doors, through the same door press as Use |
| Info text on Doom's top-left message line | Fixed: centered rows from the top like Daggerfall's HUD text, scrolled away the same way; mid-screen text at row 146 |
| Info on action doors, levers, ladders, shelves did nothing | Fixed where Doom routes them with Use (lines and sector use actions). Silent on a plain wall, as Daggerfall is |
| The Info ray passed through walking townspeople and could name the building behind them | Fixed: they stop the ray. Daggerfall opens the talk window here, which belongs to the dialogue task (not fixed) |
| A closed shop's door enters at night (Daggerfall says the door is locked) | Not fixed. Use does the same. Locks are the backlog item "Locked doors with Daggerfall's requirements" |
| Info on a door out of reach: Daggerfall shows the name and "You are too far away." | Not fixed. Doom gives the name only, because Use gives no message out of reach either |
| Doom's SmallFont, not Daggerfall's font; every row held 1 s (Daggerfall callers can pass longer delays) | Not fixed. The font is a look question for the play test |
| Corpses ("You see a dead X") | Not fixed: Doom monsters leave loot piles, and Info on a pile opens it as Daggerfall's does |
| Quest resources (Info must not trigger them) | Doom does not route quest resources yet |
| Other Daggerfall HUD text (for example "You are too far away" from containers) is still not shown in Doom | Out of scope; the same hook could carry it |

## Play-test list

1. Press Q on the store wall from the street: the name should appear centered at the top, in Daggerfall's yellow. Is it easy to read? Too big or too small?
2. Walk up to the door and press Q: the name shows and you go in, the same as Use. Does the name still show after the door transition?
3. Inside, press Q on the exit door: you should leave. Q on the shopkeeper: "You see NAME." Q on furniture: the private property question.
4. Press Q on a monster in a fight, and press it several times quickly: do the rows stack and scroll up like Daggerfall's?
5. The centered rows share the top of the screen with Doom's own top-left messages (pickups, and debug lines such as
   `DDTOWN ...`), and they overlap in the screenshots. Do they clash? Should Doom's message line move, or should the debug lines go quiet?
6. Press Q on a plain wall up close: there should be no "oof" sound, and nothing happens.
