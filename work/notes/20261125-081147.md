# Fixed drops: the two Shocktroopers with "no Daggerfall id"

Branch `agent/fixeddrops-20261125-081147`, continuing `work/notes/20261125-061121.md` (finding 4). Goal: find out why
two `RLFormerShocktrooper`s at the Privateer's Hold entrance (780,383 and 920,504) showed no Daggerfall id, stop
monsters like these from making random loot, and show it with the paired test.

## Plan

1. Find the cause from the last run's logs before touching code.
2. Fix it the general way, or report it if it is a one-off.
3. Make the paired test fail on any unseeded monster or drop anywhere on the level, not only at the entrance, then
   run the full series (fresh, save, load, fresh2).

## Cause (shown from the logs, no code change needed in the game)

**The two Shocktroopers had Daggerfall ids all along. They never died.** The previous harness took the zero seed of a
living monster as "died without an id".

- `log-fresh.txt` from the last run: `DDENC leader b9b245ae4ed99000 RLFormerShocktrooper at 780.0,383.2,0.0`. The
  placer spawned it directly as the leader of pack `b9b245ae4ed99`, so it took its id at once
  (`dd_monsters.cpp` SpawnMook). It was not a spawner or a claim, so the `RunClaims` guess in the last notes was wrong.
- The same log has `DDMON died b9b245ae4ed99001` to `...009`, every member of that pack **except 000 and 005**, the
  two Shocktroopers (780,383 and 920,504). Daggerfall-id monsters always print `DDMON died` when they die
  (`p_interaction.cpp:322`), so these two did not die.
- Why: DRLA Monsters' `RLFormerShocktrooper` (`actors/monsters/armageddon/FormerShocktrooper.txt`) spawns `-SHOOTABLE
  +INVISIBLE` and waits in its Spawn state until it sees a target, then "teleports in" and becomes shootable. The
  harness froze the level and gave each victim a `DMG_FORCED` blow, but Doom refuses all damage to an unshootable
  actor before it looks at `DMG_FORCED` (`p_interaction.cpp:1105`, `DamageMobj`). So the blow did nothing.
- The harness then printed `PDCORPSE ... seed 00000000` for every victim, dead or not. A living monster never carries
  a loot seed (`dd_lootrng.cpp`: the seed is set only when a monster starts dying), so these two looked unseeded.
- They dropped nothing in those runs, because they never died. In real play a player can only kill a Shocktrooper
  after it has teleported in, and then it dies with its id, so its drops are seeded like every other mook's.

So this is neither a game bug nor a one-off claim failure. It was a test harness false positive. No game code changed.

## Changes (test tools only)

`tools/fixed_drops/paired.zs`:
- A victim that is not shootable is woken first (target set to the player, then its See state), as a player would meet
  it. It prints `PDWOKE <class> shootable <0|1>`.
- A victim still alive after the blow prints `PDALIVE`, and so does a still-living victim at the drop listing,
  instead of a misleading `PDCORPSE ... seed 00000000`.
- New check, whole level and the whole run: any monster that dies without a loot seed (no Daggerfall id) prints
  `PDNOID`. The engine seeds a dying monster before `Die` runs, so `WorldThingDied` sees the seed.
- New check: every plain ammo pickup spawned during the kill window must carry a seed (`PDAMMOUNSEEDED` if not), and the
  count is printed (`PDAMMOPLAIN n`). The tiered `DFAmmo_` pickups that replace them are spawned by
  `DoomerfallAmmo.zs` outside any roll, so their own seed is 0. They roll their tier from the plain pickup's seed, so
  the plain pickup's seed is the right thing to check. The drop list already compares `DFAmmo_` classes between games.

`tools/fixed_drops/paired.py` compare: a run now fails if it has any `PDALIVE`, `PDNOID`, `PDUNSEEDED`,
`PDAMMOUNSEEDED`, or a corpse with seed 0.

## Known gaps

- Monsters that appear during play, not from Daggerfall's placements (for example a Pain Elemental's Lost Souls, or a
  DRLA summoner's minions), have no Daggerfall id, so if they carry a drop list their drops are random. The paired test
  does not make any (the rest of the dungeon is dormant during the kill). It would now catch them as `PDNOID`. The fix
  is a design choice (see the question below), so it is not made here.
- The tiered ammo pickups have no lasting id of their own (their tier is fixed, their floor id is a session id).
- The one-off unseeded `RLBloodSkull` from the run before (finding 3 of `20261125-061121.md`) is still unexplained.
