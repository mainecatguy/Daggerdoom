# No DRLA class in bridged games (run 20261126-184738)

## Cause of the owner's bug

The bridge already skipped Doom's class menu, but only by name: `M_SetSpecialMenu` (UZDoom `menu/doommenu.cpp`) caught
`PlayerclassMenu` and `EpisodeMenu`. DRLA X replaces the main menu's New Game target with its own
`DRLAX_PlayerClassProxyMenu` (`drlax_1.2b.pk3:menudef.txt`), so that menu opened. Choosing a row there led to
`EpisodeMenu`, which the bridge caught, and the difficulty prompt then started `PlayerClasses[0]`, DRLA's Marine with
`RLAmmochainPerk` and the Marine chaingun loadout.

## What DRLA keys on (checked before relying on it)

- DRLA picks class behavior by **perk items**, not class names. `RLSpecialStarter`
  (`actors/misc/StartingItemSpawners.txt`) gives the loadout by perk; with no perk it falls through to the
  Scout/pistol loadout (`RLPistol`, 60 bullets), the same path as DRLA's own `DRLA_noperk` option. Perk scripts
  (`DRLALIB_Player.acs`: Scout map, Technician boost) check the perk item and do nothing without it.
- Correction (after the verifier): my first search missed the PDA includes (`.pdap`, `.ach`). Class-name and index
  checks found there: `player.pdap` (PDA Classes page: strings `PDA_CLASS_<class>_NAME/_ABILITIES/_STORY/_HEIGHT`
  and portrait `DRLA_ClassIcon[PlayerClass()]`, 5 entries, index 0 = Marine `PPDAMAR1/2`), `armors.pdap:23-27`
  (Renegade armor bonus display, false for us = correct, no perk), `weapons.pdap:58` (Technician-only disassemble,
  false for us = correct). DRLA X checks `DoomRLMechanoid` (start weapon, false = correct). `DRLALIB.acs` defines
  `CLASS_*` but does not use them. Fixes in `doomerfall-drla.pk3`: `LANGUAGE.txt` adds the four
  `PDA_CLASS_DOOMERFALLPLAYER_*` strings ("No Doom class"); `graphics/PPDAMAR1.png` and `PPDAMAR2.png` (1x1
  transparent) blank the Marine portrait that index 0 would show. This is contained: the Marine can't be chosen in
  bridged games, and standalone DRLA never loads the pk3. Checked in a bridged run: the probe logs
  `pda name "No Doom class" portrait 1x1`. The PDA page itself was not opened on screen.
- Further class-name checks found in run 20261126-200147 (all false for `DoomerfallPlayer`, which is the no-class
  result): `ArsenalRarityBeams.txt:12` (a beam only the Technician sees), `Barrels.txt:710` and
  `HighPowerNuclearBFG9000.txt:638` (nuke effect given to every player except the Demolitionist), DRLA X
  `Nanomaniac.zscript`, `Nomad.zscript`, `PhaseSisters.zscript`, `Trespasser.zscript` (each checks its own class).
  DRLA Monsters `CyberneticLostSoul.txt` (Demolitionist check), DRLA X `Gizmos.zscript:262` (Nomad),
  `Misc.zscript:74-110` (arch-vile copy by class; falls back to the perk-based copy). **Not all checks are
  no-class:** DRLA X `Unlocks.zscript:419-436` would unlock the Maestro familiar for our class on game completion
  (unreachable in bridged play), and the Maestro familiar (`familiars/Special.zscript:1685-1741`) gives a non-own
  class perk for a level, which means any of the five for us. So the statement above that DRLA picks class behavior
  only by perk items is wrong for DRLA X. Full table, reachability and the known limit in `work/notes/20261126-200147.md`
  section 2.
- `DoomRLPlayer` (`actors/ArsenalPlayerPawn.txt`) is DRLA's generic parent: stock PLAY sprites, full step, armor,
  pain and death states, DRLA's infrastructure start items, no perk. Its `DamageFactor "Holy", 0.2` is DRLA's base
  value (the Marine keeps it, other classes lower it), so it is not a class factor.

## What was built

1. `mods/doomerfall/drla-src/` -> `doomerfall-drla.pk3` (`build_pk3.py --drla`): `DoomerfallPlayer : DoomRLPlayer`
   with DRLA's infrastructure start items (HUD changers, special starter and dropper, armor special/removers,
   assemblies wipe, fist, stamina 100) and no perk item; its MAPINFO sets `PlayerClasses = "DoomerfallPlayer"`.
   It is a separate pk3 because a DECORATE class with a missing parent is a fatal error, and `doomerfall.pk3` must still
   load without DRLA (`smoke.py` has a mod-only setup). Without DRLA a bridged game keeps stock `DoomPlayer`, which has
   no class effects, so no non-DRLA class was needed.
2. `scripts/play/install.py` builds `doomerfall-drla.pk3` and loads it after `doomerfall.pk3` (the play folder always
   loads DRLA). Standalone UZDoom with DRLA never loads it.
3. UZDoom `menu/doommenu.cpp`: under `-dfflow` only (`DD_BridgeNewGameMenu` returns false without a session), any menu
   with an item that opens `EpisodeMenu` (a mod's class menu) is treated as the class menu, so New Game goes straight
   to Daggerfall's character creation. No new state; one small helper.

Engineering calls (within the owner's decision): derive from `DoomRLPlayer` (not Marine), drop `DoomRLPlayer`'s own
40 bullets and 5 shells so the kit is exactly DRLA's no-class start (fists, pistol, 60 bullets). The starting kit is
still an open owner question (proposal section 7); the pistol is the neutral default and matches the plain-load path
(`DD_ItemsSendStarter` already assumes a pistol starter).
