## Result: the light Schism cut wins
Pictures: `D:\dev\DoomDaggerfall-loop\review\burn-look\candidates.png` (3 scenes x 3 looks x 2 shots) and
`shipped-look.png` (the final look).

| candidate | reads as fire? | same on any monster? | without DRLA? | cost (400 burning, in view) |
|---|---|---|---|---|
| Engine particles (the previous run's pick) | **No.** A few orange dots, easy to miss even in the dark. | yes | yes | +1-2 ms avg |
| Arch-vile flame (one Doom II FIRE sprite per monster) | Yes, but a wall of flame. It hides small monsters and packs completely, and the sprite rises above the body. | no | **Doom II only**: DOOM.WAD has no FIRE sprites | erratic: +0.3-3.5 ms avg, p99 up to 26 ms in one run |
| Schism lite (FRPR flames only: no flares, smoke, or damage actors) | **Yes.** Flames cling to each body and the monsters stay visible. | yes, after a fix (below) | yes, once its 8 frames ship in the mod | +2.7 ms avg, p99 10.5 ms, worst 11-12 ms |

- The first Schism-lite shots were too sparse on big monsters (one flame on a Baron). The fix spawns one flame per
  ZombieMan-sized area of body (radius x height / 1120, 1 to 4), sized by height (clamped 0.6-1.6).
- The winner is in `mods/doomerfall/src/zscript/DoomerfallBurnLook.zs`. Every 4 tics, staggered per monster, it
  spawns 1-4 `DoomerfallBurnFlame` actors (NOINTERACTION, additive, 24-tic life) over the body, rising slowly and
  carried along with the monster. Damage is untouched: the look is still the one `Draw` call behind `dd_burn_look`.
- Sprites: Schism's `FRPRA0`-`H0`, renamed `DDBF*` so they cannot clash if Schism is loaded, are in
  `mods/doomerfall/src/sprites/burn/` (15 KB). They are committed on the owner's copyright OK for the Schism effect
  and recorded in `art/README.md`, like the DRLA Light Carbine files. There is a question for the owner below.

## Frame times (`python tools/burn/look_shots.py --exe ...uzdoom-burnlook... --frames`)
400 ZombieMen in view, all burning, every flame on screen at once (the worst case for overdraw). Private desktop,
1280x720, other lanes running on the machine. Times are ms per rendered frame.

| case | avg | p99 | worst | frames > 33 ms |
|---|---|---|---|---|
| not burning | 4.3-5.4 | 6.3-8.6 | 13.8-15.2 | 0 |
| burning, look off | 5.1-6.1 | 7.1-10.2 | 8.3-62.5 | 0-2 |
| **shipped look** (4 runs) | 8.7-12.3 | 14.8-27.0 | 19.6-23.4, one run 118.9 | 0, 0, 0, 9 |

- With all 400 burning in view, the look costs about 3-6 ms per frame. Three of four runs had no frame over 33 ms. One
  run had 9 frames over 33 ms (worst 119 ms) and did not repeat. A look-off run also had a 62 ms spike, so I read the
  spikes as interference from other work on the machine. They are still worth a visible play-test (list below).
- The flame actors are the main cost: about 6-7 alive per ZombieMan, so about 2,600 for 400 monsters. If it needs to be
  cheaper, spawn every 5-6 tics instead of 4, or cap flames per monster. Both are one-line edits in `Draw`.
- **DRLA frame runs are not valid.** With DRLA loaded, my scene spawns ZombieMen with replacement allowed. DRLA
  replaces them with random spawners, so the list held spawners that had already removed themselves, and nothing
  burned: "burning" measured the same 4.3 ms as not burning. The DRLA damage test (`run_test.py drla`, stock monsters
  with DRLA loaded, look on) does pass. A picture of DRLA monsters burning is still missing.

## Burn test with the new look (`quiet_run.py --timeout 300 -- python tools/burn/run_test.py --exe ...uzdoom-burnlook...`)
All three setups (look on, look off, DRLA set) pass every check, all on DOOM.WAD E1M1: pack 400/400 lose exactly 600,
take 150/150, player untouched, fractions and Take(1.0), pain 400/400. The burn handler's tick, flame spawning
included, peaks at 0.89 ms (look), 0.20 ms (look off), and 1.08 ms (DRLA). E1M1 loads with no doomerfall script errors
stock and with DRLA. Nothing outside tests calls `Apply` yet, so normal play is unchanged.

## Failed approaches
- A shell-launched test reported "OK" when UZDoom had not started (exe still locked by the linker, error 32).
  `look_shots.py` now treats an empty log as a failure.
- `+set dd_bls_style -2` on the command line: `-2` is read as a new option, so the cvar stayed 0. The first
  "not burning" and "look off" frame runs were really burning runs. Fixed by using positive codes (3, 4).
- I spent several runs "debugging" an invisible Arch-vile flame. It was rendering fine; my crops used the second
  screenshot, which landed when every flame (spawned in sync) was on its tiny last frame. Each flame now starts at a
  random frame, and the contact sheet shows both shots.
