# 2026-11-27 21:23 — One pattern: Daggerfall sends the sheet, Doom applies the rules

Goal: perks and attributes follow one pattern (owner, Q&A item 45): Daggerfall sends the character sheet, Doom applies
the rule formulas from it in one shared place, Agility on the shared attribute handler; documented in
`architecture.md`.

## Plan (as carried out)

1. New `mods/doomerfall/src/zscript/DoomerfallRules.zs`: sheet reads (`HasCharacter`, `Stat`) and every formula:
   Strength, Speed, Agility (handling, evade), Luck (ammo drop), Jumping (height, air jumps, fall immunity), falling
   damage (5 m, 5 HP per metre), and all gun skill perk rules (Automatics, Explosives, Shotguns, Energy Weapons, ported
   line for line from the four Daggerfall `Doomerfall*Rules.cs` files). Perk rules: `DoomerfallRules.Get(rule)` reads
   the live skill from the sheet and computes; 0 without a character, as before.
2. Perk files keep their `Rule(index)` call sites; the index constants now name `DoomerfallRules` ids and `Rule` calls
   `DoomerfallRules.Get`. No rule numbers left in them.
3. Agility merged into `DoomerfallAttributeEffects` (DoEffect for reload/switch speed, passive ModifyDamage for evade).
   `DoomerfallAgility` handler removed from MAPINFO, its file no longer included.
4. Jumping and falling damage formulas moved from `DoomerfallJump.zs` into the rules file.
5. Daggerfall: `DoomerfallSheet.cs` no longer fills perk rule slots 155-180 (left 0, reserved; layout and format
   version unchanged, so no engine rebuild needed and old saves/peers are unaffected). The four `*Rules.cs` files are
   emptied (see "Could not do").
6. `architecture.md`: new section "Character sheet and rules" with the pattern, how a new perk copies it, and the
   exceptions (Daggerfall's moddable FormulaHelper results such as climbing chances; Willpower's damage reduction in
   the engine's C++ damage path; Endurance max HP in Daggerfall).

## Tests

- New `tools/rules/rules_test.py` (+ `.zs`): prints every rule from `DoomerfallRules` over its whole input range and
  compares with a Python port of the old formulas (the four C# Fill methods, the old attribute/Agility/Jump/Luck code).
- Doom-only perk tests (`tools/{automatics,explosives,shotguns,energy}/*_test.py`): Python unchanged. Their fake
  Daggerfall still writes hand-picked rule sets (for example "burst only") into slots 155-180, which a real character
  cannot produce from one skill value. The harness `.zs` now hands those slots to `DoomerfallRules` each tic
  (`PerkRuleFeed`, using the 2-field test override `testRules`/`testRule[]`, set only from tools/). So each test feeds
  the perk code exactly the numbers it fed before, and every check is unchanged.
- Paired tests (`*_paired.zs`) now log `DoomerfallRules.Get(...)` instead of the sheet slots, so their "rules Doom read
  match the skill" check now checks Doom's formulas against the real Daggerfall skill.
- `tools/agility/agility_paired.zs`, `tools/willpower/willpower_paired.zs`, `tools/jumping/*.zs`: renamed references.

## Decisions (engineering calls)

- Kept the sheet layout (slots 155-180 reserved, format 11) instead of shrinking it: shrinking forces a format bump,
  an engine rebuild and edits to every test peer for no gameplay gain. A later bridge change can drop them.
- Willpower stays in C++ (`dd_bridge.cpp`): it is applied last on all damage inside the engine; moving it to ZScript
  would change the damage pipeline (not allowed by this goal). Documented as an exception.
- Jumping keeps using the base skill and gun perks the live skill (existing rules, unchanged).
- Debug log of the Luck roll still prints the raw Luck value (unchanged).
