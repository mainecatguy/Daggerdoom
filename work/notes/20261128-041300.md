# 2026-11-28 04:13: Doom weapon materials (weaponmaterials 01)

Goal: Iron starter guns, no "Iron" in Doom weapon names, melee Doom weapons get a material and its bonus, the fist none.

## What I found

- Every Doom weapon Daggerfall holds is made by `DoomerfallDoomItem.Create` (`DoomerfallDoomItems.cs`). A gun's
  material lives in `nativeMaterialValue`; the name came from one place, `GunName` ("<material> <Doom name>").
- Starter guns had a seeded *roll* (`LootSeed.DoomStarterGun`), so a new character's gun could be any material. Three
  call sites: the new-character kit (`DoomerfallStartingGun.cs`), the converted-save pistol (`DoomerfallHotkeys`
  plain load), and `DoomerfallHotkeys.Adopt` (a gun Doom's new game held).
- Melee weapons: Doom's `IsGun` (dd_items.cpp) counts any `Weapon`, so a chainsaw taken with Use already *was* a
  Daggerfall item with a rolled material. The fist never becomes one (it has no pickup and no world sprite;
  `DoomerfallGuns.zs` `PickupFor` returns ""). So the material roll already matched the owner's rule.
- **The real gap was the bonus.** `DoomerfallAmmo.UpGun` returned null whenever Doom's ready report said "melee"
  (status 1 = `WIF_MELEEWEAPON` or no weapon), so a drawn chainsaw got no material bonus, the same as the fist.
  Daggerfall could not tell the chainsaw from the fist, because the report carried only that one bit.

## What I changed

1. `GunName`: Iron gives the plain Doom name ("Pistol"); other materials keep theirs ("Steel Pistol"). Floor look
   labels use the same function. The info box still says "Material: Iron".
2. `DoomerfallDoomItem.CreateStarter(cls)`: `Create` with the material fixed at Iron (through the existing `carried`
   argument). All three starter call sites use it. `LootSeed.DoomStarterGun` is now unused but left in place
   (it is in `Game/Items/LootSeed.cs`, a shared list of seed purposes).
3. Bridge: `DFB_KIND_AMMO_READY`'s status is now bits: `DFB_AMMO_READY_MELEE` (1, as before) and new
   `DFB_AMMO_READY_FIST` (2): the ready weapon is the fist (stock `Fist` or DRLA's `RLFist`, by class ancestry, the
   same rule as `DoomerfallWeaponCategory.zs`) or none. Regenerated bindings (schema hash changes, so bridge DLL,
   UZDoom and Daggerfall Unity must all be rebuilt together).
4. `DoomerfallAmmo.UpGun` now hides the gun only while the fist is up (`readyFist`), not for every melee weapon.
   `ReadyMelee` keeps its meaning for the fist test.
5. Engine change is inside `ReportAmmo`, which returns at once without a Daggerfall item session, so stock Doom and
   DRLA without Daggerfall are untouched.
6. Docs: `manual.md` (new "Weapon materials" section), `gamedesign/damage.md`.

Why an engine bit instead of a Daggerfall-only guess: Daggerfall knows when the player pressed hotkey 1, but Doom can
also lower an empty gun to the fist by itself (DRLA's Energysaw, for example, uses cells), and then a Daggerfall-only
rule would give the fist the chainsaw's bonus.

## Verification

Test: `tools/ammo/ammo.py material` (existing harness, extended). Added to it: a Daedric Chainsaw on key 6 (expects
x1.6: no reserve ammo so no ammo bonus), then hotkey 1's fist with that chainsaw still the active gun (expects
unscaled); the starter gun must be Iron (-10%); the names line (Iron "Pistol", Steel "Steel Pistol").

Results: see below.

## Play-test list

- Start a new character: the starting gun in the inventory reads "Pistol" (or the class's gun) with no "Iron", and
  Info shows "Material: Iron".
- Find a non-Iron gun: it keeps its material in the name ("Steel Shotgun"); an Iron one dropped in a dungeon shows its
  plain name on the floor look label too.
- Pick up a chainsaw: it has a material; hitting with a high-material chainsaw should feel stronger than Iron.
- Press 1 for the fist while a chainsaw is your active weapon: fist damage is plain.
