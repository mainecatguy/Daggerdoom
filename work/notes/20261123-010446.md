# Run notes: 20261123-010446 — one random enemy per placement

## Findings
- Daggerfall enemy placements are RDB editor flats in texture archive 199: record 15 = random enemy, record 16 = fixed enemy
  (see `RDBLayout.cs` and `DaggerfallBillboard.cs`). Fixed ones carry a mobile id in `FactionOrMobileId`; random ones do not.
  Neither sets any HP; Doom decides that.
- The converter previously ignored these flats. Towns (RMB blocks) have no archive-199 enemy flats, only NPC records, so nothing to do there.

## Mapping (tools/dungeon_converter/EnemyRoster.cs, Program.cs `AppendEnemies`)
- Each placement becomes one UDMF `thing` at the cell centre of the converter grid, on the span whose floor is highest at or below the marker (+ one step) and
  tall enough for a body. `height` is the offset above the sector's base floor, as the player start does.
- Doom type = `Types[FNV1a(mapId, blockX, blockZ, block name, raw x/y/z, record, mobileId) mod 15]`. All inputs are static data from BLOCKS.BSA and the map table;
  none depend on cell size, scale, conversion order, or any RNG. Same placement → same monster on every run.
- Roster, vanilla doomednums so DRLA's replacements apply: zombieman, shotgun guy, chaingunner, imp, demon, spectre, lost soul, cacodemon, hell knight, baron,
  revenant, mancubus, arachnotron, pain elemental, arch-vile. No bosses, no keen, no Wolf SS (not DOOM.WAD/Doom II-neutral). Uniform weights; no tiering by dungeon type
  or Daggerfall monster level (owner said encounter scaling is out of scope).
- Roster uses Doom II monsters, so converted maps need DOOM2.WAD (the current demos already do). With DOOM.WAD they would not spawn the Doom II-only types.
- UZDoom untouched; nothing under `daggerfall-unity-master/`, `launcher/`, `bridge/` edited.

## Tested
- Converted Privateer's Hold: `enemies: 42 placed, 0 skipped, of 42 placements`, type spread across all 15 classes.
- Two separate conversions give byte-identical WADs (same md5), so the choice is deterministic.
- `review/random-enemy/count.py` launches UZDoom (30-40 s limit, private `test.ini`, stdout log) with a ZScript census at tick 10:
  - stock DOOM2 + converted Privateer's Hold: 42 monsters, classes as picked (Cacodemon, Archvile, ...), no script errors.
  - DRLA + DRLA Monsters + DRLAX: 42 monsters at the same coordinates, replaced by RL* classes with DRLA HP (RLBaronOfHell hp1000, RLImp hp60, ...). Some
    non-vanilla results (RLFormerCaptainPlasmaRifle, RLNightmareArchvile) come from DRLA's own replacements, as intended. The pre-existing menudef script
    errors in that log come from DRLA Monsters under this engine, not from this change.
  - DOOM.WAD E1M1: 6 monsters both stock and with DRLA, no errors (UZDoom was not modified).
- Not tested: other dungeons (only Privateer's Hold converted); no player-eye check of placement heights.

## Not done / limits
- Mobile type of the Daggerfall fixed enemies is hashed in but not otherwise used (owner: Daggerfall does not set Doom stats).
- Towns have no enemy placements in the data, so nothing was emitted for them.
- The mesh exporter path (`--export-mesh`) does not emit things; only the `.wad` carries the monsters.
