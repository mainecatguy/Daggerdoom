# Stand-in for an unaffordable regional favourite (2026-11-27)

Goal: dungeons in one region cell share a favourite kind, guaranteed about 10% of the army (`work/notes/20261124-100533.md`).
A low-level dungeon often cannot afford it. Owner (2026-11-26): pick an affordable stand-in that fits the theme and region,
preferring the favourite's own colour or DRLA family, then the nearest kind on the kind ring. Same seeds, same stand-in.

## Plan

1. Define "cannot be purchased" from rules the budget already has.
2. If the favourite kind can be bought at all, leave the planner exactly as it was.
3. If it cannot, add an affordable stand-in that fits the theme, ranked by the owner's preferences.
4. Extend the planner test: a level ladder in the cell with the dearest favourite, and checks for every stand-in.
5. Run the planner and budget tests in every mod setup. Diff the armies against the original planner.

## Round 2 (after the verifier's rejection)

The first version was rejected for four reasons. Each was fixed:

1. **Theme fit was only a tie-breaker and untested.** The stand-in is now chosen among affordable monsters that fit
   the dungeon's theme (`theme.Matches`: theme kind, class pattern, or theme trait) whenever any is eligible. If none
   is, it is chosen among all affordable monsters. The test recomputes theme matching from the data file and asserts
   it.
2. **An unaffordable favourite already in the army through another role blocked the stand-in.** Now, when the kind
   cannot be bought, a stand-in is always added, even if the core, support, wildcard or theme role holds an
   unpurchasable class of the kind. That class becomes the reference for the colour or family match. The other role's
   entry is left in place (see the question). The test checks every plan and every ladder rung: stand-in if and only if
   the kind cannot be bought.
3. **Ring distance no longer wraps (unapproved).** Reverted. The stand-in uses the planner's existing wrapping
   `RingDistance`, and so does the test's `ring_distance`.
4. **The "affordable" threshold changed higher-level armies (unapproved).** A kind that can be bought is now handled
   exactly as before: no cost filter on the region pick, and no cap on DRLA spread variants. The threshold now comes
   from the budget's own rules instead of a new setting (see below). Only a stand-in's own family variants must be
   affordable.

## Design as built

- **Cannot be purchased.** `plan.regionAfford` = the area level's average points × `boss_share_max` × 3/4. That is
  the dearest single monster any budget rule can buy. The largest placement budget is a strong boss at
  `boss_share_max` (8) times the average, and `BossLeader` lets its leader take 3/4 of that. If every usable, uncapped
  class of the favourite kind costs more, no rule of the budget can buy one. No new data setting is used.
  - Stock: Cyberdemon (43) and Spider Mastermind (46) cannot be bought at levels 0 to 4 (level 4 affords about 37.8).
    Every other region kind (Archvile is never a region kind, being Civil War unsafe) can be bought from level 0.
- **Stand-in ranking** (`RegionStandIn`, fixed, no random draw). Eligible: another kind, usable, uncapped, not in the
  army, within the colour lock and family rules, affordable. Ranked by:
  1. Theme fit (engineering call: the owner said the stand-in must fit the theme).
  2. The favourite's colour or DRLA family (owner's first preference).
  3. Nearest kind on the wrapping kind ring (owner's second preference).
  4. Shared look traits.
  5. Dearest.
  If nothing is affordable, the cheapest candidate stands in. That cannot happen with the current data.
- The favourite the stand-in replaces is recorded as `army.regionRef`. The stand-in gets role `standin`, and
  `regionHow` becomes `standin`.

## Failed approaches

- Version 1: "affordable" = 1 average encounter, cost-filtering the favourite at every level, a non-wrapping ring,
  and theme as the 3rd tie-breaker. Rejected (see round 2).
- The first ladder in a fixed cell (10,5) did not have an unpurchasable favourite under the boss-based threshold in
  DRLA (Revenant). The hook now searches for the cell with the dearest favourite.
- The family rule could block the reference pick when the army already held a family class of the kind (idx 997,
  DRLA). Fixed by using the army's own class as the reference.
