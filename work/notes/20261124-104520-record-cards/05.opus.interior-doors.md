# Records 5: doors inside buildings

Read D:\dev\DoomDaggerfall\AGENTS.md first. The survey is `work/notes/20261124-104520-record-types.md`, section 1.2.

## Goal
Building interiors have their doors. RMB interior door records (25,922 in the 920 block templates) become swinging
Doom doors like dungeon doors.

## What we know
- DFU places one action door per record: model `9000 + DoorModelIndex`, at the record's position and `YRotation`,
  swinging by `OpenRotation` (`DaggerfallInterior.cs:1234-1243`).
- `SiteExport.cs` never reads `BlockDoorRecords`, so every interior doorway is an open hole today.
- Dungeon doors already work through `DoorExport.cs` and `door_objects.zs`. Reuse them.
- Locks wait on the owner (backlog *Locked doors with Daggerfall's requirements*). Build doors unlocked. If DFU locks
  any interior doors, report which and by what rule.

## What must stay true
- Entry landings and exits still work (the landing code looks for door planes; make sure new doors do not confuse it).
- NPCs, piles and containers keep their positions.
- Interior conversion time stays within about 10% of today. Measure it.

## How to prove it
- Convert a tavern, a guild hall and a palace interior. Count doors per building and compare with the record count.
- Run the interior through the existing door pose and parity checks.
- Paired session: open and close a door; monsters and NPCs path as before.
