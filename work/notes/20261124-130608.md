## What changed

- `ActionExport.ReadActionRecords` no longer turns an enemy marker (199:15, 199:16) into a flat action record.
  Reason: DFU's `RDBLayout.AddFlat` calls `SetActive(false)` on every enemy marker (`RDBLayout.cs:1253-1255`).
  `AddFlats` still adds a `DaggerfallAction` to it (`:403-406`), but an inactive object cannot be clicked or touched.
  A coroutine also cannot start on it if a chain reached it, and no record chains into any of them (diff below).
  On a fixed marker the field means "passive" (`EnemyReactionTypes.Passive = 99`, read by `AddEnemy`, `:1540`), not
  an action.
- `Program.LoadGeometry` skips a fixed marker whose mobile type (`FactionOrMobileId & 0xff`) is 99, as
  `RDBLayout.AddFixedRDBEnemy` does (`:1484-1487`). There is one, in Wayrest (block S0000080).
- New `--list-markers` (`MarkerCensus.cs`): a census of every marker kind in the 187 RDB and 920 RMB block templates,
  with DFU's and Doomerfall's handling of each.
- Not changed: `Program.cs:283` still notes flat action links for enemy markers in `actionLinks`. That map only feeds
  trapdoor and lid geometry lookups by position, and no chain points at an enemy marker, so this changes nothing.
  I left it alone to keep the geometry identical.

**Still spawning hostile monsters at passive markers.** What a passive castle guard marker should become is the
owner's call (question below). Until then the converter places the same encounter marker as before, with the same
placement hash, so monster ids and drops are unchanged.

**Beyond the 70 passive markers:** Orsinium's blocks S0000020-22 hold 4 more fixed markers with an Action field (29
three times, 100 once). They are just as inert in DFU, so they lose their action records too. Before this change,
Doom put an invisible usable action object at each of them that only logged `DFRULE`. The card expected "70 fewer
flag 99 records, nothing else changed". This is the one extra change, and it follows the same DFU rule.

  _ingredient_` never fires. The same goes for 199:18 in buildings (3,022, for example `O0B10Y05` Valuable Artwork).
