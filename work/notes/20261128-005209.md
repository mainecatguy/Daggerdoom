## Plan

1. Find how "Enhances Skill" works now: `EnhancesSkill.cs` hid slots 4-12 from the item maker and made any power in
   those slots do nothing (shown as "<Language> (no effect)").
2. Give new item maker powers for slots 4-10 a marker so they never mix with classic language powers in the same slots.
3. Map every classic (unmarked) power in slots 4-12 to a playable skill with a fixed table.
4. Show the right skill name everywhere the power is shown (item maker, item info `%mpw`).
5. Test in the real game: item maker list, every language slot, the two Daedra souls, the classic item that carries a
   language, and the new marked powers, each by equipping a ring and reading the live skill value. Run twice and

## What was built

- `Doomerfall/DoomerfallSkillPowers.cs` (new): the marker, the language table and `SkillOf(classicParam, customParam)`.
- `EnhancesSkill.cs`: the item maker lists every playable skill (slots 11-12 stay hidden). Slots 4-10 (Shotguns,
  Automatics, Explosives, Pistols, Rifles, Energy Weapons, Melee) are stored as a **custom enchantment** with param
  `DoomerfallSkill:<SkillName>` (for example `DoomerfallSkill:Shotguns`): this is the marker. DFU already stores any
  power with a custom param that way (`DaggerfallUnityItem.SetEnchantments`), and saves keep it. A classic power in
  slots 4-12 (from a soul, `MagicItemTemplates.txt`, or an imported classic save) has no custom param, so it is always a
  dead language and raises its table skill. Cost stays 900 points for both.
- Melee and Energy Weapons are offered too (owner: "like any other skill"; they are playable skills in slots 4-10).
- `DaggerfallUnityItemMCP.cs`: the item info list (`%mpw`) shows a dead language power under its target skill's name,
  and also lists the marked weapon skill powers (classic code lists only classic powers; one-line hook).
- Souls (`SoulBound.cs`) keep their classic forced param 9 (Daedric): the generic mapping handles them.

## Mapping table (for the owner's review)

Rule: the playable skills are the ones Skill XP can buy (`DoomerfallSkillXp.Buyable`: all except Critical Strike and
the two unused slots), 32 in slot order. The nine classic languages take every 32/9-th one: language k (0 = Orcish ...
8 = Impish) gets playable skill number floor(k * 32 / 9). This spreads them over all skill groups (body, weapons,
stealth, magic, melee) instead of plain round-robin from the top, which would have put all nine on Medical through
Energy Weapons. Each skill gets at most one language.

| Classic language (slot) | Now enhances | Where it appears in data |
|---|---|---|
| Orcish (4) | Medical | old saves only |
| Harpy (5) | Jumping | old saves only |
| Giantish (6) | Pistols | old saves only |
| Dragonish (7) | Melee | "%it of Venom Spitting" (regular magic item) |
| Nymph (8) | Stealth | old saves only |
| Daedric (9) | Backstabbing | Fire Daedra and Frost Daedra souls (forced power) |
| Spriggan (10) | Restoration | old saves only |
| Centaurian (11) | Thaumaturgy | old saves only |
| Impish (12) | Hand-to-Hand | old saves only |

The table is computed from the playable skill list, so if a skill is ever added to or removed from the playable list,
the table moves. That keeps it even but would change old items' skills; if the owner prefers it frozen, it is a
one-line change to a literal array.

## Findings

- `MagicItemTemplates.txt` has only one regular item with a language power ("%it of Venom Spitting", Dragonish). The
  other Enhances Skill items (Skeleton's Key, Chrysamere, Ebony Blade) name real skills and are unchanged.
- Upstream `%mpw` never listed custom-param powers, so a marked power would have been invisible in the item info
  without the hook.

- DFU's `ItemEquipTable.UnequipItem(DaggerfallUnityItem)` returns before it stops the item's enchantments (upstream
  quirk). The inventory and trade windows use the slot overload, which does stop them, so play is unaffected; the test
  uses the slot overload too. Not changed.
- `DFCareer.Skills.ToString()` for slots 4-10 can return the obsolete language alias ("Orcish" for Shotguns), because
  the enum keeps the old names as duplicate values. The first build's marker came out as `DoomerfallSkill:Orcish`; the
  marker now uses a fixed name table. Worth knowing for anyone serialising skill names.

- **Verifier catch (fixed):** an item whose only powers are marked weapon skill powers stores them all as custom
  enchantments, so `legacyMagic` is an empty array. `ItemHelper.GetItemInfo` read `legacyMagic[0]` for books and for
  the default group (jewellery, clothing...) and threw, so the info popup of a crafted gun-skill ring could not open.
  Both reads now also check `Length > 0` (`ItemHelper.cs`, two lines). The test now opens the info popup and `%mpw` of
  a ring, an amulet and a clothing item made with each marked power.
- The inventory's info popup (`DaggerfallInventoryWindow.ShowInfoPopup`) is two boxes: the first from
  `GetItemInfo` (name, condition, worth, weight), then, when `legacyMagic` is not null, a second box (TEXT.RSC 1016)
  listing the powers. A marked-only item has an empty, non-null `legacyMagic`, so it gets the second box. The test
  expands both boxes as the inventory does and requires the second to name the skill; for example
  `Item powers: | Enhances skill Shotguns` on a ring, an amulet and a clothing item. (An earlier version of these notes
  said the popup lists no powers for rings; that was wrong: it only read the first box.)
