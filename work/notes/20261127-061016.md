# Daggerfall menu text at full resolution (run 20261127-061016)

Stopped early: usage limit reached after investigation only. No code changes yet.

## Findings so far

- The UI surface is NOT 320x200. `DoomerfallUi.ChooseSurfaceSize` (`daggerfall-unity-master/Assets/Scripts/Doomerfall/DoomerfallUi.cs:628`)
  sizes it to Daggerfall's `Screen.width x Screen.height`, capped at `DFB_SURFACE_MAX_W/H` (1920x1200). Paired-run logs show
  `ui: menu 4 opened, surface 1280x800`.
- Doom draws that surface scaled to its screen (`UZDoom/src/dd_bridge.cpp` `PumpUi` / `UiRect`), keeping aspect. No 320x200 step there.
- So the blockiness most likely comes from inside Daggerfall Unity's rendering into the custom `UserInterfaceRenderTarget`:
  - Candidate 1: `SDFFontRendering` is off in the paired run's settings (default `defaults.ini.txt:105` is True;
    `DaggerfallFont.IsSDFCapable` requires it plus `sdfFontInfo`). Check the paired run's `settings.ini`.
  - Candidate 2: the render target or panels are drawn at 320x200 then upscaled (check `UserInterfaceRenderTarget`
    CustomWidth/CustomHeight handling and whether `DaggerfallUI` uses the target's size for text scale).
  - Candidate 3: the 1280x800 surface is downscaled when Doom's window is larger (cap 1920x1200; also the Daggerfall
    window may be smaller than Doom's window, since the launcher starts it minimized).
- `dfb_face.display_width/height` in `bridge/doomerfall_bridge.h:313` is documented "in 320x200 HUD units": that is HUD
  layout units, not a resolution cap, but list it in the 320x200 audit.
