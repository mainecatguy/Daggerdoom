Goal: Doomerfall's own tag for rifles, worked out from the weapons themselves where possible. It changes no skill yet.

## How the rule works

The owner's definition, applied by `tools/rifle_tag/derive_rifles.py` to DRLA's own DECORATE:

- **Ballistic:** an ammo type (magazine or reserve) descends from Clip or Shell.
- **Not explosive / energy:** no RocketAmmo or Cell ammo, and not on the existing self-charging energy list in
  `DoomerfallWeaponCategory.zs` (the tool reads that list from there, so they stay the same).
- **Not shotgun / pistol / melee:** no DRLA Shotgun, Pistol or Melee token and no MELEEWEAPON flag.
- **Semi-automatic:** the tool fires the gun on paper with the trigger held forever and finds the loop it settles
  into. It follows each state's next state, keeps the gun's own counters (burst and spin-up guns count shots with
  inventory tokens), treats ammo as always loaded, takes no optional jump (no mods, no perks), and knows that an
  action runs as a state is entered (so `TGUN A 12 A_Refire` refires at once). If the two closest shots are at
  least 6 tics apart, the gun is semi-automatic. DRLA's automatics come out 1 to 4 tics apart and its bursts 2 tics
  apart inside the burst. Its semi-autos come out 7 or more, so there is a clear gap around the line. A gun that never
  fires while fire is held (the Gauss Rifle, which charges and fires on release) is measured pressed once per shot.

Exceptions (3, all owner rulings, in `EXCEPTIONS` in the tool):

- **Assault Chaingun** (RLAssaultRifleChaingun): the rule reads it semi-automatic (shots 37 tics apart). The owner
  says it's an Automatic.
- **Autocannon** (RLAutocannon): the rule reads it semi-automatic (a one-round chamber, 13 tics). The owner says
  it's an Automatic.
- **Assault Minigun** (RLAssaultRifleMinigun): the rule already reads it automatic (its spin loop fires 1 tic apart),
  so this exception changes nothing today. It stays so the owner's ruling doesn't depend on how the tracer reads its
  spin counter. The research measured about 15 tics per shot by hand, so the two disagree there. Either way it is
  not a rifle.

Why the list is generated, not worked out in the game: ZScript can see a state's tics and next state, but not its
action, so it can't tell which states fire a shot. DRLA also gives its type tokens only while a gun is held. So the
rule runs on the DECORATE files, and the game reads the generated class list. `derive_rifles.py --check` (part of the
test) fails if the committed list and the rule disagree, for example after a DRLA update. Classes match exactly, not
subclasses, because each gun was judged on its own data. Without DRLA the list matches nothing, and stock Doom has no
rifles.

Checked against the rifles research (`work/notes/20261126-003658.md`): the Marksman (7), HP Marksman (8), Sniper (37)
and Gauss tap (68) cycles match it exactly. The Scoped Rifle reads 30 against the research's 18 (14 scoped). It is
semi-automatic either way.

## Verification

`python tools/rifle_tag/run_rifletag_test.py D:/dev/DoomDaggerfall-build/uzdoom-skillcore/Release/uzdoom.exe D:/dev/DoomDaggerfall-build/rifletag-test`
(through quiet_run, private configs, 30 s and 60 s timeouts). All 11 checks pass:

- derive `--check`: the committed list matches the rule.
- stock (DOOM.WAD E1M1, doomerfall.pk3 only): starts, no script errors, 76 weapon classes, nothing tagged.
- drla (DOOM.WAD E1M1, play_drlax.bat's DRLA set + doomerfall.pk3): no script errors. The tagged set is exactly the
  owner's rifles (the test's expected set is written from the definition and the research, not from the tool). No
  named non-rifle is tagged (the 3 owner Automatics, Steel Beast, Railgun, all automatic and burst rifles, the energy
  rifles, the Rigelatin rifle, rifle-family pistols). Each tagged gun, held, reads as `precision` or `other`. None
  reads Automatic, Shotgun, Explosive, Energy, Pistol, melee or unarmed.

No engine change. The only new runtime code is a static class check and a test handler behind `dd_rifletag_test`.

## Failed approaches (all inside the tool, kept for the record)

1. Following only the fall-through path, stopping at the first A_ReFire: this read wind-up miniguns as semi-auto
   (25-61 tics, counting the spin-up), the HP Thompson as 14 (it counted the 12 tics of a state that refires at once),
   and burst guns wrongly.
2. Counting Goto lines as states: DECORATE jump offsets count frames only. Before the fix, the Anti-Materiel Rifle
   and Elephant Gun "jumped" into their reloads and never fired.
3. A heredoc wrote real backspace bytes for `\b` in four regexes. They were found and fixed. The file is now checked
   for control bytes.

## Not done / limits

- DRLA modpacks (Firestorm, Sniper and so on) change fire rates. The tag is per class and uses the unmodded gun.
- The NAG (Nanomachic Armament Generator) is a single class with many modes. Its default path reads automatic (3 tics
  apart), so it is untagged. Its M14 mode is a semi-automatic rifle. This is a question for the owner.
- The Light Carbine isn't built yet. The tag holds the class name `DoomerfallLightCarbine`. The `lightcarbine` 01
  card must use that name or change the entry.
