# Doom ammo in Daggerfall's inventory, and arrow weight (20261124-075147)

## Goal

Owner (2026-11-24): bullets and the other ammo types go into Daggerfall's inventory. Weights per round: bullets
0.02 kg, shells 0.1 kg, rockets 0.2 kg, cells 0.02 kg. Base prices per round: 1, 3, 10, 5. Arrows weigh 0.01 kg each.

## Plan

1. Bridge: two new events on the `dfb_doom_item` payload. `DFB_KIND_AMMO` (UZ to DF): Doom's count of one ammo class,
   plus the last delta Doom applied. `DFB_KIND_AMMO_ADD` (DF to UZ): a numbered signed delta.
2. Doom (`dd_items.cpp`): report Clip, Shell, RocketAmmo, and Cell counts each frame they change; apply Daggerfall's
   deltas inside the playsim (as `dfa_add` network events), allowing counts above Doom's maximum (gamedesign.md).
3. Daggerfall (`DoomerfallAmmo.cs`): one stackable item template per ammo type (9101-9104) with the owner's weight and
   price. Mirror Doom's counts into stacks; send Daggerfall-side changes (drop, wagon, trade, pile) to Doom as deltas.
4. Arrows (`DaggerfallUnityItem.cs`): 0.01 kg each, counted against encumbrance.
5. Test tool `tools/ammo` (from `tools/gun_icons`): a paired take run, a load run, and the E1M1 check.

## Design and why

- **Doom stays the live counter.** Guns spend ammo many times a second inside Doom's playsim, and DRLA's weapons read
  Doom's ammo inventory directly. Daggerfall holds the record in its inventory and save, mirrored from Doom.
- **Deltas with an acknowledgement, not absolute sets.** Daggerfall's side sends `+N`/`-N` with a request number. Each Doom
  report carries the last request it applied. Daggerfall's belief of Doom's count is the report plus deltas not yet
  applied, so a change from either side is never lost or counted twice while the other is in flight.
- **Load.** Each side restores its own half of the bundled save. Daggerfall forgets old reports on load, and Doom
  re-reports after both games resume. If the halves disagree, Doom's count wins (it keeps old `-dfsynctest` saves and
  their starting ammo working). See the questions below.
- **New game / test start.** Whatever Daggerfall holds when it enters a game is its side; Doom's first report adds the
  starting ammo to Daggerfall's inventory.
- Loaded magazines (DRLA's `RL<Gun>Clip`) are part of the gun's state, not reserve ammo, and weigh nothing extra.
- Only the player's own inventory counts. Ammo moved to the wagon leaves Doom.

## Failed approaches and fixes along the way

- One item class per ammo type template: `ItemHelper.RegisterCustomItem` throws when the same class registers twice,
  which stopped `DoomerfallBridge.Awake` and broke the whole Daggerfall side. Now the class registers once.
- Relying on the custom templates: Daggerfall rebuilds its template list after the bridge registers, so templates
  9100 to 9104 were gone at play time ("Item template index out of range", stacks showed as "Ruby"). Ammo items now
  carry their own name, weight, and value, and use the group index as their type. `DoomerfallAmmo` adds its templates
  again when it starts mirroring.

## Play-test list

- Open the inventory: Bullets, Shotgun shells, Rockets, and Energy cells appear as stacks with Doom's sprites and
  match Doom's HUD counts. Fire a few shots and reopen: the count dropped.
- Drop part of a bullet stack, close the inventory: Doom's bullet count drops by the same amount. Pick the pile up again.
- Move ammo to the wagon: Doom loses it. Move it back: Doom gets it again, even above Doom's normal maximum.
- Save, load: the counts and carried weight are unchanged.
- Pick up a stack of arrows: carried weight rises by 0.01 kg per arrow.
- The ground pile of dropped ammo uses the placeholder picture (Letter of Credit).

## Findings

- Daggerfall's arrow template has `hasNoEncumbrance`, so `EffectiveUnitWeightInKg` returned 0 for arrows while the
  item info said 0.25 kg per arrow. That is why picking up arrows did not change the carried weight.
- The existing Doom item template 9100 (`DoomerfallDoomItems.Register`) is lost the same way. Doom items survive only
  because each item sets its own weight. Every weight check on one logs "Item template index out of range". It is
  reported as an oversight and left alone here.
- DRLA X's random starting class changes the starting ammo (60 bullets in one run, 0 in another), so the harness
  picks up two boxes to reach the test hook's 60-bullet threshold whatever the start.
