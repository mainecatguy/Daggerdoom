# Talk to stationary NPCs

## Plan

1. Reuse Info's NPC pick (the view ray in `dd_info.cpp`) for Use. Use already handles piles and containers first
   (`DD_UsePress` in `dd_items.cpp`); when no item is in view, it now tries an NPC.
2. Mirror the container route, which already works: Doom asks, Daggerfall answers "window", Doom pauses and opens a
   Daggerfall menu (`DFB_UI_TALK`), and only then does Daggerfall run its own activation, so whatever it pushes is drawn
   into Doom with input routed to it. Closing the window goes through the existing UI close path.
3. Daggerfall runs its own code: `PlayerActivate.ActivateStaticNPC` in Grab mode, or Steal while crouching (Daggerfall
   treats both the same on a static NPC), with Doom's measured distance. A far press gets Daggerfall's own
   "You are too far away" through the Info HUD capture, and no window.
4. Test harness (`tools/npc_dialogue/`) and a Daggerfall test component (`-dftalktest`) that logs whom the talk window
   talks to and closes it.

## Design calls

- **Talk does not depend on Daggerfall's player position.** `FindNpc` looks the NPC up by id among loaded static NPCs, and
  the reach check uses the distance Doom measured along its view ray (Doom units / 0.75 = classic units), compared with
  Daggerfall's own `StaticNPCActivationDistance` (256 classic units = 192 Doom units).
- **Shopkeepers, guild service NPCs, bankers, tavern keepers, and coven NPCs open the plain talk window** for now, through a
  one-line flag in `StaticNPCClick` (`doomerfallTalkOnly`), which goes straight to `TalkToStaticNPC` after Daggerfall's
  quest checks. Daggerfall itself would open their service menu. Services are out of scope for this goal and
  the owner's open question [20261123-221130] covers what Use on a shopkeeper should open, so this is a placeholder
  that keeps every NPC talkable without deciding services. Removing the flag gives Daggerfall's full behavior.
- **Quest checks still run as Daggerfall does**, before talk: a quest Person resource click, a faction listener (which
  makes Daggerfall do nothing), and `TalkToStaticNPC`'s own quest offer window. Skipping them would silently break
  quests; quest work itself is out of scope and untested here.
- NPCs with ShowText actions are ignored, as in Daggerfall.
- The talk window closes on Daggerfall's Goodbye or Escape, and also on Doom's Use key (the key that opened it), as the
  other menus close on the key that opened them.

## Results

`python tools/npc_dialogue/npc_dialogue.py run NAME [--building Tavern]` runs both games minimized with DRLA, DRLA
Monsters, and DRLAX, walks into the building, presses Use (`df_interact`, the same `DD_UsePress` that Doom's own Use
button calls in `p_user.cpp` and the town door check) on up to four NPCs from 56 units, then once from far away.
Daggerfall's `-dftalktest` logs whom the talk window is talking to and closes it through the window's own code.

|---|---|
| General store shopkeeper (merchant, faction 510) | `s1`: talk window, `talking to "Uthywyr Ashford" ... greeting "Well met, stranger."` |
| Tavern, four different NPCs | `t4`: each press opened the window for the NPC Doom aimed at: Uthore Hearthsly, Bedane Greening, Barbyvyra Kingford (talk windows, their own names and name seeds), Evelayne Hawkham (quest offer) |

| Stock E1M1, no bridge | `check`: exit 0, no bridge lines, 0 script errors. DRLA E1M1: exit 0, no bridge lines, 3 script errors and 765 unknown-class lines, the same as the Info and container runs (from DRLA). |

Window open latency: 5 to 40 ms after Doom's request.

## Which NPCs can be talked to

- Stationary NPCs inside buildings: proven (shops, taverns). Every social group opens the talk window, including
  merchants, guild service NPCs, bankers, tavern keepers, and coven members (placeholder, see design calls).
- Stationary NPCs outdoors (`DFNpc` in towns) and in dungeons (`DFDungeonNpc`): same pick and same Daggerfall path. Not
  run. `FindNpc` only finds NPCs inside Daggerfall's loaded range (known limit from the Info task): a far one gives no answer.
- Not covered: mobile townspeople (`TalkToMobileNPC`, a separate task), ShowText NPCs (ignored, as in Daggerfall).
- Steal while crouching: Doom sends Steal, and Daggerfall treats Steal on a static NPC exactly like Grab. Not run (the
  harness cannot hold crouch through a network event).

## Failed approaches

- Harness far press: placing the player straight back from the NPC landed inside walls, and once inside another NPC's
  billboard (distance 0, so that NPC's talk opened). Sweeping angles around the NPC with a sight check fixed it.

## Remaining

- Shop, service, and guild menus (owner question [20261123-221130] and separate tasks).
- Quest offers open, but quest acceptance and turn-ins are untested (separate task).
- Talking to mobile townspeople.
- Outdoor and dungeon NPC talk not run.

## Play-test list

Demo: `D:\dev\DoomDaggerfall-loop\review\npc-dialogue\play.bat` (starts facing a tavern).

1. Go in with Use, look at a patron and press Use (or E). Does the talk window open for that person, readable, with
   mouse and keyboard working? Ask about a topic or two.
2. Close with Goodbye, Escape, the Use key, and E. Does Doom resume cleanly every time, with no stuck keys or a fired weapon?
3. Press Use on someone from across the room: "You are too far away..." in the middle of the screen, no window.
4. Talk to the barkeep: the talk window opens now, not Daggerfall's tavern menu. Is that acceptable until services land?
5. If a patron offers work, the quest offer opens. Try accepting and declining.
6. Crouch and press Use on a person: it should be the same talk window (Daggerfall does the same).
7. Outdoors, Use on a stationary NPC in town (if any are near), and in a dungeon with NPCs.
