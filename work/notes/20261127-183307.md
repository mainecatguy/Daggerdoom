# Paired New Game driver and message boxes (20261127-183307)

Goal: Q&A item 66. Find out whether the paired New Game test driver still stalls at Daggerfall's message boxes. If it
does, find out whether players are affected (keyboard yes/no in Daggerfall popups shown in Doom), and fix that, then the
driver.

## Result: it no longer happens, so this run reports and stops

**In 5 of 5 saved runs, the committed, unchanged driver got through every New Game message box, each in about half a
second. In 3 of 3 saved runs of a separate single-key check, N alone, Y alone, and Enter alone each answered their box.**
Nothing in the repository changes except this note.

An earlier version of this run changed `tools/new_game/run_new_game.py` and added a test tool. Both are reverted,
because the goal says to report and stop. They are now suggestions for the owner (below).

## Evidence: keyboard yes/no for players (3 runs of the single-key check)

The check posts one key per box to Doom's window, the way a player's keys arrive, and never Enter on a Yes/No box.
Each `popupN-stdout.txt` has a timed `sent <key> alone to box <n>` line for every key, a result line for each box, and
`popup keys: PASS`. All 3 runs passed. Each `popupN-df.log` shows the windows changing to match:

| Box | Key | Window after (popup1, popup2, popup3) |
|---|---|---|
| "Is this your race?" Yes/No | N | CreateCharRaceSelect in all 3 (No: back to the list) |
| Same box again | Y | CreateCharGenderSelect in all 3 |
| Class confirmation Yes/No | Y | CreateCharChooseBio in all 3 |
| Reputation box (no buttons) | Enter | CreateCharNameSelect in all 3 |

Each box stayed up 0.92-0.98 s, including the check's own 0.4 s wait before the key.

Y does nothing on the reputation box, because it has no Yes button. That is the same in Daggerfall Unity. Escape does
nothing on boxes that have buttons (`AddButton` sets `AllowCancel = false`, already recorded by
`tools/new_game/run_escape.py`). Both are Daggerfall's own rules, not bugs. That accounts for the Escape half of the
earlier report that the travel box "ignores N and Escape". The travel box uses the same `DaggerfallMessageBox` Yes/No
buttons and the same `DoomerfallInput` route (`DaggerfallTravelMapWindow.cs:1747-1752`). I did not drive it.

## Earlier runs this evening, with no saved logs (not counted)

Before the saved set, I made about 22 launches. Each run's logs were overwritten by the next, because the driver
deletes its logs at start. They are not evidence, but they showed:

- **Full CPU load (16 busy-loop processes).** One driver run hit the 50 s limit on the bonus-skills screen. Its boxes
  had already closed. Another run, and two single-key runs, printed nothing.
- **Stock mode (no `--drla`).** The driver timed out before Doom wrote any log. It always loads
  `doomerfall-drla.pk3` when the staged folder has it, and that file needs DRLA.
- **The single-key check's first version** pressed Y on the reputation box. That box has no buttons, so it stayed open,
  and the check stopped after 3 s with FAIL. This was a mistake in the check, not in the game. The check now presses
  Enter there.
- **The 50 s limit.** With other lanes running, one single-key run went over 50 s after arriving.

## Why it stalled before (best guess, not proven)

All the earlier stalls were between about 04:30 and 06:15 on 2026-11-27, while many lanes were building and testing at
once, and an older Daggerfall build stalled the same way. It passed at about 04:00, and it passes now. A New Game takes
about 36-40 s, longer on a busy machine, and the driver's limit is 50 s. A timed-out run prints the last window it saw.
The old reports also said clicks worked while keys did not. Nothing tonight showed that, and that cause is unknown.

  return of the key problem is told apart from a slow machine.
- Commit the single-key check (`evidence\run_popup_keys.py`) under `tools/new_game/`, if wanted.

No game, engine, mod, or tool changes, so the E1M1 check, builds, and demo do not apply.
