# Paired New Game driver and message boxes (20261127-183307)

Goal: Q&A item 66. Find out whether the paired New Game test driver still stalls at Daggerfall's message boxes. If it
does, find out whether players are affected (keyboard yes/no in Daggerfall popups shown in Doom), and fix that, then the
driver.

## Result: it no longer happens

**The stall did not happen in 16 New Game runs this evening, and keyboard yes/no works for players.** No game code was
changed. The driver got a clearer failure message and a longer time limit, and there is a new single-key popup test.

Build used: `review\batch9-stage`, copied to `D:\dev\DoomDaggerfall-loop\review\newgame-keys` so other lanes' staging
was not touched (integration at 399b9c24, the Daggerfall and UZDoom builds staged at 18:26 today). The DRLA set was
loaded, as in the play folder. Every run went through `quiet_run.py` with `--inside-quiet`.

| Runs | What | Result |
|---|---|---|
| 1 + 1 + 5 | `run_new_game.py create --drla` (Y then Enter on each box) | 7 of 7 reached "both games running". All 3 New Game boxes closed in about 0.5 s each. |
| 2 | Same, every CPU core busy (16 busy-loop processes) | Every message box closed in under 1 s. One run hit the old 50 s limit on the bonus-skills screen. The other got to the summary and printed nothing (see below). |
| 4 | `run_popup_keys.py` (new; one key per box) | 4 of 4 PASS: N alone said No, Y alone said Yes, Enter closed the info box. |
| 3 + 2 | After the driver change: driver x3, popup test x2 | 5 of 5 reached. 2 of 2 PASS. |

What the popup test checks (`tools/new_game/run_popup_keys.py`), with the keys posted to Doom's window as a player's
keys are:

- "Is this your race?" Yes/No: **N** alone goes back to the race list.
- The same box again: **Y** alone goes on to gender.
- The class confirmation Yes/No: **Y** alone goes on to the bio.
- The reputation box after the bio (no buttons): **Enter** alone goes on to the name screen. Y does nothing there,
  the same as in Daggerfall Unity, because that box has no Yes button.

Escape does nothing on boxes that have buttons. That is Daggerfall Unity's own rule (`AddButton` sets
`AllowCancel = false`), already recorded by `run_escape.py`, so it is not a bug. This also explains half of the earlier
report that the travel box "ignores N and Escape". Escape is expected. N uses the same `DaggerfallMessageBox` Yes/No
button hotkeys and the same `DoomerfallInput` route that work above (`DaggerfallTravelMapWindow.cs:1747-1752`). I did not
drive the travel box itself.

## Why it stalled before (best guess, not proven)

All the earlier stalls were between about 04:30 and 06:15 on 2026-11-27. In that window many lanes were building and
testing at once, and an older Daggerfall build with no new code stalled the same way, so the cause was outside the game
change being tested. It passed at about 04:00, and it passes now. I could not bring it back, even with all 16 cores
busy. Two things probably made it worse:

- **Time limit.** The driver allowed 50 s. A New Game alone takes about 36-40 s. A run while other lanes were busy
  took 46 s just to reach the dungeon, and one under full load ran out of time on a wizard screen. A run that times out
  prints the last window it saw, so a box that was slow to close can look like a box that never closed.
- **Unknown.** The old reports also say clicks still worked while keys did not. Nothing tonight shows that. If it
  comes back, the driver now says so directly (below) instead of timing out.

## Changes

- `tools/new_game/run_new_game.py`
  - `TIMEOUT` is now 90 s instead of 50 s. Callers that set their own limit (`--set TIMEOUT=180`, `--limit`) are
    unchanged.
  - If Daggerfall's top window is a message box that ignores Y and Enter 10 times (about 5 s), the run stops at once
    with `result: stuck: Daggerfall's DaggerfallMessageBox ignored Y and Enter N times`. A new window of the same name,
    such as a second box straight after the first, starts the count again. This applies only to the driver's own
    `act`. Callers that replace it, such as `shields_paired.py --click-boxes` and the popup test, are not affected.
- `tools/new_game/run_popup_keys.py` (new): the single-key test above. Use
  `python quiet_run.py --timeout 120 -- python tools/new_game/run_popup_keys.py --review <staged folder> --inside-quiet --drla`.

No game code, engine, or mod changes, so the E1M1 check and the builds do not apply. Nothing a player can see changed,
so there is no demo. The `newgame-keys` folder only holds the test copy.

## Failed or partial attempts

- **Stock runs (no `--drla`).** These time out before Doom writes any log (2 of 2). The driver always loads
  `doomerfall-drla.pk3` when the staged folder has it, and that file needs the DRLA set. This is a setup mismatch in the
  driver's stock mode, not the box problem. It is not fixed, because callers that want stock use folders without that
  file.
- **One run under full load printed nothing.** The second driver run under the CPU stress, and the two popup runs right
  after it, gave no stdout. That run's Daggerfall log reached `CreateCharSummary` with every box closed. The cause is
  probably the stress processes and quiet_run competing for the machine. The same runs passed as soon as the stress
  ended.

## Play-test list

- New Game: on "Is this your race?" press N (back to the race list), then pick a race and press Y. On the class box
  press Y. On the reputation box press Enter. Each should act at once.
- In a running game, open Find Location on the travel map (K), type a town, then press N on "Do you wish to travel
  to ...?". It should close and do nothing. Then do it again and press Y: the travel popup should open.
