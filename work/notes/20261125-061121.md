# Fixed drops: the paired test

Branch `agent/fixeddrops-20261125-061121`, continuing `work/notes/20261124-232246.md` (the seeding itself). Goal: two
fresh New Game runs and a save-reload run, with Daggerfall and Doom together, clear the Privateer's Hold entrance and get
identical drops and gun materials, including at least one real gun pickup through the bridge.

## Plan

1. Build a play folder from this branch: UZDoom, bridge and launcher in this lane's own trees (`uzdoom-items`,
   `bridge-items`, `launcher-items`, configured from this worktree), Unity player, fresh data from this checkout's
   converter. `tools/fixed_drops/paired.py assemble` does it with `scripts/play/install.py`'s functions.
2. Harness `tools/fixed_drops/paired.zs` (test only, loaded as a pk3 by the runner):
   - real New Game (`-dfflow`, character creation driven by `tools/new_game`'s window driver), arrival in
     Privateer's Hold;
   - god mode and no-target from the first tic;
   - waits 10 s (the save run makes a bundled autosave 1 s in);
   - kills every monster whose spawn point is within 1200 units of the start, with one forced blow credited to the
     player;
   - after 8 s, lists every new loose item (class and engine loot seed);
   - takes the gun pickup with the lowest seed with one real Use press, so Daggerfall rolls its material
     (`doomitems: take ... material X ..., floor id N` in Daggerfall's bridge log).
3. Runs: `fresh`, `save` (saves before the kill, otherwise the same), `load` (fresh copies of both games load the save
   run's autosave with `-dfloadtest resume:`), `fresh2`. `paired.py ... compare` checks kill lists, drop lists, the
   chosen gun, and Daggerfall's material and floor id.
4. The whole runner is wrapped in `quiet_run.py`, so the window driver shares the private desktop with the games
   (the launcher is started directly by the runner, not through a nested quiet_run).

## Changes

## Findings

Play folder `D:\dev\DoomDaggerfall-loop\review\fixed-drops-play`, area level 10 (`-dfarealevel 10`), DRLA set.
Outputs in `D:\dev\DoomDaggerfall-loop\review\fixed-drops-paired\result-*.txt`.

1. **The gun and its material repeat in every run.** Every run that reached the take picked the same gun and Daggerfall
   stored the same material from the same floor id:
   - `RLBattleRiflePickup` seed 915556e6 → Steel, floor id 83681699b23d407f (three runs with the earlier kill set);
   - `RLDoubleShotgunPickup` seed 84321393 → Steel, floor id 9f4f7d065b7d6e95 (every run since).
   So the floor item's lasting id (the new `DFB_KIND_DOOM_ITEM_ID` event) and the seeded material work through the real
   bridge.
2. **Save and load are identical.** Kills (112), all 198 drops (class and seed), the gun, material and floor id matched
   exactly between the save run and the run that loaded its bundled autosave.
3. **Final series: `PAIRED FIXED DROPS PASS`.** `paired.py ... series fresh save load fresh2`: all four runs killed the
   same 112 monsters, got the same 181 drops (class and seed, ammo tiers by class), took the same
   `RLDoubleShotgunPickup` (seed 84321393), and Daggerfall stored it as Steel from floor id 9f4f7d065b7d6e95.
   No unseeded drops at all in that series.
   - The pair before it differed by one unseeded `RLBloodSkull` in one game (seed 0, so it was spawned outside any
     loot roll). It did not recur in the next four runs, and its source is unknown: nothing in DRLA, DRLA Monsters or
     DRLAX drops it from a monster death (it comes from map powerup spawners, DRLAX gizmos and player items). Known
     gap; the harness now logs any unseeded drop's target and master (`PDUNSEEDED`) to trace it if it comes back.
4. **Two monsters near the start have no Daggerfall id:** `RLFormerShocktrooper` placed at 780,383 and 920,504, in every
   run (corpse loot seed 0). Their drops are therefore not seeded. Both sit next to `RLEliteCommandoMinigun` mooks
   (904,384 and 800,504), so they are probably extra monsters from a DRLA spawner whose claim went to the commando,
   or monsters that the claim did not reach (`RunClaims` takes the nearest unclaimed monster within 40 units).
   Not fixed: it is in the encounter claim system, not the loot seeding.

### What the test had to control (test harness only, not game code)

- **Civil War.** Privateer's Hold rolls Civil War, so its armies fight each other from arrival. In the first series,
  9 and 14 monsters near the start were already dead at the kill, and after the kill the rest of the dungeon kept
  fighting and dying during the 8 s wait. Those deaths vary with combat, so their drops vary. The harness now freezes
  the level until the kill (`level.SetFrozen`) and makes every other monster dormant (`Deactivate`) at the kill.
- **The kill set** is chosen by each monster's placed spot (`SpawnPoint` within 1200 of 380,1270), not by distance from
  the player, whose arrival spot drifts a few units between games.
- **The new character died** before god mode in one run; god mode and no-target now start on the first tic.
- **Use on the gun hit a corpse's Daggerfall loot pile** (Daggerfall's loot window opened and paused Doom). The gun is
  carried to a clear spot by the start before the Use press; its lasting id does not depend on where it lies.
- Bundled autosaves are named `<character>-autoNN.zds`.

## Known gaps

- The two unclaimed `RLFormerShocktrooper`s (finding 4) drop unseeded loot.
- The one-off unseeded `RLBloodSkull` (finding 3).
- The test freezes Civil War fighting; in real play, which monsters the armies kill before the player arrives differs
  between games, so what lies on the floor differs too, though each monster's own drops are fixed.
- Drops land where each monster dies.

## Play-test list

1. New Game, clear the gunners at the Privateer's Hold start, take a gun, note its material. A second new character:
   same drops, same material on the same gun.
2. Save before the fight, fight, note drops; load, fight again: the same.
3. Leave a dropped gun, leave the dungeon, return, take it: the same material as taking it at once.
4. Plain DOOM.WAD and DRLA without Daggerfall: drops still random between games, as stock.

## Failed approaches

- Wrapping only the launcher in quiet_run: the window driver (EnumWindows) cannot see Doom on the private desktop.
  The whole runner is wrapped instead, and the runner starts the launcher directly.
- A `const MODE` in the harness crashed UZDoom during script compile (access violation, CrashReport.zip in the output
  folder); a static function returning the mode compiles. Not investigated further.
- First kill-set rule (distance from the player) and no freezing: kill counts 95/96/98/103 between games.
