## 1. Floor base light (`hw_flats.cpp`)

The first run's fix (floor special colour) was rejected because the special colour is the object colour, which also
scales dynamic lights and light-amp. This run changes only the **base** light. `HWFlat::DrawFlat` calls
`DD_ExteriorGroundLight` after Doom's normal `SetColor`/`SetFog`. For floors only, and not in a fullbright scene, it
does this when `DD_WeatherMeshLight` says Daggerfall exterior:
- vertex colour = sector light colour x (Daggerfall daylight + Doom extra light / 255). Weapon flashes still brighten.
- soft light level 255 (software light modes) and light parms (1, 0), so there's no distance darkening.

It leaves the object colour, add colour and dynamic light list alone. In `main.fp`, `getLightColor` scales `vColor` by
the light level, and dynamic lights are added after that, so they stay full strength. With no Daggerfall weather line
(stock Doom, `-nobridge`) `DD_WeatherMeshLight` returns false and nothing changes. The mesh layer already used this same
value (`hw_dfmesh.cpp`), so the ground now matches the town mesh at its edge by construction.

Evidence (`seam_shots.py --lights`, spot 26200, `before` = the day/night build, `after` = this build; mean luma by
band, near the horizon to near the player):

| Case | before | after |
|---|---|---|
| snow, level view west | 22.6 / 23.0 / 41.5 | 98.8 / 95.5 / 95.1 |
| night, ground with no light | 2.2 / 2.4 / 7.0 | 16.1 / 16.2 / 19.6 |
| night, ground with an orange dynamic light (radius 320) | 27.6 / 26.8 / 30.1 | 100.1 / 96.1 / 88.5 |
| night, light-amp | 64.9 / 65.2 / 68.5 | 207.5 / 206.9 / 198.3 |

Before and after use different ground textures (green grass vs snow), so absolute values aren't comparable. Use each

and (100.1-16.1)/207.5 = **0.40** after: unchanged. Light-amp still draws the ground fullbright.
`sheet-light.png`. In the walk run at night, imp fireballs visibly light the snow (`sheet-walk-snow.png`, last row).

## 3. Season change (`dd_towncache.cpp/.h`, `dd_treadmill.cpp`)

- `DDTownCache::Entry` records whether it came from a winter file (`T<id>W.ddt`).
- GPU mesh keys include the season (`WINTER_MESH_KEY`, 1<<30). Before, the key was the same in both seasons, so
  swapping the entry would never have re-uploaded the mesh.
- **Distant (LOD) town on the overworld:** `ScanLocations` keeps drawing the current LOD town in its old season while
  the cache re-reads or converts it in the new one. Before this, a season change made it vanish until it was ready.
  Once the new-season entry is ready, the town reloads (`lodTown = -2`, the existing reload path), billboards included.
- **Town the player is in:** `RefreshTownSeason` (called from the in-town tick) requests the new season. When it's
  ready, it replaces `mapEntry` (mesh) and the plain `DFCityFlat` billboards (trees, rocks, lamps; lamps re-register
  through `DD_LightsFlat`). The map and the people (`DFNpc`) are left as they are. Log:
  `DDTOWN season winter: town mesh and 3585 billboards replaced`.
- The cache now drops a read that finishes after the season changed, and re-queues a conversion that finishes after a
  change. Before, a conversion running across a change was marked Failed, because its file has the other season's name.

Evidence:
- `seam_shots.py --case summer-noon --flip <winter noon> --flip-wait 140`, spot 26360 (in the City of Daggerfall's LOD
  square): `DDTM season winter: ground and nature redrawn`, then `DDTLOD town=DDT09183` (reload). Summer ground and city
  turn to snow in place, with no seam (`sheet-flip-lod.png`). Both seasons were already in the cache, so this only shows
  the re-read path.
- The conversion path ran in the paired `snow` run: `DDTCONV group=7154 ok ms=9359`, then

- `seam_shots.py --walk` with the real snow lines: even ground (110/110/106 in snow, 40/41/40 at night) before and after
  a 36-tile walk with window shifts (`sheet-walk-snow.png`).

## Known gaps

- **Sprites (trees, monsters, billboards) still use Doom's sector light with distance darkening.** This was deliberate:
  changing it changes how visible monsters are, which is combat visibility. At snowy night, Doom's trees are much darker
  than Daggerfall's (`sheet-paired-snow.png`, row 3). The ground matches.
- Snowy night sky: Doom shows a dark red band where Daggerfall shows stars (fog colour `160301`/`030201` from
  Daggerfall's line). Sky work, not ground; not investigated.
- Swapping a whole town costs a mesh upload (138 ms in Gothway Garden, 360 ms for a large mesh), a one-time hitch per
  season change. The first swap after a change also needs a background conversion (about 9 s for Gothway Garden).
  Meanwhile the old season stays drawn.
- During that conversion, the overworld still draws the LOD town, but entering it waits until it's ready (as for any
  town not yet converted).
- A saved game resumed in town in a different season gets the new-season mesh, but its billboards come from the save
  (old season) until the next visit.
- In-town nature flats (`SpawnTownNature`) aren't respawned on a swap. Gothway Garden has none (`flats=0`).
