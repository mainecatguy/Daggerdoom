# Fix: Use on NPCs is refused after a real New Game (20261124-044747)

## Cause

After a real New Game, `StartGameBehaviour.FinishNewCharacterStart` starts Daggerfall's `_TUTOR__` and `_BRISIEN`
quests. Both show a message right away: `_TUTOR__` asks "do you want the tutorial?" (`prompt 1010`, line 321 of
`_TUTOR__.txt`), and `_BRISIEN` says message 1025 when the player is in Privateer's Hold (line 245). Each one pushes a
`DaggerfallMessageBox`, and that window has `PauseWhileOpen`, so `UserInterfaceManager.AddWindow` pauses Daggerfall.

Nothing showed that window. Doom shows Daggerfall's windows only while it has a Doom-opened menu open, so this window
sat unseen on top of the HUD and Daggerfall stayed paused. Every feature that checks `GameManager.IsGamePaused`
refused: talk (status 3), Info, items, Doom items, and hotkeys. The quest clock and world time also stood still.
`-dfsynctest` sessions start in town without these quests, so they never saw it.

The `ui: top window is ...` log line is written only while a Doom menu is open, which is why the old log showed no
window between `new game: ... paused False` and the refusals.

## Fix

Daggerfall can now ask Doom to show a window it opened by itself. The architecture already says Daggerfall's windows
show over Doom while Doom pauses, so this follows that rule.

- `bridge/doomerfall_bridge.h`: `DFB_KIND_UI_ASK` (25, DF to UZ) and `DFB_UI_DAGGERFALL` (7). Bindings regenerated.
  The schema hash changed, so the launcher, bridge DLL, UZDoom and Daggerfall Unity must all be rebuilt together. The
  installer does that.
- `DoomerfallUi.cs`: when no Doom menu is open, play is running, and Daggerfall's top window is not the HUD for
  0.25 s, it sends `UI_ASK` and repeats it every second until Doom opens the menu or the window goes away. Opening
  `UI_DAGGERFALL` shows the window that is already there. The menu closes the usual way once Daggerfall is back at
  the HUD.
- `dd_bridge.cpp`: on `UI_ASK`, if no menu is open and `UiCanOpen()` allows it (not during a door, save or load), Doom
  opens `DFB_UI_DAGGERFALL`. No Doom key closes it. The player answers it in Daggerfall's window.
- `DoomerfallTalk.cs`: a refusal now logs its reason (load running, no game, or paused with the top window's name).

Alternatives I rejected: skipping the tutorial quest would also hide `_BRISIEN`'s message and every later quest
message, and Daggerfall would still freeze on the first one. Closing such windows automatically would throw away
quest text and choices.
