# Real Daggerfall drops from slain Doom enemies

Branch `agent/drops-20261123-212059`. Demo: `D:\dev\DoomDaggerfall-loop\review\real-enemy-drops\play.bat`.

## Plan

1. Decide each dungeon placement's Daggerfall enemy the way Daggerfall does, without the time seed or the player's level, so it never changes.
2. Roll the drop by building a real Daggerfall `EnemyEntity`, so the loot table, class equipment, Orc equipment, map, potion, and recipe all come from Daggerfall's own code.
3. Use the area level wherever Daggerfall used the player's level.
4. Prove it with a separate audit build against the real tables, then run the death route again (stock, DRLA, save and load).

## How each enemy's Daggerfall type is chosen

- **Quest foe:** the foe's own `FoeType`, plus any items the quest queued on it. This did not change.
- **Fixed marker (editor record 16):** the marker's mobile ID, as `RDBLayout.AddFixedRDBEnemy` reads it. Type 99 is skipped, as Daggerfall skips it.
- **Random marker (editor record 15):** follows the player's `AlternateRandomEnemySelection` setting.
  - Classic (the default): Daggerfall seeds its generator with the dungeon's location ID and fills 256 land and 256 water slots from the dungeon type's encounter table. The marker's `Flags` picks the slot. This is exactly Daggerfall's list, except the area level replaces the player level. When `Flags` is 0, Daggerfall rolls slot 1 to 6 from a time-seeded generator. Doomerfall takes it from the placement hash instead.
  - Alternate: Daggerfall's index window, which is the area level / 20 times the table length, plus or minus the dungeon's variance. The draw inside the window comes from the placement hash instead of a time seed.
  - The marker uses the water table when it is below the block's water level, as in Daggerfall.
- A Slaughterfish, Dreugh, or Lamia at a dry marker is not placed in Daggerfall, so that Doom monster drops nothing.
- The type is a pure function of the location, the placement, the setting, and the area level, so save, load, and re-entry cannot change it. The rolled drop is kept in the ledger, as before, so even a changed setting cannot change a drop that already happened.

## Area level

- Gold, ingredient chances, weapon, armor, and magic item levels, class enemy level, the poison chance, and the encounter table window all read the area level, never the player's level. During the roll, the player entity's level is set to the area level and restored at once in a `finally` block.
- Materials use the owner's approved tier odds (`work/notes/20261123-material-tier-proposal.md` in the main checkout), active only during a Doomerfall drop roll. Shops, real Daggerfall enemies, and normal launches keep Daggerfall's own formula.
- **How an area's level is defined is still the owner's open question** (backlog item "Area level replaces player level"). Until then every area is level 1, which matches what a new character sees in Daggerfall. `-dfarealevel N` (0 to 30) sets it for tests. Levels below 1 count as 1 for loot, as the tier proposal says.

## Engine changes (Daggerfall Unity, all small)

- `RDBLayout.ChooseRandomEnemyType(table, level)`: an overload; the original now calls it with the player's level.
- `FormulaHelper.DoomerfallMaterialRoll`: null except during a Doomerfall drop roll.
- `DaggerfallEntity.DetachFromGameEvents()`: a temporary entity would otherwise stay subscribed to two static events forever.
- No UZDoom or bridge change.

## Findings

- Daggerfall itself does not keep a random placement's type stable. It seeds layout with `DateTime.Now.Ticks`, and its loot code reseeds Unity's generator for every enemy. Only its save file keeps the type. So "the type Daggerfall would have placed" can be matched exactly only for the classic slot lists. Slot choice for `Flags` 0 and the alternate draw use the placement hash.
- Daggerfall rolls loot at enemy creation, not at death. Doomerfall rolls at death. The result is the same distribution, and it avoids keeping state for monsters that never die.
- The worktree's `gamedesign.md` is older than the main checkout's. The "world does not scale to the player", "surprise", and "material tiers" sections exist only in the main checkout.

## Failed approaches

- Reusing the monster death demo's Doom binaries. They predate the New Game merges, so the tool now builds bridge, launcher, and UZDoom from this branch (`real_drops.py build`).
- Running the audit inside the dungeon through the death route. The route never got past the town door (see "Not verified").

It is copied into the Unity project only for that build and removed afterwards, so the shipped game has no audit code. It ran inside a real bridged Daggerfall game, using Privateer's Hold read from the real `ARENA2` data. Result: `AUDIT PASS`, with 0 failures.

## Play-test list

1. Run `D:\dev\DoomDaggerfall-loop\review\real-enemy-drops\play.bat` (DRLA, DRLA Monsters, and DRLAX loaded). Press Use at the Privateer's Hold door.
2. Kill monsters. Archer, Rogue, and other class placements should leave piles with a weapon and often armor. Rats and bears should leave nothing.

5. Kill the quest Imp. The quest kill still counts once.
