# Daggerfall's top-of-screen messages in Doom: Daggerfall Unity's font (run 20261127-074304)

Continues `work/notes/20261127-055226.md`. That run made every Daggerfall HUD message show and animate in Doom, below
a band kept for the compass. Its verifier failed the look: Doom drew the classic FONT0003 pixel font, and Daggerfall
Unity draws the smooth SDF face by default (`SDFFontRendering=True`), so Doom's rows were a different typeface and about
1.7x wider.

## Plan

1. Find exactly what Daggerfall Unity draws: the asset, glyph metrics, baseline, scale, and shader.
2. At data-build time, rasterize those glyphs into a high-resolution UZDoom folder font with the same advances and
   baseline. Keep the export reusable for the later `menufont` card.
3. Draw it in `Doomerfall.zs` at Daggerfall Unity's size, with its shadow offset.
4. Matched side-by-side frames from a paired run. Then the E1M1 checks.

## What Daggerfall Unity draws (from the code)

- `DaggerfallFont.LoadSDFFontAsset("Fonts/FONT0003-SDF")`: a TextMeshPro asset,
  `Assets/Resources/Fonts/FONT0003-SDF.asset`, made from **Kingthings Petrock** at point size 250, with a 2048x2048
  Alpha8 SDF atlas. The atlas is stored in the asset as hex (`_typelessdata`), so the export reads the exact glyphs
  Daggerfall Unity samples. No TTF rasterizer is needed. The font is a freely usable modder's resource
  (`TESFonts/Readme_TES_Fonts.txt`) and is in Daggerfall Unity's own repository, not Daggerfall game data.
- Size: scaling ratio = classic glyph height (7 for FONT0003) / point size x the panel's y scale. Advance, bearing
  and box all use that ratio. SDF glyph spacing is 0.
- Baseline: row top - 2 + 7 Daggerfall pixels (`DrawSDFGlyph`, `TextLabel.DrawLabelSingleCallSDF`). The asset's
  `faceInfo.baseline` is 0.
- Edge: `Daggerfall/SDFFont` shader, `smoothstep(0.5 - fwidth, 0.5 + fwidth, dist)`.
- Shadow: `TextLabel.DrawLabel` offsets the SDF shadow by 0.4 x the classic (1, 1). The old Doom code used 1 pixel.

## What changed

1. **Converter: `FontExport.WriteSdf`** (`tools/dungeon_converter/FontExport.cs`). `--runtime-assets` now also writes
   `fonts/dffont3sdf` into `ddruntime.pk3`: 202 glyphs (ASCII and Latin-1, plus the asset's few others) at 8 texels per
   Daggerfall pixel. Each texel samples the atlas inside the same glyph quad Daggerfall Unity draws and applies the
   shader's smoothstep. Three things work around how UZDoom places folder-font glyphs:
   - UZDoom advances a folder font by each glyph's whole texture width plus one global `Kerning`. So every glyph
     texture is its rounded advance plus a shared margin K wide, drawn at a shared left offset (PNG `grAb` chunk), with
     `Kerning -K`. The net advance is exactly Daggerfall Unity's advance, and ink that overhangs the advance box is kept.
   - All glyphs have one canvas height, and the top offset puts the baseline where Daggerfall Unity puts it.
   - `FontHeight` = 7 x 8, so the mod finds the texel scale as `GetHeight() / 7`.

   The asset is found with `--dfu-fonts <folder>`, or `daggerfall-unity-master/Assets/Resources/Fonts` above the
   working folder or the converter. `scripts/play/install.py` passes it explicitly. If the asset is missing, the export
   prints why and Doom uses the classic font.

   Reuse: `WriteSdf(zip, asset, classicHeight, folder)` works for any `FONT000N-SDF.asset`. `ClassicHeight` reads
   the matching FNT height. The `menufont` card can call it with FONT0000/0001/0002/0004.
2. **Mod** (`mods/doomerfall/src/zscript/Doomerfall.zs`): font order `dffont3sdf`, then `dffont3`, then SmallFont. The
   draw scale is the panel scale / texels per pixel. Rows stay 7 + 1 Daggerfall pixels apart. The shadow is 0.4 pixel
   for the SDF face and 1 for the classic font. Layout, hold times, scroll, and the compass band are unchanged from the
   last run.
3. **Test** (`tools/hud_messages/hud_messages.py`): both games now get the same screen size (1252x721, which fits
   quiet_run's private desktop), and Daggerfall Unity's frames are its own screen size. In the last run, Daggerfall
   Unity's text was squashed: `-dfhudtestsize` drew into a 1252x721 render texture while the SDF labels use
   `GL.LoadPixelMatrix(Screen.width, Screen.height)` (1280x800). Doom's window size counts its frame (asking for
   1280x800 gives a 1252x721 screen), so the script adds that border for Doom. `pairs` now refuses to compare frames of
   different sizes instead of pasting them side by side.

## Where the messages go, and why

Unchanged from the last run (see its notes). Rows are centred as in Daggerfall Unity but start 26 Daggerfall pixels
lower (`HudCompassBand`). A row scrolling away is clipped at the band's bottom edge, as Daggerfall Unity clips at the
screen top, so no row ever draws over the planned top-centre compass. Mid-screen text stays at Daggerfall Unity's row
146.

## Known gaps

- **`SDFFontRendering=False` is not followed.** Doom always uses the SDF face when it exists. Following the setting
  would need Daggerfall to send it over the bridge (one bit). This is small, but it adds to the bridge contract for a
  setting players rarely change in a paired run, so it is left out.
- **Resolution.** The glyphs are baked at 8 texels per Daggerfall pixel. At 1252x721 (scale 3.6) Doom shrinks them
  about 2.2x without mipmaps, and at 1080p (5.4) about 1.5x. At 4K (10.8) it enlarges them 1.35x. 1080p and 4K were
  not tested: quiet_run's private desktop is smaller. If shrinking looks grainy, 6 is the other reasonable value. It is
  one constant, `FontExport.SdfTexelsPerPixel`, and the mod reads it from the font.
- With `gl_texture_filter` set to nearest (a retro setting), Doom would scale the glyphs without smoothing. Daggerfall
  Unity's SDF always smooths.
