## Findings

### Explosives "the shot's splash reached the player" (DRLA) — DRLA's random class, not this change

DRLA hands the player a random class. The failing runs (batch `b-explosives/drla.out`, `b-explpair/.../log-exppair.txt`)
and only those carry `RLFireangelPerk` ("You feel safer..."): the **Demolitionist**, whose player class has
`RadiusDamageFactor 0` (`DoomRL_Arsenal_1.1.5/actors/classes/Demolitionist.txt` line 11), so no splash ever reaches
them, own rockets included. The passing runs rolled other classes (Trespasser and so on). That is also why the "off"
rule set failed, where no Explosives rule applies.

Fix (test harness only): both explosives harnesses set the player's `RadiusDamageFactor` back to 1 and log
`EXPTEST/PAIRED radius factor 0.00 -> 1` when they do (`tools/explosives/explosives_test.zs` StripArmor,
`explosives_paired.zs` WorldTick). The check itself is unchanged.

Proof with the class forced (scratch wrapper adding `+playerclass Demolitionist` to the launch): harness logged
`EXPTEST radius factor 0.00 -> 1`, DRLA **109/109**.

### Explosives paired "cycles at every step" — race in the test script

The script stopped the game once it saw `PAIRED end N skill=100`, but cycle 11 had started at 75 and ended after the
skill rose to 100, so the script killed the game while cycle 12 (the real skill-100 cycle) was in flight; the analysis
then (correctly) found no whole cycle at 100. Fix: wait for the end of a cycle that *started* at 100
(`tools/explosives/explosives_paired.py`). This only makes the script wait longer; the checks are unchanged.

### attributes_paired "RLRailgun (gun): no hit boosted (0/1)" — pre-existing, from the Energy perks

Log line: `energy: hit AttrBleeder direct: 200 -> 205 (x1.0250) tic 1374 by RLRailPuff`. The railgun is an Energy
Weapons gun, and the test character has Energy Weapons 5, so the Energy damage perk adds 5000 bp x 5/100 = +2.5%. The
attributes test wants a gun hit to be exactly unchanged (it tests that Strength does not boost guns), so it fails.
The old Daggerfall code sent the same 250 bp for that skill (`DoomerfallEnergyRules.Fill` at 6e7645b0:
`MaxDamageBp * clamped / 100`), so the result is the same before and after this change. The attributes test last
passed at 575c8dc3 (2026-11-27 04:44), before the Energy perks landed (f4d7d17a, 13:09). Left alone: it belongs to
the Energy/attributes tests, not this card. Reported as an oversight.
