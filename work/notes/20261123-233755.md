# Area levels computed in Daggerfall (run 20261123-233755)

Goal: Daggerfall computes every location's area level and the wilderness terrain level at runtime, from
the approved proposal (`work/notes/20261123-225515-area-level-proposal.md`, `tools/area_level/`), and the
enemy drops read it instead of a fixed level 1. `-dfarealevel N` stays as a test override.

## Plan

1. Port `area_level.py` to C# in its own file, `Doomerfall/DoomerfallAreaLevels.cs`. Same tables,
   seeds, hash, and floating point order, so levels match bit for bit.
2. Rank stability: read classic `MAPS.BSA` and `POLITIC.PAK` straight from Arena2 with fresh `BsaFile`
   and `PakFile` objects, not through `MapsFile`, so world data mods that add locations or repaint
   regions cannot move classic ranks. Only the classic count in each names record is read (what DFU's
   `ReadLocationCount` reads). A location a mod adds gets a level by placing its score among the sorted
   classic scores of its size class (`PlaceAmongClassic`).
3. Cost: build once on a worker thread, started from the bridge's `Update` as soon as DFU knows its data
   path. The first lookup joins the thread if it is not done. Measure both.
4. Wire in: `DoomerfallDrops.AreaLevel(location)` returns the override if given, else the location's
   dungeon level (or terrain level if it has no dungeon). `DoomerfallMonsters.BuildPlacements` passes the
   current dungeon and keeps the level for `Roll`, which runs right after for the same map.
5. Verify with a test hook (`-dfarealeveldump <dir>`, in `DoomerfallAreaLevelsTest.cs`, no line in any main
   class: it self-starts from `RuntimeInitializeOnLoadMethod`) and `tools/area_level/compare_runtime.py`,
   which compares every location and every land pixel with the script. Then a real paired drops run.

## Decisions (ordinary engineering calls)

- Lookups: `ForLocation` (dungeon and terrain), `ForMapPixel` (wilderness), `ForCurrentPlace` (dungeon
  level inside a dungeon, otherwise terrain of the player's map pixel). Only drops use them today.
- Water and off-map pixels count as terrain 1, as the script does (Mantellan Crux at pixel (1, 1)). The
  proposal says Crux "should get an override" but gives no value, so its dungeon level stays the formula's.
- If the table cannot be built (missing file), drops fall back to level 1 and the monsters log line says why.
