# Use on a building's wall names it and marks it on the map (run 20261125-000154)

Goal: Use on a Daggerfall building's wall (not its door) does what Daggerfall's Info does on a building: shows its
name and marks it discovered on the town map. Doors keep working as before.

## What was already there

- Doom's Info control (`netevent df_info`, `UZDoom/src/dd_info.cpp` Press) already sends `DFB_INFO_BUILDING` with
  the world point the view ray hit. Daggerfall (`DoomerfallInfo.cs`) finds the building whose footprint holds that
  point and runs `PlayerActivate.DoomerfallInfoBuilding`, which is Daggerfall's own `ActivateBuilding` in Info mode:
  `PlayerGPS.DiscoverBuilding`, then the building's display name as HUD text (plus "closed" text for a shut shop).
  Daggerfall's HUD text is captured and drawn by Doom where Daggerfall draws it.
- Discovery is what Daggerfall's town map reads: `ExteriorAutomap.cs:674` shows a building's nameplate only when
  `PlayerGPS.GetDiscoveredBuilding` finds it. So "marked on the map" = discovered in `PlayerGPS`.
- Doom's Use: `TickTownDoors` (`dd_treadmill.cpp`) handles town doors on a fresh Use press (96-unit reach, 60° cone),
  after `DD_UsePress` (items, piles, NPCs) has had its chance.

## Plan / what changed

Reuse the Info path; no bridge change (layout hash unchanged, so existing test folders still connect).

- `dd_treadmill.cpp` TickTownDoors: when a fresh Use press reaches the town door search and no door is in reach,
  call `DD_UseWall` (one line). Doors, items and NPCs take the press first, exactly as before.
- `dd_items.cpp` `DD_UseWall`: forwards to dd_info with the bridge session, only on generated maps in a bridge session.
- `dd_info.cpp` `DD_InfoUseWall`: outdoors only; picks along the view ray like Info (an NPC or monster in front
  blocks it); only a wall hit (`TRACE_HitWall`, so Use on the ground or sky does nothing) sends `DFB_INFO_BUILDING`.
  Daggerfall decides from its footprints whether that wall is a building's; a non-building wall is silent, like
  Daggerfall's Info on a plain wall.
- `DoomerfallInfo.cs`: the building log line now says whether the building was on the map before and after the press
  (log file only).

Reach: the same as Info (Daggerfall's 3072-unit activation ray at Doom scale), since the goal is "what Look/Info mode
does". Doom's own Use "oof" on a plain wall is unchanged (it is Doom's P_UseLines, not touched).

Engine change inactive elsewhere: everything sits behind `useRules` (a generated Daggerfall map), a bridge session and
`DD_AREA_EXTERIOR`, and only runs from TickTownDoors, which runs only on town maps with doors.

## Known gaps

- Wilderness spots with no town doors at all skip TickTownDoors' door search, so a Use on a lone building there would
  not name it. Every building in Daggerfall has a door, so this should not happen on converted towns.
