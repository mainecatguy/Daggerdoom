# skillbasics 01: Daggerfall interaction skills work and level as in Daggerfall

Goal (owner, 2026-11-25): Lockpicking, Pickpocket, Mercantile, Etiquette, Streetwise and Medical work exactly as in
Daggerfall and gain skill through Daggerfall's own use-based advancement. No perks.

## Plan

1. For each skill, find where Daggerfall Unity uses it and where it tallies it (`TallySkill`), and whether Doom routes
   the player to that code in a Doomerfall session.
2. Fix what is not routed. Prefer Daggerfall's own code over copies.
3. Prove each tally in a paired run with one test component that logs the six skills' tallies, plus a route harness.
4. Write the result table, the manual section and a demo.

## Where Daggerfall uses and tallies each skill (read from the code)

| Skill | Used in | Tallied in | Routed from Doom before this run? |
|---|---|---|---|
| Lockpicking | `FormulaHelper.CalculateInteriorLockpickingChance` (doors), exterior building lock roll in `PlayerActivate` | `DaggerfallActionDoor.AttemptLockpicking`, `PlayerActivate` (building doors) | Dungeon doors: yes, by the `lockpick` lane (`DoomerfallLocks.ApplyAttempt`: Daggerfall's chance drives the owner's minigame, one tally per attempt). Building doors: no, Doom does not lock building doors (`DoomerfallTransition.cs`: "Doom does not lock building doors yet"). |
| Pickpocket | `FormulaHelper.CalculatePickpocketingChance` | `PlayerActivate.Pickpocket` (Steal on a wanderer or a human enemy); shop-shelf and house-container stealing (`DaggerfallTradeWindow`, `DaggerfallInventoryWindow`) | Containers and shelves: yes (Steal mode lane). **Townspeople: no.** `DoomerfallTalk` forced Grab on a townsperson ("pickpocketing townspeople is not enabled"). |
| Mercantile | `FormulaHelper.CalculateTradePrice` (all buy/sell prices; Daggerfall Unity has no haggle dialog) | `DaggerfallTradeWindow` after each completed trade | Yes: Use on a merchant opens Daggerfall's merchant menu and trade window (`PlayerActivate.DoomerfallUseNpc`). |
| Etiquette | `TalkManager.GetReactionToPlayer_0_1_2`, polite tone | same, first polite question per talk session; court window | Yes: Use on an NPC or a townsperson opens Daggerfall's talk window. |
| Streetwise | same, blunt tone | same, first blunt question per talk session; court window | Yes, as Etiquette. |
| Medical | `FormulaHelper.CalculateHealthRecoveryRate` (Doomerfall scales the result by 3, owner's rule) | `DaggerfallRestWindow.TickVitals`, once per hour rested; the exhaustion collapse | Yes: the rest key opens Daggerfall's rest window (`DoomerfallRest`). |

Advancement: `PlayerEntity.RaiseSkills` (run when a rest ends and after fast travel, at most every 6 game hours) treats
all six like any other skill. Doomerfall only skips the removed language slots there.

## What I changed

- **Pickpocket on townspeople.** `DoomerfallTalk.OnUse` keeps Doom's Steal mode for a townsperson, and
  `PlayerActivate.DoomerfallTalkToMobileNpc` became `DoomerfallUseMobileNpc(npc, mode, distance)`, which runs
  Daggerfall's `ActivateMobileNPC` in that mode. So a crouching Use on a townsperson is Daggerfall's own Steal: once per
  person (the stand-in keeps `PickpocketByPlayerAttempted`), its 128-unit reach, its roll, its tally, gold on success,
  and on a failure the Pickpocketing crime and `SpawnCityGuards`. Doom already sent Steal for a crouching Use and already
  shows "Sneaking"; no engine change.
- **Test only:** `DoomerfallSkillBasicsTest.cs` (`-dfskillbasicstest <file> [prime]`, starts itself, no hook in a game
  class). It logs each tally of the six skills; in a talk window asks "Where am I?" polite then blunt through
  `TalkManager`; in a rest window presses Rest Until Healed (after taking HP to a quarter) and clicks away the closing
  message. `prime` starts each skill one use short of advancing and runs Daggerfall's skill check after a tally.
- `tools/skillbasics/` (route harness and runner), `--skilllog` in `tools/lockpick/paired/run_paired.py`, and
  `tools/townsperson_talk` now expects a crouched Use on a townsperson to pickpocket.
