## 1. PDA Classes page (already done in `b9ba1acb`, checked)

`player.pdap:19-34` builds `PDA_CLASS_<GetActorClass(0)>_NAME/_ABILITIES/_STORY/_HEIGHT`. It trims 3 characters only
when DoomRPG is loaded (`DRPGDRLAActive`), which Doomerfall never loads, so the key is
`PDA_CLASS_DoomerfallPlayer_NAME`. LANGUAGE lookups ignore case, so `drla-src/LANGUAGE.txt`'s
`PDA_CLASS_DOOMERFALLPLAYER_*` match. The portrait is `DRLA_ClassIcon[PlayerClass(...)]`; our class is index 0, which
shows `PPDAMAR1/2`; `drla-src/graphics/PPDAMAR1.png`/`PPDAMAR2.png` are 1x1 transparent, so no Marine portrait.
Contained: only `doomerfall-drla.pk3` has them, it loads only in bridged games, and the Marine can't be chosen there.
Bridged probe: `pda name "No Doom class" portrait 1x1`. **Known limit:** the PDA page was not opened on screen (play-test).

The only perk items given outside a class's own code: this Maestro familiar. The rest are Bunker and PhaseSisters
giving perks to themselves (`Bunker.zscript:460`, `PhaseSisters.zscript:153,215`) and the Commando's own givers. Apart
from these, DRLA keys class behavior on perk items (round 1 notes), and our class has none. The Renegade armor equip
(`NormalArmors.txt:137`, `RLShellshockPerk`) and the Commando kick (`Fist.txt`, `RLBerserkerPerk`) take their no-perk
paths, as the bridged run below shows (10% armor, 10 stamina per kick).

**Maestro familiar: can a bridged player get it?** Traced by reading the code; not tested in game.
- `Trigger()` is called only from `DRLAX_MaestroFamiliar.FamiliarTick` at `Level.Time == 70`, while the familiar is
  out (`Special.zscript:1626-1638`).
- A familiar comes only from the Familiar Deployer gizmo's menu (`FamiliarMenu.zscript:252`, then
  `spawnfamiliar:` in `Gizmos.zscript:36-47`). The menu offers only familiars in the `DRLAX_familiarunlocks` CVar
  (`HasUnlocked`, `FamiliarMenu.zscript:163,274,320`).
- `Maestro` is written to that CVar only by `GameComplete` (the only `WriteUnlock("Maestro")` in DRLA X), which is
  unreachable in bridged play (above). The play folder keeps its own `run/uzdoom.ini`, so unlocks earned in standalone
  DRLA X (a different config) don't carry over.
- So in normal bridged play the Maestro never appears. Ways around it: typing the CVar in the console, DRLA X's debug
  net event `debug_spawnfamiliar` (`FamiliarBase.zscript:19-36`), or copying an ini that has the unlock.

**Known limit (not blocked):** if a bridged player does get the Maestro, they get a temporary DRLA class perk for that
level. Marines and other DRLA classes get the same thing (any perk but their own), so it is a familiar feature, not a
class. Blocking it would mean replacing DRLA X's familiar ZScript in our pk3, which goes beyond this card. Whether DRLA X
familiars and gizmos (deployer, mod reviser, weapon recycler, demon statue, quests) should exist in bridged games at all
is a design call, so I raised it as a question for the owner. Gizmos do spawn on bridged maps (`WorldLoaded`,
`Gizmos.zscript:103-107`, every 2 to 3 map loads). A Familiar Deployer can appear only once the unlock CVar is not
empty or after 16 gizmos (`Gizmos.zscript:332-373`), and it only offers familiars that are unlocked.

## 3. Machine proof inside the dungeon

**Why round 1 saw no dungeon report:** after arrival Daggerfall opens its start message box in Doom (`ui: Daggerfall
opened menu 7`), which holds Doom paused (`pauseext=1`), and the test had stopped answering windows once both games
were running. The driver now answers any Daggerfall window (menu 4 or 7) before and after arrival.

**Probe** (`tools/no_class/probe/zscript.txt`, test-only, loaded only by the test): once, in the first non-overworld map
for `DoomerfallPlayer`, from `WorldTick`:

- Stamina: readies `RLFist` and calls `FireWeaponAlt` whenever the fist is ready, for 6 s: DRLA's own kick states
  take the stamina. (Plain punches take 1 each and DRLA's regen of 1 per 10 tics outpaced them: 12 drains, low 99.)
  Then waits for DRLA's `RLStaminaRegen` ENTER script to refill it. Injected buttons would not work here:
  `P_PlayerThink` runs before `WorldTick` (`p_tick.cpp`), and the next tic's input overwrites `cmd`.
- Armor: a 20-point hit (`DamageMobj`, type None) with no armor, then gives `RLGreenArmorPickup` and uses it as the Use
  Item key would (DRLA wants a second use to put it on), then the same hit again.
