## Plan

1. **Door from map data** (`DoomerfallFindNpc.BuildingDoor`). Daggerfall's town scene is inert under Doom and may hold
   no `DaggerfallStaticDoors`, so the building's door is computed from the block data exactly as `RMBLayout.AddModels`
   places models and `GameObjectHelper.GetStaticDoors` their doors: building key -> block x/y and record, record
   matrix x model matrix, first `DoorTypes.Building` door centre. World units as `TownRoster` (whose townspeople already
   line up in Doom): location rect origin + block * 4096 + block-local / GlobalScale. Falls back to the building's
   origin if its models carry no door. The dungeon entrance (key 0) still uses the scene doors (unchanged).
2. **Lenient matching** (`Score`): 0 whole name, 1 name start, 2 word start, 3 anywhere, then 4 + typos when every typed
   word is the start of some word of the name or within 1 edit (3-5 letters) / 2 edits (6+); edits are Levenshtein
   with adjacent swaps, also against a name word cut to the typed length (a partial word with a typo). Closest first.
3. **Pick list**: new flag `DFB_FIND_LIST` (`dfb_info_text.style` on FIND_NPC; no layout change, no protocol bump). In
   list mode Daggerfall answers an empty query with every Person of every active quest, and a typed query with matching
   quest NPCs first, then everyone else. Doom always forwards a list answer to the menu (never auto-picks, never clears
   the current marker until a pick). The menu opens with the quest list under the text box; typing re-asks after a
   180 ms pause (from the drawer, since a parent menu's ticker does not run while the text box is open); Enter with one
   match picks it, with several moves to the list (arrows/Enter/mouse), with an empty box moves to the quest list.
4. Test: the driver picks case (a) from the opening list (Enter, Down to its row, Enter), types (c) with a typo and (b)
   as one word of the name. The test component now picks its test building from block data (the scene had none).

## Findings

- Why the last run's test building was always key 0 ("test building"): the scene had no buildings, and the block-data
  fallback required interior people records; it found none. Now any record with exterior models counts. Daggerfall's
  `Residents` scan relies on the same people records, so it now logs how many it scanned (see results).
- Building key 0 is never 0 in Daggerfall: `MakeBuildingKey(0,0,0)` returns `1 << 24` (`buildingKey0`).
- Build output for this lane is `D:\dev\DoomDaggerfall-build\<part>-quiet` (the lane's own `../DoomDaggerfall-build`
  is outside this session's allowed folders); `findnpc.py` now uses those when present.

## More findings during the run

- **The test town is two Daggerfall locations stitched into one Doom map.** `T07154.ddt`'s `DDTOWN` has two rects: the
  Privateer's Hold dungeon (Daggerfall's `CurrentLocation`, no buildings, not a townsfolk location) and Gothway Garden,
  a 175-building town about 23,000 Daggerfall units (~600 m) away. So every building on that map belongs to a location
  that is *not* Daggerfall's current one, which is why both last run's test building and `Residents` came up empty
  ("residents scanned 0"). Fix: `Towns()` lists the current location plus every location within one map pixel
  (32768 units, an engineering call; 8192 was too small for this case) of the player, from the 3x3 map pixels around
  them. Quest NPCs, building doors and residents are searched in all of them. A nearby location's label names it
  ("in the test building, Gothway Garden").
- **Doom's text box ignores Enter while empty** (`textentermenu.zs`), so an "Enter on the empty box goes to the list"
  design can never work. The menu now opens with the list focused (arrows, Enter, mouse) and typing any letter opens
  the text box with that letter (characters in the first 250 ms are ignored, so the N that opened it does not type).
  If no active quest names anyone, it opens straight on the text box.
- The second Unity build seemed to finish but wrote no new player (no new log; possibly the project was still locked
  by the build that had just exited). The DLL timestamp is the reliable check; rebuilt with full paths.
