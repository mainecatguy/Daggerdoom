# Gun skills core (Shotguns, Automatics, Explosives) — 2026-11-26

Goal: add the carded gun skills to Daggerfall's skill system within the 35 skills by removing the monster
languages, send them to Doom, and give every Doom weapon a category. No perk effects.

## What was built

### Daggerfall: skills (slots reused, count stays 35)
- `DFCareer.Skills`: slot 4 = **Shotguns**, 5 = **Automatics**, 6 = **Explosives** (were Orcish, Harpy,
  Giantish). Slots 7–12 (Dragonish … Impish) keep their enum names but are **removed**: hidden everywhere
  (`DFCareer.IsRemovedSkill`). The old names Orcish/Harpy/Giantish stay as `[Obsolete]` aliases of 4–6.
  - Why keep names: saves store career skills as enum *names* and `SaveLoadManager.Deserialize` uses
    `AssertSuccessWithoutWarnings`, so an unknown name would make an old save fail to load. Old "Orcish" now
    reads as Shotguns; old "Dragonish" reads as slot 7 and is then remapped (below).
- `DaggerfallSkills`: the stored fields for 4–6 are renamed `Shotguns/Automatics/Explosives`. An old save has
  no such field, so the new skills start at Daggerfall's default for an untrained skill (random 3–6) instead of
  inheriting the unrelated language value. Values for 7–12 are kept in the save but unused.
- Governing stat (shown on the sheet): Shotguns STR, Automatics AGI, Explosives INT. Advancement multiplier 2
  (same as Daggerfall's melee weapon skills). Both are provisional engineering calls (question below).
- Character sheet: the new skills appear wherever the class puts them, otherwise in Miscellaneous. Removed slots
  are left out of Miscellaneous (`DaggerfallEntity.GetMiscSkills`), out of the class maker (they have no name), and
  out of the Enhances Skill enchantment list.
- Classes: vanilla Mage and Sorcerer list Dragonish and Daedric as minors, one Knight-type class lists Orcish.
  `DFCareer.RemapRemovedSkills` (run when a class file is read and when a save is loaded) replaces each removed
  language with a gun skill the class does not already have: language L → gun (L−4) mod 3, else the next free one.
  So Mage/Sorcerer get Shotguns + Explosives as minors, the Orcish class gets Shotguns (slot reuse). Every class
  keeps 12 listed skills (an empty slot would crash `GetLiveSkillValue`).
- Biography answers that gave language bonuses now give nothing for those (`BiogFile`).
- Languages no longer pacify monsters (`FormulaHelper.GetEnemyEntityLanguageSkill` returns None for monster
  kinds; Etiquette/Streetwise for people, vampires and liches is untouched). `IsLanguageSkill` is always false.
- Guilds: languages removed from every guild and temple skill list. Fighters Guild: Orcish→Shotguns,
  Giantish→Explosives, plus Automatics, in both promotion and training lists (so gun skills can be trained).
- Names: "Shotguns", "Automatics", "Explosives" (localization keys `shotgunsSkill` etc. with English fallback).

### Bridge
- `DFB_SHEET_FORMAT_VERSION` 2 → 3 (slot meanings changed), new `DFB_SKILL_SHOTGUNS/AUTOMATICS/EXPLOSIVES` = 4/5/6.
  Bindings regenerated. The sheet already carried all 35 skills (base and live), so no layout change.
- Both sides' sheet log lines now end with `shotguns b/l automatics b/l explosives b/l`.

### Doom: weapon categories (`mods/doomerfall/src/zscript/DoomerfallWeaponCategory.zs`)
- `DoomerfallWeaponCategory.Of(weapon)` → Other, Melee, Pistol, Shotgun, Automatic, Precision, Explosive, Energy;
  `SkillSlot(category)` → 4/5/6 for Shotgun/Automatic/Explosive, −1 otherwise.
- Signs: MELEEWEAPON flag / stock classes / DRLA type tokens; ammo (either ammo type) descending from RocketAmmo
  or Cell. Precedence is the proposal's lean: Melee > Explosive > Energy > Shotgun > Precision > Automatic > Pistol.
- Known gap: DRLA gives its type tokens only while a gun is held (Select gives them, `RLRarityTokenRemover` takes
  them), so an un-held DRLA gun is known by ammo only. Perks apply to the held gun, so this is enough for now. A
  static generated table would cover un-held guns but would commit a list derived from DRLA's files.

## Tests
- `tools/weapon_category/run_weaponcat_test.py <uzdoom.exe> <work>`: stock (no DRLA) and the DRLA set, selects
  each sample gun with `+set dd_weaponcat_test 1` and checks the category.
- `bridge/test/sheet_test.py <demo>` (existing) with the extended `DoomerfallSheetTest`: loads an old
  pre-skills save if the demo has one named "PreSkills", raises Shotguns before the save and Explosives after it,
  then reloads and starts a new character. Doom's `sheet: read` lines must match every published sheet.

## Results
- Builds: Daggerfall Unity `CliBuild result: Succeeded`. UZDoom Release, bridge DLL and launcher built into
  `D:\dev\DoomDaggerfall-build\{uzdoom,bridge,launcher}-skillcore`.
- Weapon categories: `run_weaponcat_test.py` **PASS** (stock and DRLA). Stock: Fist and Chainsaw melee, Pistol
  pistol, Shotgun shotgun (slot 4), Chaingun automatic (5), Rocket Launcher explosive (6), Plasma Rifle and BFG energy
  (DOOM.WAD has no Super Shotgun). DRLA: RLShotgun, Combat, Double and Autoshotgun are shotguns; RLChaingun, Minigun
  and Uzi are automatics; Rocket, Missile and Grenade Launchers are explosives; Plasma Rifle, Plasma Pistol, Laser Rifle,
  Railgun and BFG are energy; RLChainsaw melee; RLPistol pistol. Logs: `review/skill-categories/run/*.log`.
- Plain Doom with the new exe: DOOM.WAD E1M1 loads ("E1M1 - Hangar"). With the DRLA set it runs and shows the
  same DRLA script errors ("translation" line 1, DRLA Monsters menudef) as the older `uzdoom/Release` build, so
  this change did not cause them.
- Paired sheet test (`bridge/test/sheet_test.py review/skill-core`):
  - The old save (Mage, saved before this change with Dragonish and Daedric as minors) loads. Its minors become
    Shotguns (shown in the log as its alias name "Orcish") and Explosives.
  - Shotguns 3 → 8 before the save; Explosives 5 → 25 after it; the reload brings Explosives back to 5 and keeps
    Shotguns at 8. A new character publishes small values (5/3/6).
  - Every Doom `read` line has the same values and checksum as Daggerfall's `published` line for that version.
  - Overall **FAIL** on the strict "Doom read every published version" check. Run 1: Doom skipped v8, which was
    published 4 ms before v9 in the test's original level-up step. Run 2: Doom attached late and missed v1–v4.
    Doom only reads the newest version, so this check depends on timing; it is not a skill problem. I did not
    weaken the check.
