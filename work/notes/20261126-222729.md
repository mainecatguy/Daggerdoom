# Travel map danger word for dungeons only (2026-11-26, run 222729)

## Goal
Owner (2026-11-26): show the travel map danger word only for dungeons. A city's word followed its palace dungeon's level
(`Level.Area`, see `20261126-184614.md`), which misled about the streets.

## Plan
1. `DoomerfallTravelHint.ForLocation` returns no word unless the place is a dungeon. Both the hover label suffix and
   the "Danger:" line in the travel confirmation box go through it, so one check covers both.
2. "Dungeon" = the five location types Daggerfall's own travel map **Dungeons** filter button hides
   (`DaggerfallTravelMapWindow.GetPixelColorIndex`, indices 0-4): DungeonLabyrinth, DungeonKeep, DungeonRuin,
   Graveyard, Coven. Engineering call: it matches what the player already sees grouped as dungeons on that map.
   Cities, villages, hamlets, homes, farms, temples, cults and taverns get no word.
3. Extend the existing `-dftravelhintshots` test (its own file) to report the place type and the word the hint
   actually shows, and add a confirmation-box shot for the city.
4. Manual: `manual.md` does not mention the danger word or the travel hint (grep for danger/travel map/hover), so no
   change is needed.

## Findings
- Area levels themselves are untouched; only the travel hint display changed. Encounters still use `Level.Area`.
