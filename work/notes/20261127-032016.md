# 20261127-032016: Ammo without a material has a plain name (ammoname 01)

Goal: Regular ammo shows only its own name (Bullets, Shells, Rockets, Energy Cells) in Daggerfall's inventory and
shops, Doom's pickup messages and HUD, and the look label. Tiered ammo keeps its material ("Silver Bullets"). Old saves
show the new name.

## Plan

1. Find every place an ammo name is built. Found three:
   - Daggerfall: `DoomerfallAmmoTiers.Name(type, tier)` (`daggerfall-unity-master/Assets/Scripts/Doomerfall/DoomerfallAmmoTiers.cs`).
     Item name, long name, item template name, info popup, HUD lines ("Loading ..."), and every log line use it.
   - Doom: `DoomerfallAmmo.zs` built "Regular bullets" twice, in the loaded ammo HUD (`RenderOverlay`) and in
     `DoomerfallAmmoPickup.PickupMessage`.
   - Look label: `dd_items.cpp ItemName` uses the pickup's Tag, else its `Inventory.PickupMessage` property. DFAmmo
     classes had neither (they override the `PickupMessage()` function instead), so the label showed the class name
     (`DFAmmo_Clip_0`).
2. Change the name rule on both sides, without an engine change.
3. Verify each place with real runs, and that an old save shows the new name.

## What changed

- Daggerfall: each ammo type has an item `name` ("Bullets", "Shells", "Rockets", "Energy Cells"). `Name()` returns it
  alone for Regular and "<Material> <name>" for the others ("Silver Bullets"). `lowerName` ("shotgun shells") stays for
  sentences such as "You have no other shotgun shells." The Regular info popup says "Bullets: no damage bonus."
  instead of "Plain bullets: ...".
- Old Daggerfall saves: a save holds only the template index (9101-9104 for Regular) and `ItemName` is computed from it,
  so an old stack already shows the new name. `GetSaveData` now also writes the new name over the stored `shortName`,
  so the next save no longer carries "Regular bullets".
- Doom: each of the 40 `DFAmmo_<type>_<tier>` classes has a default `Tag` with its name. The pickup message
  ("Picked up 10 Bullets.") and the HUD (`DoomerfallAmmoTiers.AmmoName`, `clearscope` so the render code can call it)
  read that tag, and the look label reads it through `ItemName`. Because it is the class default, a pickup in an old
  Doom save gets it too (Tag is serialized only when it differs from the default).
- Title case. Names were "Silver bullets"; they are now "Silver Bullets", as the goal card writes them.
- "Shells", not "Shotgun Shells": the goal card lists "Shells". Judgment call; one line in `DoomerfallAmmo.Types`
  and four tags change it.
- `manual.md` (Ammo pickups) and `gamedesign.md` (ammo tiers line) say how ammo is named.
- Test tools: `tools/ammo/ammo.py` parsed "<Tier> <kind>" from Daggerfall's log lines; it now splits names with
  `split_name` (a name without a tier word is Regular). It also points at a new review folder and this lane's builds,
  because `review/doom-items`, `review/pickups` and the `merge-skillcore` builds no longer exist.
- New `tools/ammoname/`: a Doom-only test (no bridge) of tags, HUD name, pickup message, and an old Doom save.

## Findings and failed approaches

- First Doom run: `AmmoName` was a play-scope function called from `RenderOverlay` (ui scope): script error. Made it
  `clearscope`.
- The `uzdoom-quiet` engine build (03:03) was older than the Agility merge (`DD_SheetStat` missing), so the mod did not
  compile on it at all. Rebuilt it incrementally; I made no engine changes.
