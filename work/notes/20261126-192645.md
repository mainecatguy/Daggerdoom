# 20261126-192645: weapon types in a gun's Daggerfall description (weapontypes)

## Goal

A Doom gun's Daggerfall item description shows its name and the weapon skills it counts as ("Plasma Rifle. Types:
Energy"), plus a brief description where the mod's data has one, matching the tags the skill code uses, for stock and
DRLA guns. Add the player-facing rule to `manual.md`.

## Plan (as built)

1. **The problem with the skill code's tags.** `DoomerfallWeaponCategory.Both(Weapon)` reads DRLA's
   `RL*TypeWeapon` tokens from the player's inventory, and DRLA gives them only while a gun is held. A gun in
   Daggerfall's inventory is not held (often not even in Doom's inventory), so its tokens can't be read at run time.
2. **Token table.** `tools/weapon_types/derive_weapon_tokens.py` reads which tokens each DRLA gun's DECORATE gives
   (`A_GiveInventory("RL...TypeWeapon")`, reusing the rifle tool's DECORATE loader) and writes
   `mods/doomerfall/src/zscript/DoomerfallWeaponTokens.zs` (167 guns). `--check` fails when it is stale.
3. **Same rules, two token sources.** `Both`'s rules moved unchanged into `BothWithTokens(weapon, tokens)`. `Both`
   builds the token bits from the held gun's inventory exactly as before; the new `BothOfClass(class)` uses the class
   defaults and the table. So the description and the skill code cannot drift apart by rule, only by token source,
   and the test checks the token sources agree for every gun it holds.
4. **Types text.** `DoomerfallWeaponTypes.Types(class)`: the first and second category names that have a skill
   (Pistol, Shotgun, Automatic, Explosive, Energy, Melee, Hand-to-Hand), then "Rifle" where `DoomerfallRifleTag` tags
   the gun. Precision and Other have no skill, so they add nothing; a gun with nothing shows "Types: none".
5. **Brief.** DRLA has a PDA description for every gun in `language.weapons` (`PDA_WEAPON_<class without RL>_DESC`;
   213 of 213 DRLA guns with type tokens map by that name). Each description has one quoted summary line, for example
   "Your trusty 10mm pistol. It may be nice, but better find something stronger." The brief is that line, with color
   codes removed. Stock Doom has no weapon descriptions, so stock guns get no brief.
6. **Transport.** Doom already sends a class's sprite and display name to Daggerfall when Daggerfall first draws the
   item (`DFB_ITEM_ART_SLOT`). `dfb_item_art` grew `types[64]` and `brief[256]` (header 144 -> 464 bytes; bindings
   regenerated, schema hash changed, so both games must be rebuilt together). `dd_items.cpp` `SendArt` fills them by
   calling the two ZScript functions; with no Doomerfall mod loaded the functions are not found and the fields stay
   empty. This runs only in a bridge session, so stock UZDoom and E1M1 are untouched.
7. **Daggerfall.** `DoomerfallDoomItem.GetInfoTokens` for a gun: "<Doom name>. Types: <types>", the brief wrapped at
   44 characters, then the existing Material and Weight lines. Before Doom's answer arrives it falls back to the old
   first line (the item name).

Daggerfall owns the item and its description; Doom owns weapon data and sends the facts. No combat, skill choice or
category changes: `Both` gives the same answers as before (checked by the held-vs-class comparison and the existing
weapon category test).

## Findings

- The owner's example "Plasma Rifle. Types: Energy, Automatic" does not match the skill code: by the precedence the
  owner approved, a cell-fed Plasma Rifle is only Energy (the two-skill rule pairs Energy only with Pistol or
  Shotgun). The description follows the skill code, so it says "Plasma Rifle. Types: Energy". Raised as a question.
- The Assault Rifle Chaingun, Assault Rifle Minigun and Autocannon are Automatics by owner ruling, but carry DRLA's
  single-shot rifle token, so the skill code reads them as Precision (no skill). Their description says "Types: none"
  until the skill code maps Precision. This is the existing state of the skill code, not something this card changes.
- Rifle-tagged guns show "Rifle", though no skill code uses the Rifles skill yet (the rifle tag changes no skill;
  `work/backlog/rifles-skill.md`). The card asked for the tags once rifletag exists, so they are shown.

- Daggerfall stores a DRLA gun by its **pickup** class (`RLChaingunPickup`), not the weapon class. The first
  end-to-end run showed empty types for that reason; `WeaponText` now goes through `dd_items.cpp`'s existing
  `WeaponOf` (pickup to weapon, the same rule DoomerfallGuns.zs uses).
- Only some DRLA guns have a quoted summary line (`\cu"..."\c-`). The others (most advanced and exotic guns) have
  lore paragraphs, so the brief falls back to the first sentence, cut at a word with "..." past 200 bytes (the
  Elephant Gun's first sentence is the longest). About 8 DRLA guns put stat lines (`Fire rate: ...`) first; those
  lines are skipped.
- `RLNanomachicArmamentGenerator` also has no types (no ammo, no category).

## Failed approaches / mistakes caught

- `return BothWithTokens(...)` in ZScript passes on only the first of two return values. The existing weapon category
  test caught it (energy pistols lost their second skill); fixed by unpacking into locals first.
- ZScript static functions cannot see class-scope `static const` arrays, and `out` is a keyword.
