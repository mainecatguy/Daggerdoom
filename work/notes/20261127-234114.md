# DDLOC lines off the screen (run 20261127-234114)

## Change

All 20 `DDLOC` prints (12 in `UZDoom/src/dd_locations.cpp`, 8 in `UZDoom/src/playsim/dd_treadmill.cpp`, including the
orange and red warnings the card's count of 16 left out) now use the existing `DD_DebugPrintf`
(`playsim/dd_log.h`) instead of plain `Printf`. Text is unchanged. One include added to `dd_locations.cpp`.

**Differs from the card's suggestion.** The card proposed `PRINT_HIGH | PRINT_NONOTIFY`, which keeps the lines in the
console. `DD_DebugPrintf` is what run 20261124-202353 set up for exactly this (76 other calls), and the written rule is
that diagnostics reach the screen *or the console* only behind a flag. So:

| | screen | console | stdout and `+logfile` |
|---|---|---|---|
| normal play | no | no | yes |
| `dd_debugmessages 1` | yes | yes | yes |

If you want them in the console in normal play, it is `Printf(PRINT_HIGH | PRINT_NONOTIFY, ...)` instead.

## About `uz.log`

`run\uz.log` is the `-dfbridgelog` file. DDLOC lines were never in it, before or after (0 lines in a baseline run). The
lines tools parse are in UZDoom's `+logfile` log (`run\log-NAME.txt` in the test harnesses) and stdout; both still get
them (29 lines in both the baseline and the new run). `play.bat` passes no `+logfile`, so in a normal play session they
are now written nowhere you would look unless you add `+logfile` or `dd_debugmessages 1`. That is already true of the
other Doomerfall diagnostics.
