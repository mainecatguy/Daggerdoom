# Ammo does not appear in Daggerfall's inventory (20261124-195226)

## Goal

Owner play test (2026-11-24, play folder from `integration` at `044211d`, DRLA set, critical): ammo does not appear in
the inventory. Find out why and fix it.

## Plan

1. Read the owner's own session logs in the play folder before guessing.
2. Fix what they show.
3. Prove it in a paired New Game with the play folder's setup (DRLA, DRLA Monsters, DRLAX), through a save and a load.

## Findings

- **Daggerfall did hold the ammo.** The owner's session log (`D:\dev\DoomDaggerfall-loop\play\run\df.log`, session
  `000079dc`, 19:39) shows the whole sync working after a real New Game with the DRLA set:
  - `ammo: Doom changed the count, Daggerfall holds Clip 40; Shell 5 ... stacks [Regular bullets x40 ...] [Regular shotgun shells x5 ...]`
    right after arrival (DRLA X's starting ammo).
  - Tiered pickups: `ammo: picked up Silver bullets x40`, `Adamantium shotgun shells x8`, `Ebony bullets x20`, ...
  - Shots: `Clip 40 -> 38 -> 28 -> 27 -> 4 -> 0`, later 160 -> 159, 239 -> 233, and so on.
  - Saves: `save 1: ... Doom items 3 [RLChaingunPickup x1] [Regular bullets x40] [Regular shotgun shells x5]`.
- **The window hid it.** Since `3d8826e` (gun pickup rules), Doom guns and armor are listed on the inventory's
  **Weapons & Armor** tab (`DoomerfallDoomItem.InWeaponsAndArmorTab`). Ammo stacks are `MiscItems` and were left on
  **Clothing & Misc**, so the guns and their ammo sat on different tabs. Daggerfall's own ammo, arrows, is on Weapons &
  Armor. The ammo sync's tests (`075147`) passed because they clicked items directly and never looked at a tab.
- Nothing differs in the DRLA setup itself: DRLA guns' reserve ammo is still `Clip`, `Shell`, `RocketAmmo` and `Cell`.

## Fix

`DoomerfallDoomItem.InWeaponsAndArmorTab` also returns true for `DoomerfallAmmoItem`, so ammo is listed on Weapons &
Armor with the guns, like arrows. It is the one place the tab is chosen. The trade window inherits it, so a shop's
player-side list shows ammo there too. It is not on Clothing & Misc any more.

Judgment call: Weapons & Armor, not both tabs. Arrows set the precedent, and an item on one tab only is how
Daggerfall's window works.

## Test

- `-dfinvtabstest` (`DoomerfallInventoryTabsTest.cs`, starts itself, no hook in game classes). In a bridge session,
  each time both games agree on the counts (`DoomerfallAmmo.Settled`) and the stacks have changed (including after a
  load), it runs the real inventory window's tab filter on every tab and logs which tab lists each ammo stack, with
  Doom's counters. `PASS` means every ammo stack is on Weapons & Armor only.
- `tools/ammo/inherit_desktop.py`: stands in for `quiet_run.py` inside a harness that is already wrapped in
  `quiet_run.py`. `run_new_game.py` drives Doom's window with PostMessage and cannot see a window on a nested private
  desktop (oversight from run 123655). Wrapping the whole harness keeps everything on one private desktop, so nothing
  needs `--user-desktop`.
