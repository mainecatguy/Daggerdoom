# usekey: Doom's own Use key is Doomerfall's interact key (2026-11-24)

Goal: whatever the player binds as Doom's Use does all of Doomerfall's interaction (Grab, Steal while crouching, talk,
shops, containers) as well as doors and switches, with no extra bind. Regular WADs keep normal Use.

## What was wrong

The engine already sent Doom's Use through Doomerfall's interaction (P_CheckUse calls DD_UsePress first, and the town door
check in dd_treadmill.cpp does too). The owner saw two separate keys because of the play folder:

- UZDoom's default binds put `+use` on **E** (`wadsrc/static/engine/defbinds.txt`).
- `scripts/play/install.py` wrote a `play.bat` that, on first launch, ran `+bind e "netevent df_interact"`. That replaced
  Doom's Use on E with the interact-only event (no doors, no switches, no town doors), and the setting was then saved in
  the play folder's `uzdoom.ini`, so every later launch kept it. Doom's Use was left on no key at all (space is Jump).
- The Doomerfall Controls menu also offered a separate "Interact" control.

## What changed

- `scripts/play/install.py`: `play.bat` no longer binds E. Its comment now says Doom's Use (E) does everything.
- `mods/doomerfall/src/MENUDEF.txt`: the "Interact" control is gone from Doomerfall Controls; a comment says why.
- `UZDoom/src/dd_bridge.cpp`: `MigrateInteractBinds`, run once on the first bridge frame (after the command line's
  `+bind`s). Any key bound to `netevent df_interact` becomes `+use` again, so the owner's existing play folder config
  (E = df_interact) is fixed without deleting it. Only in a bridge session; it writes `binds: key N was the old Interact
  control, now Doom's Use` to the bridge log. The talk window's extra close key for df_interact was removed with it.
- `netevent df_interact` itself is kept as an event: many test harnesses send it. No control binds it now.
- `UZDoom/src/dd_items.cpp`: comment only.

My call on "should a separate bind remain": no. Nothing needs it, and a second key invites the same confusion.

## Test: tools/usekey

`usekey.py` assembles `D:\dev\DoomDaggerfall-loop\review\usekey` (this lane's UZDoom, bridge and launcher builds, this
checkout's Daggerfall Unity build and converter, data from review\doom-items, town and interiors from
review\stationary-npcs). Each run uses a fresh private `-config`, so Doom's **default binds** apply, and no extra binds.

Every press is Doom's real Use button: the harness prints `UKUSE` and holds still, and the runner appends `use` to the
QA channel inbox (`-ddqa`, dd_qa.cpp), which sets BT_USE in the next built ticcmd, the same bit the `+use` control sets.
So each press goes through the town door check, P_CheckUse and DFActionHandler exactly as a key press does. Nothing in
these runs sends `netevent df_interact`.

## Failed approaches

- Setting `players[0].cmd.buttons |= BT_USE` from a harness WorldTick does nothing: p_tick.cpp runs DDTreadmill_Tick and
  P_PlayerThink **before** the WorldTick hook, and the next tic's command replaces the bit. The QA channel's use press,
  which goes into the built ticcmd, is the honest equivalent of a key.
- Interiors in review\doom-items' cache were in an old format ("unreadable, rebuilding"), and its old converter never
  finished the rebuild, so the first runs stalled at "Opening...". Fixed by copying converted interiors from
  review\stationary-npcs and building this checkout's converter (`D:\dev\DoomDaggerfall-build\usekey-converter`).
- Several piles in Privateer's Hold sit on high ledges; standing "40 units east" dropped the player hundreds of units.
  The harness now picks the pile lying closest to its floor.

## Known gaps

- Steal is tested by holding the player crouched (crouchfactor 0.5) rather than through a Crouch key press; the QA channel
  has no crouch command. DD_UsePress treats both the same.
- The shop route does not leave the building again by Use; town doors are covered on the way in (both runs), and the
  interior exit uses the same TickTownDoors code.
- Other lanes' older demo folders still bind E to df_interact on first launch; with a build from this branch the
  migration turns it back into Use.

**Owner change (2026-11-24, before merge):** `MigrateInteractBinds` and the test tool's `--old-bind` route were removed. The owner does not want permanent source code for a one-time config problem.
