### Frame cost in dense woodland

`python tools/nature/frame_cost.py` (new). Four sessions at 1280x720, flats on, off, on, off (`+dd_natureflats`).
Each warps to woodland pixel 122,257, stands still facing four ways for 3 s each, then runs east for 15 s across a
chunk shift. Frame times come from `RenderOverlay`. The window held **4,349 to 4,390 flats** (not the ~14,000 the first
run guessed). The machine was loaded by other lanes, so the medians drift between sessions (flats-off ranged from 11.2
to 17.2 ms standing).

| | Flats on | Flats off |
|---|---|---|
| Standing, median frame | 16.7 ms (17.3, 16.2) | 13.0 ms (17.2, 11.2) |
| Standing, p95 | 24.9 ms | 23.8 ms |
| Running, median frame | 22.4 ms (23.5, 21.2) | 15.4 ms (15.7, 15.0) |
| Running, p99 | 77.7 ms | 57.5 ms |
| Worst frame (chunk shift) | 237 ms | 227 ms |

So the flats cost about **1 to 7 ms per frame** on this machine, most clearly while moving. The shift hitch is the
terrain's, with or without flats. Per tic the flats cost little: `NOINTERACTION` actors take the short path in
`AActor::Tick`. The frame cost is the hardware renderer handling about 4,400 sprites in an open map where every sector
is visible. **Performance risk:** on a slower CPU this could be a large share of the frame. If it matters, a fix that
keeps the look would be to batch far flats into one mesh, as Daggerfall Unity's billboard batch does, using the
existing `hw_dfmesh` path. Distance culling would also work but would change the look. I did neither. Logs:
`D:\dev\DoomDaggerfall-build\nature-tests\framecost\log-framecost{0..3}.txt`.

### Kind and density against Daggerfall Unity

The old DFU desert shot (pixel 227,477) was black in every run (`dfu2`, `dfu4`, `dfu8`). The pixel is next to the
southern sea, so I did not look into why and used an inland desert pixel instead: **565,391** (climate 224, archive
503, found as the middle of a block of desert pixels in `DDNATURE`). DFU dump: `nature-tests\dfu9`; Doom: `doom7`.

Flats per map pixel, as Daggerfall Unity draws them (`drawn_*`, read from its billboard batch) and as Doom places them:

| Pixel | Climate | DFU drawn | Doom | Density correlation, 16-tile blocks |
|---|---|---:|---:|---:|
| 122,257 | woodland | 4,402 | 4,390 | 0.85 |
| 565,391 | desert (inland) | 1,128 | 1,098 | 0.40 |
| 227,477 | desert (coast) | 1,160 | 1,168 | 0.49 |

Density matches within 3%. Desert flats are spread evenly, so their block counts vary little, and the correlation
there is mostly noise. The sprite set is the same archive per climate: Doom uses DFU's own climate-to-archive rule and
all 31 records. Side by side (top DFU, bottom Doom, 1280x720): `review\nature-flats\screenshots\woodland.png`,
`desert.png` (both show sparse dead trees, cacti and rocks) and `mountain.png` (pines). Doom's ground is green
everywhere, also in desert and mountains, and its sky is a forest sky. That is the terrain texture and sky, which are
outside this goal.
