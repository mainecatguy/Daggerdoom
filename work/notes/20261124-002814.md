# Travel map danger hint (20261124-002814)

Goal: players see how dangerous a place is in Daggerfall's travel map before they travel, as a word, not a number.

## Plan
1. Read the runtime area levels (`DoomerfallAreaLevels.cs`) and the travel map (`DaggerfallTravelMapWindow`, `DaggerfallTravelPopUp`).
2. Choose word ranges from the real level distribution.
3. Show the word where the player reads the name: the hover label at the top of the region map, and the
   "Do you wish to travel to ..." box that Find Location opens.
4. Test hook that drives the real window and takes screenshots. Build, run, look.

## What was built
- `Doomerfall/DoomerfallTravelHint.cs`: level to word, cached lookup for a travel map location, and the extra
  confirmation line. It never waits for the ranking on the hover path (the label is redrawn each frame and fills in
  as soon as the worker finishes). The confirmation box waits, because it is a one-off click.
- `DoomerfallAreaLevels.cs`: two small additions, `IsFinished` (non-blocking, starts the worker) and
  `ForMapId` (lookup without loading the whole `DFLocation`).
- `DaggerfallTravelMapWindow.cs`: two one-line hooks.
  - Hover label: `Daggerfall : Castle Necromoghan (Very hard)`.
  - Find Location confirmation box: a `Danger: Very hard` line under the place name.
- The level shown is `Level.Area`: the dungeon level when the place has a dungeon, otherwise the terrain level
  around it. This is the same value enemy drops use, and it comes only from the place's own level, never its type.
  Cities with dungeons (Daggerfall, Wayrest, Sentinel) therefore show their dungeon level.
- Teleport travel (Mages Guild) uses the same window, so it shows the hover label too.
- Normal travel is unchanged: no input, timing, cost or popup code was touched. The click-to-travel popup is
  fixed art with no free space, so it has no word; the hover label stays visible behind it.

## Word ranges
Area levels are percentile ranks 1 to 30 (all dungeons together have each level equally often), so equal
six-level bands are the natural split.

| Word | Levels | All dungeons | Places without a dungeon | All 15,251 places |
|---|---|---|---|---|
| Beginner | 1-6 | 20% | 31% | 28% |
| Weak | 7-12 | 20% | 26% | 24% |
| Moderate | 13-18 | 20% | 19% | 19% |
| Very hard | 19-24 | 20% | 13% | 15% |
| Legendary | 25-30 | 20% | 12% | 14% |

Measured with `python tools/area_level/area_level.py --csv <scratch>/levels.csv` and counting the `level`
column (dungeon level, or terrain level for places without one). Towns lean easy because more towns sit in the
low-lean regions. Other splits tried: 1-5/6-11/12-19/20-25/26-30 gives dungeons 17/20/27/20/17%; 1-4/5-10/11-19/20-26/27-30
gives 13/20/30/23/13%. I kept the equal bands: every word is common enough to be seen, and a band is
easy to explain (word n = levels 6n-5 to 6n). Changing the split is one constant in `DoomerfallTravelHint.cs`.

## Test
`-dftravelhintshots <dir>` (in `DoomerfallTravelHintTest.cs`) opens the real travel map, points it at fixed
places through a subclass that replaces only the mouse hover test, saves a screenshot per place plus one of the
confirmation box, writes `report.txt`, and quits.

## Failed attempts
- First run went straight to `Builds/Windows64` with no portable settings: no Arena2 path, so the game stayed on the
  startup screen. Second run had the path but still sat on the startup screen, because Daggerfall waits there for
  the setup screen. The test now loads the game scene itself, as `DoomerfallNewGame` does.
- Copying the main checkout's Unity `Library` into the worktree to skip the first import needed approval, so the
  first build did a full import (it finished; later builds took a few minutes).
