# Release the mouse in Daggerfall menus (fullscreen)

## Cause

`I_CheckNativeMouse` (`UZDoom/src/common/platform/win32/i_mouse.cpp`) decides whether Doom grabs the mouse.

- Windowed: it lets the mouse go whenever `GUICapture` is set. `System_WantGuiCapture` already returns true while a
  Daggerfall menu is open (`DD_BridgeUiActive()`), so windowed menus worked.
- Fullscreen: it only looks at `menuactive` (Doom's own menus). A Daggerfall menu is not a Doom menu, so Doom kept the
  grab. With the raw mouse grabbed (`RIDEV_NOLEGACY`) Windows sends no `WM_MOUSEMOVE`/button messages, and the
  bridge's `DD_BridgeUiWndProc` forwards exactly those messages to Daggerfall. Result: no cursor, no clicks.

Both branches end with one shared override: `if (!want_native && eventhandlerresult) want_native = true;`, where
`eventhandlerresult` comes from `sysCallbacks.WantNativeMouse` (checked every tic in `I_StartTic`).

## Fix

One line in `System_WantNativeMouse` (`UZDoom/src/d_main.cpp`): return true while `DD_BridgeUiActive()`.
When the menu closes it returns false again and the next tic regrabs, exactly as after a Doom menu.

Why here and not in `i_mouse.cpp`: it uses the existing hook meant for "something needs the OS cursor" (ZScript event
handlers use it the same way), works in both windowed and fullscreen, and also covers the SDL and Cocoa input code,
which read the same callback. No platform file changes.

Inactive without Daggerfall: `uiState` is only set by `OpenUi`, which needs a bridge session.

## What could not be tested automatically, and why

The grab itself cannot be exercised on the private desktop: under `-noactivate` (added by `quiet_run.py`) Doom never
grabs the mouse at all (Doomerfall change in `I_CheckNativeMouse`), and fullscreen needs a real foreground window on
the owner's desktop. The scripted menu tests post marked mouse messages that bypass the grab, so a paired run would
only repeat what this change cannot affect. I did not run one. The fullscreen behavior is on the play-test list.

1. `play.bat` (fullscreen): New Game, reach Privateer's Hold. Press I: a cursor appears, moves, and clicks items/tabs.
2. Close it (I, Escape, or Exit): the cursor is gone and mouse look works right away.
3. Same with K (fast travel), J (journal), Z (rest), and Use on a shopkeeper, a container, and an NPC who talks.
4. A Daggerfall window that opens by itself (quest message): the mouse works in it too.
5. Alt+Tab out and back with a menu open, and again after closing it.
6. `play-windowed.bat`: menus with the mouse behave as before.
7. Watch for one thing: the click on a menu's Exit button should not fire the Doom weapon after the menu closes.
