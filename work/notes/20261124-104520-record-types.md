# Records 1: Daggerfall record types and how Doomerfall handles them

Task notes: `work/notes/20261124-104520-records.md`. Proposed cards: `work/queue/records/proposed/` (git-ignored like all of
`work/queue/`, so committed copies are in `work/notes/20261124-104520-record-cards/`).

**Status key.** *Handled*: Doomerfall does what Daggerfall Unity does, or DFU does it and the bridge carries it to
the player. *Partly*: some cases are done. *Ignored on purpose*: a design or a documented engineering choice says to
skip it, or DFU itself ignores it. *Unhandled*: Daggerfall uses it and Doomerfall does not, with no recorded reason.
*Who*: Conv = dungeon converter (`tools/dungeon_converter`), Town = town and interior conversion (`CityExport.cs`,
`SiteExport.cs`), Doom = Doom-side scripts and `UZDoom/src/dd_*.cpp`, Bridge = `Assets/Scripts/Doomerfall/`,
DFU = Daggerfall Unity unchanged.

**Scope.** The goal names every format, and the owner's examples lead with block records. I read it as: block
records in full (they are what the converters translate, so that is where Doomerfall can get them wrong), location
and world records next, and the other formats briefly, because DFU still reads and uses them unchanged. Counts come
from a throwaway census over the real `ARENA2` data (method at the end). Counts are records in the 187 RDB and
920 RMB block templates, unless a row says otherwise.

## 2. Gaps and risks, grouped

1. **Editor markers.** Passive castle guards spawn as hostile monsters and leave a stray action record; mobile 99
   spawns a monster DFU skips; quest persons and items at markers have no Doom side; random enemy slot, underwater
   table and spawn distance are dropped. (Most of the enemy-marker fields belong to the encounter planner cards.)
2. **Action records that only log.** 11 action types, about 300 records, reach `DFRULE` and stop. Two groups:
   messages and quest state (11, 12, 29, 31, 99), and harm and spells (9, 21-28), plus Daggerfall action sounds.
3. **Treasure and flats carrying actions.** Treasure markers with chains (867 dungeons) and editor 199:20 actions.
4. **Lights.** 4,268 dungeon light records and about 44,000 light sprites give no light.
5. **Interior doors.** 25,922 door records are never converted.
6. **Interior furniture.** Ladders and bookshelves.
7. **Flats by archive.** One pass checking every archive draws, scales, animates and sounds as in DFU in all three
   converters, including interior flats with a faction.
8. **World look.** Sky, wilderness nature, climate in the treadmill, castle blocks.
9. **DFU-owned formats.** One smoke pass that sound, music, video, books and text reach the player through Doom.

Door locks (432 locked dungeon doors, actions 16 and 17) already have a backlog item that waits on the owner, so no
card is proposed for them. Card 2 only makes sure lock and unlock actions report correctly.

## Method

A throwaway C# tool compiled DFU's own readers (as the converter does) and walked every block in `BLOCKS.BSA` and
every location in `MAPS.BSA`, counting record kinds, archives, editor records, action flags, trigger values, lock
indices, and which dungeons contain each rare kind. File kinds come from a directory listing of `ARENA2`. Counts for
monsters, items, spells, factions, text, quests and classes come from `work/rpg-survey-review.md` section 2. The tool
and its output stay in the scratchpad; nothing derived from game data beyond counts and place names is committed.
Statuses come from reading the code cited; no game was launched for this survey, so "Handled" means the code path
exists, not that it was play-tested here.
