# Player HP from Endurance and level (hpformula), 2026-11-25

Branch `agent/hpformula-20261125-231947`. Rules: `gamedesign/hp.md`.

## Plan

1. Max HP formula and retroactive recompute in Doomerfall code (`DoomerfallEndurance.cs`), through FormulaHelper's
   override hook where Daggerfall computes HP (`RollMaxHealth`, `CalculateHitPointsPerLevelUp`), plus a cheap per-frame
   check that catches every other change to level or permanent Endurance (level-up stat points, training, console,
   loads).
2. Class Endurance bonus as real Endurance: added at the creation roll, and once to any character made without it
   (older saves, classic imports). A saved flag in `DaggerfallStats` says the bonus is already in.
3. Per-character Endurance maximum (100 + bonus) everywhere a stat cap is checked.
4. Custom class editor label and value.
5. Test behind `-dfhpformulatest`, paired run, screenshot, demo.

## What was built

### Formula (`DoomerfallEndurance.cs`, bridge session only)

- `MaxHealth(level, END) = round(50 + END + (level - 1) x END / 15)`. The fraction is never exactly .5
  (2(level-1)END = 15(2k+1) has an even left side and an odd right side), so the rounding rule never matters.
- Uses permanent Endurance only. Fortify and Drain are effect mods and do not touch it.
- `RollMaxHealth` override returns the formula (new characters, the console `reroll` command, classic imports
  without a stored max).
- `CalculateHitPointsPerLevelUp` override returns 0. The character sheet's level-up adds it to max HP, and the
  per-frame check then raises max HP to the formula and current HP by the same amount. (Returning the exact gain would
  set max HP directly, and Daggerfall's level-up never raises current HP, so the "current HP rises with max" rule
  would be lost.)
- Per frame in game (`Update`) and right after a load (`SaveLoadManager.OnLoad`): if raw max HP differs from the
  formula, set it; a rise raises current HP by the rise, a fall clamps current HP. A dead player is not revived.
  The cost is a few integer operations per frame.
- The override provider is a code-made `Mod` with the highest load priority, so a formula mod cannot replace
  Doomerfall's HP.

### Class Endurance bonus

- `bonus = career.HitPointsPerLevel - 8`.
- Stored in Endurance itself. `DaggerfallStats` got a saved flag `doomerfallEnduranceBonus` ("the permanent Endurance
  includes the bonus") and an unsaved Endurance maximum bonus that Doomerfall sets from the career every frame.
  Both travel with `Copy`/`Clone`, so the creation windows and the level-up rollout see them.
- Creation: `StatsRollout.Reroll` adds the bonus to the rolled Endurance (one-line hook) and sets the flag and the
  maximum, so the creation windows already show it (Barbarian rolls show +17).
- Characters without the flag (any save made before this change, classic imports, a character made outside a
  bridge session) get the bonus added once on the first in-game frame, clamped to 1..(100 + bonus). The flag is then
  saved with the stats, so a second load does not add it again.
- `SetPermanentFromCareer` and `SetDefaults` clear the flag (those values are class or default values).

### Endurance maximum (100 + bonus, both signs)

- `DaggerfallStats.GetMaxPermanentValue(stat)`: `MaxStatValue()` plus the bonus for Endurance.
- Used by: live stat clamp (`GetLiveStatValue`, so Fortify cannot push past it either), `IsAllMax` (the level-up
  window's "must spend points" check: a Mage with everything maxed and Endurance at 98 is not stuck), and the stat
  spinner in `StatsRollout` (creation bonus points and level-up points).
- Other permanent stat writes in Daggerfall: classic save import (`CharacterRecord`, subtracts race/transform
  bonuses), class templates, and the console. None raises a stat past a cap, so nothing else needed a change.

### Custom class editor

- The "HIT POINTS PER LEVEL" words are painted into `CUST00I0.IMG` (x 260-306, y 22-41). In a bridge session a
  panel covers them with plain panel texture from rows 42-44 of the same image and draws
  `ENDURANCE` / `(AND MAX END)` / `BONUS` in three centered lines, at the painted text's line spacing.
- The value shows the bonus (`-4` to `+22`, signed). `HitPointsPerLevel` and the difficulty points are unchanged.

### Where HP per level is shown to the player

- Class selection: the class descriptions (TEXT.RSC 2100+) are flavor text with no HP number. Nothing to change.
- Character sheet: shows only current/max health, not HP per level. Nothing to change.
- Custom class editor: changed (above). Its help text and the Endurance stat help text still say Endurance governs
  "hit points ... you gain each level", which is still roughly true, so I left the game's text alone.

## Engineering calls

- Older saves get the class bonus added to their Endurance once, so old and new characters follow the same rule.
- Level-up adds no HP of its own; max HP is recomputed and current HP rises by the gain.
- Rounding: the formula's fraction can never be exactly one half, so "nearest" is unambiguous.
