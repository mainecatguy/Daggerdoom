# Privateer's Hold: the first enemy room is easy (20261126-192455)

Goal: the first enemy room (just outside the cave a new character wakes in) holds Former Humans who drop battle rifles,
and no chaingunners. Fixed per seed. The rest of Privateer's Hold plans normally. Small targeted rule, not a planner
change for every dungeon.

## Plan (as revised)

1. Find which placements are "the room outside the cave". Done, with a detour (below).
2. A story-theme start room rule in the planner: replace the monsters at those placements with battle rifle Former
   Humans, keeping their number. Done.
3. Check the drops really are battle rifles. Done (UZDoom test under `tools/`).
4. Planner test, budget test (I touched `EncounterBudget.zs`), a real paired New Game, E1M1 regression. Done.

## What was built

- `doomerfall_encounters.txt`, the PlainHumanoid row (Privateer's Hold only) gets three new keys:
  `start=RLFormerHumanBattleRifle,RLFormerHumanBattleRifle2,RLFormerHumanBattleRifle3,Zombieman startat=510,1672,960 startradius=640`.
- `EncounterBudget.zs` `StartRoom()`, run after `Fill()`: each placement whose origin is within `startradius` (straight
  line) of `startat` keeps its number of monsters, but each one becomes a start class the pool has. The pick uses a new
  RNG purpose (`P_START`), so it is fixed per seed. The role becomes `start`. A boss or titan there is dropped from
  the boss list. The points this saves stay unspent (the plan's leftover). `Promote` in a start placement only buys
  start classes. Rows without the keys are unchanged, so every other dungeon plans exactly as before.
- `EncounterLeaders.zs` Summary: one more line, `DDENC startroom <placement>:<monsters>,...`, printed with the existing
  `DDENC plan` line.
- Tests: `EncounterBudgetTest.zs` (test hook file) plans Privateer's Hold at 13 seed offsets, with placements beside the
  cave, below it, and just outside the radius. `run_budget_test.py` checks them. New `tools/first_room/` drop test.

### Engineering and judgment calls

- **Which classes.** DRLA's three battle rifle Former Humans (`RLFormerHumanBattleRifle`, `2` and `3`) have the same 20
  health and the same attacks. They differ only in sprite, and all drop `RLFormerHumanBattleRifleDrop`, which is
  `RLBattleRiflePickup` when the Arsenal is loaded. Each monster picks one of the three at random (seeded). Without
  DRLA, the stock zombieman stands in (DRLA replaces it, so the pool leaves it out when DRLA is loaded).
- **Same number of monsters, not the same points.** Battle rifle zombiemen are cheap (1 point), so buying with the
  room's budget would have filled it with zombiemen. The owner asked for an easy room, so it keeps its count:
  2 beside the cave, 3 below it. 530 centipoints go unspent (leftover 80 to 610). The rest of the dungeon gets exactly
  what it had.
- **Why a fixed point, not walking distance.** The placer measures walking distance from the map's player start. In
  Privateer's Hold that is the exit door marker (852,372, the converter picks Daggerfall's record 10 start marker:
  `tools/dungeon_converter/Program.cs:313`). New Game puts the player at the record 8 enter marker in the cave
  (510,1672). So the nearest placements by walk (p6, p39, p30, walk 376 to 504) are about 1,300 units from the cave,
  and p25, right below it, has walk 4,680. I put the cave's floor point in the data row instead.
  - The cave floor is z 960 (measured in game: a probe at 510,1672 has floorz 960, ceiling 1056).
  - The nearest placements in 3D are p0 (258 units away, on the same floor, 2 monsters) and p25 (545 units, the floor
    below, 3 monsters, and a boss placement until now). The next one, p2, is 808 units away. The radius of 640 takes
    exactly p0 and p25.
  - I could not prove which of the two is the room the owner meant. A line trace from inside the cave hits a wall
    258 units out (the cave is closed off), so both rooms are covered. **Play test below.**
- **The owner's "3 chaingunners".** In tonight's plan, p0 held 2 pistol zombiemen, and p25 held a chaingun commando
  boss leading 2 shotgun sergeants. The owner's build may have rolled differently before card 01 (the Humanoid theme
  allowed more classes). Either way, both rooms now hold only battle rifle Former Humans.
- The start rule lives on the story theme row, so the planner test's 20 other PlainHumanoid dungeons would get it too,
  but only if a placement fell near (510,1672,960). Only Privateer's Hold sends the PlainHumanoid theme
  (`DoomerfallAreaLevels.MainQuest`).

## Failed approaches and findings

- Walking distance as "nearest the start" (the first version, `startwalk`) picked the wrong rooms, for the reason above.
- At placement time, `players[0].mo` stands at 382.5,1254,0, not at the cave. So the planner cannot read the start from
  the player either.
- A line trace from the cave to the nearest placements hits walls or floors. The cave has no straight sight line out.
- First drop test runs failed on the harness, not the game. UZDoom writes `+logfile x.log` as `log-x-log.txt`, and
  DRLA's `Midas_Statue_Fatality` warning matched a plain "Fatal" stop check.
- One New Game run timed out in the menus at the default 50 s. It passed on rerun with `--set TIMEOUT=80`.
