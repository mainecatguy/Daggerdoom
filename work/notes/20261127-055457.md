  test mode, also starts the paired Daggerfall Unity with `SW_SHOWMINNOACTIVE` on its own desktop. A minimized Unity

- New `tools/visual_parity/hidden_desktop.py` runs the capture player unminimized on a further desktop nobody sees
  (the same trick the launcher uses for the paired Daggerfall Unity). First try with the old capture build: still an
  empty UI layer. With the diagnostic build, the player hung before its first shot (killed at the 180 s timeout,
  nothing written): most likely `WaitForEndOfFrame` never returning, i.e. the unseen window presents no frames with
  VSync on. Rebuilt with VSync off (as `DoomerfallSyncTest` does), a bounded end-of-frame wait and progress lines.
- **Diagnostic build result (06:13):** `MENUSTART pixel 109 158 location Privateer's Hold screen 960x720 iconic False
  gui none`. So with the window unminimized on an unseen desktop, at the paired spot, the capture player gets **no
  IMGUI events of any type** (not even Layout). Unity's own GUI pass never runs, which is why Daggerfall's windows
  never draw there. Minimizing is not the only cause. The player then hung inside the first shot and was killed at
  180 s, with no per-shot line written. Not yet known where it hangs: the camera `Render`, the "draw it yourself" path
  (`Event.current` set to a synthesized Repaint), or the bounded end-of-frame wait.
