# Perk popup (skillcore card 02), run 20261126-021025

## Plan

1. Find how Daggerfall windows already show in Doom. **Found:** `DFB_KIND_UI_ASK`. When Daggerfall opens a window
   on its own (a quest message, say), `DoomerfallUi.AskForOwnWindow` asks Doom to open menu 7 (`DFB_UI_DAGGERFALL`).
   Doom pauses (`pauseext`) and shows the surface until the window closes. So the popup needs **no bridge or engine
   change**: Daggerfall only has to open a `DaggerfallMessageBox`.
2. `DoomerfallPerks` (new, `Assets/Scripts/Doomerfall`) watches permanent skill values every frame, the way
   `DoomerfallSheet` watches the sheet. Training, the level-up check, a future skill purchase, and the test hook
   need no hooks of their own. A rise past 25/50/75/100 queues the perk. The box opens only once the top window is
   the HUD. A box pushed over the travel window could be closed by it: `PopWindow` pops whatever is on top.
3. Loads (`OnStartLoad`), new games (`OnStartGame`) and any non-play state (not in game, load running, phase not
   PLAY, new character held) set a fresh starting point, so a loaded or new character never sees perks it already
   has. A perk already queued survives a brief non-play state, but a load clears it.
4. Test hook `-dfperktest <skill>` in its own file (`DoomerfallPerksTest.cs`). Two lines in `DoomerfallBridge.Awake`
   (the component and the test attach).
5. Paired test `tools/perk_popup/perk_popup.py`. It uses the test start in Daggerfall city and raises the skill
   20 to 26. It checks: Daggerfall showed the perk, the top window is `DaggerfallMessageBox`, Doom opened menu 7,
   Doom's `level.maptime` stopped while it was open (a harness pk3 prints `PPTICK` each second), a mouse click
   closed it, and the clock ran again.
6. A section in `manual.md`.

## Decisions (engineering calls, change freely)

- **Permanent** skill value, not live. Fortify Skill rising and falling would re-show the popup again and again.
  Effects of the perks themselves are for later cards to decide.
- **Perk text lives in a C# table** in `DoomerfallPerks.cs`, keyed by the `DFCareer.Skills` *name*. Card 01
  (`agent/skillcore-20261126-005053`, not merged into this branch, which started from `overnight/skillcore` without
  it) reuses slots 4-6 for Shotguns/Automatics/Explosives. Keying by number would show gun perks for Orcish here.
  By name, the gun skill entries do nothing until card 01 merges, then work with no change. No merge conflict
  with card 01: I touched no file it touched except `manual.md`, where both add a new section at the end.
- Texts are the owner's decisions in `work/backlog/skills-in-doom.md`, in player wording. Perks still open
  (Automatics 75, and everything for skills with no decided perks) have no entry, so **no popup** shows for them.
  Rifles and Pistols and Energy Weapons are not skills yet.
- **No perk works yet**, so every text ends "(This perk does not work yet.)". Each entry has a `built` flag; a perk
  card sets it to drop the line. This is honest player-facing text while effects are missing. The owner may prefer
  no popup for unbuilt perks: then the popup could show nothing at all today.
- Several perks gained at once (a jump from 20 to 55, or two skills in one level-up check) share one box.
- A skill lowered and raised again past a threshold shows the perk again (no record of perks seen is saved).
  Permanent skills only fall through the test hook or the console today.
