## Results

### Perlin noise: fixed, exact

`Mathf.PerlinNoise` is Ken Perlin's **3D** improved noise evaluated at z = 0, remapped `(n + 0.69) / 1.483`. The 3D
form keeps the z level's permutation lookup, so each corner's hash is `p[p[p[X] + Y] + 0]`, not `p[p[X] + Y]`. The
first run's 2D form left that lookup out. Fitting variants against the 64 Unity samples (`unity.txt`): the 2D form,
4- and 8-gradient sets and swapped axes all fail (worst 0.35 to 0.99). The 3D-at-z=0 form gives worst error
**0.0000005** (float rounding). One-line fix in `dd_nature.cpp` (`UnityPerlin`), mirrored in `tools/nature/compare.py`.
`compare.py unity` now reports every Unity primitive as matching (Perlin, `Random.value`, `Range(0f,1f)`,
`Range(1,32)`, `Unity.Mathematics.Random`).

### Why the DFU dump said "terrain not loaded" in the first run

Daggerfall Unity had no Daggerfall data path in its settings on this machine (the setup wizard was showing,
`WOODS.WLD` was null). The test now takes `-dfpath <folder holding ARENA2>` and sets it **in memory only**, as
`DoomerfallReflexProbe` does, starts a blank game (`StartMethods.Void`, as `DoomerfallSyncTest`), turns on the
exterior and unsuppresses the streaming world, and polls up to 60 s for the terrain. Command:

    DaggerfallUnity.exe -dfpath D:\dev\DoomDaggerfall\GameResources\DAGGER -dfnaturedump <dir> 122 257 227 477 564 3 207 213

### Screenshots

- Doom shots on the private desktop come out at **320x200**, whatever the size asked for (`-width`, `vid_setsize`
  after the map loads, fullscreen: all tried). Daggerfall Unity's are 1920x1080. The side-by-side images scale both.
- The first DFU shots stood on the tile **corner** (16, 64) while Doom's `dd_tm_warp` puts the player in the tile
  **centre** (16.5, 64.5). Flats stand on tile corners, so the nearest trees fell on opposite sides of the two views
  and looked mirrored. The layout data match exactly, and `ToLocal` has no axis flip, so the difference was the
  standing point. The DFU test now stands in the tile centre too.
- What the shots show, by eye: woodland has the same broadleaf trees, dead trees and bushes; desert has sparse desert
  plants (about a quarter of woodland's density, as DFU's 0.25 desert scale gives); mountains have pines. The ground
  texture in Doom is green everywhere, also in the desert. That is the terrain's texture, not part of this goal.

### E1M1

`python tools/nature/e1m1_check.py`: stock `DOOM.WAD -norun` exit **1337**; E1M1 stock and with the DRLA set from
`play_drlax.bat` both load and screenshot, no fatal errors. The DRLA run prints `Error in translation ''` and
`Unknown class name 'Midas_Statue_Fatality'`; the baseline build `uzdoom\Release` prints the same lines, so they are
the mod's own.

### Frame cost

`python tools/nature/doom_shots.py --bench [--noflats] ...` (stock `bench` command, `benchmarks.txt`), woodland then
mountain then woodland again, with `dd_natureflats` on and off. The machine was loaded by other lanes and the
renderer was at 320x200, so the numbers are noisy:

| Run | Woodland | Mountain | Woodland again |
|---|---|---|---|
| flats off (ms per frame, All) | 17.7 | 13.0 | 28.7 |
| flats on, ~2,000 flats in view | 30.6 | 23.1 | 13.0 |

Render time (the part flats touch) was 2-8 ms either way. Nothing here shows a large cost, but this is not a real
measurement at play resolution. It goes on the play-test list.

`dd_natureflats` (new, default on, not saved) turns flats off for ground laid out after it changes. It is for such
comparisons and for a slow machine.

### Town transition

By construction, a town map lays out the same global tiles from the same rule (`SpawnTownNature` calls the same
`NatureOf` and `SpawnNature`), so the trees outside a town wall are the same ones the overworld shows there. I tried to
check it in game with `tools/overworld/runtime_test.py` (it walks into a generated town), but its harness waited for
the town and gave up with no conversion started (`RTLEG FAIL leg=0 group=1 not ready`). Debugging that harness is
outside this goal; I left it unchanged. The look-back is on the play-test list.
