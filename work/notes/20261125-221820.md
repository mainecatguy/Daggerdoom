# Drop labels: Doom guns on the floor show their material before pickup

Goal card: "Dropped Doom guns show their material before pickup" (owner, 2026-11-25). Branch
`agent/droplabel-20261125-221820`.

## Research (what was there)

- A gun's material is rolled by Daggerfall only at the take (`DoomerfallDoomItems.OnTake` → `DoomerfallDoomItem.Create`):
  `DoomerfallDrops.RollMaterial(WorldLevel.Current)` inside `LootSeed.Scope(LootSeed.Of(DoomFloorItem, class, floorId))`,
  where the floor id is `DD_LootItemId` (map item id, or `SESSION_ID | ddLootId` for a fixed drop). That is a pure
  function of (class, floor id, area level), so **no spawn-time sync is needed**: the look label can ask Daggerfall the
  same question lazily, once per gun in view, the way it already asks for pile and NPC names (`DFB_KIND_LOOK`). No new
  round trip per spawn, no frame cost, and Daggerfall still decides.
- Three gaps found:
  1. **Guns dropped from Daggerfall's inventory lost their material.** `DropToDoom` sent only the class and the gun's
     state; the pickup had no id, so taking it back rolled a new material (free roll), and after a park it got a new
     session id (another roll).
  2. **Fixed-drop guns changed material after leaving and coming back.** Daggerfall's location record packs loose
     session items into 8 bytes *without their id* (`DoomerfallPlaceCodec`), and Doom re-mints every session id on
     restore (`dd_treadmill.cpp`, `if (f.session) r.id = SESSION_ID | ++nextDynamic`). The fixed drops' floor id was
     lost at the first leave/return. Shown by the first full run: B was "Adamantium Battle Rifle" before leaving and
     "Mithril Battle Rifle" after. This bug was already there before this goal (fixed drops' own tests covered
     fresh/save/load, not leave/return).
  3. Guns with no lasting id (a script or console spawn) rolled freely at the take, so no label could promise anything.
- "Tier-swapped pickups" are ammo only (`DoomerfallAmmo` replaces placed ammo; `Reconcile` gives the heir the map id).
  No gun is tier-swapped. Daggerfall maps place no guns as map things that I could find; a gun that a map does place
  gets a map item id, and the label takes the same path as for a fixed drop (`DD_LootItemId`).

## What changed

- **Bridge** (`bridge/doomerfall_bridge.h`, generated files regenerated): new look target `DFB_INFO_DOOM_GUN` (6). Doom
  sends the pickup class in a `DFB_KIND_INFO_NAME` just before (as Info does for monsters), the floor id in `id`, and the
  carried material + 1 in `world_x`. The schema hash changed, so the bridge DLL, launcher, UZDoom and DFU must all be
  rebuilt together (done for the play folder).
- **UZDoom `dd_look.cpp`**: a Doom gun in view is named by Daggerfall (`AskGun`), cached per (class, floor id, carried
  material), asked again every 35 tics while in view like a pile (the roll uses the area level). It shows Doom's plain
  name until the first answer; an empty answer (Daggerfall did not have the class's display name yet) is asked again
  after 4 tics.
- **UZDoom `dd_items.cpp`**: `DD_LookGun` (floor id + carried material for the label); the take also sends the carried
  material as a `DFB_KIND_DOOM_ITEM_GUN_STATE` line (`DoomerfallGunMaterial`), and a gun's take uses
  `DD_LootFixItemId`.
- **UZDoom `dd_lootrng.cpp/.h`**:
  - `DD_LootFixItemId`: an id-less floor gun gets a lasting id (a hash of map time, position and class into
    `ddLootId`, saved as `ddlootid`) the first time Daggerfall names or takes it. Its material is then fixed from that
    moment. Doom picks only an identity; Daggerfall still rolls the material.
  - Lasting floor ids now carry bit 58 (`LASTING_MARK`), which the treadmill's counter session ids never have. **This
    changes every fixed drop's floor id, and so which material each fixed-drop gun rolls** (allowed by the card: "changing
    seed values to fix a bug"). What drops is unchanged; only the gun material seeds moved.
  - `DD_LootGunKeepsId`: a gun with a lasting id is recorded in Daggerfall's location record as a full fact with its id
    (40 bytes), not as an anonymous session item (8 bytes). One line in `dd_treadmill.cpp` `ToFact`. Only guns, so
    ammo and health drops stay compact. The id comes back on restore, so the material does too.
- **Doomerfall mod `DoomerfallGuns.zs`**: new `DoomerfallGunMaterial` inventory token (amount = material + 1). A gun
  dropped from Daggerfall's inventory gets it on its pickup (through the existing gun state lines), and it persists
  through Doom saves, the treadmill and the location record as carried text, like a DRLA gun's mods. When the dropped
  gun was in Doom's hands, the material line is kept while the live state replaces the rest.
- **DFU `DoomerfallDoomItems.cs`**: `DropToDoom` sends the gun's material line first. `OnTakeState` takes the material
  line out of the gun state. `Create` keeps a carried material instead of rolling. `FloorGunLabel` answers the look with
  `GunName(material, class)`, the same text `ItemName` uses, rolled by the same `RollMaterial(FloorSeed(...))` inside a
  `LootSeed.Scope`, which restores Unity's shared generator, so a look changes nothing. The take log line also names
  the item (`named "..."`), which the test reads. **`DoomerfallInfo.cs`**: the `DFB_INFO_DOOM_GUN` case.
- **Tools** (test only): `tools/droplabel/droplabel.py` + `droplabel.zs`; `tools/fixed_drops/paired.py` got an
  `EXTRA_DF` list for extra Daggerfall Unity arguments.

No test logic in game source. Without a bridge session nothing runs: `DD_LookFrame` needs a session, `DD_LookItem` and
the take need `useRules` and a session, and the token exists only on pickups Daggerfall dropped.

## Not verified / known gaps

- `tools/fixed_drops/paired.py series fresh save load` was not re-run. The floor id shape changed (bit 58), so its
  recorded gun material and floor id differ from older result files; the droplabel save/load runs show the ids are the
  same across save/load.
- The look label is re-asked every 35 tics while a gun is in view. If the player stands on the border between two
  area levels, the label follows the level of where the player stands, as the take does.
- The first look at a gun shows Doom's plain name ("Battle Rifle") for a few tics until Daggerfall answers, or longer
  the first time a class is seen (its display name comes with its art, re-asked every 4 tics). A play-test item.
- A gun with no lasting id that is never looked at or taken still gets a counter id when parked. Its material is
  decided when it is first named or taken. Nobody saw it before, so nothing visible changes.
- A gun on a map placed by the map itself was not tested directly (none found on Daggerfall maps). It uses the map item
  id, the same path as a fixed drop.
