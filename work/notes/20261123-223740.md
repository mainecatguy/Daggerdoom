# Daggerfall holds Doom items (20261123-223740)

Branch `agent/doomitems-20261123-223740`.

## Plan

Identity of a Doom item in Daggerfall: the Doom **world pickup class** the player took (for example `RLPistolPickup`, `RLGreenArmorPickup`, `BlurSphere`). That class is what Doom can spawn and touch again, and it carries the floor sprite. DRLA guns are `CustomInventory` pickups that give the real weapon (`RLPistolPickup` gives `RLPistol`), so the pickup class is the only name that works for every item.

Daggerfall side:
- One custom item class, `DoomerfallDoomItem : DaggerfallUnityItem`, registered for save deserialization, with one added item template (index 9100, `MiscItems` group so Daggerfall never tries to equip it, not stackable, no loot group so it never appears in loot or shops).
- The Doom class name is stored in the item's `shortName` (saved by Daggerfall's normal `ItemData_v1`). The display name and sprite come from Doom at runtime.
- Weight: one default, 2 kg per item (`weightInKg`, saved per item so the later real-weight task can change it item by item).
- Sprite: Doom sends the item's sprite pixels through bridge bulk slot 5 on request. Daggerfall builds a texture and `ItemHelper.GetItemImage` returns it for Doom items (one small hook). Nothing is written to disk.

Bridge (protocol 7, kinds from 140), payload `dfb_doom_item { request, status, class[40] }`:
- 140 `DOOM_ITEM_TAKE` UZ→DF: the player pressed Use on a Doom item.
- 141 `DOOM_ITEM_RESULT` DF→UZ: Daggerfall added it, or refused (too heavy, not now).
- 142 `DOOM_ITEM_USE` DF→UZ: the player used the item in Daggerfall's inventory.
- 143 `DOOM_ITEM_USED` UZ→DF: Doom applied it or refused it.
- 144 `DOOM_ITEM_ART_REQUEST` DF→UZ, 145 `DOOM_ITEM_ART` UZ→DF: sprite and tag for one class, in bulk slot 5.

Flow:
- Use on a Doom item (only where Use is already required: generated map, bridge session) asks Daggerfall first. The actor stays until Daggerfall answers. Accepted: a gun (Weapon or DRLA weapon pickup) is also given to Doom by its normal pickup, so it stays usable until the hotkey task; any other item just leaves the world and waits in Daggerfall's inventory. Refused: the item stays on the floor and the press goes to a door as before.
- Using a Doom item in Daggerfall's inventory spawns that pickup at the player in Doom and touches it (armor is worn, a powerup starts). Daggerfall removes the record only when Doom reports it was taken.
- Dropping a Doom item in Daggerfall's window makes a normal Daggerfall loot pile, which Grab takes back.
- Save and load: Daggerfall saves the records in its own save. Doom's own save keeps the gun it holds.

## Findings
- DRLA weapon pickups (`RLPistolPickup` and the rest) are `CustomInventory` children of `RLBaseWeaponPickup` whose `Pickup` state gives the weapon and counts `RLWeaponLimit`. So "is a gun" is `Weapon` or `RLBaseWeaponPickup`.
- Daggerfall Unity already supports custom item classes (`ItemHelper.RegisterCustomItem`, `ItemData_v1.className`), so Doom items save and load through Daggerfall's normal item serialization. It had no way to add a template from code, or a per-item picture, so two small hooks were added to `ItemHelper.cs` (marked `[Doomerfall]`): `AddCustomItemTemplate` and the `ICustomItemImage` check at the top of `GetItemImage`.
- `ItemTemplate` lives in `DaggerfallConnect.FallExe` (the first Unity build failed on the missing `using`).
- The pickup's sprite comes from the actor the player took. After a restart Doom has no actor, so it walks the class's `Spawn` and DRLA's `SpawnFrame` states for the first drawn frame, then falls back to `Inventory.Icon`.
