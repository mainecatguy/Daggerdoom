# 20261127-134458: character sheet attribute popups explain Doomerfall's rules

Goal: left-clicking an attribute on Daggerfall's character sheet shows Doomerfall's effects and formulas alongside
Daggerfall's own text (owner, 2026-11-26).

## Plan

1. Find the popup: `DaggerfallCharacterSheetWindow.StatButton_OnMouseClick` shows the RSC text record for the stat.
2. Find each built rule (the `attributes` cards' code) and copy its formula exactly:
   - Strength: `mods/doomerfall/src/zscript/DoomerfallAttributes.zs`, melee x (1 + STR/100), clamp 100.
   - Willpower: `UZDoom/src/dd_bridge.cpp` `DD_BridgeWillpowerDamage`, x (300 - WIL)/250, last step, clamp 100.
   - Agility: `DoomerfallAgility.zs`, handling x (1 + 0.4 AGI/100), evade 15% x AGI/100, clamp 100.
   - Endurance: `DoomerfallEndurance.MaxHealth`, 50 + END + (level-1) x END/15, no clamp.
   - Speed: `DoomerfallAttributes.zs`, x (0.75 + SPD/200), clamp 100.
   - Luck: `DoomerfallAmmo.zs` `LuckDrop`, Luck-in-100 chance of a second ammo drop, clamp 100.
   - Intelligence, Personality: no Doomerfall rule; the popup says they work as in Daggerfall.
3. New `Doomerfall/DoomerfallAttributeHelp.cs` builds Daggerfall's expanded text + a blank line + the Doomerfall lines
   (rule, formula, and "Yours (value): result" from the live value). Hook in the sheet is one `if`.
4. Only in a bridge session (`DoomerfallBridge.SessionActive`), since the rules only apply there.
5. Test `-dfattrhelptest <dir>` (own file): standalone DFU, fixed stats, clicks each attribute through the real
   handler, screenshots each popup, writes the text to report.txt.

## Decisions (engineering)

- Same popup, not a second chained box: the owner said "alongside". Lines are pre-broken (the box does not wrap).
- Daggerfall macros are expanded first, then the Doomerfall lines added without expansion (they contain `%`).
- The sheet's stat button carries the text id; the helper maps it back to the stat through the text provider, so a
  text-provider mod that renumbers records still works.
- "Yours" uses the live value (fortify/drain count), as the rules do.

## Known gaps

- The text is a copy of the formulas. If a rule changes, the popup must change with it; the helper's header lists
  where each rule lives. `killdrops` 01 (queued) replaces the Luck rule with "Luck/2 % chance a kill drops ammo",
  so that card must update `DoomerfallAttributeHelp.Lines` for Luck.
- Daggerfall's own Endurance text still talks about its HP per level; the Doomerfall line says it is replaced.

## Results

- Unity build (windowed, via quiet_run): `CliBuild result: Succeeded` in `daggerfall-unity-master/Logs/cli-build.log`.
- `python tools/attribute_help/run_shots.py`: PASS. Standalone Daggerfall Unity, fixed character (level 5; STR 62,
  INT 45, WIL 70, AGI 33, END 55, PER 40, SPD 80, LUC 120 which Daggerfall caps at 100). All 8 clicks through the
  sheet's real `StatButton_OnMouseClick` opened a message box; the script checks each "Yours" line against values it
  computes itself from the formulas (+62% melee, -8% damage taken, +13.2% handling / 4.95% dodge, 120 max HP,

  every popup fits on screen (Endurance, the tallest, has room to spare; the widest line is Speed's). The first run
  captured at 1920x1080, not the 1280x800 the arguments asked for: Daggerfall Unity applies settings.ini's resolution
  over `-screen-width/-height`. The script now writes 1280x800 windowed into the staged settings.ini, and the rerun's
  shots are 1280x800 (checked with PIL); they fit at both sizes.
- Verifier fix: the Willpower popup first said "changes all damage you take". Wrong: the rule runs only in Doom
  (`P_DamageMobj`, `P_PoisonDamage`); Daggerfall's own damage (spell effects, poison and disease ticks), health that
  Doom scripts set directly, and kill calls are not scaled (`work/notes/20261127-004045.md`, Known gaps). It now says
  "the damage you take in combat and from the environment", as `manual.md` does, and the script checks that phrase.
  Rebuilt, rerun: PASS.
- No engine or mod change (Daggerfall Unity only), so DOOM.WAD E1M1 is unaffected; not re-run.
- Not run: a paired game clicking the sheet inside Doom. The gate is `DoomerfallBridge.SessionActive`, the same flag
  `DoomerfallShields` uses, set when the bridge session starts. The demo below is paired, for the owner to check.
