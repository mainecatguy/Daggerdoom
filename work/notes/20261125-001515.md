# Stealth and ammo text one size larger (20261125-001515)

## Plan
1. Find how "Sneaking" and the loaded-ammo label are drawn, and whether they share a path with stock Doom text.
2. Give Doomerfall's own labels a single size setting, one step larger, without touching Doom's font or HUD scaling.
3. Paired before/after screenshots with a stock pickup message on screen, then measure the pixels.

## How Doomerfall's on-screen messages are drawn (for the look-at label card)
There are two kinds. Neither goes through Doom's message system (Printf, the notify area, MidPrint, `con_scaletext`, `hud_scale`).

**1. Doomerfall's small labels.** These are `Screen.DrawText(SmallFont, ...)` calls inside a handler's
`RenderOverlay(RenderEvent e)` (ui scope), drawn every frame:
- "Sneaking": `mods/doomerfall/src/zscript/Doomerfall.zs`, `Doomerfall_Events.RenderOverlay`. Gold, centred, two
  lines above `bottom`.
- Loaded ammo ("Regular bullets", its tags in green, and the tinted pickup sprite at 1.5x the text scale):
  `mods/doomerfall/src/zscript/DoomerfallAmmo.zs`, `DoomerfallAmmoTiers.RenderOverlay`. Drawn at 3/4 of the screen width,
  three lines above "Sneaking".
- "Climbing" or "Slipping": `mods/doomerfall/src/zscript/DoomerfallClimb.zs` `RenderOverlay`. Four lines above `bottom`.
- Common layout: `bottom = min(StatusBar.GetTopOfStatusBar(), int(Screen.GetHeight() * 0.85))`, and offsets are
  multiples of `SmallFont.GetHeight() * scale`, so the labels keep their spacing when the scale changes.
- **Size:** `int scale = DoomerfallText.Scale();` (new, `mods/doomerfall/src/zscript/DoomerfallText.zs`), passed as
  `DTA_ScaleX, scale, DTA_ScaleY, scale`. It returns `max(1, CleanXfac_1) + dd_hudtextstep`. `dd_hudtextstep` is a new
  user CVar (`mods/doomerfall/src/CVARINFO.txt`), default 1. Before this change, each label used `max(1, CleanXfac_1)`
  directly. A new label (look-at) should call `DoomerfallText.Scale()` and draw the same way.
- `CleanXfac_1` is UZDoom's small-text scale (`UZDoom/src/common/rendering/v_video.cpp:288-298`). The width is first
  clamped to a 17:10 aspect. Below 1360 wide the scale is 1, below 1920 it is 2, and from 1920 up it is
  `int(w/640 * 0.7)`. So 1920x1080 (clamped to 1836 wide) is 2, 2560x1440 is 2, and 3840x2160 is 3.

**2. Daggerfall's HUD text** (the top-of-screen popup rows and the mid-screen line, sent as `dfhud_top:` and
`dfhud_mid:`): `Doomerfall.zs` `DrawDaggerfallText` and `DrawDaggerfallLine`. It is drawn at Daggerfall's own 320x200
scale, `min(w/320, h/200)`, to match Daggerfall Unity, with Daggerfall's yellow and its shadow. **I left it unchanged.**
It copies Daggerfall's size rather than Doom's small-label size, it is already larger than the labels, and the card
named only stealth and ammo text. If the look-at label should look like Daggerfall's Info text, reuse
`DrawDaggerfallLine` instead.

Stock and DRLA text (pickup messages, the DRLA HUD, menus) do not use any of these, so they keep their size.

## Decision: one whole step
SmallFont is a pixel font. Whole-number scales keep every glyph pixel the same size, while fractional scales make
uneven pixel rows. So "one font size" is one whole step above Doom's own small-text scale. The effect depends on
resolution: 2x where Doom's scale is 1 (windows under 1360 wide), and 1.5x where it is 2 (common full-screen sizes,
1920x1080 and 2560x1440). The owner can set `dd_hudtextstep 0` in the console for the old size. See the question below.
