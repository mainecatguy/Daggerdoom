# Class cards for both modes (run 20261126-164636)

Goal: replace the placeholder class filler (`DFCareer.RemapRemovedSkills`) with the owner's hand-made class cards from
`work/notes/20261126-class-skill-remap-proposal.md` (hand-made section, approved 2026-11-26; the file lives in the main
checkout's `work/notes`, not on this branch).

## Plan
1. One table file with both cards per preset class, a custom-class rule, and a guns-mode switch (always on).
2. Apply the card wherever class lists come in: `CLASS*.CFG` (`DFCareer.StructureData`) and save load.
3. Save load: rebase `startingLevelUpSkillSum` by the change in the level-up sum, so the level holds.
4. Class maker: in guns mode offer the Doom skills, not the five Daggerfall weapon skills; never Critical Strike.
5. Paired test (both real games) with its own flag and checker; build; demo.

## What was built
- `daggerfall-unity-master/Assets/Scripts/API/DoomerfallClassCards.cs` (new):
  - `NoGunsCards` and `GunsCards`: full 12-skill lists for CLASS00-17, generated by a scratch script from the CFG bytes
    plus the proposal's two tables, with asserts (12 distinct skills each, no language or Critical Strike left, every
    Daggerfall weapon slot replaced in guns mode). Kept as full literal lists so each card reads as a card.
  - `GunsMode = true` (no no-guns option exists yet; flipping it gives the no-guns cards).
  - `PresetIndexOf`: which preset a 12-skill list is. **By its fixed skills, not by name** (names can be localized on
    selection, and a custom class could be called "Knight"): every non-weapon slot must hold the card's skill or
    something an older build put there (monster-language / gun-slot number 4-12, or Critical Strike), at most two such.
    This recognises classic CFG data, saves from before the cards (raw languages, or the placeholder's gun filler) and
    saves with the cards, so the result is the same card every time.
  - `Apply`: a preset gets its card; a custom class keeps its picks: languages -> first free of Etiquette,
    Streetwise, Mercantile, Medical; Critical Strike -> first free of Short Blade, Long Blade, Axe, Blunt Weapon,
    Archery, Running; then (guns mode) Short Blade/Long Blade/Axe/Blunt/Archery -> Pistols/Automatics/Shotguns/Melee/
    Rifles, a repeat taking the first free of Pistols, Shotguns, Automatics, Rifles, Explosives, Energy Weapons, Melee.
    If every listed fallback is taken, the first free usable skill in enum order.
  - `OfferedInClassMaker`: no Critical Strike, no unused slots 11-12, and in guns mode no Daggerfall weapon skills.
- `DFCareer.RemapRemovedSkills` replaced by `DFCareer.ApplyClassCard(firstLanguageSlot)` + `SkillLists()`.
  `StructureData` passes `Shotguns` (classic data: 4-12 are languages).
- `DaggerfallSkills.FirstLanguageSlotOf`: a save from before the gun skills now returns `Shotguns` (its slots 4-6 were
  Orcish/Harpy/Giantish in the class lists). Only class lists use it.
- `SerializablePlayer.RestoreSaveData`: reads the save's level-up sums as before, then applies the card, recomputes
  the current sum and shifts the starting sum by the same amount, so progress through the level is unchanged.
- `CreateCharCustomClass`: one condition added to the skill list filter.
- Test: `Doomerfall/DoomerfallClassCardTest.cs` behind `-dfclasscardtest` (2-line hook in `DoomerfallBridge`), and
  `bridge/test/class_card_test.py`, which rebuilds the expected cards itself from the CFG bytes and the proposal's
  tables (not from the C# arrays).

## Decisions and judgment calls
- Critical Strike is removed from class lists (owner's card) and from the class maker. It still exists as a skill
  elsewhere (trainers, sheet); hiding it everywhere was not asked for.
- Custom repeat rule: slots are converted in tier order; when a slot's default Doom skill is already on the class, that
  slot takes the fallback. The proposal says "the lower slot takes" the fallback; when the clash is with a Doom skill the
  player picked in a lower slot, this version changes the higher (Daggerfall weapon) slot instead of the player's own pick.
- Class careers for class-based enemies also load through `StructureData` and get cards (the placeholder did the same).
  Enemy skills do not come from career lists, so no behaviour change.
- Starting gun (light carbine card) and Battlemage/Knight energy guns: not part of this card; untouched.

## Known gaps

- Starting gun still follows the old rule (separate card; Battlemage/Knight energy gun is "later").
- A custom class whose non-weapon skills exactly match a preset's (same skills, same slots) is treated as that preset.
