# Steal mode while crouching

## Plan

1. Find what already exists. The containers task left most of the route in place: `DD_UsePress` (UZDoom `dd_items.cpp`)
   already sends `DFB_TAKE_STEAL` instead of `DFB_TAKE_GRAB` when the player crouches, and Daggerfall only logged it.
2. Daggerfall side: run Daggerfall's own activation in its real `PlayerActivateModes.Steal` mode for a crouching Use, and
   `Grab` otherwise. No copy of Daggerfall's rules.
3. Doom side: show "Sneaking" at the bottom of the screen while crouching, only on a generated Daggerfall map.
4. Prove both modes with both games, check stock E1M1, leave a demo, and write the list of stealing features still missing.

## What Daggerfall's Steal mode does (read from `PlayerActivate.cs`)

| Target | Grab | Steal |
|---|---|---|
| Loot piles, corpses, house containers, shop shelves (`ActivateLootContainer`) | opens the window | identical: the mode is never read except Info on corpses |
| Locked exterior building door | "locked" message | lockpicking roll (Lockpicking skill, last-attempt memory, guild tally) |
| Locked interior/dungeon action door | toggles (fails, locked) | `AttemptLockpicking` |
| Wandering townsperson (`MobilePersonNPC`) | talk | pickpocket (once per NPC); failure is a Pickpocketing crime and spawns guards |
| Human-class enemy | "You see a ..." | pickpocket (DFU allows classes only) |
| Stationary NPC | talk | talk (same as Grab) |
| Closed shop shelf | n/a | DFU opens the inventory in shelf-stealing mode whatever the mode is; taking is Theft |
| House container | private property question; taking is Theft | same |

So in Daggerfall, Steal changes nothing about containers. Theft from containers happens in Grab mode too, through the
private property question and closed-shop shelves. Everything that Steal really changes (lockpicking, pickpocketing)
acts on targets that Doom does not yet route to Daggerfall.

`PlayerSpeedChanger.isSneaking` (Daggerfall's sneak key) only halves the hidden player's speed. Detection belongs to Doom
under the owner's detection bar design, so I did not mirror crouch into it.

## What I changed

- `UZDoom/src/dd_items.cpp`: when the map context changes, it sends `dfi_rules:1` or `dfi_rules:0` to the mod with the
  existing `dfi_clear`. This only runs in a bridge session (the item frame is not called otherwise) and changes no engine behavior.
- `mods/doomerfall/src/zscript/Doomerfall.zs`: `RenderOverlay` draws "Sneaking" (gold, small font, centered, just above the
  status bar, at most 85% down the screen) while `dfi_rules` is on and the player crouches. The crouch test is the engine's
  own (`BT_CROUCH` held, or `crouchfactor < 1`), so the message shows exactly when Use will steal, including when a low
  ceiling keeps the player crouched after releasing the key.
- `DoomerfallItems.cs`: the take request's mode is kept with the container, and `OpenWindow` calls Daggerfall's
  `PlayerActivate.ChangeInteractionMode(mode, false)` (no Daggerfall mode message) before `DoomerfallActivateLoot`.
  The log line `items: activating in Steal mode` records it.
- `tools/containers/containers.py` and `harness.zs`: `--crouch` holds crouch through the Use press, and `--review`,
  `--uz-build`, `--source` let the same tool assemble and run this lane's build in `review\steal-mode`.

No bridge message kinds were added.

## Result

What Steal mode does now:

- Crouching (held, Crouch Toggle, or kept crouched by a low ceiling) on a generated Daggerfall map shows "Sneaking" at the
  bottom of the screen, and Use or Interact then runs Daggerfall's activation in Steal mode. Standing Use runs it in Grab mode.
- For every target that Doom routes to Daggerfall today (loot piles, monster drops, house containers, shop shelves),
  Daggerfall's own rules make Steal behave the same as Grab, so play is unchanged. That matches Daggerfall.
- Theft already works without Steal, through Daggerfall's own code: the private property question on house containers,
  and closed-shop shelves (the inventory in shelf-stealing mode). On a house container, taking an item runs Daggerfall's
  shoplifting detection roll, which can trigger guards (see the feature list).
- Crouching is still plain Doom crouching. Nothing about movement changed.

with DRLA, DRLA Monsters, and DRLAX, both games minimized, built from this branch (UZDoom `uzdoom-quiet`, Daggerfall Unity `CliBuild result: Succeeded`):

- `steal3` (crouching, house container): `CTPRESS eye 33.5 ... crouchfactor 0.50 daggerfallRules 1`, then
  `items: use 1 on 665ac73524e91529 (steal, HouseContainers)`, `items: activating in Steal mode`, private property question,
  Yes, inventory window, took "Candle". After exit and re-entry it was restored with 0 items. `CTDONE reentered`.
- `steal-shelf` (crouching, third box, a shop shelf, shop open): `(steal, ShopShelves)`, `activating in Steal mode`,
  `DaggerfallTradeWindow` with 11 merchant items, as Daggerfall does in an open shop whatever the mode.

- `check` (no bridge, DOOM.WAD E1M1): stock exit 0, no bridge lines, 0 script errors. DRLA: exit 0, no bridge lines,
  3 script errors and 765 unknown-class lines, the same as the containers task's run, all from DRLA's own content.
- The mod with the new overlay, loaded into UZDoom on stock E1M1 with no bridge, compiles and logs only `Doomerfall: mod loaded`.
  `daggerfallRules` stays false there, so nothing draws.
- The only `Player.log` exception kind is the startup `NullReferenceException` earlier notes also record.
- Normal Daggerfall Unity: the change is inside `Doomerfall/DoomerfallItems.cs`, which runs only in a bridge session. Not launched separately.
- Registry: the review copy uses `install.isolate_registry`, like the other demos. I did not hash the registry.
- Not verified by a machine: what the "Sneaking" text looks like. The harness proves the flag and the crouch state, not the pixels.

and Use furniture or a shelf.

## Failed approaches and problems

- The first harness held `BT_CROUCH` from `WorldTick`. The engine thinks for players before `WorldTick` (`p_tick.cpp` 261 then 264),
  so the player never crouched (`crouchfactor 1.00`), although Use still sent Steal because the engine also reads the button.
  The harness now sets Crouch Toggle's state (`player.crouching = -1`), which is the engine's real crouch path (`crouchfactor 0.50`).
- Intermittent, not caused by this change, as far as I can tell: 2 of 7 building runs (`steal2`, `grab1`) timed out with no `CTLIST`.
  In both, Doom and Daggerfall both entered the store (`DDTOWN active DDS4D0L4`, `items: list 1 has 0 piles and 5 containers`),
  but Doom never spawned the container actors. The containers task notes one similar failed run. My only engine change adds one
  `dfi_rules` event that a different handler reads, so I do not think it is the cause. I could not run a clean baseline,
  because the updated harness needs the updated mod (`Unknown identifier 'daggerfallRules'` against the containers build). Not investigated further.

## Stealing features still needed (suggested order)

Steal mode is connected, but the things Daggerfall's Steal really changes (lockpicking and pickpocketing) act on targets
Doom does not route to Daggerfall yet. Each item below names what it waits on.

1. **Show Daggerfall's messages in Doom.** Results of stealing ("You are not successful", lockpick success or failure,
   "You are too far away", pinched gold) show only in Daggerfall's hidden HUD. Every later item needs this, and it is small.
2. **Crime consequences for theft that already happens.** A detected theft from a house container sets `Crimes.Theft` and calls
   `SpawnCityGuards`. Indoors this spawns 2 to 5 real Daggerfall City Watch enemies at the door in Daggerfall's hidden world
   (`PlayerEntity.cs` 621-641). `PreventEnemySpawns` does not stop it. Doom shows nothing, and Daggerfall's halt or arrest flow is
   invisible. This needs the owner's design for guards in Doom (architecture: "Crime, Bounties & Arrests"; backlog: NPC self defense, greater NPC bot variety).
3. **Lockpicking doors.** Steal on a locked exterior building door rolls Daggerfall's exterior lockpicking, and on an interior or
   dungeon door calls `AttemptLockpicking`. Today Doom enters every building and opens every door without asking Daggerfall, so there
   is nothing to pick. Waits on backlog "Locked doors with Daggerfall's requirements". When that lands, the door request should carry
   the same Steal flag (bashing is separate: Daggerfall bashes with a weapon hit, not with Use).
4. **Closed shops and houses at night.** Once doors follow Daggerfall's locks, entering a closed shop needs a pick, and its shelves
   already open Daggerfall's shelf-stealing inventory (`SetShopShelfStealing`). Worth a test then. Today it can be tried by walking in at night.
5. **Pickpocketing townspeople.** Steal on a wandering `MobilePersonNPC` runs Daggerfall's `Pickpocket` (once per person; failure is
   a Pickpocketing crime and guards). Waits on backlog "Sync wandering NPCs", because wanderers do not exist in Doom yet. Steal on a
   stationary NPC is the same as talking in Daggerfall, so it follows "Talk to stationary NPCs".
6. **Pickpocketing enemies.** Daggerfall Unity lets Steal pickpocket human-class enemies. In Doomerfall, enemies are Doom monsters.
   Whether any Doom actor can be pickpocketed, for example a hostile human NPC bot, is an owner design question for later.
7. **Sneaking and the detection bar.** Crouching could count as Sneaking for the planned detection bar, and Daggerfall's Stealth skill
   only trains during enemy stealth checks, which never happen in a bridge session. This belongs to the detection bar work.

Guild bookkeeping (`TallyCrimeGuildRequirements`, Pickpocket and Lockpicking skill tallies) comes free with items 2, 3, and 5,
because they call Daggerfall's own code.

## Play-test list

1. Run the demo. Crouch: does "Sneaking" appear at the bottom of the screen, readable and not covering DRLA's HUD? Is the placement
   (just above the status bar, at most 85% down) right? Try held crouch and Crouch Toggle (if bound).
2. Stand up: the text disappears at once. Crouch under a low ceiling and release: the text stays while the player stays crouched.
3. Crouch-walk and jump: movement feels like stock Doom crouching.
4. Standing, Use the shop shelf: trade window. Crouching, Use it: also the trade window (Daggerfall's open-shop behavior).
5. Crouching, Use other furniture: private property question, then the loot window. Take a few heavy items to provoke detection,
   and say what you see. Expect nothing visible in Doom even if Daggerfall spawned guards (feature 2).
6. Outside on the town map with no building, crouch: the text shows (it shows on any generated Daggerfall map). Load stock Doom with
   the same mods and no bridge: the text never shows.
