# Changing ammo type plays DRLA's reload (ammoinv card 02)

Goal: the change ammo key (Z) is a reload, not an instant swap. The gun plays DRLA's reload, and the new tier is what
fires once the reload ends. Counts in Doom and in Daggerfall's inventory stay right throughout.

## What happened before (checked first, as the card asked)

DRLA does **not** do this by itself today. The change key ran:

1. Daggerfall picks the next tier and sends `AMMO_UNLOAD`.
2. Doom (`dd_items.cpp UnloadMagazine`) zeroes the gun's magazine (`RL<Gun>Clip`) and answers with the rounds.
3. Daggerfall puts those rounds back as the old tier, switches the loaded tier, and sends Doom the reserve difference.

Nothing started a reload. The magazine just sat empty until the player pressed Fire (DRLA's `Fire` state jumps to
`Reload` on an empty magazine, `A_JumpIfNoAmmo("Reload")`) or Reload. The owner's expectation is half right: DRLA's
`Reload` state fills the magazine from the reserve (`ReloadWorking` moves `Clip` to `RLPistolClip` one round at a time
in a 0-tic loop, after a 4-16 tic animation), so if the reserve already holds the new tier, the reload loads the new
tier on its own. What was missing was starting the reload, and making sure the reserve holds the new tier first.

## The change

- **Daggerfall (`DoomerfallAmmo.cs HandleChange`)**: on the key, it switches the loaded tier first (`SwitchTier`, which
  also records the tier on the gun) and sends Doom the reserve difference *before* the unload request. Doom handles
  bridge events in the order they were sent (`doomOutgoing` queue), so the reserve holds the new tier before the magazine
  is emptied. `ApplyUnloaded` then only puts the magazine's rounds back as the old tier. The automatic change (the
  loaded tier ran out) is unchanged.
- **Doom engine (`dd_items.cpp UnloadMagazine`, about 15 lines, only reached from Daggerfall's change key)**: after
  emptying the ready gun's magazine for a change by the key, if the gun is in a ready frame (`WF_WEAPONREADY`) it
  sets the gun's own `Reload` state in the same tic. A gun without a magazine or a `Reload` state (stock Doom) is
  lowered and raised (`PendingWeapon` = the same gun, `Deselect` state), so the new tier fires only after it is back
  up. A busy gun (mid-shot, mid-raise) is handed to the mod as `dfa_reload:<class>`.
- **Doom mod (`DoomerfallAmmo.zs TickReload`)**: waits for that busy gun to be ready with an empty magazine, then does
  the same. It gives up after 3 s, on a swap, or if DRLA started its own reload.
- No bridge change: the bridge layout hash is unchanged, so other lanes' test folders still work. The engine change
  is inactive unless Daggerfall sends a change key unload, which needs a bridge session on a Daggerfall map.

### Failed approaches

1. Mod-only (no engine change): the mod listened for `dfa_unload`. It never saw it: `d_net.cpp:3117` gives that
   event to the engine (`DD_BridgeItemNetEvent`) and does not pass it on to ZScript event handlers. The first test run
   showed no reload on any gun.
2. Engine forwards `dfa_reload` to the mod for every change: the reload played, but it started 2 to 4 tics after the
   reserve switched (the forwarded event goes through the local network queue). A stock gun could fire new-tier
   shells in that gap (test: `Shotgun ready fire=1 reserve=Shell:1` at tic 8, `down` only at tic 12). Hence the
   same-tic start in the engine, with the mod only for busy guns. The mod's waiting path is the one run 2 exercised
   end to end (all three guns reloaded through it).

### Settled by DRLA's reload and the existing ammo design (no owner question needed)

- **Rounds left in the magazine** go back to Daggerfall's inventory as their old tier, as before (owner, recorded in
  `gamedesign/decisions.md`).
- **A switch interrupted midway** (a hotkey swap during the reload animation): DRLA's `Deselect` cuts the reload before
  `ReloadWorking`, so the magazine stays empty and the reserve holds the new tier, which the gun has already recorded.
  The next Fire or Reload with that gun loads the new tier. Nothing is lost or duplicated. A second change key press
  during the reload works the same way: the magazine is still empty, the reserve switches again, and the running
  reload fills from whatever the reserve holds when it gets to `ReloadWorking`.
- **Stock guns** draw straight from the reserve and have no reload. The lower and raise is my engineering stand-in for
  "the switch is a reload" there. It is about 0.5 s.

### Known gaps

- The **automatic change** (loaded tier ran out with an empty magazine) does not start a reload. The gun reloads the
  new tier the next time the player presses Fire, as DRLA does for any empty magazine. The card is about the key.
- Doom's damage bonus follows Daggerfall's loaded tier, which switches when the key is pressed. During the reload
  nothing can fire, so this matters only for rounds already in flight.

## Play-test list

- Press Z (Change Ammo) with a DRLA pistol, shotgun and chaingun: the reload animation and sound play, and the HUD
  says "Loading <tier>". The ammo HUD at the bottom shows the new tier straight away.
- Press Z with a stock Doom gun (no DRLA): the gun dips and comes back up.
- Press Z, then swap guns mid-reload, then come back: the gun reloads the new tier on Fire.
- Does the reload feel right as the cost of a switch, or too slow or too fast?
