# Daggerfall font in Daggerfall menus (20261127-121932)

Goal: the merchant Talk / Sell popup (and other Daggerfall menus in Doom) use Daggerfall's font, and a Daggerfall
font replacement from a texture pack shows up.

## Findings

- Doom does not draw Daggerfall menus. Daggerfall Unity renders its own UI into a render target sized to Doom's screen
  and Doom shows that surface (DFB_UI_*). So every live text label in a Daggerfall menu already uses Daggerfall Unity's
  font (FONT0003, drawn with its SDF variant), and Daggerfall Unity's own font replacement applies.
- The inconsistency is in stock Daggerfall Unity: `DaggerfallMerchantServicePopupWindow` uses `GNRC01I0.IMG`, which
  has **TALK painted into the image** (blocky 320x200 pixels, scaled up to Doom's resolution), while **Sell is a live
  TextLabel** in the smooth SDF font. Two fonts in one box.
- The same mix is in the guild popup (`GILD00I0/GILD01I0.IMG`: JOIN GUILD and TALK painted, service label live).
  The repair (`REPR01I0`) and witches' coven (`DAED00I0`) popups have all three words painted, so they ignore any font
  replacement.
- Daggerfall Unity's font replacement ("texture packs for text"): `DaggerfallFont.LoadFont` reads `FONTxxxx.FNT` from
  `StreamingAssets/Fonts` (falling back to ARENA2) and `ReplaceTMPFontFromFile` swaps the SDF face for
  `FONT0003-SDF.ttf/.otf` from a mod (`ModManager.TryGetAsset`) or `StreamingAssets/Fonts`. Image texture packs
  replace `GNRC01I0.IMG` etc. through `TextureReplacement.TryImportImage` (`StreamingAssets/Textures/Img`, or mods).

## Plan / what was done

1. `Doomerfall/DoomerfallPopupText.cs`: in a bridge session, cover a painted button word with the plain service row of
   `GNRC01I0.IMG` (scaled for larger texture-pack images) and draw the word as a TextLabel in Daggerfall's default font,
   styled exactly like the popups' own service label (1 px down, centred, no shadow, default yellow).
2. One-line hooks in the four popups (merchant service, guild, repair, witches' coven). Guild members get a greyed
   "Join Guild", as `GILD01I0` paints it.
3. `DoomerfallMenuTextTest` (test-only, `-dfmenutexttest <folder>`) now also opens the four popups and saves
   Daggerfall Unity's own render of each.

Judgment calls: words use the service label's mixed case ("Talk", "Join Guild", "Repair Item"; localized keys where
Daggerfall Unity has them: `serviceSell`, `serviceDaedraSummon`, `quest`). The red EXIT buttons stay painted: they are
button art that every Daggerfall window uses, not a row of text beside live text.

## Not covered / known gaps

- Repair and coven popups borrow GNRC01I0's plain row for their cover strips (see above).
- Painted words elsewhere (the red EXIT buttons, and the many other Daggerfall windows whose buttons are pictures,
  such as the inventory's tabs and the character sheet's buttons) stay pictures. They are button art in every
  Daggerfall Unity window, follow image texture packs, and sit apart from live text. Not changed; see the question.
- Doom's own HUD messages use `dffont3sdf` rasterized into ddruntime.pk3 from Daggerfall Unity's built-in SDF font;
  a font replacement does not reach them. They are not Daggerfall menus, so out of this goal's scope.
