# Location state 3: the location ledger for interiors, towns and the overworld

Run 20261124-141035, branch `agent/locationledger-20261124-141035`, on top of card 2 (`c369613`). Research:
`work/notes/20261124-105104-location-state-research.md` section 4; card 2 notes: `work/notes/20261124-133643.md`.

## Plan (as carried out)

1. Bridge: two new place kinds in the reserved kinds 200-205 (no new event kinds needed): `DFB_PLACE_INTERIOR`
   (map id + building key) and `DFB_PLACE_CHUNK` (exterior world chunk x, y), plus `DFB_PLACE_WORLD` (ask for every
   exterior chunk; also the empty record that ends the answer). `dfb_place.pad` became `dfb_place.key`.
2. Doom: interiors use card 2's path unchanged (report on leaving and on save, ask on entry, compare with the cache,
   rebuild if different). The exterior is one world table area in world units (towns and the overworld share it), so
   it is reported per chunk: Doom marks a chunk dirty whenever a table row in it changes, and reports every dirty
   chunk, plus the chunks of live actors that would park as a row, on leaving any map and with every save.
3. Daggerfall: `DoomerfallLocations.cs` keys `B<map>:<key>` and `O<cx>,<cy>` next to `D<map>`; a chunk record replaces
   that chunk; an id lives in one chunk only (a monster that walked into another chunk leaves the old one).
4. After a load Doom asks for every exterior chunk at once, compares each with its cache, and rebuilds what differs;
   overworld chunks are not built until the answer is in (at most 5 s).
5. Prove it with a paired session: street, house, wilderness, travel, save, load, load without Doom's table.

## Design decisions (engineering calls)

- **Exterior key = world chunk** (32 x 32 tiles, 8192 Daggerfall units, the world table's own bucket). A town street
  and the wilderness around it are the same kind of place in Doom's table (real world units), so one key covers both
  and a monster that walks out of town stays one fact. Positions are chunk-relative (x, y from the corner, z world
  height), so 32-bit floats keep full precision. A town is therefore not a single record; it is the chunks it covers.
- **When chunks are sent.** Only Daggerfall's save makes anything permanent, so the save-time report is what
  matters: it covers every chunk changed since the last report (from the table) and every chunk with a live changed
  actor. Leaving an exterior map also reports (after its actors are parked), so the ledger is current between saves.
- **Apply after a load, not per entry.** Exterior chunks stream in as the overworld window moves; asking per chunk would
  stall the treadmill. Instead all chunks come once after each load (`DD_LocationsResync`), and the table is fixed
  before any chunk is built (`ProcessPending` holds while the answer is pending). A chunk whose actors are live on the
  running map (the current town, or built overworld chunks) keeps Doom's actors from the save, which Daggerfall's
  ledger came from too; only tombstones are added there.
- **Overworld monster ids.** They already had a Daggerfall-derivable id: tag 2, world chunk y and x, index in the
  chunk's seeded pack (`dd_treadmill.cpp BuildSeeds`). It depends only on the world chunk, not on Doom's session, so no
  new id was needed. `DoomerfallLocations.OverworldMonsterId` documents and computes it on Daggerfall's side. (The pack's
  classes still come from Doom's placeholder config; encounter design is the owner's.)
- **Guard ids vs session ids (card 2's warning).** Doom's session ids are now tag 4 with bit 60 set
  (`SESSION_ID | n`); Daggerfall's guard ids are tag 4 with a small spawn serial. Before, a Doom drop and a guard could
  share an id and overwrite each other's row in towns. `IsSessionId` tells them apart. (Saves made before this change
  carry old-style session ids, which now read as non-session ids; harmless except that they would not get fresh ids on
  a rebuild.)
- **Townspeople, NPCs and containers.** Their deaths and corpses were already table rows keyed by Daggerfall's ids
  (tag 7 townsperson, tag 6 NPC), so they now travel in the chunk and interior records with no extra code. Daggerfall's
  container ledger (loot piles) is keyed by Daggerfall's own place data already and was left as it is (not folded in).
- **Off-window overworld monsters (on hold).** Not changed: they park as rows when their chunk leaves the window, as
  before, and the ledger records those rows like any other fact.

## Findings

- Leaving the town stores every Doom pickup on the town map as "changed" (`DDTM left DDT07154: 27 stored as changed, 0
  unchanged`), so a visited town's chunks carry its pickups as facts. The count is stable across visits (no
  duplicates), so this only costs ledger size. Not investigated (outside this card).
- Chunks are re-sent on every departure from an exterior map when anything in them was live, because parking stores
  every restored row again. That is a few small records per departure.

## Not tested

- Guards in towns: no guard spawned in these runs, so the guard/session id split is shown only by the code.
- A monster walking from one chunk into another between reports (Daggerfall removes its id from the old chunk; not
  exercised).
- A load inside a town or the overworld with `-ddlocnotable`: there the current map's actors come from the level
  snapshot and only tombstones are added; the runs saved away from every checked place on purpose.

- Fast travel through Daggerfall's travel map: the route used `dd_tm_warp`, the same overworld handoff fast travel uses.

## Failed approaches and harness fixes

- `out` is a ZScript keyword (`Unexpected 'out'`); renamed.
- The house would not open: `location_ledger.assemble` copies the converter into card 1's folder, so card 2's folder
  had an older converter that writes interiors without place keys, which the town cache refuses ("unreadable, giving
  up"). `ledger3.py run` now copies this lane's converter in.
- First signatures were printed 1 s after the forced kills, while corpses still slid; the route now waits 4 s.
- Restored monsters walked a few tics before the route froze them, and on the second pass out of town the wounded
  wilderness monster was not frozen at all, so it parked 40 units from where it was printed. The route now freezes
  from the first tic everywhere a place is printed or passed through.
- The far spot's pack stands farther than 4096 units from the warp point; the far check now covers 10,000 units.

## Play-test list

- Kill a few things on a town street and in a house, take an item in each, leave town, travel far, come back, save,
  load: the corpses lie where they fell, the wounded monster is still wounded, the taken items stay gone.
- Fight a wandering pack in the wilderness, travel away and back: the dead stay dead and the rest are where they
  stopped.
- Watch for hitches when leaving a town with many corpses (the report adds well under a millisecond here).
- After loading a save, walk straight into the overworld: chunks may appear up to a moment later than before (they wait
  for Daggerfall's ledger, normally within a frame or two).
