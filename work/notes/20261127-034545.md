# Attributes in Doom 04: Luck (run 20261127-034545)

Goal: Luck keeps Daggerfall's own effects; Doom also gives more frequent ammo drops, +0 at Luck 0 rising linearly to
+100% at 100 (starting at Luck 1), live value, above 100 counts as 100. The extra ammo must not perturb the fixed-seed
loot: it rolls on its own stream. Manual line.

## Plan

1. Find where monster ammo drops are made. Done: every loose ammo pickup on a Daggerfall map in a bridge session is
   turned into one tiered pickup by `DoomerfallAmmoTiers.Convert` (`mods/doomerfall/src/zscript/DoomerfallAmmo.zs`),
   one tic after it spawns, outside any engine loot scope. A drop from a monster's fixed loot roll carries the engine's
   seed (`DD_LootSeed`, from `dd_lootrng.cpp`), and its tier roll is already a pure hash of that seed.
2. Add the Luck roll there, in ZScript, after the fixed roll. No engine change.
3. Daggerfall test hook `-dflucktest <value>` to set Luck; paired run reusing `tools/fixed_drops/paired.py` (real New
   Game, Privateer's Hold, kill the gunners near the start, list every drop) at Luck 1 and 100.
4. Manual line.

## Design and why

- `DoomerfallAmmoTiers.LuckDrop`: for an ammo pickup **dropped by a monster with a fixed loot seed** (so not placed
  map ammo, and not drops of summoned monsters, which vanish anyway), roll `u = Unit(Mix(seed, LuckSalt), 1)`; if
  `u * 100 < min(Luck, 100)` spawn one more **ordinary** drop of the same ammo type and size, with its tier rolled
  from the same Luck stream (`RollTier`, same area-level odds, no jackpot). Expected ammo drops: x(1 + Luck/100), so
  +1% at Luck 1, +50% at 50, +100% at 100. Luck 0 or no character (-1, plain Doom) does nothing.
- **Own stream without any random state:** the Luck number is a hash of the drop's fixed seed with its own salt. It
  draws from no Doom random stream (a `Random()` call would advance a gameplay stream that other things share), so the
  fixed loot (what drops, tiers, jackpots) is untouched at every Luck. Side effect, a deliberate engineering call: the
  same drop gets the same number in every game, so a luckier character gets every extra drop a less lucky one gets,
  and reloading does not reroll it. This matches Daggerfall's "same place, same loot" rule.
- Extra drop is a plain ordinary drop rather than a copy of the jackpot: a jackpot is 20 pickups, and doubling a
  jackpot would make Luck matter mostly through rare jackpots. Constrained call within "more frequent ammo drops".
- The extra pickup is made like every other tiered pickup (`SpawnTier`, outside a loot scope, no lasting id), so the
  treadmill, saves and Daggerfall's take path treat it as any converted ammo pickup.
- Live Luck via `Actor.DD_SheetStat(7)` (the sheet Daggerfall already sends). Nothing new crosses the bridge.
- Diagnostics: `DFAMMO luck drop <type> tier <t> at x y luck L` through `DDLog.Debug` (log file; on screen only with
  `dd_debugmessages`).
- Test hook: `DoomerfallLuckTest.cs` (`-dflucktest <1-100>`), one `Attach` line in `DoomerfallBridge.cs`.

## Open question (affects whether Luck matters in the real game)

With DRLA, the common monsters (former humans) drop guns, and guns never give ammo (owner, 2026-11-24). So monster
ammo drops are rare and Luck's bonus mostly does nothing; Privateer's Hold gave zero ammo drops in 977 kills. Should
Luck's extra ammo also roll on other monster drops (for example a Luck-in-100 chance of an ammo drop matching the gun a
monster drops, or on every seeded monster death), or stay limited to monsters that already drop ammo?

## Play-test list

- Start a character with high Luck and one with low Luck; clear the same group of monsters (for example the Privateer's
  Hold start). The high-Luck character should see noticeably more ammo pickups; the guns and other drops the same.
- Does doubled dropped ammo at Luck 100 feel right against slaughter-map pack sizes, or too generous?
