### 1. Regression scripts default to an old engine build: do now

- **Wrong:** a passing regression may not be testing the current engine.
- **Confirmed:** 14 scripts under `tools/` name `uzdoom-mesh`, including `special_door_regress.py`, `action_regress.py`, `city_walk.py`, and `smoke_load.py`.
- **Confirmed:** that exe is dated 2026-11-22 11:22. `UZDoom/src` has 25 non-merge commits since then, 15 of them in `playsim` or the mesh renderer. The exe does not contain the `dfbridge` string.
- **Confirmed:** some scripts accept `--exe` (`action_regress.py`), but others have no override. Some old pins are deliberate, such as `BASELINE` in `tools/hp_sync/no_session_hp.py`.
- **Not checked:** which exe past runs actually used. This does not show that any past result is wrong.
- **Simplify:** add one small shared paths module with a single "current UZDoom" setting. Keep deliberate baselines explicit and named.

### 2. C# bridge is a hand copy: do now, after position sync merges

- **Wrong:** every protocol change must be made by hand in `bridge/doomerfall_bridge.h` and in C#. Payloads are packed by hand, such as `(int)(ev.p0 >> 32)` in `DoomerfallBridge.cs:315-349` and `DoomerfallSave.cs:315-321`.
- **Confirmed, no current drift found:** all C# `Kind*` values match the header. The state struct fields match by reading. Other copied constants were not compared mechanically.
- **Confirmed, check hole:** `DfbDfState` and `DfbUzState` declare `Size = 256`, so their `Marshal.SizeOf` checks at `DoomerfallBridge.cs:165-168` still pass if fields are reordered, retyped, or missing.
- **Confirmed:** `dfb_layout_hash` is computed from the C++ layout and only logged by C#, so it cannot detect a wrong C# copy.
- **Simplify:** add a small script that generates one C# file from the header: constants, mirrored structs, and explicit-layout payload structs. A `--check` mode fails on drift. `dfb_ui_result` has a character array and may stay manual.
- **Judgment:** generation beats a richer runtime check because it removes the copy instead of policing it. The protocol is still growing, at version 4 with 21 message kinds.

### 3. Python test helpers are copied: do later

- **Confirmed:** 18 groups of same-named helpers have similar bodies across files, including `launch`, `run`, `lumps`, `read_png`, `registry_hash`, and `wait_for`. Similarity is a rough upper-bound measure.
- **Confirmed:** 69 of 90 Python files hardcode `D:\dev` paths. Eight review-assembly scripts are near copies by the same rough measure.
- **Simplify:** create `tools/common` for paths, launching, WAD reading, and PNG reading. Replace the assembly scripts with one script and a feature table.
- **Judgment:** do not migrate all 90 files in one pass. Item 1's paths module is the starting point, and scripts can move when next edited.

### 4. `dd_bridge.cpp` has mixed responsibilities: do later

- **Confirmed:** at 1,913 lines it holds session handling, position sync, UI forwarding, HP, the save and load transactions, and test drivers. Save and load take up roughly the second half.
- **Confirmed:** named test functions total 227 lines, and `RunLoadTest` alone is 123. Similar test startup lives in `DoomerfallPositionSync.cs:63-122` and `:397-432`.
- **Confirmed:** the test paths are inactive without `-df*test` flags, and the launcher does not pass them.
- **Simplify:** move save/load to `dd_bridge_save.cpp` and test drivers to `dd_bridge_test.cpp`. Compile test drivers out of release builds before shipping.
- **Judgment:** keep the in-process tests. They exercise real entry points, which is valuable.

### 5. Terrain sampling is ported twice: do later

- **Confirmed:** `dd_treadmill.cpp:289-325` and `tools/dungeon_converter/WorldTerrain.cs:142-184` both port Daggerfall's sampler.
- **Confirmed:** the noise term looks different, because C# adds clamps, but it is equivalent. Each `Perlin` result is already 0 to 1.
- **Confirmed:** a search under `tools/` found no terrain parity test.
- **Simplify:** add a small golden-value test across a few map pixels. Do not try to share code between C++ and C#.

### 6. `dd_treadmill.cpp` is one large unit: do later

- **Confirmed:** 2,091 lines, with an anonymous namespace spanning lines 76 to about 1796.
- **Judgment:** split terrain sampling, streaming, and town handoff only after the active lanes land. Splitting now would create merge conflicts in code that may be replaced.

### 7. Converter structure: leave alone for now

- **Confirmed:** `CityExport.cs` is 1,437 lines and `Program.cs` is 1,325 with about 29 command-line flags. 738 lines of runtime ZScript live in `tools/dungeon_converter/`.
- **Judgment:** this is a developer tool already split by export type. Reorganizing it buys little today.

- **Tools:** no tool folder is proven abandoned. Having no outside references is normal for per-feature test folders, so nothing should be deleted on this evidence.
