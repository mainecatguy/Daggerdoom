# Loading holds, run 3: blocking spawn and dead Doom (run 20261127-045928)

Follows `work/notes/20261127-034855.md`. Its last commit (e7745537) keeps Daggerfall paused while Doom's last published
phase is LOADING, even when Doom's heartbeat is older than 1 s (a blocking spawn publishes nothing), and releases only
after 60 s of silence (a dead Doom). That was backed by reading the code only. This run tests it.

## Plan

1. Test-only injected block: `-ddloadingblock <ms>` in `UZDoom/src/dd_loading_test.cpp` (the existing loading test
   file; no game file changed). Once, 500 ms into the first hold, it sleeps Doom's main thread for `<ms>`, logging the
   start and end on the shared clock.
2. Checker: `check_df_pause.py DF_LOG UZ_LOG` matches the two logs on their shared clock (both stamp lines with
   `dfb_now_ns` seconds) and fails any Daggerfall release that comes before the end of Doom's hold, so Daggerfall's
   clock cannot have moved while Doom still held. `--dead-doom` checks a block over 60 s: Daggerfall must release on
   its own 60-65 s after the block began. `test_check_df_pause.py` runs the checker on made-up logs (an early release
   during a block must fail).
3. Paired runs (`run_cases_2_3.py KIT case2-block case2-deaddoom`), then the regular cases and E1M1.

## Findings

- e7745537 works: through both an injected 2.5 s block and a natural 1.14 s spawn, Daggerfall saw the heartbeat go
  stale and stayed paused until Doom's hold ended. A Doom silent for 60 s releases Daggerfall.
- The dead-Doom stand-in is a hung Doom, not a killed one. A killed Doom leaves its last publish time in the shared
  memory (`dfb_peer_state_age_ns` keeps growing), which is the same path; the launcher's handling of a killed Doom was
  not tested.
- Conversion times varied from 13.8 s to 63.4 s for the same 552 dungeon on a machine busy with other lanes' games;
  the hold covered all of them.
- The first entry's level-30 spawn took 1,139 ms this run (735-785 ms in earlier runs).

## Known gaps

- New Game on the final build: no paired run (driver stall above). Covered by the plain load (same hold) and by run 2's
  New Game result before the measurement moved to the test class (log since overwritten).
- 60 s is a long wait before a dead Doom releases Daggerfall. A dead Doom ends the session anyway, so it only matters
  if Daggerfall should stay usable afterwards.
