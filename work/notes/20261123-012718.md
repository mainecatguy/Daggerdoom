# Player HP sync (MVP)

Branch `agent/engine-20261123-012718`. Daggerfall owns the player's HP and death. Doom reports each hit or heal as a numbered event, Daggerfall applies them in order, and Doom shows Daggerfall's confirmed HP. Verified with the real games, stock and with the DRLA set.

## How it works

- **Doom to Daggerfall.** `P_DamageMobj` reports the post-armor damage as a hit event and leaves health alone, so pain, flash, and knockback still happen but no Doom death. `P_GiveBody` reports the heal Doom would have applied against the shown HP, clamped to Daggerfall's max HP so a pickup is not consumed when Daggerfall is full. Event numbers start at 1 and go up.
- **Daggerfall.** `SetHealth(current -/+ amount)` in order. Shield, armor, and scaling are deliberately skipped, so values pass through unchanged. The last applied number goes out as `hp_applied_event`. Daggerfall-side damage (`DecreaseHealth`) changes the player directly and is simply published.
- **Mirror.** At the start of each player tic Doom sets `player->health` to Daggerfall's confirmed value. No estimate. Anything that changed health in between by a path without its own hook (a ZScript assignment) is turned into a hit or heal event of the difference first, so nothing is lost.
- **Death.** Daggerfall sets a dead flag in the same state publish as `hp_current` (`CurrentHealth <= 0`, so god mode and guild `AvoidDeath` are honored). Doom then calls `P_DamageMobj` with `DMG_FORCED` and the hook bypassed. Until then the pawn is never killed by Doom, even from a 500 damage hit.
- **When it is active.** Only in a bridge session while Daggerfall publishes the valid flag. Today that means the test start (`-dfsynctest`, which puts Daggerfall in a game at 100/100). In any other case Doom's code takes the stock path.

## DRLA interaction

Scanned DRLA and DRLAX scripts (`tools/hp_sync/scan_drla_health.py`). 34 places touch health.

- **Covered by the hooks.** `A_DamageSelf` (self-damage weapons, armor mechanics, barrels) goes through `P_DamageMobj`. `GiveInventory("Health")` and `A_RadiusGive("Health")` go through `P_GiveBody`. DRLA's armor and damage factors run before the hook, so Daggerfall receives the post-armor number. `give medikit` worked and healed 25 under DRLA.
- **Covered only by the per-tic difference.** DRLAX scripts assign health directly: Nomad (`Players[i].health = default`), PhaseSisters (`owner.health = lasthealth`), a familiar (`playeractor.health = 666`), and an item (`owner.health = 10`). These become one hit or heal event of the difference. The 666 case would send a heal of about 566, which Daggerfall clamps to its max. None of these classes were played, so this is reasoned, not tested.
- **DRLA's max health.** DRLA can raise Doom's max health. A heal is clamped to Daggerfall's max, so pickups are refused when Daggerfall is full. Not tested at full health.
- **Not observed.** The ACS health `GiveInventory("Health", 1)` at `DRLALIB_Player.acs:96` did not fire in 20-second runs, so DRLA regeneration was not measured. It would send one heal event per trigger.

## Known gaps and choices

- **No instant estimate**, as designed. The shown HP lags a hit by one frame of each game (a few ms here). Heals are clamped against the shown HP, so heals sent in the same tic as a pending hit are clamped to the stale value.
- **Death flow.** Daggerfall's own death flow ran after the kill: about 3 seconds later it went back to a new game (`31/31, dead False`). Doom stays dead because the kill fires only on a living player. A Doom respawn while Daggerfall is dead would be killed again. This belongs to the death and restart task.
- **Level change.** A new pawn is adopted from Daggerfall's value, with no event for the difference.
- **Prediction.** The hooks skip the predicting player. Test code that changes health outside a tic acts on a prediction copy, which cost a failed first run; the scripted steps now run inside the player tic.
- **Voodoo dolls** share the bridged player's health and are routed through the same hook by the player check, but were not tested.
- **Valid flag.** Daggerfall reports valid only after the test start. The real startup flow has to set it.
- Strife `P_AutoUseHealth` and `SKILLP_AutoUseHealth` paths still change health directly and would be reported as direct differences.

## Failed approaches

- First scripted run applied nothing: the test ran in the main-loop pump, where the player is a prediction copy, and the mirror erased the changes. Fixed by running steps in the player tic.
- First DRLA run ended early because the fatal-error match included `Script error`, which DRLA's own load warnings contain. The match was narrowed to `Fatal error`, `FATAL`, `VM execution aborted`, `Unhandled exception`.
