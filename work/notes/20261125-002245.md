# Label under the crosshair (run 20261125-002245)

Goal: a short label just below the crosshair naming what the player looks at, only for things close enough to
interact with, drawn like Doomerfall's other HUD labels (card `hudfont`, notes 20261125-001515).

## Plan
1. Pick the target with Use's own rules, so the label and Use agree on what is in front of the player.
2. Name what Doom knows itself (monsters, Doom items); ask Daggerfall once per target for what only it knows (NPC and
   townsperson names, piles, building names), and cache the answer.
3. Draw it in the mod with `DoomerfallText.Scale()` and SmallFont, like "Sneaking".
4. Paired test with a harness walking to each kind of target in and out of reach; demo folder.

## How it works
- **Engine, `UZDoom/src/dd_look.cpp` (new).** Called once per tic from `DD_BridgeFrame` (so never without a bridge
  session) and returns at once off generated Daggerfall maps (`DDTreadmill_PlayerWorld == DD_AREA_NONE`). Target order
  is Use's order:
  1. `DD_LookItem` (dd_items.cpp): `ItemInView`, Use's own aim and 96-unit reach, also counting visible pickups taken
     by touch (they are taken too, by walking). Daggerfall pile or container -> asks Daggerfall (`DFB_INFO_PILE`).
     Doom item -> `ItemName`, the same name Doom sends Daggerfall for its inventory (`DoomerfallDoomItems.NameFor`).
  2. `DD_InfoLookPick` (dd_info.cpp): the `Pick` Use's NPC check uses (first NPC/townsperson/living monster on the view
     ray, before a wall). NPC or townsperson within 192 units (Daggerfall's 256-unit NPC activation distance at Doom
     scale) -> asks Daggerfall. Monster within 96 units -> its Doom tag (`GetTag`), or "Monster" when it has none.
  3. `DDTreadmill_DoorInReach` (dd_treadmill.cpp): the town door or exit `TickTownDoors` would take on a Use press
     (96 units, 60 degree cone). Building door -> asks Daggerfall with a point just inside the door. Dungeon entrance or
     exit from a building/dungeon -> "Door".
  4. A converted action door (`DFDoorBlocker`) on Doom's use line within the player's `UseRange` -> "Door".
  Labels Daggerfall gives are cached per target until the map changes; pile labels are asked again each second while
  looked at, since taking from a pile changes it. The mod hears the label only when it changes (`dflook:<text>`
  console event, as `dfhud_top:` is sent). Each change is logged to the log file only (`look: "..."`, PRINT_LOG).
- **Bridge.** `DFB_KIND_LOOK` 93 (UZ to DF, `dfb_info_request`) and `DFB_KIND_LOOK_TEXT` 94 (DF to UZ, `dfb_info_text`,
  multi-part like INFO_TEXT), targets `DFB_INFO_TOWNSPERSON` 4 and `DFB_INFO_PILE` 5. **The layout hash changes**, so
  old test and demo folders need this branch's bridge DLL, launcher and uzdoom.exe.
- **Daggerfall, `DoomerfallInfo.OnLook`.** Read-only: runs no interaction, discovers nothing, answers while paused.
  NPC: `StaticNPC.DisplayName`. Townsperson: `TownPerson.Name`. Building: the discovered name if the player knows the
  building (quest overrides included), else `PlayerGPS.GetBaseBuildingDiscoveryData` (made public; it changes no
  discovery state), through Daggerfall's grammar processor, exactly the text Info would show. Pile:
  `DoomerfallItems.Label` (see the judgment calls below).
- **Mod, `zscript/DoomerfallLook.zs` (new handler).** SmallFont, `DoomerfallText.Scale()`, gold like "Sneaking",
  centred on the 3D view, its top at the crosshair's lower edge (8 px x crosshair scale) plus a 4-pixel x scale gap.
  Stock Doom text is untouched.

## Judgment calls (constrained, within the card)
- **Piles.** Daggerfall's Info names only corpses ("You see a dead %s"); a treasure pile gets no Info text. The card
  requires a label for a loot pile, so a pile is named by what lies on top: one item -> its Daggerfall name (`LongName`,
  e.g. "Iron Longsword"); several -> "<first item> and more" (the same phrasing as Doom's take message). A corpse with a
  name -> "Dead <name>". Furniture containers (shop shelves, house containers) get none, as Daggerfall names none and
  naming their contents would reveal them before opening. Asked as a question.
- **Doors with no Daggerfall name** (action doors in dungeons and interiors, building exits, dungeon entrances) show
  "Door". Daggerfall's Info on them is plain Grab with no text. Asked as a question.
- **Guns have no material yet.** A gun's material is rolled when it is taken (unseeded on this branch), so on the floor
  Daggerfall's inventory name is not known. The label is the name without the material (e.g. "Shotgun"). Once the
  fixed-drops branch (seeded material from the floor item's id) is merged, Daggerfall could name the material too.
- **Monster reach** is 96 units (Daggerfall's default activation distance; Use does nothing to monsters).
- **Touch pickups** (stimpacks, ammo) get labels too: they are Doom items the player takes.

the harness re-applied its outdoor hold position on the interior map.

Not covered by the test: walking townspeople (same code path as NPCs, `TownPerson.Name`), converted action doors in
dungeons ("Door", from Doom's use trace), building exits and dungeon entrances ("Door"), touch pickups.

## Play-test list
`D:\dev\DoomDaggerfall-loop\review\look-label\play.bat` (1280x800 window, town start, DRLA).
1. Walk up to a townsperson or a standing NPC: their name appears under the crosshair at talking distance.
2. Face a building door: the building's name. Step back: it goes away. A bare wall: nothing.
3. Find a monster (or type `summon zombieman` in the console): its name at close range only.
4. Look at a dropped gun or pickup on the floor: its name. Doom players rarely look down; items on the floor just ahead
   count, as for Use.
5. Is the label placement right (not covering the crosshair, not too far below)? Try full screen and `crosshairscale`.
6. Is gold the right colour, or should it be white or Daggerfall's yellow?
