# Debug find-NPC (dd_findnpc), run 20261127-211845

## Plan

1. Bridge: four event kinds reusing existing payloads (no new structs, no layout change): `FIND_NPC` (UZ→DF, the
   typed name), `FIND_TEXT` + `FIND_MATCH` per match, `FIND_END`. Target kinds `DFB_FIND_ACTOR_WORLD/_LOCAL`
   (an NPC/townsperson id Doom may draw, with a fallback point), `_WORLD` (Daggerfall world point, a building door),
   `_LOCAL` (Doom units in the current building/dungeon), `_ELSEWHERE` (text only).
2. Daggerfall (`DoomerfallFindNpc.cs`, one call from `DrainEvents`): searches quest people of active quests, loaded
   StaticNPCs (current building/dungeon, town street NPCs), every building's residents in the current town from block
   data (named exactly as `StaticNPC` names them: seed `Position ^ key + locationIndex`, region name bank, Individual
   factions by name; DFRandom seed restored), and the town's townspeople roster (their plan step says inside which
   building, or their outdoor pose). Case-insensitive substring; exact, then word-start, then other; pointable before
   elsewhere; 30 sent at most.
3. Doom (`dd_findnpc.cpp`): `dd_findnpc [name]` console command (no name opens the mod's text box), net events from
   the mod's menu, the answers, the per-tic target (actor found by id each tic, or a point; world points converted
   with `DDTreadmill_WorldToLocal` each tic since the treadmill moves the origin), area-change clearing (map, area kind,
   maptime going back = load, a >4000-unit world jump = travel), and the overlay drawn from `D_Display` beside the quest
   faces, projected as the hardware renderer does (FOV / 4:3 fov ratio / pixel stretch / pitch).
4. Mod: `DoomerfallFindNpc.zs` text box (TextEnterMenu) and pick list; Doomerfall Controls entry; default key N in
   `scripts/play/install.py` (fresh configs only, like the other keys).
5. Everything is gated by `dd_dev` on the Doom side (the command refuses, the marker clears when dev mode goes off).
   Daggerfall only reads.

## Decisions (engineering calls)

- Building target = the building's door (Daggerfall `StaticDoor` centre in live transform coordinates), not centre.
- Distance shown in metres (Doom units / 30, from 40 DF units per metre at 75% scale).
- A resident of another building listed while you are inside a building: text ("in X, town"), since you cannot point
  through walls. A townsperson outdoors while you are inside: text.
- Residents are listed from the layout even when the shop is closed (the building still is where they live); inside
  the building, presence comes from Daggerfall's live NPCs ("lives here, away now" when switched off).
- Quest NPCs placed in a dungeon of the current location point at the dungeon entrance when outdoors.
- No protocol bump: new kinds only; unknown kinds are skipped by contract rule 7.

## Findings / failed approaches

- First Unity build failed on a missing `using DaggerfallWorkshop.Game.Utility` (NameHelper); fixed.
- `P_PointInSector` is not visible in that translation unit; used `FLevelLocals::PointInSector`.
- Did not cache the found actor pointer across tics (a destroyed townsperson could dangle); the id is searched each tic
  while a marker is up. Cost is one thinker pass per tic, only in dev mode with an actor marker up.
