## Design and engineering calls

- **Where modded pickups keep their mods.** DRLA's `GetWeaponMods` (DRLALIB_Mods.acs) copies the dropping player's
  `<Weapon>ModLimit`, `PowerMod`, `BulkMod`, ... onto the pickup actor's own inventory, and `+INVENTORY.TRANSFER` moves
  them to whoever touches it. So when Use takes a gun, `AskDaggerfall` sends every inventory item on the pickup named
  `<Weapon>...` as `DFB_KIND_DOOM_ITEM_GUN_STATE` (new kind 146) lines before the take, and Daggerfall stores them as
  the item's `GunState`, the same format a hotkey swap stores. Drawing the gun then sets them exactly as for a swap.
  No ZScript change was needed.
- **Bridge.** New kind 146 and take flags `DFB_DOOM_ITEM_ARMOR` (2), `DFB_DOOM_ITEM_WEARABLE` (4), and the slot in bits
  8-11 (`DFB_DOOM_ITEM_SLOT_MASK`, slot + 1, 0 means none). No struct change. Bindings regenerated, which changes the
  schema hash, so the bridge DLL and launcher were rebuilt.
- **Armor classification (Doom side, `TakeFlags`).** Armor: descends from `Armor` (stock armor and bonuses, DRLA's
  `RLArmorBonus100`...) or `RLArmorBonusPickup`. Wearable (cannot be worn yet): `RLGenericArmorPickup` or
  `RLGenericBootsPickup` and their subclasses. Stock armor and armor bonuses are used up when used, as Doom does, so
  Use from the inventory still applies them.
- **Daggerfall record.** `shortName` gains `<class>|armor|` and `<class>|wear|`, next to the existing `<class>|gun|<state>`.
  Items taken before this change stay in Clothing & Misc (their record has no marker).
- **Auto-draw.** "No hotkeys yet" means all five squares of that key are empty. The draw waits until the starting gun
  has been adopted and no swap is in flight, because a swap before adoption would put Doom's starting gun away as an
  unexpected gun and lose it.
- **Test change.** `tools/hotkeys` now expects the shotgun to be drawn when taken (key 3 is free), adds a modded pistol
  (key 2 taken, so it waits; the test puts it on key 4), stock `GreenArmor`, and `RLGenericArmorPickup`. The load run
  also draws the modded pistol to show the mods were in Daggerfall's save. Demo folder: `review\gun-pickup-rules`.

## Failed approaches

- First full run: the load test lost the modded pistol's mods. When Doom puts a gun away it names it by its plain
  pickup (`RLPistolPickup`), but the Daggerfall item was `RLPistolPickupModded`, so `OnStashed` did not match it and
  logged "unexpected gun" and threw the state away. Fixed by also matching `<pickup>Modded`. The swap test now also
  checks that the put-away state reached the Daggerfall item.

## Known gaps

- A gun taken in the first second of a new game, before the starting gun is adopted, could take key 2's place in the
  table check: adoption only fills key 2 when the table is empty.
- Old saves: Doom items taken before this change have no armor marker, so they stay in Clothing & Misc.

- DRLA armor bonuses (`RLArmorBonusPickup`) are listed as armor that can be used up, like stock bonuses. DRLA's bonus
  repairs worn DRLA armor, which cannot be worn yet, so using one may do little for now.
- A gun with no Doom weapon slot (none seen) stays in the inventory.
