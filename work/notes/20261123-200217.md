# First use of a town door

Branch `agent/towndoor-20261123-200217`. Test build: `D:\dev\DoomDaggerfall-build\uzdoom-towndoor\Release\uzdoom.exe`.

## Cause

A building interior is converted the first time it is needed, which took about 4.2 s on an idle machine. Pressing Use during that time prints "Opening..." and remembers the door. Two bugs were in that wait, both in `TickTownDoors` in `UZDoom/src/playsim/dd_treadmill.cpp`:

1. **The press was silently dropped.** Moving more than 160 units from the door forgot it, with no message. Conversion carried on, so the next press entered at once. This matches the owner's report. At Doom speed, 160 units is well under a second of movement.
2. **The pressed door could lose its place in line.** Its top-priority request was overwritten by the nearby-door prefetch, so a neighboring interior could convert first.

## Fix

- A pressed door now stays pending out to 768 units, the range at which nearby interiors are prefetched.
- Going past that prints "You left the door." instead of failing silently.
- The pressed door's request is made after the prefetch requests, so it stays first.

No profiling or debug code was added to the engine. `tools/town_door/first_use.py` is the repeatable test.

## Evidence

Each run starts from a cache holding only the town and presses Use exactly once. UZDoom runs alone, minimized.

| Scenario | Before | After |
|---|---|---|
| Stand at the door | Entered, 151 tics | Entered, 166 tics |
| Step 300 units away | **Never entered** | Entered, 566 tics (machine was loaded, conversion took 15.9 s) |
| Go 1000 units away | Not run | Not entered, prints "You left the door." |
| Another door converting, a third door closer | Order B, C, A. Entered at 629 tics | Order B, A. Entered at 571 tics, C not converted first |

Tic counts are not a speed comparison, because other work was loading the machine and conversion times ranged from 4 to 17 s. The ordering is the result that matters in the last row.

Both real games, cold interior cache, one press, then 300 units away: Doom entered the building and Daggerfall followed. Worst door match 1.0 unit, 2 building entries, 2 exits back on Doom's position with 0.0 units of error, 0 failed transitions, 0 new Daggerfall exceptions. The owner's registry key was unchanged.

## Failed attempts

- The first two-game runs failed with bridge error -5 (layout mismatch), because the `connected-transitions` and `bridge-codegen` launchers are older than this branch's bridge. The passing run used the launcher and Daggerfall from `review\item-pickup`, with mods from `review\bridge-codegen`.
- One `still` run hit its 30 s limit under machine load with no fatal error. It passed when rerun with 45 s.

## Limits

- The first visit to an unconverted interior still waits for conversion, about 4 s or more. This fix makes the press reliable and does not make conversion faster.
- There is no on-screen progress beyond "Opening...".

## Play-test list

1. Press Use on a new town door and stay put. It should open by itself after a few seconds.
2. Press Use on a new door, then wander nearby. You should still go in without pressing again. Does being pulled inside from a short distance feel acceptable?
3. Press Use on a new door and run far away. You should see "You left the door." and stay outside.
