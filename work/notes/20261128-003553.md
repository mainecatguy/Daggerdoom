## 1. Bands follow the firing mode and alt fire

`tools/automatics/derive_bands.py` now writes one row per way a gun fires:
- **Firing modes.** AltFire is "pressed" repeatedly with no items (a dynamic walk: inventory jumps by the counters,
  `A_Jump(256)` taken, other jumps not). The counters it changes that the Fire states check are the modes. Each mode
  is walked as its own fire. A static "everything reachable from AltFire" walk was tried first and failed: armor-mod
  conversions, scavenging and mod-removal branches all looked like modes.
- **Alt fire that shoots** gets its own row. Doom uses it while the gun's `bAltFire` is set. The engine sets that flag
  while the alternate fire runs.
- If every mode fires at the same rate, the gun gets one row (Nuclear Onslaught's side switch, the HP Marksman zoom,
  the RCP120 cloak).

Results that matter: Grammaton Beretta semi 18 tics (slow), **burst 2 (fast)**, **full auto 5 (slow)**. Full auto
really is 5 tics in DRLA's DECORATE: shot, then C1 D1 E1 G1 A1, then F with A_ReFire. Its AltFire only switches mode,
so with alt held it keeps the mode's band. Widowmaker SMG primary 2 (fast), alt 18 (slow). Marksman Rifle 7 unzoomed,
8 zoomed (both slow).

Doom: `DoomerfallAutomaticBands.BandOf(Weapon)` reads the holder's mode-item count and `bAltFire`.
`BandOfGun(holder, class)` is for hits. A projectile's tag now keeps `autoBand` from the moment it was fired
(`DoomerfallShotTag.autoBand`, copied to what it spawns), so a mode switch before it lands does not change it. A
bullet lands in the tic it is fired, so it uses the gun's band at that moment.

## 3. The extra bullet is the shot's own bullet

UZDoom already has `WorldHitscanPreFired` (`events.cpp` 708), which passes every LineAttack argument before the
bullet flies, so **no engine change was needed**. `DoomerfallAutomatics` records the player's first real bullet of
the tic: damage (after the gun's own random roll), damage type, puff, line flags, range and z/forward/side offsets.
It also records the aim at that moment: the player's angle and `BulletSlope()`, the same autoaimed pitch
A_FireBullets uses. The extra bullet repeats that LineAttack with its angle and pitch mirrored about that aim.
Mirroring gives the same spread distribution as the gun's own symmetric scatter, and an accurate first shot repeats
exactly. A projectile shot is mirrored about the aim taken when the projectile spawned (`BulletSlope`; P_SpawnPlayerMissile
autoaims over the same 1024 range). The old puff/last-hit code is gone (`NotePuff`, `baseDamage`, `tickDone`).

Judgment call: the extra bullet copies the shot's first bullet's damage roll rather than rolling its own. That is what
"identical" reads as, and it needs no knowledge of each gun's damage formula. Each shot still rolls its own, so extras
vary shot to shot (6/12/18 for the Thompson in the test).
