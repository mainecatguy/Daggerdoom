# Luck: a 0-50% chance for each kill to drop ammo (run 20261127-112323)

Goal: every kill has a Luck/2 percent chance to drop ammo (0% at Luck 0, 50% at 100), base 0%. Remove the old
Luck-in-100 extra-ammo rule (attributes 04, run 20261127-034545). Doom rolls; Daggerfall sends Luck as now.

## Plan

1. Replace `DoomerfallAmmoTiers.LuckDrop` (extra copy of an existing monster ammo drop) with a per-kill roll in the
   same handler's `WorldThingDied`. No engine change, no bridge change, no Daggerfall change.
2. Rewrite `tools/luck/luck_paired.py` to measure the per-kill drop rate against Luck/2 at several Luck values, stock
   and DRLA, on the real paired game (fixed-drops harness: New Game, Privateer's Hold, kill the monsters near the start).
3. Manual's Luck line.

## What was built

- `mods/doomerfall/src/zscript/DoomerfallAmmo.zs`:
  - `WorldThingDied`: in a Daggerfall session (`rules`, area level known), for a dying monster with a fixed loot seed
    (`DD_LootSeed() != 0`: a monster Daggerfall placed), read live Luck (`DD_SheetStat(7)`, as before). Luck <= 0 (or
    -1 with no character / plain Doom): nothing. Else hash the seed with the Luck salt; drop when
    `roll * 200 < min(Luck, 100)`, i.e. Luck/2 percent.
  - The drop is exactly one pickup: half a small pickup (Doom's dropped-clip size), tier from the area level's usual
    odds (`RollTier`), **no jackpot** (verifier fix: the first version sent it through the jackpot path, which the
    goal did not ask for). `Convert`'s body was moved into `Drop()` (pure extraction, same numbers and seeds).
  - The old `LuckDrop` and its call in `Convert` are removed.
- Diagnostics (log file only; on screen only with `dd_debugmessages`): `DFAMMO luck kill <class> luck L roll R
  drop|none` for every roll, `DFAMMO luck drop <type> ...` before the drop's own `DFAMMO drop|jackpot` line.
- `manual.md` Luck line rewritten.

## Engineering / constrained calls (owner may want to change)

- **Which ammo:** the goal does not say. I picked one of the four types evenly at random (from the same hash), not
  "ammo for the gun you hold" — the latter would be a bigger design change (Luck would also choose useful ammo).
  Asked as a question.
- **Size:** a small dropped pickup (10/2 = 5 bullets, 2 shells, 1 rocket, 10 cells), like Doom's dropped clip.
- **Jackpot:** none. Luck decides only whether ammo drops (removed after the verifier's review).
- **Which kills:** every death of a monster Daggerfall placed (fixed loot seed), whoever killed it: infighting,
  faction fights and the environment count too (the goal says every kill). Summoned and revived monsters roll nothing,
  matching the existing rule that they drop nothing. **Town guards never roll**: they are bot player pawns
  (`dd_guards.cpp`), not monsters. Asked as a question; the manual says both.
- **Determinism:** the roll is a hash of the monster's fixed loot seed, like the rest of the loot, so a kill rolls the
  same number every game and a luckier character gets every drop a less lucky one gets.
- **Spawned on the next WorldTick (second verifier fix).** The earlier versions spawned the pickup inside
  `WorldThingDied`, which runs inside the death's loot scope (`CallDie`). `ConstructActor` draws `FloatBobPhase` from
  `pr_spawnmobj`, which then reads the dying monster's loot stream, so every later draw of that monster shifted:
  chance DropItems, death-state randoms and the drops' toss velocities. Luck changed the monster's own loot. Now
  `WorldThingDied` only queues position, velocity, type and tier, and `WorldTick` spawns them, outside any loot scope,
  as the original LuckDrop did. The pickups have no loot id, like every converted DFAmmo pickup.
  Evidence of the bug (in-scope build 99b61f87): 65 of 135 stock and 373 of 977 DRLA monster drops landed somewhere
  else at Luck 100 than at Luck 1, because their toss velocities come from that stream.
  - New check in `luck_paired.py`: the monsters' own drops must land on exactly the same spots at every Luck (the
    harness kills monsters where they stand, so the spot reflects the loot stream). A first try at a chance-drop probe
    (stock zombiemen replaced by a subclass with chance DropItems) failed: the replacement made the encounter builder
    stop placing zombiemen, so I dropped it. DRLA's own chance drops (sergeants' Dosh) never reach the drop list in
    this setup, so chance drops cannot be seen directly; the landing spots can.
