## Fog and foggy sky: how

| Piece | How |
|---|---|
| Bridge | `DoomerfallWorldLook.cs` also sends `fog <on> <mode> <density> <start> <end> <r> <g> <b> <sky>`: Unity's `RenderSettings.fog`, `fogMode`, `fogDensity`, `fogStartDistance`, `fogEndDistance`, `fogColor`, and `!currentOutdoorFogSettings.excludeSkybox`. These are what `WeatherManager.SetFog` and `DaggerfallSky.SetSkyFogColor` left, so clear (linear 0 to 2400 m, sky colour), rain, snow, heavy fog (grey), interior (0.001/m black) and dungeon (0.005/m black) all come from Daggerfall at run time. Nothing is hard-coded on the Doom side. Without the line (older Daggerfall builds) Doom keeps its weather table. |
| Linear fog | Doom has only exponential fog (`exp(-d x dist / 64000)`). Unity's linear fog is matched at half its range (both half fogged at 1200 m for clear weather): per metre `ln 2 / ((end - start) / 2)`. Nearer than that Doom's fog is a little thicker, farther a little thinner. |
| Fine density | Sector fog density is a whole number and clear-weather fog is about 0.49. While Daggerfall's fog is on a map, its sectors hold densities in 1/16 steps; `hw_lighting.cpp` multiplies by `dd_fog_unit` (one line), which is 1 on every map Doomerfall has not written. |
| Black fog | Doom treats black sector fade as its light-level distance shading, not fog, so Daggerfall's black interior and dungeon fog is sent as colour (1,1,1), which Doom draws as real fog. |
| Places | Exterior: all sectors and the town mesh. Interiors and dungeons: sectors and mesh get fog only when the `fog` line arrives; their light is unchanged as before. |
| Sky | `UpdateSky` fills `DFSKY` with the fog colour when the line says the sky is fogged. Unity's 0.05/m fog at sky distance leaves only fog colour, so a solid fill is what Daggerfall shows. |

## Winter textures: how (switches at the next area load)

| Piece | How |
|---|---|
| Bridge | The `sky` line has a 10th field, `winter`: 1 when `WorldTime.Now.SeasonValue` is Winter. Older lines without it change nothing. |
| Converter | `--winter` (`CityExport.cs`) applies Daggerfall's winter rules: `ClimateSwaps.ApplyClimate`'s +1 archive for the sets with `supportsWinter` (terrain and the exterior building sets, including roofs), never in desert climates, not for archive 77, 82 records above 1, Swamp mages guild, or Castle records above 3 (Daggerfall's precedence kept). Ground archive +1 except in desert (`TerrainMaterialProvider.GetClimateInfo`). Nature (tree) archive +1 for the four snowy sets (`GetNatureArchive`). |
| Doom | `dd_towncache.cpp`: in winter, places are cached as `T<group>W.ddt` and converted with `--winter`. When the season changes, loaded places not held by a map are dropped from memory, so the next area load picks the new season. The place the player is in keeps its look until they leave. |
| Why not live | Textures are baked by the converter into each place's package (mesh, flats, terrain). A live swap would need a summer/winter name table and swaps on mesh batches, sector flats and tree actors. The next-load switch reuses all of the converter's work and costs nothing per frame. |

Winter cost: none per frame. The first visit in a season converts the place once (Gothway Garden: 14.8 s in the
background, 6.8 MB file), then it is cached like any other place.

Runs:

  converter): `DDTCACHE season winter`, `DDTCONV group=7154 ok ms=14816`. `wide.png`: snowy ground, snow-capped roofs,

Known gaps:

- **The overworld** (`DDOVER01`, from the prebuilt `overworld.pk3`, `WorldTerrain.cs`) is not seasonal yet; the

- The season is per area load; a place loaded in autumn stays autumn if winter starts while the player is inside.

## Findings

- **Daggerfall's clear fog is not linear to 2400 m in the running game.** `WeatherManager.cs` has linear defaults,
  but the game scene (`Assets/Scenes/DaggerfallUnityGame.unity`, line 2021 on) overrides every preset. Real values,
  all exponential per metre: sunny 0.0005, overcast 0.0008, rain 0.003, snow 0.003, heavy fog 0.05 (sky fogged),
  interior 0.001, dungeon 0.005. The paired run logged `fog 1 2 0.0005 0 0 168 176 198 0` for clear noon. So the
  goal card's "2400 m linear" was the script default, and the earlier hard-coded snow value (0.005) was also wrong.
  Reading the fog at run time fixes both, and the linear path stays in case a mod or setting brings linear fog back.
- Clear-weather fog colour is the sky's clear colour (168 176 198 at winter noon, 20 20 20 at night); heavy fog is grey.
- Black fog: Doom shows sector fade 0 as light-level shading, so (1,1,1) is used. The interior shot shows a faint
  darkening at distance and is otherwise unchanged.

two alternating passes (`cost-<state><pass>`). ms per frame, views street / sky / wide:

| State | Pass 1 | Pass 2 |
|---|---|---|

No cost visible above noise; fog is a shader term Doom already evaluates. Sector writes happen only when the fog or
light changes (25,842 sectors, as before). Fogged sky fill: 375 to 599 us, once per change.

## Not done: windows and winter (plans for the next lane)

**Lit windows.** Daggerfall's window textures emit where the pixel is palette index 255
(`BaseImageFile.GetWindowColors32`), coloured by `MaterialReader`: day 89,154,178 x 0.5, night 255,182,56 x 0.8, fog
117,117,117. `WindowStyle` switches with the city lights. Plan: the converter (`CityExport.cs`, which writes the mesh
textures) also writes a mask texture for each window texture and lists it in the DFMESH lump. `hw_dfmesh.cpp` draws
the mask batches a second time, additive and fullbright, tinted with a window colour that `DoomerfallWorldLook.cs`
sends (read from `MaterialReader`'s colours and the current window style). Needs a converter change and regenerated
town packages.

**Winter** is done (above). Next steps: the overworld converter, and the season before the first map.
