# Skill point sound and message (skillmenu 02, run 20261127-162114)

Goal: when the player gains a skill point, Daggerfall's sound plays and Daggerfall's message shows, on Doom's screen.

## Findings

- **Daggerfall Unity's message:** `PlayerEntity.RaiseSkills` (the skill check that rest and fast travel run) shows
  `skillImprove`, "Your %s skill has improved.", through `DaggerfallUI.PopupMessage`. It already reaches Doom's HUD:
  `DoomerfallHudMessages` forwards every `PopupMessage` as `DFB_KIND_HUD_TEXT`, and Doom holds a line sent while a
  Daggerfall window is open until it closes (`dd_info.cpp`, `hudHeld`). No new message code was needed.
- **Daggerfall Unity's sound:** there is **none for an ordinary skill point**. The only sound in `RaiseSkills` is
  `SoundClips.ArenaFanfareLevelUp` (clip 32, 2.3 s), played with the "master" message box when a primary skill reaches
  100. The level-up sheet has its own `SoundClips.LevelUp` (clip 96, 3.8 s). Engineering call: use clip 32, the sound
  Daggerfall's own skill-increase code plays, so a skill point and a level-up stay distinguishable. It is one constant
  (`DoomerfallPerks.SkillPointClip`); question for the owner below.
- Daggerfall's audio is muted for the whole bridge session (`DoomerfallNewGame`), so Daggerfall cannot play it itself.
  Doom already loads Daggerfall's clips from `DAGGER.SND` for ambient one-shots (`dd_weather.cpp`, `ClipSound`).
- **Card 01 (Skill XP, the Skills menu) is not in this branch.** It is on `agent/skillmenu-20261127-140808`, not
  merged into this branch's base (`e56e5dcc`). This card does not depend on it: the sound comes from a watcher that
  sees every rise of a permanent skill value, whatever caused it, so bought points will get the sound once both are
  merged. A bought point does not show "Your X skill has improved." today (card 01's Buy shows only the master
  message at 100); see "Merge note".

## Plan (as run)

1. Daggerfall: `DoomerfallPerks` already watches permanent skill values every frame during play (no hooks in game
   classes; loads and new characters reset its baseline, so they never fire). Any frame where at least one skill rose
   sends the bridge text `uisnd 32` once, and logs `skill point: sound 32 sent to Doom` in the bridge log.
2. Doom: `dd_weather.cpp` parses `uisnd <clip>` next to `amb <clip>` and plays the clip as a UI sound (`CHANF_UI |
   CHANF_NOPAUSE`, no attenuation, full volume), logging `ui sound <clip> from Daggerfall` to the bridge log. The text
   only arrives over the bridge, so a plain Doom run never reaches it.
3. Test hook `DoomerfallSkillPointTest.cs` (`-dfskillpointtest <file>`, self-starting, own file): at the HUD, gives
   Climbing 20000 uses and runs `RaiseSkills` (round 1), then six seconds later Climbing and Running together (round 2).
4. Harness `tools/skillpoint/skillpoint.py` (assemble, run, check); natives from `tools/skillpoint/build_native.py`.
5. Manual: a paragraph in "Levelling up". Demo `review/skill-point/play.bat`.
