# Nature flats beyond a town or dungeon exterior map's edge (20261128-030227)

Goal: from a town or dungeon exterior map, the wilderness nature flats beyond the map's own ground must show, standing
on visible ground, from the same procedural placement as the wilderness, and match the wilderness view
(`tools/nature/town_lookback.py`: 125 missing within 20 tiles at the City of Daggerfall, 130 at Ruins of Gaerhart Manor).

## Finding: the distant view already draws them; the measurement did not see it

The 125/130 numbers come from terrainflats run 3 (`work/notes/20261126-230950.md`), measured before `distantlod` run 2
merged (`work/notes/20261127-033005.md`, `hw_ddhorizon.cpp`). That run added, on the render-only terrain ring, every
nature flat the running map does not spawn as an actor, from the same `DDNature_Layout` call (never saved). On a town
map the ring starts at the map's own tiles: its fine band (one tile per quad, exact heights) meets the town map's
ground edge, and flats there stand on the exact ground height. That is exactly the fix the goal suggests ("let the
distant terrain ring carry these flats").

But `town_lookback.py` counted only `DFNatureFlat` actors, so the ring's flats were invisible to it and the gap still
read 125/130. So this run's work is to make the ring's flats measurable and measure them, not to build a new system.

## What was built

- `hw_ddhorizon.h/.cpp`: `DDHorizon_NearFlats(out)`, a read-only accessor: the ring's near flats (those within 96
  tiles of the camera's chunk, which covers 20 tiles around the player) in map coordinates, with their texture, and
  whether the ring's flats are fully built for the current view. Four statements; no behavior change.
- `hw_ddhorizon_test.cpp` (new, test only): with `-ddhorizontest`, setting the CVAR `dd_horizon_dump` to
  `"<x> <y> <radius> <file>"` writes those flats within radius of x,y to a file (dx, dy, absolute z, texture name as
  ZScript's `TexMan.GetName` names it). Without the flag the callback returns at once. Writes only to the given file.
- `tools/nature/town_lookback.py`: passes `-ddhorizontest`, dumps the ring at tic 100 of each look (overworld and town
  map), and compares overworld (actors + ring) against town map (actors + ring): count, same sprite within 1 unit,
  height difference, and ring flats drawn on the same spot as an actor (double drawing). Prints `RESULT: PASS/FAIL`.
  The old actor-only lines are kept.
- `tools/nature/town_lookback_paired.py` (new): the town-map half in a paired run (launcher + Daggerfall Unity via
  `-dfsynctest`, whose test start is the City of Daggerfall), compared with the unpaired run's overworld list.
- `tools/nature/stage_lookback_demo.py` (new): assembles `review\town-lookback` (this checkout's UZDoom, launcher,
  bridge, Daggerfall Unity build, doomerfall.pk3, nature data) with `play.bat`.

## Known gaps

- Ring flats are render only: they cannot be collided with or walked to (as `distantlod` noted). From inside the town
  map the player cannot reach them anyway: the map's ground ends there.
- Ring ground is one green texture (from `distantlod`), so a flat beyond the map edge stands on uniform grass while the
  overworld shows the tile's own ground texture. Visible in the Gaerhart pair only as a slight texture change at the
  edge. Not part of this goal.
- Only the City of Daggerfall can be checked paired: `-dfsynctest` starts there.
