  8000000000000001, removed Daggerfall's copy`. So the copy existed, but `DoomerfallGuards.CorpseOf` found no
  `MobileUnit`. First guess: `GetComponentInChildren<MobileUnit>()` skips inactive objects, and Daggerfall's inert

  The blood splash itself worked (`run\guard\gblood.png`).

  dig further, since the fix below doesn't depend on it). Now `DoomerfallGuards` reads the corpse texture **when it
  sends the guard to Doom**, from `DaggerfallEnemy.MobileUnit.Enemy` (the source `EnemyDeath` uses), with the city
  watch's own `EnemyBasics` entry as a fallback, and keeps it until the death. The spawn log now shows it
  (`corpse texture 24903681`, which `ReverseCorpseTexture` turns into 380-1). `DoomerfallCorpses.EnemyCorpse` is gone
  because nothing uses it any more.

## Verifier round 1: guard ids collided across sessions (fixed)

The verifier found by reading the code that guard ids were `tag | ++serial` with `serial` starting at 0 in every
Daggerfall session. A guard corpse is saved under its guard's id, so after a relaunch and load the first new guard got
the saved corpse's id again, and Daggerfall refused to keep its corpse ("already kept"). Doom would also have merged
the two bodies (same `ddRecordId`). My `guardload` run only listed the old corpse, so it could not catch this.

- **Fix.** `DoomerfallGuards.serial` now starts at `DateTime.UtcNow.Ticks` (about 6.4e17, inside the 61 serial
  bits), so a later session's ids are always above any earlier session's. Ordinary engineering call: it is the
  smallest change, needs no new saved state, and the ids are opaque to Doom (`ddRecordId` only).
- **Guards that outlive a load.** `copies`/`corpses` are in memory only. Guard bots should not survive a load (they
  leave at every level change, `dd_guards.cpp` header), but `CorpseOf` now falls back to the city watch corpse for
  any guard id it did not send, so a stray one would still leave its body instead of vanishing.
- **Verified** (Daggerfall Unity rebuilt, `CliBuild result: Succeeded`):
  `run guard guard` again: `guards: sent 88df4ca469a45d33 ...`, `corpse: kept 88df4ca469a45d33 ... as 380-1`, listed
  again after going out and back in. Then `run guardreload guardreload` (new harness mode: fresh launch from that
  autosave with `-dfguardtest`, kill one of the new guards): `town: ledger restored with 0 deaths and 1 corpses`, new
  guards `88df4ca48148c578`..`c57c` (no collision), `corpse: kept 88df4ca48148c578 ... 2 corpses in all`, and Doom
  lists both: `TCCOUNT gafterkill 2`, the old one at -280,-234.5 and the new one at -56,-18.8, both `DFBB380_1_0 shown`.
