# Test hooks in game classes (2026-11-24, run 191013)

Goal: review the Doomerfall test hooks in main game classes and decide for each: kept, moved, or removed.

## Plan

1. Inventory every command-line test flag and test CVAR in `UZDoom/src`, `daggerfall-unity-master/Assets/Scripts/Doomerfall`,
   `mods/doomerfall` and `bridge`.
2. For each flag, find who still runs it (`tools/`, `bridge/test`, `scripts/`). A hook nothing runs is a removal candidate.
3. Move the big inline test drivers out of game classes into their own files, leaving one-line hooks. Keep hooks that
   are fault injection at an exact failure point, or are woven through real input or logging so that moving them would
   make the game code worse.
4. Build UZDoom and Daggerfall Unity, check DOOM.WAD E1M1 stock and with DRLA, and run the tests behind moved hooks.

## How "still used" was decided

A scratch script searched `tools/`, `bridge/test` and `scripts/` for each flag. Every flag had at least one runner
except `dd_mon_test_kill` (set by `tools/monster_deaths/harness.zs`, a ZScript harness, so it is used) and
`-dfdamagetest` (no runner; see below). So nothing qualified as a dead leftover that a script never runs.

## Removed

Nothing. Every hook I found still has a runner (or, for `-dfdamagetest`, a documented manual check), so none is an old
leftover by the owner's rule.

## Behaviour notes

- Test drivers in `dd_bridge_test.cpp` now all run from one call after `PumpNewGameSave`, instead of from inside
  `PumpLoad`/`PumpSave`/`PumpNewGame`. Each step already waits on its own timers and states, so the order inside one
  frame does not matter. The pause test now runs before `dfb_flush` instead of after it.
- Normal play: without a test flag `DD_BridgeTestFrame` returns after one check, `DD_BridgeTestTic` after one check,
  and the Daggerfall test classes are never created.
