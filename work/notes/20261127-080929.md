# 20261127-080929: tag every shot the player fires with the gun that fired it

Goal: `work/goal.md` (shot source tags). Doom only: the tag lives on the Doom actors and Doom's own saves keep it.

## Review of how Automatics did it

`DoomerfallAutomatics.FromGun` (skillperks 02) kept three parallel arrays in its static event handler: projectiles
spawned within `radius + 64` of the player while an Automatics gun was held and the trigger down, with the gun's class
name and the shot's burst state. Limits found:

- Only Automatics guns, only the projectile itself: anything the projectile spawned (explosion actors, fragments) was
  deliberately untagged ("spawned away from the player").
- Static handler arrays are not saved, so a projectile in flight at a save lost its bonus.
- `Find` on an array for every hit.

## Plan (as built)

`mods/doomerfall/src/zscript/DoomerfallShots.zs`:

- `DoomerfallShotTag : Inventory` rides in the projectile's inventory: shooter, gun class, both weapon categories and
  the skill slot at fire time, fire tic, generation (0 fired, 1 spawned by that shot, ...), and Automatics' burst bit.
  Being an inventory item, it is saved and loaded with the actor by Doom's own save code. Nothing in Daggerfall or the
  bridge changes.
- `DoomerfallShots` (static handler) tags in `WorldThingSpawned` (which runs for a new actor in the same tic it was
  spawned, after the spawner set its `target`). Only actors whose `target` is the player's body; never puffs, items,
  monsters or players. Two rules:
  - fired: spawned within `radius + m.radius + 64` of the player while the trigger is down or the gun is mid-fire
    (not in `A_WeaponReady`): the held gun.
  - spawned: within 128 units of a tagged actor of the same player that is alive, or that was destroyed this tic (its
    tag is detached in `WorldThingDestroyed` and kept until the next `WorldTick`, because a rocket's death frames spawn
    the explosion and then the rocket is destroyed before the children's spawn event runs). The nearest wins; when both
    rules fit, the nearer one wins.
  GZDoom sets `target` to the original shooter for anything a player's missile spawns (`InitSpawnedItem`: it walks up
  past missiles to the originator; `A_CustomMissile` with `CMF_TRACKOWNER` the same), so the `target` filter catches
  explosions, shrapnel and fragments.
- Hitscan keeps the simple rule: `DoomerfallShots.Find` answers the held gun for a puff inflictor.
- Gated on a Daggerfall character (`DD_SheetValue(SheetValid) == 1`), like every perk: a Doom-only game tags nothing.
- `WorldLoaded` rebuilds the handler's list of tagged actors from the saved tags.

Automatics now reads the tag: `FromGun` calls `DoomerfallShots.Find` and checks the tag's skill slot; its
`WorldThingSpawned` only counts the burst shot and writes `autoBurst` into the fresh generation-0 tag. Its own arrays
are gone. Behaviour change: an Automatics projectile's fragments/explosions now count for Automatics too (that is the
goal), and an Automatics projectile in flight at a save keeps its perks after the load.

## Findings

- `WorldThingSpawned` runs in the same tic as the spawn (fresh thinkers tick in the same `RunThinkers` pass), after
  the spawner has set `target`; but a rocket whose death frames spawn its explosion is often destroyed before that
  event runs, hence the "destroyed this tic" list. `WorldThingDestroyed` runs before the actor's inventory is
  destroyed, so the tag can be detached there.
- A same-tic spray (Shrapnel Cannon) first came out as generations 0 to 3: each shard was "spawned near" an earlier
  shard. A tagged actor fired by the gun in this very tic is now a sibling, not a parent, so all shards are gen 0.
  Generation is only diagnostic (a cluster bomb's explosions read 2 to 5, since explosions also appear near earlier
  explosions); the gun is right either way.
- UZDoom does not call `WorldLoaded` on non-static handlers restored from a save (`events.cpp`), only on static ones.
  `DoomerfallShots` is static, so its rebuild runs (log: `shots: loaded 1 tagged actors`). The test harness, a
  non-static handler, detects the load with a `transient` field instead.
- `-loadgame` from the command line with these flags did not restore the game; `+load <name>` (with `-savedir`) does.
- DRLA's Shrapnel Cannon uses RocketAmmo, so `DoomerfallWeaponCategory` makes it Explosive (skill 6). The test first
  guessed Shotguns; the test was wrong, not the code.
- Existing builds in `DoomDaggerfall-build` predate batch2's engine natives (`DD_SheetValue`, `DD_PlayerFlags`), so the
  mod failed to compile on them. Built this branch: `uzdoom-shottag`, `bridge-shottag` (no engine change of mine).

## Verifier fix (helper actors)

The verifier found that the first version dropped the old `bMissile` check from Automatics' shot counting, so DRLA's
recoil and reload helper actors (`RLChaingunRecoil`, `RLStandardReloadOutRecoil`, ...: not missiles, but `target` =
player via `InitSpawnedItem`) were tagged with the held gun and counted as burst shots. Fixed:
- `DoomerfallAutomatics.WorldThingSpawned` counts projectiles only again (`bMissile`).
- `DoomerfallShots`' "fired" rule takes projectiles only, so helpers are not tagged at all. Non-missile children of a
  shot (explosion actors) are still tagged by the "spawned" rule.
- `automatics_test` logs every non-missile `*Recoil` actor aimed at the player and checks none is counted or tagged.
  Reran: Automatics 197/197; the DRLA run spawned 386 helpers while firing, none counted. Shot tags reran 43/43
  (stock, DRLA, both save/load runs, nobridge).

## Verifier fix 2 (point blank, BFG spray)

- Point blank: a missile blocked in `P_CheckMissileSpawn` explodes inside the firing action and loses `MF_MISSILE`
  before its spawn event; its impact and first-frame splash happen even earlier. Now: the fired rule also accepts a
  class whose default is a missile; `Find` tags an untagged inflictor of age 0 on the spot (the firing state still
  holds, so it gets the held gun); `WorldThingDestroyed` does the same for an untagged age-0 actor, so a shot gone
  before its spawn event still leaves a tag for its children.
- BFG spray: `A_BFGSpray` damages with the player's body as inflictor, from inside the ball's death frame.
  `Find(player, player)` now credits the player's tagged projectile that has exploded (MISSILE cleared, default set)
  and entered its current frame this tic. With no such projectile it still answers nothing, as before (so a punch or
  other body-inflicted damage is unchanged). If two of the player's projectiles explode in the same tic, the first
  in the list wins (same gun unless the player fired different guns within a tic of each other).
- Test cases added: stock rocket and harness bomb at point blank (target 60 units, gun stays up), DRLA rocket at
  point blank, stock BFG9000 after a switch to the fist (spray hits: inflictor `DoomPlayer`, tag BFG9000, skill 9).
  Shot tags: 57 of 57 (stock, DRLA, both save/load runs, nobridge). Automatics: 197 of 197.
- At point blank a fragment's blast may take the bomb as parent (gen 1 instead of 2): same gun, generation is only
  diagnostic, so the test checks gen 2 only for the normal-range bomb.
- Not tested separately: a rocket into a wall with no damage (same path as the point-blank case: the rocket stays
  alive in its death frames, so its own spawn event tags it).

## Known gaps

- Puffs are not tagged (owner's hitscan rule). Something a puff spawns gets `target` = the puff, not the player, so it
  deals damage as the puff anyway; a mod puff that spawns a damaging actor with `SXF_TRANSFERPOINTERS` would be
  untagged.
- A child that appears more than 128 units from its parent, or a child whose `target` is set to the player only later
  (after its first tic), is untagged.
- A projectile some other source spawns next to the player while they fire (a powerup or armor effect with the player
  as target) would be tagged with the held gun.
- Every tagged actor carries one extra inventory actor. Rocket smoke trails spawned with `A_SpawnItemEx` also get a tag
  (their target is the player). Cheap, but it is one extra actor per spawned trail puff while a Daggerfall character is
  loaded.

## Verifier fix 3 (point-blank Automatics burst)

A point-blank Automatics projectile was tagged at its hit (before its spawn event) with `autoBurst` false, and the
spawn handler skipped it (MISSILE already cleared), so it lost the burst bonus. Now one helper,
`DoomerfallAutomatics.MarkTag`, decides the burst state once per generation-0 tag fired this tic (`burstSet` on the
tag), called both from `FromGun` (hit first) and from the spawn handler (which now accepts `default.bMissile`; helper
actors stay excluded since their class is not a missile). Children copy the decided state. New Automatics source case
"close": a Chaingun PlasmaBall hitting at point blank gets x1.6 x1.3 on every hit (stock and DRLA). Automatics stock +
DRLA 191/191 (nobridge part not rerun this time; it was 197/197 with nobridge before this change), shot tags stock +
DRLA 24/24.
