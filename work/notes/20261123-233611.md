# Doom weapon hotkeys (20261123-233611)

Branch `agent/hotkeys-20261123-233611`. Design: `work/backlog/doom-weapon-equipping-and-hotkeys.md`.

## Plan and design calls

**Model.** Daggerfall holds every gun as a `DoomerfallDoomItem` and the hotkey table. Doom holds only the active gun
(plus weapons that are not guns Daggerfall can hold: fists and anything with no pickup and no world sprite).

**Gun state.** A gun's Doom state is every inventory item named `<WeaponClass>...` (DRLA: `RLPistolClip`
magazine, `RLPistolModLimit`, `RLPistolPowerMod` and the other mods), except `...TypeWeapon` (family token shared by
every pistol) and `...Selected` (removed, not saved). When Doom puts a gun away those amounts are sent to Daggerfall
and stored on that gun's item, in its `shortName` (`RLPistolPickup|gun|RLPistolClip=3;...`), so they save with
Daggerfall's normal item data. Drawing a gun sends them back and sets them exactly. Duplicates of one class each keep
their own magazine and mods. Weapon ammo given by `GiveInventory` is put back, so swapping never changes ammo.
`RLWeaponLimit` is set to the number of guns Doom holds after every swap (1).

**Where the swap runs.** In ZScript (`mods/doomerfall/src/zscript/DoomerfallGuns.zs`), because giving and taking
inventory is native there. The engine (`dd_items.cpp`) only forwards bridge events to network events and back.

**Bridge kinds 150-155** (payload `dfb_doom_item`, no struct change, protocol unchanged): `HOTKEY`, `GUN_STATE`
(both ways), `GUN_EQUIP` (give / adopt / clear / select), `GUN_STASHED`, `GUN_KEPT`, `GUN_EQUIPPED`.
`DOOM_ITEM_TAKE`'s status now marks guns.

**Starting gun.** When Daggerfall has no active gun (new game, or an older save) it asks Doom to *adopt*: Doom keeps
its ready gun and Daggerfall creates its item, puts it on key 2 square 1 if the table is empty, and marks it active.
Other guns Doom held are taken and added to Daggerfall's inventory. Outside adoption, an unexpected gun Doom held is
not added (so a map that re-gives a starting pistol cannot duplicate guns).

**Taking a gun with Use** puts it only in Daggerfall's inventory. Doom gives the ammo the gun class itself would
give (`AmmoGive1/2`; DRLA weapons give none, the stock shotgun gives 8 shells). DRLA's modded pickups
(`...PickupModded`) lose the mods they carried, because they are applied by ACS when touched. Known gap.

**Keys.** On a generated map with a bridge session, Doom's `slot N` command (keys 1-0 by default) becomes a hotkey
press. Ctrl or Alt held (read with `GetKeyState`, so however they are bound) picks the Ctrl or Alt square. Plain key:
the next filled square after the active one on that key, cycling. Everywhere else `slot` is unchanged.

**Popup.** In Daggerfall's inventory, a number key over an item in the item list opens five gray squares labelled
`N (1)`, `N (2)`, `N (3)`, `Ctrl+N`, `Alt+N`. Click a square to assign, the red x clears it, a grey X marks a
consumable that ran out. Escape, the same number, or a click outside closes it.

**What can be hotkeyed:** Doom items (guns drawn, others used as from the inventory), Daggerfall potions (drunk),
armor (Daggerfall's own equip/unequip, cheap). Clothing: "Clothing cannot be hotkeyed." Anything else refused.

**Equip and Use on a Doom gun** in Daggerfall's inventory show the owner's message and do nothing else. Equip on any
Doom item shows it too.

**Leaving the inventory.** Gun or armor squares are deleted when the item leaves the inventory. Consumable squares
stay (grey X) and take the next item of the same kind (same Doom class, or same Daggerfall group, template, potion
recipe). If the active gun leaves (dropped, sold), Doom puts it away and its state is stored on the item wherever it
went, so a dropped gun picked up again keeps its magazine.

**Save.** `DoomerfallHotkeys.txt` beside Daggerfall's save files (one small hook in `SaveLoadManager`): the table,
the active gun UID, and the active key and square.

## Findings
- DRLA gives the weapon class by name from the pickup (`RLPistolPickup` gives `RLPistol` and counts `RLWeaponLimit`).
  So the weapon class is the pickup name without `Pickup`/`PickupModded`, or the pickup itself for stock Doom.
- DRLA's `RLDeselectionFunction` clears per-switch confirmations; it is given when the ready gun is put away.
- ZScript cannot run console commands, so the test harness presses hotkeys through a `dd_hotkey:<key>:<mod>` network
  event that calls the same engine function as the slot key.

## Play-test list
1. `review\weapon-hotkeys\play.bat`: before entering, press 2: nothing changes (the pistol is already drawn). Open the
   inventory (I): the pistol is there as a Doom item.
2. Hover over the pistol and press 3. The popup shows five squares. Click `3 (1)`: the pistol icon fills it. Click the
   red x: it clears. Does the popup look and read right? Is it in a good place on screen?
3. Enter, take the pistol inside with Use: it should not change Doom's weapon. Put it on key 3, close, and press 3 and 2:
   the guns swap. Fire a few shots from one, swap away and back: the magazine count should be unchanged.
4. Put two guns on key 4's squares `4 (1)` and `4 (2)`; press 4 twice: it cycles.
5. Try Ctrl+N and Alt+N squares. Ctrl still crouches. Does Alt+number cause any Windows side effect?
6. Equip mode and Use mode on a gun in the inventory: the message "Press # over an item..." shows.
7. Drop the active gun from the inventory: Doom puts it away. Take it back and draw it: same magazine.
8. Save, swap, load: the assignments and the active gun match the save.
9. Put the vest or the blur sphere on a key, use it with the key, then take another: the grey X goes away.
