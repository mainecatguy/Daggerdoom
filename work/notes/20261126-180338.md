# Higher-tier ammo pickups are not smaller (run 20261126-180338)

Goal: every tier's ammo pickup and shop pack gives the same rounds as Regular. Tier odds unchanged.

## Where the share came from

`overnight/ammosize` (notes `work/notes/20261124-233842.md`) read the "Stack" column of the ammo tier card
(`work/queue/ammotiers/done/04.opus.ammo-material-tiers.md`, Regular 2x down to Daedric 0.25x) as a per-tier size and
applied it twice:

- `DoomerfallAmmoPickup.Rounds` (`mods/doomerfall/src/zscript/DoomerfallAmmo.zs`): `TierEighths` scaled every pickup
  (Steel 3/4 ... Daedric 1/8 of Regular).
- `DoomerfallAmmoTiers.Stack` (`daggerfall-unity-master/Assets/Scripts/Doomerfall/DoomerfallAmmoTiers.cs`): shop packs
  were `ShopPackBase x stackMul` (Regular 80 bullets, Daedric 10).

## Plan

1. Remove the tier share from `Rounds` (it now takes no tier). Done.
2. Remove `stackMul` from the tier table; one Regular-sized `ShopPack` for every tier (80 bullets, 20 shells,
   8 rockets, 100 cells, Regular's old sizes). Done.
3. Update `tools/ammo/ammo.py`: expected size no longer depends on tier; the `sizes` run now also touches every size at
   Ebony (the highest tier area level 1 rolls); new `pack_checks` on the `tiers` run (`-dfshoptest`) checks every shelf
   stack is a whole number of Regular packs. Point it at integration's latest builds (`merge-skillcore`) and a new review
   folder `review\ammosizefix`. Done.
4. Build Daggerfall Unity, assemble, run `ammo.py sizes`, `ammo.py tiers`, `ammo.py check` (E1M1 stock and DRLA).
5. Demo folder `review\ammosizefix-demo` (`tools/ammo/demo.py`).

Not touched: tier odds (`RollTier`, `DaedricChance`, `Falloff`, jackpots, `SmithChance`, the 2-4 / 1-2 packs per
restock). The number of packs a shelf gets per tier is stock quantity (rarity), not pack size, so it stays.

Manual: added an "Ammo pickups" section with the amounts.

### Found on the way: script-spawned zombies no longer drop anything

The first `sizes` run had 0 monster drops. Since the ammosize run, integration made summoned monsters drop nothing
(owner rule 2026-11-25, `UZDoom/src/dd_lootrng.cpp`): a monster with no Daggerfall id is "summoned", and the harness's
zombies are script-spawned. That is intended, not a bug. The harness now also tosses every pickup size the way Doom's
drop code does (TOSSED set right after spawning, before the converter judges it a tic later in PostBeginPlay), at
Regular and Ebony. The zombies are still spawned and killed and show no drops. A real DRLA monster drop is not covered
by this run any more; the `WasDropped` rule it relied on is unchanged since the ammosize run proved it.
