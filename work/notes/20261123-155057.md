# Open the inventory menu from Doom

Branch `agent/engine_r3-20261123-155057`. Demo: `D:\dev\DoomDaggerfall-loop\review\inventory-menu\play.bat`. Press I to open the inventory. I, Esc, or Exit closes it. The test character carries an iron longsword and a steel dagger.

## Result

The Open Inventory control (`netevent df_inventory`) pauses Doom and shows Daggerfall's real inventory window inside the Doom window. Doom's mouse and keyboard drive it. Closing it resumes Doom. Changes are made by Daggerfall's own code on its own `PlayerEntity`.

## Plan and how it works

1. Reuse the fast travel path: shared surface, forwarded input, pause, and close. Add menu id `DFB_UI_INVENTORY`. The bridge layout does not change, so the protocol stays 4.
2. Doom intercepts `df_inventory` only in a bridge session. With no session it reaches the mod's log line as before.
3. The inventory is allowed indoors. Only the travel map has the indoor refusal.
4. The key bound to the open menu's control closes it, read from Doom's bindings. No key is hardcoded. The demo seeds I and K only when its private config does not exist yet, so a rebind survives relaunch.
5. Daggerfall now needs 2 frames at the HUD before it reports a menu closed. The inventory can close and post a follow-up window, which appears a frame later. Without this, Doom could resume with that window stuck open.

Test-only additions: the `dd_ui_test_menu` CVAR picks the menu `-dfuitest` opens, and `-dfinventorytest` gives the blank test character two weapons and clears its career's weapon restrictions.

## Proven with the real games (`tools/inventory_menu/inventory_menu.py run route2`)

Both games were minimized, so timings are relative.

- **Equip by mouse:** a click on the Iron Longsword changed Daggerfall's state from unequipped to `Iron Longsword (equipped)`.
- **State persists in the session:** it was still equipped at the second and third opens and after each close.
- **Bindable close:** with the control bound to J for the test, J closed the menu (`Doom asked`).
- **Other closes:** the Exit button closed it. In the third open, Info mode and an item click opened a popup, the first Esc closed only the popup, and the second Esc closed the inventory.
- **Doom paused:** `maptime` stayed frozen during each open (297, 367, 437) and advanced between opens.
- **Nothing else changed:** map pixel and gold were identical before and after each open. Game time moved by at most 1 minute between opens, while Doom was running.
- **Latency, input to frame received by Doom:** p50 8 to 10 ms, max 20 ms. Opening took 10 to 65 ms.
- **Fast travel regression:** the existing route on this build cancelled with Esc, then travelled to Agakawan. Gold went 5000 to 4990 and both games reached pixel 840,456.
- **No bridge:** `DOOM.WAD` E1M1 runs clean. With the DRLA set it reports the same 3 script errors and 763 unknown-class lines as the build before this work. Both runs also sent `netevent df_inventory`.
- **Plain Daggerfall:** the private copy logged no bridge activity and no exceptions. It was stopped by the 12-second test limit (exit 124).
- **Registry:** the SHA-256 fingerprint of all 13 values in the owner's Daggerfall Unity key was unchanged after the tests.

## Not proven

- **Opening with a physical key press.** The tests open through the real console command. Closing through a bound key is tested with posted window messages.
- **Doom's real window-to-surface mouse mapping.** Minimized windows have no usable client area, so the test sends surface pixels. This is the first thing to check by hand.
- **A save and load after an inventory change.**
- **Opening the inventory indoors.** It is allowed by the code, but no test ran it.
- **Item use.** Potions, books, the spellbook, enchanted items, and quest items were not exercised.
- **Dropping items.** Out of scope. From the code, a dropped pile is created at Daggerfall's hidden player and Doom does not show it.
- **Enchanted and quest items** can act on Daggerfall's hidden world, and Doom has no equivalent yet. A teleport effect, for example, is not bridged.

## Input still not forwarded

- `Input.anyKey` and direct reads outside the window classes, as in the fast travel notes.
- Key auto-repeat. Daggerfall sees one press and tracks the held key itself.
- Alt+F4 and Alt+Enter stay with Doom on purpose.
- Mouse buttons 4 and 5, and virtual keys missing from the `DoomerfallInput` table, such as Pause and Print Screen.
- Doom's sound is still not paused while a menu is open.

## Failed approaches

- The first test run's equip click reached the item, but Daggerfall refused with a message box and nothing changed. The likely cause is the blank test character's career restrictions. Clearing them under the test flag fixed it. Daggerfall's equip rule is unchanged.

## Existing issue seen

The `NullReferenceException` in `DaggerfallUI.SetupSingleton` still appears once in bridge test launches, as recorded in the fast travel notes. The menu works despite it.

## Play-test list

1. Run `play.bat`, press I, and check that the cursor lines up with the items, in a resized and a fullscreen Doom window.
2. Equip and unequip gear, switch tabs, scroll a long list, and Ctrl-click a stack.
3. Close with I, Esc, and Exit. Confirm Doom doesn't fire or move from the closing input.
4. Rebind Open Inventory in Doomerfall Controls, relaunch, and confirm the new key opens and closes it.
5. Open it inside a building and a dungeon.
6. Hold a movement key while opening and closing, and Alt-Tab while it is open.
7. Equip something, save, change it, and load. Confirm the saved gear returns.
8. Try a potion, a book, and an enchanted item, and report anything that leaves Doom stuck or out of sync.
9. Judge the menu's sharpness and responsiveness.
