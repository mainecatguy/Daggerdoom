# Restore autosaves on stitched location changes (20261124-123655)

Owner decision (2026-11-22): keep normal autosaving. Stitched map changes (town ↔ wilderness, town ↔ building or
dungeon, fast travel arrivals) had stopped autosaving because each autosave added a hitch of roughly 220 to 240 ms.

## Plan (as done)
1. Find the skip: `UZDoom/src/g_level.cpp` `DoLoadLevel` made no `DAutosaver` while `DDTreadmill_HandoffPending()`.
2. Bring the autosave back, but at the change itself, not a tic or more into play.
3. Prove it in paired sessions through the launcher (`--minimized`), then load autosaves and compare both games.
4. Regression: Doom's save/load cycle, death screen, and the real New Game with save and reload.

## How it works now
- `g_level.cpp`: a stitched change no longer creates the stock `DAutosaver` (that path goes through a net command
  and runs one or more tics into play). It calls `DD_BridgeArrivalAutosave()` instead (same `disableautosave` and
  `autosavecount` conditions).
- `dd_bridge.cpp` `PumpArrival` (first thing in `PumpSave`, so at the first frame after the new map's first tic, when
  the treadmill has finished the handoff): if both games can save (`SaveReady`, on a Daggerfall map, alive, no menu
  pause, no pending game action) it calls the stock `G_DoAutoSave()`. That uses the normal rotating `autoNN` slot
  names (per character through `DD_BridgeSlotName`) and the bundled save path, which starts in the same frame.
  If either game cannot save at that moment (a Daggerfall window, the New Game flow still holding, etc.) the autosave
  is dropped and logged, never made later in play. While the handoff is still pending it waits up to 2 s, then drops.
- `d_main.cpp`: `D_Display` is skipped while that autosave is pending or running (`DD_BridgeHoldFrame`, capped at 12 s),
  so the screen keeps the last frame from before the change through the load and the save. The player sees one
  longer stall at the seam, then the new place; no frame of the new map is shown frozen.
- Logs: the save line now has Doom's map and position (world or space) and the file; the load "both games resumed"
  line has the map. A map change autosave logs as `map change autosave committed`.
- Ordinary saves, loads, quicksaves, the death screen, and the first-map autosave (`DAutosaver`) are unchanged code.
  Autosaves use only `autoNN` names, so they never overwrite the player's own saves. Note that the death screen's
  Load Last Save loads the newest save, which can now be a map change autosave (same as any other autosave).

### Added time per change (three walks)
"Load" is the treadmill's own handoff time (`DDSTITCH arrive ms=`); "autosave" is the time Doom is frozen for the
bundled save (from the request to the commit). The save starts 2 to 24 ms after the new map loads (its first tic
and the treadmill's setup), in a frame that is not displayed.

| Change | Load (ms) | Autosave added (ms), walks 1 / 2 / 3 |
|---|---|---|
| Town → wilderness (`DDOVER01`) | 390 to 490 | 347 / 313 / 334 |
| Wilderness → town | 452 to 532 | 133 / 153 / 141 |
| Town → house | 55 to 63 | 132 / 95 / 119 |
| House → town | 448 to 607 | 156 / 195 / 180 |

The wilderness map is the most expensive to save (1.5 MB bundle, Doom about 270 to 300 ms of the total). Each seam's
stall is now about the load plus 100 to 350 ms. Minimized frame rates are not real performance, but these are
mostly CPU and disk times.

## Failed approaches / notes
- First version froze Doom (up to 2 s) waiting for Daggerfall when it could not save at arrival. Nothing that blocks
  a save clears that fast (a window, the New Game flow), and freezing during the New Game flow risked stalling it, so
  it now drops at once.
- This run reused the lane's existing branch `agent/plainsaves-20261124-123655` (the loop's branch; I may not switch
  branches), so the branch also carries the earlier plain saves commits. The autosave change is commit 325911b and is
  independent of them.
- Not tested: dungeon doors (same handoff and the same code path as the building door), fast travel arrival, a walk
  between two different towns (it is town → wilderness → town, the same two changes tested here; no second town near
  Gothway Garden is in the cache), and stock Doom without DRLA.

## Play-test list
- Walk out of a town into the wilderness and back in: one stall at each seam, about half a second, then the new
  place appears moving. No second hitch about a second later. The old frame stays up during the stall; check it
  never shows a half-drawn or frozen frame of the new place, or a black frame.
- Go into a shop or house and back out: same.
- Open the Load menu: the newest autosaves are the places you just walked into, with the usual names. Your own saves
  are untouched.
- Load one of those autosaves: you stand where you arrived, in both games (Daggerfall's windows such as the shop
  and the map agree with where you are).
- Die after walking through a few seams: Load Last Save brings you to the last seam you crossed.
- New Game: no autosave stall during the arrival (they are dropped while the New Game flow runs); the first seam you
  walk through afterwards autosaves.
