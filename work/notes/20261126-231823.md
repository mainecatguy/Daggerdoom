**Fix for the two jitter traps (converter change, `AngledCollision.cs` `SmoothStairs`).** `tools/dungeon_converter/wad_lines.py`
lists the collision lines in a box.

- **Cause.** At both traps the old map has a 90-degree staircase corner: (720,744) in the corridor, (492,-468) at the
  ramp. The square player box stops cleanly in that corner. The smoothed-staircase fallback moved it to
  (previous + 2 x corner + next) / 4, (717,747) and (486,-474), while both chain ends stayed fixed. That left a shallow
  V-notch of two short lines, slopes 1/3 and 3, which the box bounces between.
- **Fix.** A corner that is the only interior point of its chain now goes to the chord midpoint (a + b) / 2, a straight
  line between the fixed ends. This applies only on the dungeon path (`smoothDungeon`).
- **Corridor corner.** The chords of the sliver's two sides then meet, so the converter's own conflict check put that
  corner back on the grid. It is a clean 90-degree corner again, as in the old map.
- **Converter run.** `sectors 2644, lines 20385` (was 20,450), `smoothed staircase 587, returned to grid 10,
  staircase corners left 52` (`D:\dev\DoomDaggerfall-build\dungeonedges\fix1\privateershold.stats.txt`).
- **Review folder.** The fixed WAD is now `review\dungeonedges-paired\data\privateershold.wad`. The previous one is kept
  as `privateershold-v1.wad`.

**Walk results, first new map** (`walk-after\summary.txt`, `walk-before\summary.txt`, re-analysed from the same logs with
`paired_walk.py ... --analyse`). 16 headings x 60 tics at 16 units a tic from each spot.

- *Net* is the straight-line distance from start to end; *path* sums every tic's movement, so it also counts vibration.
  Use net for progress.
- *Jitter tics*: tics inside a 16-tic window where the player moves over 12 units in total but stays inside a box 6 units
  across. That means shaking in place against geometry. A clean stop has no path, and a real slide leaves the box.
- A *snag* is a tic, between moving tics, that covers under half that run's typical tic.
- A *floor step* is a tic on the ground whose rise or fall is over 6 units and over twice its neighbours' (a slope moves
  the same each tic and has none; each stair riser gives one).

An earlier version of this table compared path lengths and called the corridor's longer paths "sliding along the wall".
That was wrong: the extra path was vibration. The table now uses net distance and jitter.

| Spot | What | Old map: net / jitter tics (headings) / snags / floor steps | New map |
|---|---|---|---|
| 700,860 | diagonal corridor | 4,609 / 30 (112.5) / 9 / 1 | 4,771 / **148 (292.5, 315, 337.5)** / 9 / 0 |
| 52,620 | 45-degree bevel | 2,768 / 0 / 2 / 7 (8-unit steps) | 2,873 / 0 / 0 / 0 (max 4.8 a tic, smooth climb) |

- **Regression: jitter trap in the diagonal corridor, headings 292.5-337.5 from 700,860.** The old map stops cleanly at
  about (709.4,754.7) (`walk-before\log-walk.txt`, e.g. line 4886). The new map gets no further (net 100-103 against
  106). It then shakes in place for 42-54 of the 60 tics:
  - at 292.5, within x 703.2-706.6, y 756.6-757.9;
  - at 315, alternating every tic between (705.23,757.17) and (706.83,758.77);
  - at 337.5, within x 706.1-707.4, y 757.4-760.8 (`walk-after\log-walk.txt`, from `PWWALK 0 13` / `0 14` / `0 15`).
  This is the opposite of the goal, at the main diagonal-corridor spot. I withdraw the earlier claim that these headings
  now slide along the wall.
- **Corridor progress:** heading 270 had the only large gain (headings 112.5, 202.5 and 225 got 13-23 units further): to (610.7,649.0), net 229, against a clean stop at
  (700.0,754.8), net 105. The old map's jitter at heading 112.5 (30 tics) is gone. Snags by heading, new: 22.5 (1),
  45 (3), 112.5 (1), 202.5 (2), 225 (1), 270 (1). Old: 22.5 (1), 45 (3), 112.5 (1), 202.5 (3), 225 (1). So 270 is a new
  snag, and 202.5 has one fewer.
- **Regression: jitter trap at 690,-300, heading 202.5.** Both maps follow the same trace to about (504,-481.6), on the
  flat floor at z 864 past the ramp. The old map then slides to (478.72,-481.41) and rests
  (`walk-before\log-walk.txt` 7798-7828). The new map is deflected and shakes for the rest of the run around x
  483.6-484.9, y -472.2 to -475.6 (`walk-after\log-walk.txt` 7822-7851; 28 jitter tics, 4 snags). This is new geometry
  near the ramp's foot, not the ramp. Heading 247.5 went the other way (old 43 jitter tics, new 0). Headings 135, 225,
  270, 292.5 and 315 jitter in both maps, with nearly equal net distances.
- **Bevels:** the clearest gain. At 52,620 the old map's 8-unit steps are gone: the player rises 5-7 units smoothly
  onto the bevel. At 931,1490 the 8-unit steps (headings 225-337) became 6.6-unit steps on the same headings. Net
  distance rose 813, mostly headings 22.5-67.5 (about 365 against 210) and 292.5 (467 against 131). Jitter at 247.5 is
  gone, and 225 jitters in both maps. Heading 202.5 drops 20 units off a real ledge in both maps.
- **Caveat on the method.** The harness sets the player's speed every tic and pushes straight into walls for 60 tics. A
  player's own acceleration and turning differ, so how bad the jitter feels must be checked by hand. But the same
  harness stops cleanly at these places in the old map, so the difference is in the new geometry.

## Failed approaches and snags

- The first launches stalled on Daggerfall's race screen: EnumWindows cannot see a window on another desktop, so the
  whole script must run inside quiet_run.py. Importing `run_new_game` also removes `--inside-quiet` from `sys.argv`, so
  the script asks that module for the flag.
- Without `-dfuitest 0` the creation clicks are not accepted. That flag also makes Doom screenshot every open menu (the
  `shots` folders); harmless.
- `level.MakeScreenShot()` from the harness left no files, so I removed it. There are no in-game pictures of the walk;
  the top-down before/after views are in `review\dungeonedges\screenshots` from the first run.
- The first choice of a 26.6-degree spot (2300,1700) came from the collision scan alone and turned out to be hidden
  filler. Every spot is now checked against the mesh.

  area (around 2300,1700) has a 26.6-degree floor where the old map had a flat one; not explained.
- Ramps steeper than 45 degrees stay stepped (from the first run; it needs a movement-rule decision).
