# Smooth dungeon collision: paired walk-through (continuation)

Goal: the one item left from `work/notes/20261126-225039.md`: a paired Daggerfall + Doom walk through Privateer's Hold's
diagonal halls and a converted 45-degree ramp.

## Plan

1. Install the play build from this branch to `D:\dev\DoomDaggerfall-loop\review\dungeonedges-paired` with
   `scripts/play/install.py` (private build folder `D:\dev\DoomDaggerfall-build\dungeonedges`).
2. New tool `tools/dungeon_converter/paired_walk.py` + `paired_walk.zs`: the launcher with `--minimized` under
   quiet_run.py, a real New Game (driver from `tools/new_game`, same as `tools/demo_combined/walk.py`), arrival in
   Privateer's Hold with Daggerfall in play, then runs in 16 headings from the diagonal corridor (700,860) and the
   45-degree ramp (840,-96). Per-tic positions go to the console log; the script counts snags and floor steps.
   Two real synchronized autosaves (at the first spot and at the end) give Daggerfall's position next to Doom's.
3. Run it on the new map and, swapping only `privateershold.wad`, on the old map (`review\dungeonedges\before`).

How the runs move: each tic the harness sets the player's horizontal speed to 16 (running) in the heading; the engine's
normal player move does the rest (wall slides, step-ups, slopes). God mode, notarget, and pass-through-actors keep
monsters out of the measure. This is test-only and lives in the harness pk3.

## Findings

**The paired walk works.** A real New Game in both games (character created through Daggerfall's screens by the
`tools/new_game` driver), arrival in Privateer's Hold with Daggerfall in play (`dd_sync_df_phase` 3), 64 runs, then two
synchronized autosaves that both games committed. Command (whole script on the private desktop, since the creation
driver must see Doom's window):

```
python D:\dev\DoomDaggerfall\scripts\overnight\quiet_run.py --timeout 480 --cwd <worktree> -- python tools/dungeon_converter/paired_walk.py
    D:\dev\DoomDaggerfall-loop\review\dungeonedges-paired --out <review>\walk-after --inside-quiet [--wad <old privateershold.wad>]
```

Logs and `summary.txt`: `review\dungeonedges-paired\walk-after` (new map), `walk-before` (old map, only the WAD swapped;
mesh and doors are identical between the two). Daggerfall's side: `df.log` has `save 2: wrote 16 files ... Doom committed
the bundle` at the end of the walk; Doom's `uz.log` records the position it saved in Daggerfall's space (`at
3409.6,1998.3,512.0`, which is Doom's 2557.2,1498.7 x 4/3, the dungeon scale). Daggerfall's own `position` field is the
world map position (same in every save, as expected inside a dungeon).

**The ramp in the earlier notes was not a ramp.** `warp 840 -96` is a steep stair: flat sectors stepping down 96 units
every 32 (an engine probe of floor heights). The player cannot move there at all. I scanned the whole map in the engine
for floor normals: the only 44-degree planes are the beveled sides of corridors, about 32 units wide and 31 high
(for example x 4-36, y 420-916). These are the "45-degree ramps" the first run converted. Wide walkable ramps in this
dungeon are 26.6 degrees and were planes already. So "a converted 45-degree ramp" here means a corridor bevel.

Measures per spot, 16 headings x 60 tics at 16 units a tic. A snag is a tic, between moving tics, that covers under half
the run's typical tic. A floor step is a tic on the ground whose rise or fall is over 6 units and over twice its
neighbours' (a slope moves the same each tic and has none; each stair riser gives one).

| Spot | What | Old map: distance / snags / floor steps | New map |
|---|---|---|---|
| 700,860 | diagonal corridor | 5,319 / 9 / 1 | 5,700 / 9 / 0 |
| 52,620 | 45-degree bevel | 3,021 / 2 / 7 (8-unit steps) | 3,135 / 0 / 0 (max 4.8 per tic, smooth climb) |
| 931,1490 | 45-degree bevel | 4,369 / 1 / 9 (8-unit steps) | 5,215 / 1 / 6 (6.6-unit steps) |
| 2300,1700 | 26.6-degree ramp | 5,398 / 0 / 0 | 5,172 / 0 / 0 |

- **Bevels:** the clearest gain. At 52,620 the old map's 8-unit grid steps are gone; the player rises 5-7 units
  smoothly as it runs onto the bevel. At 931,1490 steps remain but are smaller (6.6 instead of 8) on the west headings
  (225-337 degrees); heading 202 drops 20 units off a real ledge in both maps.
- **Diagonal corridor:** the snag count is the same (9). The difference is that the new walls let the player slide on:
  headings 270-337 ran 105-110 units and stopped dead in the old map, 168-254 in the new. The remaining snags are on
  headings 22-45 (down the corridor's own stair, -179 units) and 202-225; I did not separate them further.
- **26.6-degree ramp:** running north-west from 2300,1700, the new map climbs the slope from z 482 to 550 up to the
  wall at x 2164. The old map kept the player flat at z 480 along the same path. This ramp is not one the converter
  change targeted; the new map is the one that matches the scanned floor plane. A person should look at it.

## Failed approaches and snags

- The first launches stalled on Daggerfall's race screen: EnumWindows cannot see a window on another desktop, so the
  whole script must run inside quiet_run.py. Importing `run_new_game` also removes `--inside-quiet` from `sys.argv`, so
  the script asks that module for the flag.
- Without `-dfuitest 0` the creation clicks are not accepted. That flag also makes Doom screenshot every open menu (the
  `shots` folders); harmless.
- `level.MakeScreenShot()` from the harness left no files, so I removed it. There are no in-game pictures of the walk;
  the top-down before/after views are in `review\dungeonedges\screenshots` from the first run.
