## How

| Piece | How |
|---|---|
| Which textures | Daggerfall's `ClimateSwaps.IsExteriorWindow` (ported unchanged into `CityExport.cs`, since that file needs Unity). Its emission map is white where the palette index is 255 (`BaseImageFile.GetWindowColors32`). |
| Converter | `--runtime-assets` (the shared `ddruntime.pk3`) and the per-place package write `dfwin/aNNNrNN.png` beside `dfmesh/aNNNrNN.png`: white, opaque where the index is 255, clear elsewhere. 98 masks. Town cache files (`DFMESH`) are unchanged, so cached places keep working; only `ddruntime.pk3` must be regenerated. |
| Doom | `hw_dfmesh.cpp`: at mesh load each batch looks up `dfwin/<same name>`. After the normal mesh pass, if a window colour is set, the window batches are drawn again: additive, unlit, depth test less-or-equal with depth writes off, mask tinted by the window colour, near-black fog so the glow fades with distance like Unity's fog over emission. Same for the town mesh seen from the overworld. |
| Bridge | `DoomerfallCityLights.cs` also sends `windows <r> <g> <b>` (0 to 255): `MaterialReader`'s `NightWindowColor x NightWindowIntensity` while city lights are on, `DayWindowColor x DayWindowIntensity` otherwise (Day only when automated texture swaps are off, as `DaggerfallLocation` does), black inside buildings and dungeons (`DaggerfallInterior` uses `WindowStyle.Disabled`). Sent when it changes and every 5 s with the city-lights line. Colours and schedule are read from Daggerfall at run time. |
| Off by default | The colour starts at black: no pass. Without a bridge session, or on a map with no `dfwin` textures (every stock map), nothing changes. |

Daggerfall's day style is not "off": it adds a faint blue (89,154,178 x 0.5), which looks like glass rather than glow.
Doom does the same, so by day windows are tinted blue, not lit; at night they glow orange.
