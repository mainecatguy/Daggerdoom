# Quest-placed NPCs appear in Doom (2026-11-27 night run)

## Plan

1. Daggerfall: in the NPC presence list (DoomerfallNpcs), also list quest Persons that Daggerfall placed at quest
   markers (StaticNPC, `Context.Custom`, with a `QuestResourceBehaviour`) under the current interior or dungeon, with
   their billboard archive/record, size and where they stand (Doom units in the space's map). New event kind
   `DFB_KIND_NPC_PLACED` (69), payload `dfb_world_item` (already has id, generation, archive, record, x, y, z, width,
   height), sent between `NPCS_BEGIN` and `NPCS_END`.
2. Stable id: tag 6 | FNV hash of (scope 4, quest uid, FNV-1a of the Person symbol name). `IdOf` returns it for these
   NPCs, so `FindNpc`, talk (`DoomerfallTalk.OnUse`) and anything keyed by NPC id work unchanged.
3. Lists are now sent in dungeons too (Doom requests them in interiors and dungeons). A dungeon's list carries only
   quest Persons; the dungeon's own NPCs (DFDungeonNpc) are untouched.
4. Doom (dd_npcs.cpp): each list spawns a `DFNpc` for every placed row it has no actor for, marked `args[2] = 1`,
   moves/re-skins existing ones, and destroys marked ones the list leaves out. Layout NPCs are shown/hidden exactly as
   before (interiors only). Since they are `DFNpc`, Use, Info and the look label find them with no other change.
5. Changes (hide/restore/destroy/move/place while inside) need no special path: Daggerfall's quest code activates or
   deactivates the Person's GameObject (QuestResourceBehaviour.Update, QuestResource.Tick), the 0.25 s poll's hash
   changes (ids + billboard + rounded position), and a new list goes out.
6. Converter: the runtime package shipped only billboard archives that blocks name, so faction billboards 171, 175,
   178, 180, 334, 346, 357 were missing. `--runtime-assets` now also adds every `flat:` archive in FACTION.TXT.

## Findings

- `GameObjectHelper.AddQuestNPC` parents the Person under the interior (or dungeon) transform and centres the
  billboard on its transform (raised by half its height and ground-aligned outside dungeons). So feet z = local y -
  height/2 works in both.
- Hidden or destroyed quest Persons get `SetActive(false)` (QuestResourceBehaviour.Update); restore turns them back on
  (QuestResource.Tick). The poll already skips inactive GameObjects.
- Find-NPC (`findnpc` 01) is not merged on this branch, so goal item 5 is skipped. Its target id comes from
  `DoomerfallNpcs.IdOf`, which now returns the quest id, so it should follow once merged.
- Quest items at markers (goal item 4): see "Left over" below.

## Failed approach

- First version applied the list from `DD_NpcsFrame` (the bridge's per-frame hook, outside the playsim). The DFNpc
  spawned (logged at 96,48) and was gone by the next tic, with no destroy site in Doomerfall code: actors spawned
  outside the playsim do not last in UZDoom 5. Layout show/hide survived there only because it changes renderflags.
  Fix: `DD_NpcsTick(Level)`, called from `DDTreadmill_Tick` (one line, before its town-only return so dungeons get
  it). The list request stays in the frame hook.
