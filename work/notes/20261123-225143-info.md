# Info mode keybind

## What Daggerfall's Info mode actually does

Read from `PlayerActivate.cs` (Daggerfall Unity), Info mode on each kind of target:

| Target | Daggerfall Unity, Info mode |
|---|---|
| Building (wall or door) | Discovers it, HUD text with its name (quest names included); if a shop or guild is closed, a second HUD line with its hours. A door click also goes on to enter the building (no mode check in `ActivateStaticDoor`). |
| Static NPC | HUD text "You see NAME." No distance limit. NPCs with ShowText actions are skipped in every mode. |
| Enemy | `PopupMessage("You see a/an NAME.")` (same in Grab and Talk) |
| Loot pile, shop shelf, house container | Exactly the same as Grab: opens the window. |
| Corpse (`CorpseMarker`) | "You see a dead NAME." |
| Mobile townsperson | Talks to them (same as Grab) |
| Action door, ladder, bookshelf | Same as Grab |
| Quest resource | Grab would trigger it; Info does not |

Key finding: `DaggerfallUI.Instance.PopupMessage` is HUD text, not a window. So every Info result is HUD text. No Daggerfall window opens and
neither game needs to pause. The owner allowed pausing "if necessary"; it is not necessary, so neither game pauses for Info messages.
Containers still open Daggerfall's window through the existing paused loot route.

## Design

A new Doom control, **Info** (`netevent df_info`, menu "Doomerfall Controls", bound to **Q** by the play installer and the demo).

1. Doom picks the target, in the same order a crosshair ray would meet them:
   - a pile or furniture container in view (the same pick as Use) sends the existing take request, because Info on a container *is* Grab in Daggerfall;
   - otherwise the nearest NPC billboard (`DFNpc`, `DFDungeonNpc`) or living monster crossed by the view ray before a wall, up to 2304 Doom units (Daggerfall's 3072-unit activation ray at 75%);
   - otherwise, outdoors, the point where the view ray hit the world, converted to Daggerfall world units.
2. Bridge kinds 90 to 92: `DFB_KIND_INFO` (UZ to DF, `dfb_info_request`), `DFB_KIND_INFO_TEXT` (DF to UZ, `dfb_info_text`, split with `DFB_INFO_MORE`),
   `DFB_KIND_INFO_NAME` (UZ to DF, a monster's Doom name).
3. Daggerfall (`DoomerfallInfo.cs`) runs its **own** Info code: `PlayerActivate.DoomerfallInfoNpc` and `DoomerfallInfoBuilding` are small public
   wrappers that set the mode to Info and call the private `ActivateStaticNPC` / `ActivateBuilding`. For a building, Daggerfall finds which
   building footprint holds the point (Daggerfall's `HasHit` tests in 3D, and Doom heights do not match, so this tests the footprint only, with a 1 m margin).
   For a monster, it formats Daggerfall's own "youSeeA"/"youSeeAn" text with the Doom monster's tag, as `ActivateMobileEnemy` does.
4. Every HUD message Daggerfall shows during that call is captured through a new static hook, `DaggerfallUI.DoomerfallHudText`, which is null
   outside a bridge session and set only for the duration of the call. Messages go back to Doom: HUD text on Doom's message line, mid-screen text with `C_MidPrint`.

Deliberate differences from Daggerfall:
- Info on a building door shows the name but does not enter. Use enters; doubling that onto the Info key seemed wrong for a separate key.
- Monster names are Doom's (DRLA's tags), because Doom owns the monsters.
- Mobile townspeople are not targets: in Daggerfall, Info on them opens the talk window, which belongs to the dialogue task.

## Result

| Target | State |
|---|---|
| Building outdoors (wall or door) | Works, proven: Doom shows "First Class Supply Store"; at night also "Store is closed. Open from 6:00 to 23:00." |
| Doom monster | Works, proven: "You see a Former Human [Pistol]." (DRLA's tag, Daggerfall's sentence) |
| Stationary NPC indoors | Works, proven: "You see Uthywyr Ashford." |
| Furniture container / loot pile | Works, proven for a house container: Daggerfall's private property question, then its loot window, as Daggerfall's Info does. Piles use the same route as Use (proven in the container run). |
| Dungeon and outdoor NPCs | Same code path (`DFDungeonNpc`, outdoor `DFNpc`); not run. Outdoor and dungeon NPCs beyond Daggerfall's culling range are not found (`FindNpc`'s known limit) and give no message. |
| Mobile townspeople, corpses, action doors, ladders, bookshelves | Not targets. See gaps. |

Demo: `D:\dev\DoomDaggerfall-loop\review\info-mode\play.bat` (DRLA, DRLA Monsters, DRLAX). Starts facing a general store. Press **Q**
on the store, go in with Use, press Q on the shopkeeper, Q on furniture.

## Evidence

`python tools/info_mode/info_mode.py run NAME [--night]` runs both games minimized with DRLA and a harness that presses Info on each target.

- `i2`: `info: request 1 target 2 on building 196622 ... | First Class Supply Store`; `request 2 target 3 on monster Former Human [Pistol] | You see a Former Human [Pistol].`;
  `request 3 target 1 on npc cbe13269a0433b7f | You see Uthywyr Ashford.`; container: `items: use 1 ... HouseContainers: status 5`, message box, Yes,
  inventory window, `menu 5 closed, reason 1`, route finished. Doom's console log shows each message right after its press.
- `n1 --night` (test-only `-dfnpcreport -dfnpcnight`, hour 23): the building press gives both lines, including the closed message.
- `check`: stock E1M1 with no bridge: exit 0, no bridge lines, 0 script errors. DRLA E1M1: exit 0, no bridge lines, 3 script errors, 765 unknown-class
  lines, the same as the container run's numbers (they come from DRLA; the Doomerfall mod is not loaded there).
- Player.log: one `NullReferenceException` kind, the known startup one in `DaggerfallUI.SetupSingleton`.
- Registry: the review copy uses `install.isolate_registry`, as the other demos. Not hashed.
- Normal Daggerfall Unity: outside `Doomerfall/`, only the null `DaggerfallUI.DoomerfallHudText` hook and two unused public wrappers in `PlayerActivate`. Not launched.

## Failed approaches

- First harness run: the harness was a per-map `EventHandler`, so its state reset at the building door. A `StaticEventHandler` fixed it. The outdoor
  part had already passed in that run.
- `quiet_run.py` here has no `--desktop` option (the note in AGENTS.md mentions one), so Unity was built minimized with plain `quiet_run.py`.

## Gaps

- Info on a building door does not enter (Daggerfall's does, after showing the name). Use enters.
- Mobile townspeople: Daggerfall's Info on them opens the talk window; left for the dialogue task.
- Corpses: Doom monsters leave `DroppedLoot` piles, so "You see a dead X" never appears; Info on the drop opens it, as Daggerfall's Info on a pile does.
- Interior and dungeon walls, action doors, ladders, bookshelves: Info does nothing (Daggerfall's Info on doors, ladders and shelves is the same as Grab, which Use already covers or does not yet support).
- Building aim uses the Doom view ray's first hit and a footprint test with a 1 m margin. A point on the ground right beside a wall can still name that building.
- The message appears on Doom's normal message line (top left), not centered like Daggerfall's HUD text.
- Daggerfall HUD text from other interactions (for example "You are too far away" on containers) still shows only in Daggerfall's hidden HUD. The new hook could carry those too.

## Play-test list

1. In the demo, press Q on the store from the street, from far away, and at a sharp angle. Is the name easy to get? Try a wall and a roof, not only the door.
2. At night, Q on a closed shop: both lines appear?
3. Inside, Q on the shopkeeper and other people. Then Q on furniture: the same as Use (the private property question).
4. Q on a monster in a fight. Is the message readable while things happen? Does pressing Q ever do anything else in DRLA (it is unbound by DRLA)?
5. Is the top-left message line the right place, or should Info text be centered like Daggerfall's?
