# DRLA guns that empty in one shot reload by themselves (2026-11-24, overnight)

Goal: with DRLA loaded, guns whose magazine empties from full in one shot (DRLA's pump shotgun is the main case)
reload by themselves. Without DRLA, nothing changes.

## What I found

- DRLA already has this as a user option. In `cvarinfo.txt`: `user bool DRLA_autoreload = false;`. Its options menu
  calls it "1-shot weapons autoreload" (`menudef.arsenal`). After firing, 31 guns run
  `A_JumpIf(CallACS("DRLA_AutoReload"), "Reload")`, and the ACS script (`scripts/DRLALIB_Misc.acs:127`) only returns
  the CVar. The shotgun, for example, is at `actors/weapons/standard/Shotgun.txt:1052`.
- I scanned every DRLA weapon whose magazine (`RL<Weapon>Clip`, an Ammo item) holds no more than one shot's worth
  of ammo (MaxAmount <= AmmoUse1). Two such guns never ask the script:
  - **RLBaronBlaster** (legendary). It holds 1 shot, and a manual reload costs 100 cells (50 with the Fireangel perk).
  - **RLMarathonShotguns** (unique, "WSTE-M5"). It holds 2 shells and uses 2 per shot. It reloads after a shot only
    if fire is still held (`A_Refire("Reload")`).
- DRLAX adds no guns besides its fist, so nothing extra comes from it. DRLA Monsters has no player guns.

## What I did

- `mods/doomerfall/src/zscript/DoomerfallReload.zs`, a new StaticEventHandler registered in MAPINFO:
  - `OnRegister` looks up `DRLA_autoreload` and sets it on. The CVar exists only when DRLA is loaded, so without
    DRLA nothing happens. This runs once each time UZDoom starts. The player can still turn the option off in
    DRLA's options menu for the rest of that session. The next launch turns it on again.
  - `WorldTick` covers the two guns DRLA misses, only while the option is on. When one of them sits in its Ready
    loop (current PSprite state inside the `Ready` sequence) with an empty magazine, enough reserve ammo, and no
    weapon switch pending, it is sent to its own `Reload` state, as if reload were pressed. The reserve needed is
    what each gun's own Reload state checks (100 or 50 cells; 2 shells). The Marathon Shotguns are skipped while
    held as a pair (demon artifacts), because that mode has separate left and right magazines and reload keys.
- No engine change and no new CVar.

Approaches rejected:
- `DEFCVARS` cannot change a mod CVar's default. UZDoom reads it only from the IWAD (`d_defcvars.cpp:43`), and it
  runs before CVARINFO is parsed (`d_main.cpp:3667` and `3692`).
- Redefining `DRLA_autoreload` in our own CVARINFO would create the CVar even without DRLA.

Through Doomerfall's fallback (2): RLBaronBlaster, RLMarathonShotguns (single mode only).

DRLA's option also reaches two guns that are not one-shot, wherever DRLA itself calls the script: RLShredderPistol
(16-round magazine, two fire-finish paths) and RLGaussRifle (after each shot). That is DRLA's own behavior for its
option, and I did not change it.

## How I proved it

`python tools/autoreload/run_test.py D:\dev\DoomDaggerfall-build\uzdoom-sync\Release\uzdoom.exe D:\dev\DoomDaggerfall-loop\review\autoreload`
gives **8/8 passed**. The logs are in `D:\dev\DoomDaggerfall-loop\review\autoreload\*.log`.

The test loads DOOM.WAD E1M1 minimized, with a private config, `-nomonsters`, god mode, and each run stopped on a
real error. The test-only harness pk3 (`tools/autoreload/harness`) gives each gun with a full magazine and a full
reserve. It waits until the gun is ready, fires once through `PlayerPawn.FireWeapon` (the same call the fire button
makes), never presses reload, and logs the magazine and reserve.

| Run | Files | Result |
|---|---|---|
| stock | DOOM.WAD + doomerfall.pk3 | E1M1 loads, no script errors from our files, `option=missing` |
| control | DRLA set, no doomerfall.pk3 | `option=off`; Shotgun, Double Shotgun, Baron Blaster, and Marathon stay empty |
| optout | DRLA set + doomerfall.pk3, option turned off in game | Baron Blaster and Marathon stay empty |
| drla (4 parts) | DRLA set + doomerfall.pk3 | `option=on`; all 31 guns `reloaded` (magazine back to full, reserve spent) |

Sample lines: `RLShotgun result=reloaded lowest=0 clip=1 use=1 reserve=50->49 tics=41`,
`RLBaronBlaster result=reloaded lowest=0 clip=1 use=1 reserve=300->200 tics=71`.
The Baron Blaster once spent 50 cells, which means DRLAX's random start gave the Fireangel perk.

Test notes:
- The DRLA set prints script errors of its own at every load: DRLAX's empty translation, DRLA Monsters' menudef
  lines, and unknown-class warnings for its optional DoomRPG and LegenDoom addons. The game runs on after them. So
  the test counts only script errors from our pk3s, plus real stops (VM abort, fatal error).
- A command-line `+set DRLA_autoreload 0` runs before our `OnRegister` and is overwritten. To test turning it off,
  the harness sets it off in game instead.
- I used the existing `uzdoom-sync` build. The change is ZScript only, so no engine build was needed.

## Play-test list

- Fire DRLA's shotgun and let go of fire. It should pump by itself, without the reload key. Check that it feels right.
- Double shotgun, rocket launcher: same check.
- DRLA options menu, "1-shot weapons autoreload": turning it off should stop all of the above for that session.
  Restarting turns it on again.
- Baron Blaster: each shot now spends 100 cells on the next magazine automatically (50 with Fireangel).
- In a paired game, swap to an empty Baron Blaster with a hotkey. It reloads as soon as it is raised. Empty DRLA
  shotguns do not reload when raised. They reload on the first fire press, as before.
