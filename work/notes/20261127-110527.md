# Shop levels 3: town classes and the town exterior level (run 20261127-110527)

Goal: outdoors in a town, the area level is the town's level, the higher of the map pixel's terrain level and the
town's class level (village 5, hamlet 10, city 15, capital 20). Design: `work/notes/20261124-124736-shop-levels.md`
section 4. Buildings, dungeons and the wilderness are unchanged.

## Plan

1. Town class and town level per classic location in `DoomerfallAreaLevels` (built with the rest of the table on
   its worker), mirrored in `tools/area_level/area_level.py`; `compare_runtime.py` checks the town level too. Done.
2. `ForCurrentPlace`: outdoors on a town's Doom map, return the town level. Done (boundary below).
3. Travel hint shows the town level for towns (`Level.Place`). Done.
4. Tests: town lines in `-dfarealeveldump` (new file `DoomerfallTownLevelsTest.cs`); `-dftownlevellog`
   (new file `DoomerfallTownLevelWatch.cs`) logs the level whenever it changes; `-dfworldleveltest` in the City of
   Daggerfall for guard levels; `tools/town_levels/town_run.py` + `gate_walk.zs` walk out through a city gate.
5. Demo `review/town-levels/play.bat`, notes.

## Decisions (engineering calls)

- **Class rule ("type" scheme, owner 2026-11-26):** TownVillage small 5, TownHamlet medium 10, TownCity large 15, a
  TownCity whose name equals its region's name (aliases from `tools/shop_levels/proposals.py`, case-insensitive) a
  capital 20. Town level = max(terrain level, class level). Other location types (temples, taverns, homes, dungeons)
  get town level 0 and are unchanged. Privateer's Hold is a dungeon, unaffected (still level 1).
- **`Level.Area` is unchanged** (dungeon level, else terrain level), because its callers are dungeon paths
  (`DoomerfallMonsters.BuildPlacements`, `WorldLevel.ForDungeon`). A new `Level.town` field and `Level.Place`
  (town level for a town, else `Area`) carry the town level. The travel hint uses `Place`. So the City of Daggerfall,
  which also has a dungeon (level 7), shows level 20 ("Very hard") on the travel map; inside its dungeon the dungeon
  level still applies.
- **Boundary: the town's location rectangle extended by 24 tiles (6,144 Daggerfall units) on every side.**
  How it was chosen:
  - UZDoom's town map (`dd_treadmill.cpp`, `Town`) is the union of the group's location rectangles (the
    converter's flattened rectangles, about 1.5 tiles larger than the block rectangle; Gothway Garden's DDTOWN `rect`
    is 67 x 51 tiles for 4 x 3 blocks) plus `margin` = 24 tiles. The player enters it 12 tiles out and leaves it
    for the overworld 20 tiles out (hysteresis), so no position line equals "on the town map".
  - Daggerfall's `IsPlayerInLocationRect` (night spawns, guard spawns) is the block rectangle + 16 tiles: it would
    leave the outer 4-5 tiles of the town map at the terrain level.
  - Daggerfall does not know which Doom map the player is on: the bridge reports only "exterior" and a position.
    An exact answer needs a new bridge field from Doom (schema change in both engines). Not done; see gaps.
  - So the town level covers block rectangle + 24 tiles: everything the town map can reach, and Daggerfall's own
    location rect lies inside it. The cost is a ring on the overworld map (between the entry/exit lines and 24
    tiles) that already counts as the town. Walking in, the level rises up to about 10 tiles before the town map
    loads; walking out, it drops about 2.5 tiles after the town map hands off.
  - The town's own map pixel and its eight neighbours are checked, because a town map near a pixel edge reaches
    into the next pixel. Where two towns overlap, the higher level wins. Rectangles are cached per pixel (main
    thread only, a few dictionary lookups per call).
  - A town group can hold other, non-town locations (group 7154 holds Gothway Garden and Privateer's Hold). Only
    the town's rectangle carries the town level; the area around a temple or dungeon entrance in the same Doom map
    keeps the terrain level, as before.
- **Inside buildings** `ForCurrentPlace` still returns the map pixel's terrain level (card 04 changes that).
- Tests attach from existing test files (`DoomerfallAreaLevelsTest.Run`, `DoomerfallWorldLevelTest.Attach`); no game
  class gained test code.

## Known gaps

- **Doom's ammo drop tiers on town maps** still use the terrain level. Doom asks Daggerfall for the level of a map
  pixel (`dd_items.cpp` `PublishAreaLevel`) and caches the answer per pixel forever, so the same pixel key serves
  both the overworld and the town map. Fix (not done; needs a small UZDoom change): key the request on "town map"
  (for example add 3,000,000 when the current map is a generated town map) and answer such keys with
  `DoomerfallAreaLevels.TownAt` / the town level. The design note lists this as a consumer of the town level; the
  goal card does not ask for it explicitly.
