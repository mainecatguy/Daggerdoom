# Report monster deaths to Daggerfall

Branch `agent/deaths-20261123-195759`. Demo: `D:\dev\DoomDaggerfall-loop\review\monster-deaths\play.bat`. It starts at the Privateer's Hold door with the real quest `N0C00Y12` running.

## Result

Every monster in a converted dungeon now has a stable ID. When it dies in Doom, Daggerfall records the death once, updates the quest foe, rolls the drop from its own loot tables, and shows the drop in Doom through the existing Interact path.

## ID format

A monster ID is 64 bits: **tag 5 (3 bits) | placement hash (53 bits) | pack member (8 bits)**.

- The placement hash is FNV-1a over the map ID, block name and position, the marker's position, record, and mobile ID. The converter (`EnemyRoster.Hash`) and Daggerfall (`DoomerfallMonsters.PlacementHash`) compute it separately and must stay identical.
- A quest foe's hash comes from the quest UID and foe symbol.
- The ID is stored in `AActor::ddRecordId`, which already survives door trips and Doom saves.

## How packs extend it

All members of a placement share the 53-bit hash and differ in the low 8 bits, so one placement can own 256 members. The ledger, bridge events, and Doom's record table already key on the full ID. A pack needs the converter to write one `DDMONST` row per member. Quest foes with a count above 1 already use members this way, with one Doom actor each. How a pack counts toward a quest kill is still the owner's open question.

## How it works

1. The converter writes a `DDMONST` lump: map ID, monster ID, and position for each placed thing.
2. On a first dungeon visit, Doom gives each ID to the nearest monster. It waits up to 35 tics, because DRLA replacements can appear after the map thing.
3. Daggerfall lists living quest foes at their real quest markers and all dead IDs (bridge kinds 51 to 53). Doom spawns the foes.
4. `AActor::Die` reports tagged monsters (kind 50). Events are ordered, so a death always arrives before a later save request.
5. `DoomerfallMonsters.cs` ignores repeats, calls `Foe.SetInjured` and `Foe.IncrementKills`, and rolls the drop once.
6. The ledger (`DoomerfallMonsters.json`) travels in the save bundle. It keeps the rolled drop, so a rebuilt dungeon shows the same pile. The item ledger still tracks what was taken from it.

## Bug found and fixed

With DRLA, returning to a dungeon recreated all 42 monsters, including dead ones (84 living). DRLA's spawners are not flagged as monsters, so the revisit cleanup missed them. The cleanup now also removes anything that replaces a monster.

## Known gaps

- **The quest's dungeon is forced by the test hook.** `N0C00Y12` rolled another dungeon, and only Privateer's Hold is converted. The hook points the quest's place at this dungeon and uses its real markers.
- **Quest messages are closed unseen.** Daggerfall pauses behind a quest popup and Doom cannot show those yet, so popups in the 4 seconds after a quest kill are closed and logged.
- **The quest was not played to its reward.** Talking to the quest giver does not exist yet.
- `EnemyDeath.OnEnemyDeath` does not fire, because no Daggerfall enemy object exists. Nothing in this repo subscribes to it, but a Daggerfall mod could.
- Drops use the loot table only. A class enemy's generated equipment is not rolled. Items queued on a foe are included by the code, but no test quest used that.
- A random placement's Daggerfall type is rolled at death from the encounter table, so it is not the type Daggerfall would have placed.
- Quest foes work in dungeons only. Building markers such as `M0C00Y11`'s house and `create foe` ambushes are not connected.
- If Daggerfall's smaller-dungeons setting changes the layout, IDs will not match its placements. The death still counts, with no drop.
- A monster raised by an arch-vile keeps its ID and cannot count twice. After a load, Daggerfall's dead list removes it.
- A save in the first 35 tics of a first visit could leave some monsters unclaimed.

## Failed approaches

- `K0C01Y00` was the first pilot. It cannot parse at a dungeon because it needs a local Thieves Guild NPC.
- Retrying the quest parse until it picked Privateer's Hold was replaced by the explicit test site above.
