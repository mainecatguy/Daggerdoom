# Weapon material damage bonus (run 20261124-194205)

Goal card: the drawn Doom gun's Daggerfall material adds a percent damage modifier (Iron -10% .. Daedric +60%),
through the existing damage bonus path, multiplied with the ammo bonus. Runs after card 01 (Doom weapons have a
Daggerfall material, run 20261124-190702).

## Plan

1. Add one element to `DoomerfallDamageBonus.Multiplier`: `(1 + ammo) x (1 + 0.10 x GetWeaponMaterialModifier())` of
   the drawn gun. Daggerfall's own `GetWeaponMaterialModifier` gives exactly the owner's table (-1 Iron .. +6 Daedric).
   No bridge or engine change: Doom already applies `damage_bonus_bp` to all player-sourced damage.
2. Which gun: `DoomerfallAmmo.UpGun`, the gun Daggerfall has drawn (`DoomerfallHotkeys.ActiveGun`), only once Doom
   has reported it ready after the swap (the same binding the per-gun ammo tier uses), not mid-swap, and not while
   Doom holds fists (Doom lowers to fists while the gun is still Daggerfall's active gun). See the revision below.
3. Test hook `-dfmaterialtest` in its own file (`DoomerfallMaterialDamageTest.cs`, one line in `DoomerfallBridge`):
   stand-in Shell ammo bonus +25%, an Iron Shotgun on key 3 and a Daedric Shotgun on key 4.
4. Harness: `tools/ammo/ammo.py material` / `materialload` (`harness.zs` phases 60-64). Hits a Cyberdemon for 1000
   with the player as source: Iron, Daedric, Iron, fists, Daedric, autosave; the load run hits once more. Checks the
   bridge's "1000 -> N (bp)" line per hit and the Daedric/Iron ratio against 1.6/0.9.
   Expected: Iron 1.25 x 0.9 = 1.125 (1125), Daedric 1.25 x 1.6 = 2.0 (2000), fists unscaled. Adding instead of
   multiplying would give 1.15 and 1.85, so the test also tells multiplication from addition.

## Decisions and why

- **Revised after the first run.** The first rule ("the drawn gun counts only while Doom's ready weapon uses reserve
  ammo") left DRLA X's common starting gun, the RLBlaster, with no material bonus: it uses no reserve ammo, and Doom
  reported it exactly like fists. Fix, a small engine change in `UZDoom/src/dd_items.cpp` `ReportAmmo` (bridge
  sessions only, so standalone Doom and E1M1 are untouched): Doom now sends `DFB_KIND_AMMO_READY` on every ready
  weapon change, not only when the reserve ammo changes, and puts 1 in its (previously unused, always 0) `status`
  field when the ready weapon is a melee weapon (`WIF_MELEEWEAPON`; DRLA's `RLFist` has `+MELEEWEAPON`) or none.
  `DoomerfallAmmo.UpGun` withholds the bonus only for melee. No header constant was added (the layout hash covers
  every header constant), so no lane's test folders break; the meaning of status 1 is documented at both ends.
- Consequence: a melee Doom weapon held as a Daggerfall item (a chainsaw, say) gets no material bonus. Asked the owner.
- The old ammo-only test hooks (`-dfequiptest`, `-dfchangeammotest`) now set every held Doom gun to Steel (0%), via
  `DoomerfallMaterialDamageTest.SteelGuns`, so they keep checking the ammo bonus alone. Their expectations are unchanged.
- Guns from before card 01 have material value 0, which Daggerfall reads as Iron (-10%). Exploratory saves only.
- The accepted known gap from the backlog item stands: a projectile in flight when the gun changes uses the new bonus.
