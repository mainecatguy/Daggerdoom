# Spellbook from the character sheet and a hotkey (run 20261127-023449)

Goal: Daggerfall's magic menu (spellbook) opens in Doom from the character sheet and from its own key, works as in
Daggerfall Unity, and Doom resumes when it closes. Casting is separate (backlog `magic-casting-and-self-spells`).

## Plan

1. Find how the other Daggerfall menus open from Doom (journal `work/notes/20261124-235038.md`, rest `20261126-113251.md`).
2. Add a spellbook menu id and Doom command, the same way as the journal: `DFB_UI_SPELLBOOK`, `netevent df_spellbook`.
3. The character sheet: today it only shows in Doom when Daggerfall opens it for a level-up. There is no key for it, so
   "from the character sheet" could only be reached at a level-up. Add `DFB_UI_CHARACTER` / `netevent df_character`
   the same way (the owner's S12 list in `work/notes/20261123-154554.md` names character sheet and spellbook keys).
   The sheet's own Spellbook button then works unchanged: Daggerfall pushes its spellbook on top inside the same Doom menu.
4. A paired test harness and a test hook, a demo folder, manual and notes.

## Findings

- No Doomerfall code opened the character sheet; it appears only through `DFB_UI_DAGGERFALL` (the level-up sheet).
- `DaggerfallUI` handles `dfuiOpenSpellBookWindow` with two refusals: a cast animation still playing (no window, no
  message) and no spellbook in the inventory (a HUD line, "noSpellbook", that Doom never sees because Daggerfall's HUD is
  hidden). Doom's menu would wait 30 frames and then say "Daggerfall cannot open that menu here." For the key, the
  spellbook check is made first in `DoomerfallUi.OnOpen` with Daggerfall's own condition and text, which goes to Doom's
  HUD (`DFB_KIND_HUD_TEXT`, held until the menu closes) and the menu closes with no generic refusal message.
  From the sheet's Spellbook button without a spellbook, Daggerfall's HUD line goes to its hidden HUD (not forwarded).
- The character sheet's **Logbook** button opens the quest journal, and clicking a quest can open the travel map and
  travel. The journal key's rule (Doom follows travel only from outdoors, `DoomerfallUi.RefuseJournalTravel`) is applied
  to the sheet menu too, with Doom's world context sent along. Without it, Daggerfall could travel while Doom stayed put.
  The level-up sheet (`DFB_UI_DAGGERFALL`) has the same path and is not covered: reported as a suspected oversight.
- Choosing a spell in the spellbook is Daggerfall's own (`SpellsListBox_OnUseSelectedItem`): it calls `SetReadySpell` and
  returns to the HUD. A caster-only spell is then cast at once by Daggerfall's `EntityEffectManager` (magicka spent, its
  effects applied to Daggerfall's player). A ranged or touch spell stays ready until Daggerfall's own Activate input,
  which Doom never sends. I left this stock (no change): the goal says the spellbook works as in Daggerfall Unity and
  casting is separate. Whether to keep or block spell choice until the casting card is a question for the owner.

## Key choice

- **Backspace** for the spellbook: Daggerfall's own default (`InputManager`: Backspace = Cast Spell, which opens the
  spellbook). Free in Doom's default binds (`commonbinds.txt`, `defbinds.txt`), in the DRLA set's `defaultbind`s (L V B
  C M) and in Doomerfall's keys (Q I K J Z E Tab). Inside the spellbook, Daggerfall's own Backspace closes it too.
- **P** for the character sheet: Daggerfall's F5 is Doom's Display Options menu, and C is DRLA's armor special. P is
  free in all three sets. "P for player".
- Both are bound by `play.bat` on a fresh install (`scripts/play/install.py`) and can be rebound in Doomerfall Controls.

## Verifier round 1 and fixes

The verifier rejected the first version for three reasons, all fixed:

1. **Spell choice cast spells.** Choosing a caster-only spell cast it in Daggerfall, outside the goal (casting is the
   unapproved backlog card), and effects such as Teleport/Recall would move Daggerfall's player with no Doom handoff.
   Now, in a bridge session, choosing a spell readies and casts nothing and shows "You cannot cast spells yet." in a
   message box inside the menu (`DoomerfallUi.HoldsSpellChoice`, a two-line hook at the top of
   `DaggerfallSpellBookWindow.SpellsListBox_OnUseSelectedItem`). This covers every route to the spellbook, including
   using the spellbook item from the inventory. Browse, sort, rename, delete and effect descriptions are unchanged.
   Manual corrected.
2. **Backspace in the rename box closed the whole menu.** Doom no longer intercepts Backspace in the spellbook menu
   (`IsOpenMenuKey`): it goes to Daggerfall, whose spellbook closes on its own Cast Spell key (Backspace) when it is on
   top, and whose text box deletes a letter when the rename prompt is on top. A spellbook key rebound to another key
   still closes it from Doom, as other menus' keys do (the same text-box caveat as J in the journal's notebook).
3. **No-spellbook line from the sheet was invisible.** The sheet's Spellbook button without a spellbook now shows
   Daggerfall's line in a message box inside the menu (`DoomerfallUi.NoSpellbook`, one call next to Daggerfall's
   `AddHUDText` in `DaggerfallUI`). The key route still shows it on Doom's HUD.
