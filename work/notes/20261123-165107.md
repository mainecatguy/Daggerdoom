# Wilderness terrain height bug hunt

## Result

The player stood inside the ground because the overworld and the town meshes were built from different height data.

- Recent demo overworld packages used raw `WOODS.WLD` heights with no `DDLOCS`.
- Town meshes use Daggerfall's smoothed heights and location flattening. Each mesh also draws a wide ring of wilderness around its town.
- Inside that ring the player saw the mesh but collided with the raw grid.
- `tools/fast_travel_menu/assemble.py` called `gen_overworld.py` without `--world-dir`, and the generator silently fell back to raw heights. Later demos copied that package.

## Fix

`tools/overworld/gen_overworld.py` now uses the shared smoothed world data (`D:\dev\DoomDaggerfall-build\stitch-data`) by default. It stops with a clear error if the data is missing. Raw heights now need an explicit `--raw-world`. No engine code changed.

Existing demo folders keep their old `overworld.pk3` until they are reassembled. `tools/fast_travel_arrival/assemble.py` and similar scripts copy an existing package, so regenerate the source package first.

## Remaining gap

**Small terrain bumps still differ from real Daggerfall.** Both engine and converter use a stand-in for Unity's `Mathf.PerlinNoise`. Against real values dumped from Unity 2019.4.41f2 over five map pixels (83,205 samples), the height error is mean 14.48, 95th percentile 36.52, and largest **76.92** Doom units. Player and visible ground still agree, because both use the stand-in.

Fixing this needs the same noise change in `UZDoom/src/playsim/dd_treadmill.cpp` and `tools/dungeon_converter/WorldTerrain.cs`, and every cached town must be rebuilt. The converter was off limits for this run, and changing only the engine would break the town seam.

Not measured: Unity's triangle diagonal against the grid's fixed diagonal.

## Regression checks

- Town stitch in and out on group 14178: seam worst 0.0032 over 10,530 points.
- Warp handoff, which is the path fast travel uses, arrived correctly. The full Daggerfall fast-travel menu was not run.
- Save in town, load, and walk out: passed.
- Stock `DOOM.WAD` E1M1, save, reload, and a converted dungeon: passed with the treadmill inactive.
- DRLA set on E1M1: ran to the 30-second limit. Its log has three non-fatal script parsing errors from the mods' `translation` and menu lumps.
- Position sync through the bridge was not run. No engine or bridge code changed.

## Failed approaches and dead ends

- Feet against the grid plane showed no sink in open wilderness, so the physics and treadmill were not the cause.
- The sampler port, WOODS array order, and mesh and collision diagonals all matched on inspection.
