## Findings in one paragraph

A Doom save fails to load if a mod is removed, if the mod order changes, or if the current map's TEXTMAP changes. All
three were reproduced. A failed Doom half loses the whole bundled save. So "where the history lives" matters only
together with a rebuild load that does not need the snapshot. Daggerfall already keeps death, container, and
townspeople ledgers in the bundle, keyed by stable ids. The recommendation extends that into a location ledger of
facts. The report gives the stages.

## What did not work, or surprised me

- `+logfile <absolute path>` wrote nothing. UZDoom writes `+logfile NAME` as `log-NAME.txt` in the working folder.
- `-loadgame <absolute path>` is joined onto the save folder, which gave "Cannot find savegame". I used `-savedir`
  plus a bare file name instead.
- I expected different converter builds to produce different town maps. They did not: five builds from the last 19
  hours gave the same TEXTMAP for group 7154. The converter is deterministic, and town geometry has been stable
  recently. Interiors and dungeons changed today (pickup markers), but I did not convert one to compare.
- The shell permissions blocked compound commands, variables, and `git -C`. The tests ran as Python scripts in the
  scratchpad.
