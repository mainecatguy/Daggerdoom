# Run 20261122-015827: terrain treadmill kill test

Full results: `work/notes/terrain-treadmill-results.md`.

## Plan as executed

1. Port the Daggerfall height sampler to Python and pick a high-relief route from `WOODS.WLD`.
2. Add an opt-in engine file with small hooks. Rewrite floor planes, invalidate renderer heights with NaN so only drawn sectors re-upload, and shift actors.
3. Measure rewrite and baseline runs, then check glitches and stock compatibility.

## Findings

- Rewrite plus actor shift takes about 1.7 ms. The worst full shift frame was 13.41 ms at 3044 x 1649.
- Lazy invalidation works: about 16,700 of 32,768 floors upload on a typical shift frame.
- Doom slope physics speeds the player up to as much as 77 units per tic on this terrain. A static control map with the treadmill off also exceeded normal speed.

## Failed approaches and bugs found

- UZDoom's registered `FArg` launch options would not accept plain strings. The patch scans the argument list instead.
- The first camera shift also moved `ViewPos`, which is an offset. That double shift caused visible view jumps of thousands of units, caught by the harness and fixed.
- The first player interpolation check was meaningless because it ran before the player moved. It was replaced with a velocity-based step check.
- The first jump threshold (40 units per tic) falsely flagged real slope speed.
