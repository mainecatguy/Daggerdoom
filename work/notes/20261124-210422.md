# monsterwidth: monsters narrowed like the player (run 20261124-210422)

Continues `work/notes/20261124-202008.md` (open doors are solid). Owner answer, 2026-11-24: monsters are too wide for
Daggerfall's spaces the same way Doomguy was. On Daggerfall maps they should fit spaces narrowed by the same proportion
as the player (16 to 10.5). Open leaves stay solid for everyone, with no exemption. Stock WADs keep stock sizes.

## Plan

1. One rule, in one place: on Daggerfall maps every monster's radius becomes its class radius x 10.5/16. Height stays stock.
2. Make everything that sizes monsters ahead of time (the encounter placer and planner) use the same width.
3. Door check: measure a real monster at whatever width the loaded rules give it, and score it.
4. Prove regular maps are unchanged (E1M1 stock and DRLA), stock and DRLA monsters are narrowed, placement still works.
5. Census of monsters that still fit no open doorway.

## Design and why

- **Where the rule lives:** `mods/doomerfall/src/zscript/DoomerfallBodies.zs`, an event handler in the Doomerfall mod.
  The player's width is set by several generated packages (ddruntime.pk3, overworld.pk3, the converter's player package,
  older demo `_width.pk3` files), each with its own map test. Putting the monster rule in each would mean four copies and
  regenerating game-data packages. The mod is always loaded in real play, and the encounter placer already depends on it.
  - `OnDaggerfallMap()` is the union of the player handlers' map tests: generated locations (`DDTnnnnn`, `DDSnnnnn`),
    the overworld (`DDOVER*`), and converted dungeons (`MAP01` with the converter's `DDDUNGN` or `DFPOINTS` lump).
  - `MonsterScale()` is 10.5/16 = 0.65625 there, otherwise 1.
  - `WorldThingSpawned` narrows any monster still at its class default radius (so a mod script's own resize is left
    alone, and repeating it is harmless). `WorldLoaded` sweeps existing monsters, for saves made before this rule.
    Shrinking never needs room, so it cannot fail or move anything.
- **No engine change for the rule itself.** UZDoom changes are only in Doomerfall files and run only on Daggerfall
  encounter maps:
  - `dd_encounter_placer.cpp`: `Body()` multiplies class radius by `bodyScale`, read once per run from
    `DoomerfallBodies.MonsterScale`. Spots, spacing and leader fit tests now use the real body size.
  - `dd_monsters.cpp` `SpawnMook`: calls `DoomerfallBodies.Narrow` right after spawning a monster. Without it, a mook is
    narrowed only on its first tic (`WorldThingSpawned` fires from PostBeginPlay), so for that moment it stood wide in a
    spot chosen for the narrow body. The spawn-time stuck count showed it: 100 stuck at level 10, back to 1 with the fix.
- `EncounterBudget.zs` `Fits()`: compares `radius x MonsterScale()` with the placer's measured fit radius.
- `door_check`: `MonsterThrough` now uses a real `DoomImp`, spawned early and parked so its first tic (when spawn
  handlers size it) has run. `DTMONSTER radius=` reports its width. `action_regress.py` loads the mod and scores
  `monster_doors`: the imp must be 13.125 wide and no doorway may shut it out because of the leaf (`0`). A doorway too
  narrow even without a leaf (`n`) is reported.

## Known gaps

- Monster hitboxes shrink with collision width. In Doom the same radius is used for movement and for being hit, so
  narrowed monsters are 34% narrower targets for hitscan, projectiles and melee, while their sprites stay the same
  size. Shots that visually graze a sprite's edge can miss. Play-test item 3.
- A mod script that later resets a monster to its default size (for example DRLAX's Pit Guardian release,
  `PitGuardian.zscript:895`) makes it stock width again until the next save load. Rare. Not handled.
- `OnDaggerfallMap()` copies the player handlers' map tests rather than sharing them, because those live in generated
  packages. If a new kind of Daggerfall map is added, both need the new test.
- On a standalone converted map (`MAP01` with `DFPOINTS`) loaded without a player-width package, monsters are narrowed but
  the player is not. No game setup does this. Only hand-assembled tool runs can.
- Monsters spawned by mods without the Doomerfall mod loaded keep stock widths (no rule is loaded).

## Failed approaches and notes

- First door run: the imp measured 20. `WorldThingSpawned` runs from PostBeginPlay on the actor's first tic, and the
  check measured in the same tic it spawned the imp. Fixed by spawning it early and parking it.
- First placer run: 100 mooks stuck at spawn, for the same reason. Fixed with the spawn-time narrowing in `SpawnMook`.
- Starting `uzdoom.exe` directly under `quiet_run.py` stopped right after `V_Init` with no map loaded. The same launch
  from a Python script that is itself wrapped in `quiet_run.py` works, so the smoke test uses that
  (`review\monsterwidth\smoke.py`).
- The placer test takes `--exe` and `--runs` now, so other lanes can point it at their own build and log folder.

## Questions for the owner

1. Demons and Spectres (radius 30) and Cacodemons and Pain Elementals (31) narrow to 19.7 and 20.3. The best open
   Privateer's Hold doorway leaves 18 units beside the solid leaf, so they still pass no open doorway there (bigger
   monsters such as Mancubi, Arachnotrons and Cyberdemons are too big as well). Keep it (big monsters stay in their
   rooms), or should these monsters get more help, for example a slightly stronger factor or a radius cap of 18 on
   Daggerfall maps?
2. Narrowing collision also shrinks the hitbox (Doom uses one radius for both). Monsters are 34% narrower targets while
   their sprites stay the same size. Acceptable, or should hit detection keep a wider box? A wider box is an engine
   change to Doom's hit tests.
