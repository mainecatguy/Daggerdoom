# Equipping a gun sets Doom's ammo and damage from Daggerfall (run 20261124-090831)

Card: `work/queue/ammotiers/03.opus.equip-sets-doom-ammo-and-damage.md`. Branch `agent/ammotiers-20261124-090831`
(lane-items worktree), on top of cards 01 (damage bonus) and 02 (ammo pickup in the inventory).

## Plan

1. Daggerfall must know which ammo the gun in Doom's hands uses. Daggerfall's gun items only know their Doom pickup
   class, and the ammo a gun uses lives in Doom's weapon definition (DRLA: `AmmoType1` is the gun's magazine,
   `AmmoType2` the reserve). So Doom reports it.
2. When that changes (a gun equipped from a Daggerfall hotkey, a gun raised again after fists, a load), Daggerfall
   tells Doom how many loaded rounds of that type it holds, and the damage bonus takes the loaded ammo's material.
3. One path for "the loaded ammo changed", so card 05's change ammo key only has to change which stacks are loaded.
4. Prove it in the paired harness with stand-in bonuses, through Daggerfall's real hotkey equip, and across save/load.

## What was built

- Bridge: `DFB_KIND_AMMO_READY` (173), UZ to DF, `cls` = the reserve ammo class (Clip, Shell, RocketAmmo, Cell) of
  Doom's ready weapon, or empty for none. Bindings regenerated (`python bridge/generate_bindings.py`). The layout hash
  changes, so old launchers, bridge DLLs and UZDoom builds do not attach to new ones.
- Doom (`UZDoom/src/dd_items.cpp`): `ReadyAmmo` finds the first of the ready weapon's `AmmoType1`/`AmmoType2` that is
  or derives from one of the four reserve classes. `ReportAmmo` (every frame in a bridge session) sends
  `AMMO_READY` when it changes; `DD_ItemsResync` forces a resend after a load.
- Daggerfall (`DoomerfallAmmo.cs`):
  - `OnReady` stores the ready gun's ammo type and asks for a *tell*.
  - `Tell`: once Doom has reported its counts, compares Daggerfall's loaded rounds of that type with what Doom is
    believed to hold (last report plus deltas in flight) and sends the difference as an `AMMO_ADD` delta. A delta
    rather than an absolute set, so a round Doom spends while the message is in flight is still counted exactly once.
    Logs `ammo: equip: the ready gun loads <type>; Daggerfall holds N, Doom held M; ammo damage bonus X`.
  - `IsLoaded(item, type)` is the one place that says which stacks Doom's counter stands for. All sync code (mirror
    of Doom's spending, Daggerfall-side changes, `Settled`) now uses `LoadedTotal`/`IsLoaded`, and rounds Doom gains
    become `NewLoaded` stacks. Today every stack of a type is loaded, so behaviour is unchanged.
  - `Reload()` asks for a tell. Card 05 changes the loaded tier (what `IsLoaded` and `NewLoaded` return) and calls
    it. The existing delta loop then sees the loaded total change and sends Doom the difference; the tell confirms.
  - `LoadedMaterialBonus()`: the material bonus of the ammo loaded in the ready gun; 0 with no ready gun (fists).
    Ammo has no tiers yet, so it is 0 except under the test hook.
- `DoomerfallDamageBonus.AmmoMaterialBonus` now reads `LoadedMaterialBonus`, so the published bonus follows the ready
  gun and its loaded ammo, every frame.
- Test only: `DoomerfallEquipAmmoTest.cs` (`-dfequiptest`, one-line hook in `DoomerfallBridge.cs`). Stand-in
  bonuses Clip +50%, Shell +25%; adds a stock shotgun to Daggerfall's inventory on hotkey 3 once the starting gun is
  adopted. `tools/ammo/ammo.py equip` / `equipload` and `tools/ammo/harness.zs` (EQUIPRUN) drive it.

## Engineering calls

- The ready weapon, not "the gun Daggerfall holds as active", decides the loaded ammo. So lowering to fists drops the
  ammo bonus to 0, and raising the gun brings it back. This keeps a material bonus off fist damage.
- After a load, Doom's count still wins any difference (the open question from `20261124-075147.md` is unchanged):
  the mirror step runs before the tell, so the tell finds both sides equal. With one tier, the tell never changes a
  count in normal play; it starts to matter when the loaded tier changes.
- A gun whose two ammo types are both reserve ammo uses the first one for the bonus.

`ammo: Doom's ready gun uses Shell` / `damage bonus: publishing 2500 bp (x1.25)` /

`ammo.py equipload` loads that autosave in fresh games: the shotgun is still ready, Doom re-reports `Shell`,
Daggerfall publishes 2500 bp again, the hit is `10 -> 12`, counts MATCH. (Both runs.)

One middle run started with RLStealthRifle: the bridge applied the same bonus, but health lost was 16 and 13, not 15
and 12. A DRLA X starting perk multiplies the damage again after the bonus (fists stayed at 10). That is why the check
reads the bridge line rather than health lost.

Regressions: `ammo.py take` (the window drop and pick-up test from card 02) ends `same as the counts before the drop`
and MATCH; without `-dfequiptest` the published bonus is 0%. `ammo.py load` MATCH. `ammo.py check`: stock DOOM.WAD

Failed attempt, harness only: the first two `take` runs crashed UZDoom while it compiled the harness ("Not in a
level", access violation). The harness had `if (EQUIPRUN) { ...; break; }` with EQUIPRUN a constant 0 inside a
`switch`. With the `break` moved out of that `if`, the take harness compiles and runs. The equip harness (constant
1) never crashed. Probably a ZScript compiler bug with a `break` in constant-folded dead code. Not investigated.

## Notes for cards 04 and 05

- To add tiers: make `IsLoaded` check the loaded tier and `NewLoaded` build that tier, and give
  `LoadedMaterialBonus` the tier's bonus. To change the tier: set it and call `Reload()`. The loop then sends Doom
  `loaded - believed` as one delta, so no rounds are created or lost, even with a shot in flight.
- Rounds Doom picks up by touch go to the loaded tier (`NewLoaded`). Card 04's tiered pickups need their own path
  into Daggerfall for tiers that are not loaded.
- The loaded tier is not stored anywhere yet. Card 05 decides whether it belongs to each gun or each ammo type, and
  saves it.
