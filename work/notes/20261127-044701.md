# Typing in Daggerfall text boxes is not eaten by Doom (20261127-044701)

## Cause

Doom already forwards every key and character to Daggerfall while one of its menus is open
(`DD_BridgeUiWndProc`, `UZDoom/src/dd_bridge.cpp`). Two Doom-side rules got in the way of typing:

1. **Map panning** (`MapPanKey`): in the map screens (`DFB_UI_MAP`, `DFB_UI_TRAVEL_MAP`), keys bound to Doom's
   movement are sent as arrow keys so they pan the map. The Find box sits on top of the travel map, so W A S D
   still arrived as arrows. Daggerfall's `TextBox` treats Left and Right as cursor moves and drops the
   character (A, D); the others arrive in the wrong state.
2. **Menu key closes the menu** (`IsOpenMenuKey`): the key bound to the command that opened the menu closes it.
   Typing that letter (K for the travel map in the tests) would close the whole map.

## Fix (one general rule)

Daggerfall tells Doom when a text box takes typing; while it does, Doom sends every key unchanged and its own
controls never close the menu.

- `bridge/doomerfall_bridge.h`: new menu state `DFB_UI_TYPING` on the existing `DFB_KIND_UI_STATE` event
  (generated bindings refreshed with `bridge/generate_bindings.py`).
- `TextBox.cs`: one line records the frame a text box last passed its own "do I take input" check
  (not read only, and focused when it uses focus). This is Daggerfall's own definition, so it covers every
  text box: the map's Find, save names, the spellmaker's name, bank amounts, character names, and so on.
- `DoomerfallUi.cs`: each frame, while a menu is open, compares that with the last report and sends
  `DFB_UI_TYPING` or `DFB_UI_OPENED` when it changes.
- `dd_bridge.cpp`: `uiTyping` gates `MapPanKey` and `IsOpenMenuKey`. A key's release is sent as its press was
  (`UiKey`), so a key held across the change never stays held in Daggerfall.

Why this way: Doom cannot see Daggerfall's focus, and Daggerfall cannot undo Doom's remap (it cannot tell a
real arrow from a remapped W) or stop Doom closing the menu. A state flag on the event that already reports
the menu's state is the smallest contract. Inactive outside a bridge session: the gate lives in bridge code
that runs only while a Daggerfall menu is open.

## Play-test list

- Open the travel map (K), pick a region, click Find, type a town's name with W A S D in it, Enter: the map
  finds it. Then W A S D pan the map again, and K closes it.
- Type in a save name (Daggerfall's Save window from its own menus, if reachable in Doom) and the
  spellmaker's name box: every letter, including your Doom menu keys, goes into the box.
- After closing any of these, walk around: Doom movement and keybinds behave normally.
