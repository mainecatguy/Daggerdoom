# Dungeon texture second pass (20261123-011044)

Goal: find textures in the Scourg Barrow action demo that do not match Daggerfall, fix what can be fixed, list the rest.

## Method
- Read the exporter (`MeshExport.cs`, `DoorExport.cs`, `ActionExport.cs`) against Daggerfall Unity's own code: `DungeonTextureTables`, `MeshReader.LoadVertices` (UV normalization), `RDBLayout.AddModels`, `MaterialReader`, `TextureFile`.
- New harness `tools/dungeon_converter/texture_shot.py` (+ `texture_shot/`): off-screen UZDoom, no focus steal, ~30 s limit, teleports a camera 72 units from every distinct action object, flat and door model (four sides), or to every Nth reachable node (`<points file> <step>` as extra args). Screenshots go outside the repo.
- Looked at about 80 screenshots plus the PNGs inside the pk3s.

## What was wrong
1. **Flat sprites had an opaque black box.** Action flats (the wall torch that works as a switch in Scourg Barrow) were written as RGB PNGs, so palette index 0 drew black. Daggerfall Unity draws billboards with alphaIndex 0. Seen in `action2_0_180.png` before the fix.

## Fixed
- `WriteTexturePng` has a `transparentZero` option (RGBA, index 0 clear). Only the action flat sprites use it. Model textures stay RGB, because Daggerfall Unity loads model materials with alphaIndex -1 (opaque); no model texture in Scourg Barrow has a large index-0 area anyway (checked all 106 PNGs).
- After the fix the torch renders with no box (`shots2/action2_0_180.png`).

## Checked and found to match Daggerfall Unity
- Texture table: `ClassicTextureTable`/`SwapArchive` equal `RandomTextureTableClassic`/`ApplyTextureTable` (same arrays, same climate index math, same seed). Scourg Barrow uses 19,20,22,23 sets, which is what DFU's code gives for a Mountain dungeon.
- UVs: normalized by the unswapped record size, same as `MeshReader.LoadVertices`. Action and door OBJs use the same key function as the static mesh and the same PNG names, so the same texture appears in both. Static and moving objects look the same in screenshots.
- Solid-colour archives 0 and 1 (`a000r75-78` etc.): handled through the same `TextureFile` class, 32x32 solid. They render as flat colour panels on some doors; that is what the data says.
- Sarcophagus marble (archive 41, "Desert Marble Floors") really is a noisy 64x64 texture stretched over the whole side (UVs 0 to 1 across 108 units). It looks streaky but matches the data. A human should compare with the real game.
- Privateer's Hold: re-exported with `--export-mesh`, loads, screenshots fine (`privshots/`).

## Remaining (not fixed)
- **Animated textures show frame 0 only.** Scourg Barrow uses two: `a086r04` (16x16, 6 frames, blue, on action model 74039) and `a087r00` (fireplace fire, 4 frames). Daggerfall Unity animates them. UZDoom can do this with ANIMDEFS, but it is a new visual feature, so not done.
- **Ordinary flats (wall torches, lights, plants, etc.) are not exported at all** in dungeons. Only flats with actions are. This is the biggest visual difference from Daggerfall, but it is a new feature.
- Door model 55xxx variants with a flipped placement: `WriteDoorPackage` writes the OBJ as `m<id>f.obj` but MODELDEF references `m<id>.obj`. A flipped-only door model would have no OBJ. Not a texture issue and not seen in Scourg Barrow's output; unverified, noted only.
- No ground truth screenshots from Daggerfall Unity itself were available (Unity cannot run here, and `daggerfall-unity-master/` is off limits), so "matches" means matches DFU's code and data, not a pixel comparison.
