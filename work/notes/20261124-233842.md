# New Game while a game is running (run 20261124-233842)

## Problem

In a `-dfflow` session, choosing New Game from Doom's menu mid-game printed "End the current game before starting a
new one." (`DD_BridgeNewGameMenu`, `UZDoom/src/dd_bridge.cpp`) and did nothing, and the menu offers no way to end
the game.

## What changed

- `UZDoom/src/dd_bridge.cpp`: `DD_BridgeNewGameMenu` now asks to confirm when a game is running (and no load, save
  or New Game is in flight), instead of refusing. At the title it behaves as before. Yes calls the new
  `DD_BridgeNewGameFromGame`: it drops the pending new-game start save, then reuses the existing `ReturnToTitle()`
  (the path behind Doom's End Game and the death menu's Main Menu: Daggerfall is held, campaign id cleared, death
  state cleared, Doom's title started) and starts the normal New Game flow at once (`NgBegin`, shared with the
  title path). No menu entry was added.
- `UZDoom/src/menu/doommenu.cpp`: `M_DDConfirmNewGame`, a stock message box: "Start a new game? Anything not saved
  in the current game is lost." Yes is the default, as in Doom's End Game question.
- Everything is behind `session && flowMode`, so stock Doom and Doomerfall without `-dfflow` are unchanged.

### Why no leftover state

Nothing new was needed; the existing reset points cover it once the flow gets to run:

- Daggerfall: character creation runs `StartGameBehaviour.StartNewCharacter` → `NewCharacterCleanup` (UIDs, quest
  machine, scene cache, guilds, discovery, bank, weapon manager, OnNewGame event), and `DoomerfallNewGame.BeginCreation`
  clears Doomerfall's item, monster and townspeople ledgers; the hotkey table clears too ("hotkeys: new game: table
  cleared" in the log, once per character).
- Doom: `G_InitNew` makes a fresh player, and entering `DDOVER01` without a pending handoff clears the world table,
  visited spaces, return point and monster plans (`dd_treadmill.cpp` `Start`). The new campaign id keeps the new
  character's auto and quick saves apart from the old one's.

## Known gaps

- Backing out of character creation after confirming leaves the player at the title: the old game is already gone.
  That matches "the running game is dropped".
- A treadmill handoff (door or travel) pending at the moment Yes is chosen would make `DDOVER01` keep the old world
  table. Handoffs finish within a tic and `G_Ticker` runs them even with a menu open, so this should not happen in
  practice; not guarded.
- Built with the lane's `uzdoom-encounters` tree (configured from this worktree).
