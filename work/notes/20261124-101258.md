# Change ammo key (run 20261124-101258)

Card `ammotiers/05`. Branch `agent/ammotiers-20261124-101258` (lane-items worktree), on top of cards 01 to 04.

## Plan

1. A Doomerfall control, "Change Ammo", that Doom forwards to Daggerfall (Daggerfall decides, Doom only does what
   Daggerfall asks).
2. Daggerfall picks the next tier it holds for the ready gun's ammo type, asks Doom to empty that gun's magazine, puts
   the emptied rounds back as the old tier, then changes the loaded tier, which sends Doom the new tier's rounds through
   card 03's delta path.
3. Automatic change when the loaded tier runs out and the gun's magazine is empty.
4. Doom's HUD shows the loaded ammo (tinted sprite and name) at the bottom of the screen, plus the ammo's tags (none
   exist yet). Daggerfall keeps the tags as player state and clears them when the ready weapon uses no reserve ammo.
5. Save the loaded tiers; prove it all in the paired harness, plus the E1M1 and regression checks.

## Design call: per gun, not per ammo type

The open question [20261124-090831] asked whether the tier belongs to each gun or each ammo type. I chose **per gun**,
because the owner's decisions on this card point there and the other choice breaks one of them:

- "Changing ammo empties the magazine" (one magazine, the held gun's), and a DRLA magazine travels with its gun: when a
  gun is put away, its magazine goes into the gun's saved state (`DoomerfallDoomItem.GunState`). With one tier per ammo
  type, changing the bullet tier while holding the chaingun would leave Regular rounds in the pistol's stored magazine
  that later fire, or unload, as the new tier.
- Tags "clear when the weapon changes", which reads as the loaded ammo belonging to the weapon.
- Blood West, the owner's example, keeps the selected ammo per weapon.

It is easy to undo: `SyncGunTier` in `DoomerfallAmmo.cs` is the only place a gun's record decides the loaded tier.
Without it the code is the per-type model.

## What was built

### Bridge (`bridge/doomerfall_bridge.h`, bindings regenerated)
- `AMMO_CHANGE` 177 (UZ to DF): the key was pressed. `AMMO_UNLOAD` 178 (DF to UZ) and `AMMO_UNLOADED` 179 (UZ to DF):
  empty this gun's magazine and report the rounds; automatic unloads are refused while the magazine holds rounds.
  `AMMO_LOADED` 180 (DF to UZ): the loaded tier and type for the HUD, plus the ammo's tags. The layout hash changes
  again, so old launchers, bridge DLLs, and UZDoom builds do not pair with new ones.

### Doom (`UZDoom/src/dd_items.cpp`, `mods/doomerfall`)
- "Change Ammo" control in Doomerfall Controls (`netevent df_change_ammo`), unbound by default like the mod's other
  controls. The demo binds Z on a fresh config. Doom only forwards the press; Daggerfall decides.
- `UnloadMagazine`: the gun is the ready weapon if it uses that reserve ammo, else the first held gun that does. Its
  magazine is its other ammo type when that is not reserve ammo (DRLA's `AmmoType1`). Stock guns have none, so they
  return 0 rounds.
- `AMMO_READY` is now also sent when the ready weapon changes to another gun with the same ammo. Daggerfall needs this
  to know when a gun it handed over is up.
- `DoomerfallAmmo.zs` draws the loaded ammo at the bottom of the screen, three quarters of the way across and above
  "Sneaking": the type's stock pickup sprite in the tier's tint, "Steel bullets" in gold, and the tags in green under
  them (none yet). It is hidden with fists or with a gun that uses no reserve ammo.

### Daggerfall (`DoomerfallAmmo.cs`, `DoomerfallDoomItems.cs`, `DoomerfallHotkeys.cs`)
- Each Doom gun item remembers its ammo type and tier in `typeDependentData`, which Daggerfall saves for every item and
  uses only for potions and arrows. `SyncGunTier` makes the active gun's tier its type's loaded tier once Doom reports
  that gun ready. It does nothing while a hotkey swap is in flight, and only counts ready reports that arrive after the
  swap began. A gun without a record takes its type's current tier.
- The change key: the next tier in the owner's order (wrapping) that the inventory holds. Doom empties the magazine, the
  rounds come back as a stack of the old tier, then `SetLoadedTier`. In that same frame the existing delta loop swaps
  Doom's reserve to the new tier's count. With no other tier the key shows "You have no other bullets." With fists it
  shows "This weapon has no ammo to change." On a change, Daggerfall's HUD text (relayed to Doom) says
  "Loading Steel bullets."
- Automatic change: when Doom's count and Daggerfall's loaded total of the gun's type are both 0, no delta is in
  flight, and another tier is held, an automatic unload is tried every 0.5 s. Doom refuses it until the magazine is
  empty too, so a magazine never mixes tiers. The gun's type is kept if Doom lowers an empty stock gun to fists.
  The HUD text is "Out of ammo: loading Silver bullets."
- `DoomerfallAmmo.LoadedTags`: the loaded ammo's tags, kept as player state and cleared when the ready weapon uses no
  reserve ammo. `DoomerfallAmmoTiers.Tags` returns none for now. That is the place Silver's bonus and the quiet tag
  will fill.
- Save: an `ammotiers a b c d` line in `DoomerfallHotkeys.txt`, restored during the load, before Doom's restored
  counts are mirrored. Without this, a load would mirror Doom's count onto the wrong tier's stacks. Older saves and new
  games load Regular.
- Test only: `DoomerfallChangeAmmoTest.cs` (`-dfchangeammotest`, a one-line hook in `DoomerfallBridge.cs`).

## Failed approaches and findings
- First version: a gun counted as ready only after a ready report that came after Daggerfall saw the active gun
  change. Doom reports the new gun before the swap's confirmation arrives, so the drawn pistol never bound. The tier was
  right in play only because the per-type tier was already correct. Fixed by counting from when the swap began.
- Second run: while swapping back from the Blaster, Doom raised the pistol before the swap finished. The old gun's
  stale record (the Blaster had recorded "bullets" from an early ready report) set Regular for 23 ms before Silver
  loaded. Counts still matched, but it sent two pointless deltas. Fixed by doing nothing while a swap is in flight.
- Known gap: a stale record like the Blaster's is harmless now, since it applies only when its gun is up and reports
  that type. It is never cleaned up, though.

## Play-test list
Use `D:\dev\DoomDaggerfall-loop\review\ammo-change\play.bat` (Z = change ammo).
1. Enter the dungeon and press 4 for the test pistol. The bottom of the screen shows a dark-grey bullet icon and
   "Regular bullets". Is it placed well, and does it clash with DRLA's HUD?
2. Press Z: the pistol's magazine empties (reload needed), the HUD says "Loading Steel bullets", and the icon turns
   steel. In the inventory (I), Regular went up by the magazine's rounds.
3. Reload and fire until both the magazine and the reserve are empty: Silver loads by itself. Does DRLA's reload pick
   it up smoothly?
4. Press 2, then 4: each gun keeps its own tier and the icon follows. With fists the icon disappears.
5. A stock gun (no magazine), such as a shotgun: when it runs dry, Doom may lower it to fists before the next tier
   arrives. Is that acceptable, or should the gun come back up by itself?
6. Save, quit, load: the pistol still loads the same tier, and the counts are unchanged.
7. Z with only one tier held: "You have no other bullets." and nothing else changes.
