# New start 2: start where Daggerfall really starts in Privateer's Hold (20261124-105730)

## Plan
1. Find how Daggerfall Unity places a new character in Privateer's Hold.
2. Send that point to Doom with the New Game event; Doom lands there when it enters the dungeon for New Game only.
3. Daggerfall's hidden player follows Doom as before (position sync), so both are at the start point.
4. Check which monsters the converted map and the encounter planner put near that room.
5. Prove it: paired New Game through the launcher (`--minimized`), log both positions, save and reload.

## Findings
- New character start: `StartGameBehaviour.StartNewCharacter` (StartGameBehaviour.cs:401) calls
  `PlayerEnterExit.StartDungeonInterior(location, preferEnterMarker: true, ...)`. That uses the dungeon's
  **Enter marker** when there is one, else the Start marker (PlayerEnterExit.cs:983-987), puts the player
  `0.6 * controller height` above it, and faces north (`SetFacing(Vector3.forward)`, PlayerEnterExit.cs:1013).
- Markers are editor flats (archive 199) in the dungeon's starting block (`DaggerfallDungeon.FindMarkers`,
  first of each): record 8 = Enter, record 10 = Start. Walking in through the door uses the **Start** marker
  (`TransitionDungeonInterior`, PlayerEnterExit.cs:934), beside the exit door.
- The converter places Doom's player start at record 10, falling back to 8 (tools/dungeon_converter/Program.cs:303,
  comment "Record 8 can be a sealed room (Privateer's Hold)"). So Doom always arrived at the entrance.
- Doom's New Game path (dd_bridge.cpp PumpNewGame) travels to the start pixel, then `DDTreadmill_RequestDungeon`
  goes through the town's real dungeon door (EnterDoor, landing at the map start). Daggerfall then follows Doom.
- Privateer's Hold data: Enter marker at 510, 1672, 25 (Daggerfall units, dungeon space, x east, y north, z up);
  the floor under it is z 0. The Start marker (entrance) is about 1330 units away.

## What changed
- `bridge/doomerfall_bridge.h`: `dfb_new_game` gains `start_x/y/z/yaw` (32 to 48 bytes). Generated files rebuilt
  with `python bridge/generate_bindings.py`. **The layout hash changes**: every demo or test folder needs this branch's
  launcher, `doomerfall_bridge.dll` and `uzdoom.exe` together.
- `DoomerfallNewGame.cs`: the New Game event carries the marker StartDungeonInterior used (Enter marker, else Start
  marker) and the facing it gave (Unity yaw 0 = north = Doom 90). No marker sends NaN, and Doom keeps the entrance.
  The `new game: ... held at` log line names the marker and the hidden player's distance from it.
- `dd_bridge.cpp`: passes that point to `DDTreadmill_RequestDungeon`. On arrival it logs the Doom player's dungeon
  position and distance from Daggerfall's point, and the monsters near the start (`LogMonstersNearStart`).
- `dd_treadmill.cpp/.h`: `EnterDoor` takes an optional dungeon start; only the New Game request passes one, so
  walking in, fast travel and loads are unchanged. Landing uses the normal handoff (snapped to the floor below).
- `DoomerfallPositionSync.cs`: the indoor landing log also gives the distance from the Enter marker.
