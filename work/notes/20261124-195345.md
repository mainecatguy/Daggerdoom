# Clean launcher startup (cleanlaunch, 2026-11-24)

Goal: starting the play folder should look like one game starting and end at Doom's title, with no window fighting
for focus and Daggerfall never covering the screen.

## Findings

- **Why Daggerfall came up fullscreen.** Daggerfall Unity's `defaults.ini` has `Fullscreen=True` at 1920x1080, and
  `SceneControl.Start` and `StartGameBehaviour.ApplyStartSettings` call `Screen.SetResolution` from those settings at
  start. That overrides Unity's `-screen-fullscreen 0 -screen-width 1280 -screen-height 800`. `install.py` replaces the
  `dfu` folder on every install, so the play folder always ran on the defaults.
- **Why the order looked random.** The launcher resumed both games at the same moment. Doom opens a window at once;
  Unity shows and activates its own window on start whatever it is asked (the launcher's own comment, from the test
  path), so whichever finished first got covered or lost focus.
- **Daggerfall's window is not needed in play.** Doom shows Daggerfall's UI (`DoomerfallUi` renders it into a surface
  Doom draws) and sends it all keyboard and mouse input (`DoomerfallUi` injects keys and buttons). Every paired test
  already runs Daggerfall on a private desktop through `--minimized`, including New Game and the cinematics.

## What changed

1. **Launcher** (`launcher/main.cpp`): Daggerfall Unity now always runs on a private desktop owned by the launcher
   (`doomerfall-dfu-<pid>`), not only in test mode, so its window never reaches the player's screen and cannot take
   focus. Doom is the only window. `--show-dfu` brings back the visible window for debugging. In normal play the
   launcher also calls `AllowSetForegroundWindow` for UZDoom so Doom's window comes up in front. Test mode
   (`--minimized`) is unchanged apart from the desktop's name.
2. **Daggerfall** (`DoomerfallWindow.cs`, new, no hook in any existing class): in a bridge session, Daggerfall's
   settings are set in memory to windowed at the command line's `-screen-width`/`-screen-height` (default 1280x800)
   before the first scene loads, so `-screen-fullscreen 0` is honoured even with `--show-dfu`. It also never locks the
   cursor in a bridge session. That matters now that it is always on a private desktop: a locked Unity cursor is a
   ClipCursor that Windows applies to the real pointer from any desktop (found by an earlier lane, see
   `DoomerfallQuiet.cs`). Doom reads the mouse, so Daggerfall loses nothing.

No UZDoom change, so stock `DOOM.WAD` E1M1 is unaffected.

## Known gaps

- If Daggerfall Unity shows an error dialog of its own (for example Unity's crash reporter), it is on the private
  desktop and nobody sees it. The launcher still ends Doom when Daggerfall's process exits. Use `--show-dfu` to see it.
- Doom still starts windowed (`+vid_fullscreen 0` in `play.bat`). Whether the game should start fullscreen is a design
  choice, asked below.

## Questions for the owner

- Should the game start fullscreen or windowed? `play.bat` passes `+vid_fullscreen 0`, so Doom starts in a window, and
  with this change Doom's window is the only one. Options: keep windowed by default; start fullscreen; or start
  windowed only on the very first launch and then use whatever Doom's own setting says (drop `+vid_fullscreen 0`, so
  the Options menu choice sticks in `run\uzdoom.ini`).

## Play-test list

Demo: `D:\dev\DoomDaggerfall-loop\review\cleanlaunch\play.bat` (a full play folder from this branch).

1. Double-click `play.bat` three or four times in a row (quit Doom between runs). Each time only Doom's window
   should appear, in front and focused, ending at Doom's title. No Daggerfall window, no flash, no fullscreen cover.
2. Judge the wait of about 7 to 10 s between the double-click and Doom's window. Is it OK, or should something show
   at once?
3. Choose New Game: the character creation screens and cinematics should still show inside Doom with Daggerfall's
   sound, and the mouse should stay free (not pinned to one spot) throughout.
4. Quit Doom from its menu: the whole game (Daggerfall too, check Task Manager) should end within a few seconds.
5. Check the Doom window's size and position on your monitor are sensible on a first start (delete
   `review\cleanlaunch\run` to repeat a first start).
