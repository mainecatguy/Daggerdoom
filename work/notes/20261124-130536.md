# Location state 1: stable place keys, and store only changes

Run 20261124-130536, branch `agent/locationledger-20261124-130536` (from `integration` at bbe7366, after the encounters
merge). Research: `work/notes/20261124-105104-location-state-research.md`, option C stages 1 and 2.

## Plan

1. **Place keys (F4).** Converter writes `place <map id> <building key>` into each interior's DDTOWN; dungeons already
   carry `mapid`. Doom derives each space's world-table slot and its visited-space name from these keys only. The space
   id and the `DDSxxxxx` map name stay session-only (cache file name, map name, transition target).
2. **Changes only (F6).** `Park` drops actors that something rebuilds identically: untouched seeded overworld monsters
   (as before, now actually working), untouched encounter mooks (tag 5), Daggerfall-listed NPCs and townspeople at full
   health (tags 6, 7), and map items still on their spot with their default amount (new tag 1 ids). Dungeons re-plan on
   every visit and spawn every mook that is neither dead nor present.
3. **Robust restores (F3).** Corpses store a death label (`Death`, `XDeath`, `Death.<type>`), never a state index.
   A row whose class is missing is logged and kept.
4. Prove it in a paired dungeon run and a standalone interior run, with a fake regrouping, and report save sizes.

## What changed

- `tools/dungeon_converter/SiteExport.cs`: `place` line in the interior DDTOWN; interior pickups seeded by map id plus
  building key (not the space id).
- `UZDoom/src/playsim/dd_treadmill.cpp`:
  - `Town::place`; `InteriorSlot`/`DungeonSlot`; `PlaceSpace` puts the space at a rectangle computed from the slot
    (20 bits of map id, 3+3 bits of block layout, 8 bits of record; dungeons bit 34). Interiors without a `place` line are
    refused with a log line.
  - `visitedSpaces` holds place names (`B<map>:<key>`, `D<map>`), not map names.
  - `AssignMapItemIds`: every item the map placed gets id `1<<61 | hash(class, world spot)` and a SpawnPoint, so a take
    becomes a tombstone and an untouched item is not stored.
  - `StartTown`: an actor the map placed is replaced only when the table has a row for its id; id-less monsters and
    spawners are still cleared on a revisit. `DD_MonstersEnterDungeon` now runs after the rows are restored.
  - `IsUnchanged` decides what `Park` may skip. Seeded overworld monsters now get a SpawnPoint (Spawn() left it at 0, so
    every seeded monster looked moved and was always stored).
  - Rows store a death label. `TABLE_FORMAT` 2 is written as `ddtableformat`; other formats are not loaded (logged).
  - The save logs `DDTM saved table: rows by kind, bytes`; leaving a map logs stored vs unchanged.
- `UZDoom/src/playsim/dd_towncache.cpp`: an interior cache file without a `place` line counts as unreadable and is
  rebuilt once (the cache has no converter version, so this is how stale interiors get the key).
- `UZDoom/src/dd_monsters.cpp`: every dungeon visit plans. The first visit's quest placements are kept per dungeon
  (`DungeonPlan`, saved as `ddplans`), so a revisit sends the same request and gets the same mooks on the same spots even
  after the quest foe died. Quest foes that appear later get a second pass, as before. A cleared dungeon (planned mook
  count all dead or present) is not planned again. During a revisit's planning, restored mooks are made non-solid so they
  do not push rebuilt mooks off their first-visit spots. Mooks get a SpawnPoint when spawned or claimed.

The route kills the quest foe and 9 more mooks, takes one loose item, moves another, drops a clip, autosaves, leaves and

although the quest foe was dead by then (its placement comes from the stored first request). The sorted signatures of

The baseline engine would have stored all 107 actors on leaving (every map-placed and planned monster was parked).
At about 85 bytes per text row, the 69 rows skipped are about 5.9 KB per visit of this small level-1 dungeon (estimate

## Findings

- Items a map marker spawns keep MF_DROPPED (Inventory.BeginPlay sets it; only map things clear it in
  `AActor::LevelSpawned`), so "dropped" cannot tell a player drop from a placed pickup. Map item ids are therefore given
  to every loose item present at map start, before rows are restored.
- With a bridge session, DoomerfallAmmo replaces placed plain ammo with a rolled `DFAmmo_*` item a few tics after map
  start. The plain item's map id becomes a tombstone and the replacement is stored as a dynamic row, so placed ammo in a
  real game is stored even when untouched (2 rows each). It is correct (the revisit removes the plain item and restores
  the rolled one) but not minimal. A follow-up could pass the map id to the replacement from DoomerfallAmmo
  (`ddRecordId` is not visible to ZScript today). Not done here.
- The dungeon in this harness (the packaged Privateer's Hold) places no map items; its loose items are Zombieman clip
  drops converted by DoomerfallAmmo, correctly stored as changes.
- Two tombstones appeared for the town in the standalone run (`DDTM left DDT07154: ... table rows 2` before any
  building). They are items with map ids that vanished in town, probably picked up while the harness parked the player
  at the door. Not investigated further; a tombstone for a vanished item is correct.
- The revisit hitch is now a full plan: 112 ms at area level 1 here. At area level 30 the encounter lane measured 0.5 to
  2.8 s for a first visit, so revisits now cost the same (see questions).
- Seeded overworld monsters never had a SpawnPoint (Spawn() leaves it at 0), so the existing "untouched seeded monsters
  are not stored" rule never applied. Fixed; not separately tested in an overworld run.
- Return points still name the town map (`DDT<group>`), which follows group order. Outside this card (interiors and
  dungeons); a regrouping of towns would also need it.

## Play-test list

- Clear part of a big dungeon, leave and come back several times: the untouched monsters should be the same classes in
  the same spots each time, and nothing you killed comes back.
- Kill a quest foe, leave, come back: the rest of the dungeon should look the same as before the kill.
- Notice the revisit hitch at a high area level (it is now the same as the first visit's).
- In a shop or house, take a pickup, kick another one along, drop something, leave and return, save and load: all of it
  stays as you left it.
- Walk past an overworld pack without engaging, leave the area and return: it should be back at its spot, unhurt.
- Townspeople you did not hurt are rebuilt by Daggerfall where Daggerfall says they are; check none duplicate or vanish
  when going in and out of buildings.
- A corpse killed by a special damage type (fire, extreme gib) should keep its death look after leaving and returning.
