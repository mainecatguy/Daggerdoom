# Run 20261122-061342: Daggerfall mesh layer, stage 1

Final results, commands, and the play-test list are in `work/notes/daggerfall-mesh-results.md`.

## Plan as executed

1. Export real models, placement, textures, and UVs from Daggerfall's data with the existing converter readers.
2. Draw them with one static vertex buffer, independent of Doom sector visibility.
3. Add F1 and `dfmesh_view`, then compare viewpoints, test popping, measure timing, and check E1M1.

## Decisions

- Skipped stock model actors. The whole dungeon is only 9,079 triangles in 81 batches, so drawing it all each frame is simpler and cannot depend on sector visibility.
- Set `pixelratio = 1.0` in the generated mesh package, because the default 1.2 stretch made the real mesh taller than Daggerfall's.

## Failed approaches and corrections

- First comparison scored the mesh worse than the collider. The causes were the 1.2 pixel stretch and the brightness difference.
- First timing run was invalid: `cl_capfps 1` capped every frame at 35 Hz (28.5 ms).
- First popping detector was too weak. Its control caught 2 of 31 injected disappearances. The block-average detector caught 78 of 78.
- `+logfile` adds its own `log-` prefix and `.txt`, so the first F1 check read no log and reported a false failure.
