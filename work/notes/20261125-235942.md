## Plan

1. Formula input: permanent Endurance -> live Endurance (`DoomerfallEndurance.Apply` and the `RollMaxHealth`
   override). Card 01's per-frame check already catches every change, so effects need no new hook.
2. Check that a live stat never passes through a transient value that would cost or gift HP (the per-frame check
   would clamp then raise current HP).
3. Text: design doc, manual, code comments; nothing may say the class bonus is the only way past 100.
4. Test: real Fortify Endurance and Drain Endurance spells through Daggerfall's effect manager, max HP up and down,
   Fortify expiry, Drain healed; paired run stock and DRLA with Doom following each step in order.

## Findings

- Live stats: `EntityEffectManager.UpdateEntityMods` rebuilds the mod arrays and assigns them in one call
  (`DaggerfallStats.AssignMods`), every 0.2 s. No frame sees half-cleared mods, so in play the per-frame check sees only
  real changes.
- **Load hazard (fixed).** The effect bundles are restored before `SaveLoadManager.OnLoad`, but their stat mods reach
  live Endurance only on the effect manager's next refresh (up to 0.2 s later; it does nothing during the load). Card
  01's `OnLoad` recompute would then use stale mods: a save at 120/150 with Fortify +20 would load as 120/130, then
  rise to 140/150, a free 20 HP on every load (and the reverse with Drain). Fix: `OnLoad` first calls the effect
  manager's `UpdateEntityMods` (made public, one marked word in `EntityEffectManager.cs`), then recomputes.
- The live clamp already uses `GetMaxPermanentValue(stat) + maxMods[stat]`, so anything that raises a stat maximum
  (an effect's max mod, or a future rule) already counts. Code and text now say the class bonus is the current way,
  not the only one.
- Drain Endurance is a live mod until healed (`DrainEffect`, incumbent), not a permanent loss, so it lowers max HP and
  healing it raises max HP (and current HP by the gain).
