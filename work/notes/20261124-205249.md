# No Doom pickups in houses (20261124-205249)

Goal: no generated Doom pickups (stimpack, clip, shells) in house interiors; dungeons and the outdoors keep theirs.

## Plan
1. Find where pickups are generated: `tools/dungeon_converter/PickupExport.cs`, called from `WriteMap` for dungeons
   (Program.cs) and for every building interior (SiteExport.cs). Nothing else places them.
2. Skip pickups in the interior converter when Daggerfall's building type is a house.
3. Prove it in a real paired run: a house has none; a shop and the dungeon still have some.

## What changed
- `PickupExport.cs`: `PickupsInBuilding(type)` is false for House1 to House6 and HouseForSale.
- `SiteExport.cs`: keeps the building type as the enum, and passes no pickup nodes to `WriteMap` for houses (prints
  `pickups: none in a house (House2)`). No engine or mod change. Dungeon conversion is untouched.
- **Shops, taverns, temples, guild halls, banks, palaces and every other non-house building keep pickups**, as before.
  This is asked in `questions`.
- `tools/housepickups/`: `housepickups.py` (build, survey, assemble, run house|shop|dungeon, wad) and `harness.zs`.

## Findings
- **Outdoors never had generated pickups.** The town converter (CityExport.cs) places none, before or after this
  change. Every run counted 0 generated pickups in town DDT07154. So "the outdoors still do" holds only in the sense
  that nothing changed outdoors. Asked in `questions` whether the outdoors should get them.
- Converter survey of every building in Gothway Garden (group 7154), this converter: House2 143 buildings / 0 pickups,
  House3 6 / 0, House5 13 / 0 (no usable interior anyway), GeneralStore 5 / 46, GuildHall 2 / 31, Tavern 3 / 34,
  Temple 2 / 11, Bank 1 / 8.
- Control: the previous converter (review\usekey\data\converter) puts 1 stimpack in house 8325696 (DDS4D0JK); this one
  puts none.
- Ammo pickups do not stay RLClip/RLShell in Doomerfall: the ammo tiers turn them into `DFAmmo_*` piles
  (`DFAMMO drop Shell tier 2`). The harness counts those too; my first shop run missed them.
- The Privateer's Hold wad in the recent review folders (usekey, doom-items data) has **0** pickup things; it predates
  the pickup feature. Demos built from that data show a dungeon without pickups. `assemble` here reconverts it (58).
- Cached interiors are not rebuilt: the town cache has no converter version check (already reported as an oversight),
  so a player or demo folder that already converted a house keeps its old pickups until that cache file is evicted
  or deleted. Fresh caches are correct.

## Verification (real paired runs, both games minimized via quiet_run, DRLA set unless noted)
`python tools/housepickups/housepickups.py run <mode>`, logs in `D:\dev\DoomDaggerfall-loop\review\housepickups\run`.
- house: interior converted on demand by this converter (`DDTCONV group=8325696 ok`), `HPCOUNT map=DDS4D0JK pickups=0`, pass.
- house --stock-mods (no DRLA): 0 pickups, pass.
- shop (general store 8325752): 1 pickup (a DFAmmo shell pile), pass.
- dungeon (Privateer's Hold, reconverted): 58 pickups, pass.
- Outdoors in town: 0 in every run (unchanged; none were ever generated).
- wad: DOOM.WAD E1M1 stock exit 0, no errors; with DRLA exit 0, 3 script errors that are DRLA's own (translation
  lump and DRLA Monsters menudefs), no fatal. No engine change in this work.
