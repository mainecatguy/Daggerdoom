## Contract (as built)

| Kind | Way | Meaning |
|---|---|---|
| `DOOR_USE` 190 | UZ to DF | Use on a door Doom holds as locked. `dfb_door.id` = LoadID |
| `DOOR_STATE` 191 | DF to UZ | One door: `state` unlocked/locked/magic, flags `OPEN` (open it now), `PICK` (start the minigame with `chance`), `LIST_BEGIN`/`LIST_END` (the full locked list) |
| `LOCKPICK` 192 | UZ to DF | The minigame result, `state` = `PICK_MISS`/`HIT`/`CANCEL` |
| `DOORS_REQUEST` 193 | UZ to DF | Send the locked list again (new dungeon space on Doom's side, or after a load) |
| `DOOR_TEXT` 194 | DF to UZ | Daggerfall's message about a door (`dfb_info_text`, split like `INFO_TEXT`) |

The look label uses the existing `DFB_KIND_LOOK` with a new target `DFB_INFO_DOOR` (id = LoadID). Daggerfall answers
with `DoomerfallLocks.Label`: "Locked.", the magic lock text, or "Door". Doom forgets a door's cached label whenever a
`DOOR_STATE` names it.

Flow: the mod's `DFDoor.TryUse` on a door with `lockState != 0` sends `dfdoor_use:<id>:<state>`. `dd_doors.cpp` turns
it into `DOOR_USE`. Daggerfall (`DoomerfallDoors.OnUse`) looks up the live `DaggerfallActionDoor`:

- unlocked (Doom was stale): `DOOR_STATE` with `OPEN`, and the list is sent again;
- magically held: Daggerfall's `magicLock` text;
- locked, no picks: "Locked. You have no lockpicks." The door stays shut;
- locked, with picks: `DOOR_STATE` with `PICK` and Daggerfall's interior chance. The engine turns it into
  `dflp_start:<chance>:<id>`, which the first run's minigame already accepts.

The minigame's `dflp_result:<id>:<hit|miss|cancel>` becomes `LOCKPICK`. Daggerfall accepts it only for the door it
started the minigame on, then runs `DoomerfallLocks.ApplyAttempt`: one Lockpicking tally, `CurrentLockValue = 0` on a
hit, one broken pick on a miss, and no `FailedSkillLevel` (the owner's retry rule). It shows `lockpickingSuccess` or
`lockpickingFailure` and opens the door on a hit. A cancel costs nothing and tallies nothing.

Locked list: `DoomerfallDoors.Update` polls every 0.5 s while the player is in a dungeon that matches Doom's space. It
hashes the locked and magic doors (LoadID, state) and sends the whole list when the hash changes, when Doom asks, and
after every Daggerfall load (`LoadRunning` clears the hash). The mod's `DFDoorHandler` takes `dfdoor_clear` (list
begin: every door unlocked), then one `dfdoor_lock:<id>:<state>` per locked door. Daggerfall's own save keeps
`CurrentLockValue`, so a reload sends the restored list.

`DoomerfallLocks.Find` now searches the current dungeon or interior with inactive objects included, because
Doomerfall hides Daggerfall's 3D world (`FindObjectsOfType` skips inactive objects).

## Engine change scope

- `dd_doors.cpp` and the hooks in `dd_bridge.cpp`, `dd_info.cpp` (`DD_InfoShow`) and `dd_look.cpp` act only in a bridge
  session. `d_net.cpp` already passes a network event to the bridge only when a session exists. Without one,
  `dfdoor_use` and `dflp_result` still reach ZScript as before.
- `door_objects.zs` exists only in converted maps and `ddruntime.pk3`. Without Daggerfall's events every door behaves as
  before.
