# Piles, containers, and trade through Daggerfall's windows

## Plan

1. Use on a loot pile opens Daggerfall's real loot window inside Doom, instead of taking everything.
2. The same route for furniture containers (house containers, shop shelves), which have no sprite in Doom.
3. Shop shelves open Daggerfall's trade window (Buy), because that is what `PlayerActivate` does.
4. Keep the ledger correct for whatever the window did (part taken, items added, bought, restocked).
5. NPC trade (talk to the shopkeeper, Sell) only if stationary NPCs make it cheap. Otherwise report.

## Design

The route is Daggerfall's own activation, end to end:

1. Doom's Use (or Interact) picks the pile or container in view and sends the existing take request (kind 43).
2. Daggerfall checks the reach and answers with a new status, `DFB_ITEM_WINDOW`, and remembers the container for 3 s.
3. Doom opens a new menu id, `DFB_UI_LOOT`, through the same path as the inventory (pauses Doom, shows the surface, forwards input).
4. Daggerfall's `DoomerfallUi.OnOpen` calls `PlayerActivate.DoomerfallActivateLoot`, a three-line public wrapper around
   Daggerfall Unity's private `ActivateLootContainer`. So every container type behaves exactly as in Daggerfall:
   piles and monster drops open the loot window, shop shelves stock and open the trade window when the shop is open
   (closed shop: the stealing inventory), house containers stock and ask the private property question, owned houses open directly.
5. When the window closes, Daggerfall writes the container's current contents (and, for furniture, its stocked date) to the ledger.

Furniture containers are map geometry in Doom, so Daggerfall sends their space-local bounding box in a new message,
`DFB_KIND_CONTAINER` (80), inside the normal item list. ZScript keeps an invisible `DoomerfallWorldContainer` per box,
removed by list generation like piles. `DD_UsePress` casts the view ray against the boxes (and a second ray 20 degrees lower
for low chests, the same idea as the floor rule for items), and a `P_LineTrace` hides boxes behind walls.

The old take-everything code (`Take`, `TakeItem`, `CanHold`, the weight test) is gone. Daggerfall's window does transfers,
weight, gold, maps, and quest items with its own code now, which is the project rule.

Bridge: `DFB_ITEM_WINDOW` 5, `DFB_UI_LOOT` 5, `DFB_KIND_CONTAINER` 80, struct `dfb_world_container`.

## Corpses

Real Daggerfall `CorpseMarker` containers come from Daggerfall's own enemies, which do not exist in a bridge session.
A Doom monster's death becomes a `DroppedLoot` pile (DoomerfallMonsters), so "corpses" are piles here and use the pile route.
`CorpseMarker` is listed too, in case one ever exists.
