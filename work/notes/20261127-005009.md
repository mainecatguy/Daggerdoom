# Dungeon support, continuation (run 20261127-005009)

Follows `work/notes/20261126-235852.md`. What broke: dungeons other than Privateer's Hold were never supported in the
play build, from `3abf92dc` on. Runtime dungeon conversion in d83df44b/663f9ade fixed it. This run handled the three
verifier asks and found and fixed one more bug (New Game and load wait, below).

## Result

- Every one of the 19 Daggerfall dungeon types now has a passing paired entry, in both real games, through the real
  town door and back out. 9 of those were converted by the running game at the door press. No run printed
  "not available yet".
- Tilted doors: no dungeon is refused (details below).
- New Game and plain load into an unconverted dungeon **never** entered, because the wait never requested the
  conversion. Fixed in `820a3daa` and shown working in paired runs.

Harness fixes along the way (tools only):
- The game's date is winter, so the town cache reads `T<group>W.ddt` (`dd_towncache.cpp` `FileFor`). The harness
  cached towns under the summer name, so the game reconverted the town before the dungeon. That doubled the wait
  and made 552 time out. The harness now caches the winter town.
- The door wait went from 40 s to 90 s. On this loaded machine the converter, which runs at `BELOW_NORMAL` priority,
  took 13 to 27 s in game for one dungeon, and standalone 18 to 36 s (the previous run measured 7 to 11 s).
- The harness now picks the lowest dungeon door.

Greensmith Tower (1457): all 13 of its dungeon door planes are at z 198.5 or 392, on the upper floors of the ruin model.
The harness places the player at the door and the player drops out of `CanUse`'s height reach. No "Opening..." and no
refusal is printed, so this is not the "not supported" bug. Whether a real player can climb to those doors is
unchecked (play-test item 3). It is reported as a suspected oversight.

## (2) Tilted doors

`tools/runtime_dungeons/tilted_doors.py` (new) wraps `--list-tilted-doors`. RDB blocks hold 2,475 door objects; 8 have
X/Z rotation, in 5 blocks, used by 4 dungeons: 3 HumanStronghold (Daggerfall, Woodborne Hall, Wayrest) and Mantellan
Crux. Each of the 8 has an X or Z rotation of 180 or 360 degrees. That keeps the door upright or flips it upside
down, which MeshExport accepts (`|up.Y| < 0.999`). I converted all 4 with `runtime_dungeon_check.py --only ...` and
none was refused. Three have 6 or 7 exits; Mantellan Crux has none, as expected. **No dungeon is affected.**

## (3) New Game and plain load wait for conversion

**Bug found:** `DDTreadmill_Tick` handles a New Game or plain load into a dungeon (`dungeonRequest`, from
`dd_bridge.cpp`). When the dungeon was not converted, it set the request again and **returned**, which skipped
`TickTownDoors`, the only code that asks the town cache for the dungeon's group. Nothing ever started the
conversion, so the player stood at the entrance forever. Shown before the fix: New Game reached "at the entrance in
DDT07154, going inside dungeon 187853213", then ran 60 s with no conversion started. This came in with d83df44b,
which added the runtime wait. Play builds have not hit it, because Privateer's Hold is prebuilt. Any save inside
another dungeon, loaded with an empty cache (for example on a new install), would have.

**Fix** (`820a3daa`, one line in `dd_treadmill.cpp`): the wait branch requests the dungeon's cache group itself.

**Shown** with `tools/runtime_dungeons/stage_wait.py` (new). It stages `review\dungeon-wait` with empty stand-ins for
the Privateer's Hold packages, so Privateer's Hold converts at runtime like any dungeon:
- New Game (`python quiet_run.py -- python tools/new_game/run_new_game.py create --review <dungeon-wait> --drla --inside-quiet --wait-df "Daggerfall is in dungeon"`):
  at the entrance at 209354.0. "Doom is inside the dungeon on DDSHCYJH" at 209368.8, 0.0 units from Daggerfall's
  start point. Daggerfall reports "Daggerfall is in dungeon Privateer's Hold". Result: reached.
- Plain load of a Daggerfall save inside Privateer's Hold (bundle from `review\arrival-spawn`), after deleting the
  dungeon from the cache: at the entrance at 209450.1, inside at 209471.7, 0.0 units from the save. Result: reached.
- The New Game arrival line says "0 monsters on the map" at the moment of arrival. It was not compared with a
  prebuilt New Game; play-test item 1.
