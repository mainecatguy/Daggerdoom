# Dropped ammo looks like ammo (20261126-201527)

## Goal

Owner (2026-11-26): "dropped ammo should look like ammo". Bullets dropped from Daggerfall's inventory look like
bullets, and Daggerfall remembers them; a pile that also holds other things uses the loot pile graphic. Decision:
`gamedesign/decisions/20261126-ammo-pile-look-owner.md`.

## What was there

- A dropped pile is a `DaggerfallLoot` (customDrop, DroppedLoot). `DoomerfallPiles` already keeps every dropped pile in
  the location record (contents, position, texture) and puts it back after leaving and after a load.
  `DoomerfallItems` lists each pile to Doom as `dfi_item` with Daggerfall's texture archive and record, and
  `DoomerfallWorldItem.Show` (DoomerfallItems.zs) draws the `DP<archive><record>` picture from the sprite package.
- Finding: the pile itself never used the Letter of Credit picture. A window drop makes a pile with Daggerfall's
  random treasure icon (archive 216). The Letter of Credit (209:7) is only the ammo item templates' world/inventory
  placeholder (`DoomerfallAmmo.cs`), and the inventory shows Doom's sprite instead once Doom sends it. Either way,
  ammo piles did not look like ammo.

## Plan and design

1. **The look follows the contents.** `DoomerfallAmmoPileArt.TryGet` (new, Daggerfall side): a dropped pile whose items
   are all one ammo type (any tiers) gets the art code archive 9100, record = type (0 bullets, 1 shells, 2 rockets,
   3 cells), plus 4 when it holds at least a Doom box's worth (50, 20, 5, 100: stock Doom's box sizes). Any other pile
   keeps its own texture: the loot pile picture.
   - Why not change the pile's stored texture: deriving it means the location record and Daggerfall's save need
     nothing new, a pile that comes back after leaving or loading looks the same because it holds the same things,
     and dropping a sword onto a bullet pile turns it into a loot pile (and taking the sword back turns it into
     bullets again) with no bookkeeping.
2. `DoomerfallItems.cs` sends that code (and size 0, so Doom uses the sprite's own size) and hashes it, so a change
   of look resends the row.
3. Doom side (`DoomerfallItems.zs`): `Show` draws Doom's own pickup sprite for the code: CLIPA0, SHELA0, ROCKA0,
   CELLA0, or the boxes AMMOA0, SBOXA0, BROKA0, CELPA0. DRLA's ammo pickups (RLClip, RLShell, RLRocketAmmo, RLCell)
   use these same sprites (DoomRL_Arsenal actors/misc/Ammo.txt), so this is the pickup look with or without DRLA.
   Falls back to the old picture if a sprite is missing.
4. Test: `-dfammopiletest` (`DoomerfallAmmoPileTest.cs`, one hook line in `DoomerfallBridge`) and
   `tools/ammo_pile/` (route, harness, own build trees).

Judgment calls (constrained, within the owner's decision):
- The box sprite for a big pile. The owner asked for "looks like that ammo"; a box of bullets is still bullets.
- Mixed tiers of one type still count as one ammo type (all bullets).
- Only player-dropped piles (customDrop, DroppedLoot) change. Corpses and treasure keep their pictures.

## Engine changes

None. Only Daggerfall Unity C# and the doomerfall mod's ZScript. The ZScript path runs only for rows the bridge sends
with archive 9100, so stock and DRLA E1M1 are untouched.

## Play-test list

- Drop some bullets from the inventory and close it: the pile on the floor is a clip. Drop 50 or more: a box of bullets.
  Do the same with shells, rockets, and cells.
- Drop bullets and a sword together: the pile shows the loot sack picture.
- Open a bullet pile, put a ring in it, close: it becomes a loot sack. Take the ring back: it is a clip again.
- Leave the dungeon and come back, and save and load: the piles look the same and hold the same amounts.
- Ammo tier tints (Silver bullets etc.) show only in the inventory. The floor sprite is untinted (known gap).
