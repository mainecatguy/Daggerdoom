# QA bot 1: core channel, replay, and Privateer's Hold from the start to the exit

Read D:\dev\DoomDaggerfall\AGENTS.md first. The design is `work/notes/20261124-120622-qa-bot.md`; the prototype is
`UZDoom/src/dd_qa.cpp`, `tools/qa/qa.py` and `tools/qa/nav.py`.

**Overnight only.** The pilot run is long: run it only in an overnight lane between 2AM and 7AM. Building and short
checks (under a minute of game time) may run at any time.

## Goal
A Claude agent, using only `qa.py`, walks a fresh New Game character from Privateer's Hold's start room to the exit
and out into Gothway Garden, honestly (no teleport), and the run can be replayed as a regression test.

## What to build
- `qa.py start --newgame`: the real New Game flow (reuse `tools/new_game/run_new_game.py`'s window driving) so the
  run starts where Daggerfall starts (Enter marker), not at the door.
- Doors and exits in `actors` (or a new `doors` command): the converter's door list and the dungeon exit, with
  open/closed state. `goto` presses Use before crossing a door link.
- `path_to exit` and `path_to <df id>` in `qa.py`, planned with `nav.py` over the points file produced with the same
  WAD the session plays (make `assemble` copy it next to the WAD).
- Stuck recovery: when `move_to` reports `stuck`, back off, re-plan from the current spot, and report it.
- An events digest in every reply (damage taken, kills, pauses since the last call), and a `died` event.
- Run summary: `qa.py summary` lists honest jobs, setup commands used, and whether the run is a valid completability
  claim (no setup movement between start and end).
- Replay: `qa.py replay <outbox>` feeds a recorded inbox back, waits for each job, and compares outcomes (job results,
  final positions within 32 units, maps entered).

## What must stay true
- Nothing happens without `-ddqa`. The engine hooks stay one line each.
- No world change from between tics: every command still runs inside the tic.

## How to prove it
- The pilot run: Privateer's Hold start to exit with god mode on (setup is allowed for survival, not for movement).
  Record calls used, tokens if visible, game seconds, and every `stuck`.
- Replay the recorded run once and get the same outcomes.
- Normal play check: a paired session without `-ddqa` behaves as before (startup check exit 1337 and one short
  scripted harness run, such as `tools/npc_kill/npckill.py run`).
