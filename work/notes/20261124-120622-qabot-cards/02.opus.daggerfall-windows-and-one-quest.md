## Goal
The bot can read any open Daggerfall window as text and answer it (pick a choice, type text), and completes one real
quest end to end.

## What to build
- `DoomerfallQa.cs` (its own file; one-line hook in `DoomerfallBridge`), active only with Daggerfall's `-ddqa <folder>`:
  writes `<folder>/df_window.json` when the top window changes and on request: window class, text components with
  native 320x200 rectangles, list items, buttons with rectangles and names, and the text box.
- Adapters for message boxes, quest popups and yes/no questions, talk (topics), shops/trade, inventory, loot, travel
  map, rest, and text input. Each gives `{"window":..., "text":..., "choices":[...]}`.
- Answers go through `DoomerfallInput` (the path Doom's mouse and keys use): `choose <n|label>`, `type <text>`,
  `press <key>`.
- Read-only Daggerfall queries through the same folder: `inventory`, `quests` (active quests and their current
  messages), `journal`, `stats` (HP, fatigue, level, gold).
- A QA god mode on Daggerfall's side too (Daggerfall owns HP and death), so `god` holds across both engines.
- Events: `window`, `quest_message`, `died`.

## What must stay true
- No change to `bridge/doomerfall_bridge.h` unless the file route proves impossible (kinds 210-219 are reserved for
  that case). A layout hash change breaks every other lane's test folder.
- Nothing runs without `-ddqa` on each side.

## How to prove it
- Short checks: read and answer the `_TUTOR__` question after a New Game, a shop window, and a talk window.
- Pilot: `C0B00Y03` (The Missing Scholar) from accepting it to the reward, honestly except for god mode. Record the
  call count.
