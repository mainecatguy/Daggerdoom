# Doom's map command opens Daggerfall's map

Branch `agent/map-20261123-165110`. Demo: `D:\dev\DoomDaggerfall-loop\review\daggerfall-map\play.bat`. It starts in Gothway Garden, beside houses and the Privateer's Hold entrance. Tab is the map command.

## Result

| Where the player is | What the map command opens | Real-game result |
|---|---|---|
| Town | `DaggerfallExteriorAutomapWindow` | Daggerfall city draws its street and building layout |
| Building | `DaggerfallAutomapWindow` | A tavern draws its revealed room geometry |
| Dungeon | `DaggerfallAutomapWindow` | Privateer's Hold opens, but **no geometry is revealed** (see Known gaps) |
| Wilderness | `DaggerfallTravelMapWindow` | Draws the region map |
| Small dungeon location, outdoors | `DaggerfallExteriorAutomapWindow` | Privateer's Hold surface opens with almost nothing to draw |
| Regular Doom map | Doom's automap | Opened and closed on MAP01 in a bridge session |

Daggerfall has no wilderness automap, and its own map key does nothing there. The travel map is its only real map for that case, so it is the judgment call here. It follows the normal fast travel rules and can start a trip.

## How it works

- `togglemap` remains the bindable command. On a Daggerfall map in a bridge session it opens menu `DFB_UI_MAP` through the shared menu path. The key bound to it also closes the menu.
- Doom sends its area in the existing padding field of the UI command, so the bridge layout and protocol do not change.
- Daggerfall refuses if its area differs from Doom's, or if the town at this map pixel has not loaded. The map therefore cannot show a stale place.
- When Daggerfall reports a fast travel arrival, Doom closes its own map and leaves the collider view.
- The test-only `dd_ui_test_doommap` CVAR opens Doom's map on a Daggerfall map, because the normal command no longer can.

## Proven with the real games

Tool: `tools/daggerfall_map/run_map.py`. Both games ran minimized, with a private config and a 30-second limit.

- **Open and close:** town, wilderness, building, and dungeon each opened through the real command and closed with a key bound to `togglemap`.
- **Doom paused:** `maptime` was identical before and after each open (for example 410 and 410 in town).
- **Fast travel with the collider view on:** the route opened the wilderness map with `togglemap`, travelled to Agakawan, and logged `left collider view 1`.
- **Fast travel with Doom's map open:** the route logged `closed Doom's map 1` and reached Agakawan.
- **Stock Doom:** `DOOM.WAD` E1M1 with `togglemap` ran clean with no bridge lines.
- **DRLA set:** 3 script errors and 763 unknown-class lines, the same as the previous build.
- **Plain Daggerfall:** no bridge activity and no exceptions. It was stopped by the 12-second test limit (exit 124).
- **Registry:** the fingerprint of all 13 values in the owner's Daggerfall Unity key matched before and after the main test suite.
- **Demo:** `play.bat`'s real command, run minimized from a private folder, brought both games live.

## Known gaps

- **The dungeon map is blank in the test.** The window, player marker, and controls appear, but no rooms are revealed. Daggerfall reveals geometry with raycasts from its hidden player. I did not prove why they reveal nothing at the Privateer's Hold landing. Re-test after the position sync task lands. I did not force a reveal, because that would change how the map plays.
- **The player's marker indoors** may be wrong until the position sync task lands, as expected.
- **Physical keys and real mouse mapping** are not proven. Tests use the console command and posted window messages.
- **Automap controls** such as rotate, zoom, and view modes were not exercised.
- **Frame rate:** the building and dungeon runs delivered far fewer frames (22 and 13 in about 2.5 seconds) than the town run (145). Both games were minimized, so this needs a visible check.
- **A slow Daggerfall frame during travel** can trip Doom's heartbeat check and close the menu just before arrival. It happened once and the trip still completed. This behavior predates this work.

## Failed approaches

- The first regular-map test never fired, because Daggerfall stays out of its play phase on a non-Daggerfall map. The test now sends the real console command.
- The first travel runs reported a failed town conversion. The test's time limit had killed the converter mid-run. Seeding the private test cache with the converted town fixed it.
