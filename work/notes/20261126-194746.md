## 1. One frozen tic after setup is done

`dd_bridge.cpp`, `PumpArrival`: once the setup gate is ready on a frozen arrival (`arrivalFrozenTics > 0`, not the
handoff path), the bridge notes `gametic` (`arrivalReadyTic`) and ends the freeze only after a later tic has run. The
spawn happens in a tic (`DD_MonstersTick` from `DDTreadmill_Tick`), and `PumpArrival` runs once per frame between tics,
so this keeps exactly one more frozen tic (~28 ms) with the monsters present. `arrivalReadyTic` resets in
`DD_BridgeArrivalAutosave`. An arrival whose setup was done before any frozen tic is unchanged. Without a bridge
session nothing changes (`PumpArrival` returns on `!arrivalPending`).

`run_freeze.py`: normal now uses the same check as slow/nosave/use, `monsters == 73` (seen on a frozen frame and
unchanged), instead of `monsters + spawned == 73`. That is stricter.
