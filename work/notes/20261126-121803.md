# Rest in Doom, continue (20261126-121803)

The previous run's fix for the rest key (a2cd8b1c) was incomplete, and this run's first notes wrongly treated it as done.
The verifier found the gap.

## What was wrong

Doom sends a close request on every rest-key press while the rest menu is open. `DoomerfallUi.OnClose` handed it to the
rest window only while the rest window itself was on top. Once `EndRest` had shown its message ("you wake up", "you are
healed", "finished loitering" and so on), the message box was on top, so the next press fell through to `PopToHUD`.
`PopToHUD` pops windows without raising their `OnClose`, so `RestFinishedPopup_OnClose`, and with it `RaiseSkills`, never
ran: no skill check, no level-up sheet, no HUD line. The same fall-through popped a running rest with no `EndRest` at all
when another popup (a quest message, for example) covered the rest window.

## Fix

- `DoomerfallUi` keeps the rest window it opened (`restWindow`, taken when the menu opens and cleared in `Finish`). Any
  rest-key press while the rest menu is open goes to `DaggerfallRestWindow.DoomerfallRestKey` (replaces
  `DoomerfallEndRest`). That method decides:
  - selection screen, no rest started yet (the hours prompt and the illegal-rest warning included): returns false, and
    the menu closes outright as before;
  - rest or loiter running with the rest window on top: Daggerfall's own `EndRest` (wake-up message);
  - rest ended and its end-of-rest message on top: `CloseWindow()` on that message, as a click does, so its `OnClose`
    runs `RaiseSkills` (level-up sheet, then the HUD line);
  - anything else (another popup over a running rest, or the level-up sheet after the rest): the key does nothing.
    The player closes that window normally.
- `tools/rest/rest.py run stop` now presses Z a second time on the wake-up message, instead of clicking it, and still
  requires the level-up sheet, the HUD line and matching HP.
