# Tab tween menu (2026-11-27, agent/tabmenu-20261127-170741)

## What was built

- **Generated resource.** `mods/doomerfall/skyrimui/tweenmenu.swf` (copied, not moved, from
  `GameMods/SkyrimUi-60FPS/interface/`; committed by the owner's exception, noted in `art/README.md` and the folder's
  README). `scripts/doomerfall/build_pk3.py` runs `tools/skyrim_ui/convert.py` for every SWF in `skyrimui/menus.txt`
  and writes into the pk3: one PNG per vector shape (`graphics/skyrimui/tweenmenu/S<id>.png`, rasterised with Pillow at
  2x stage scale, 4x supersampled, gradients included) and `skyrimui/tweenmenu.txt`, the display list of every frame
  of every sprite. ~1.6 s per build. Every pk3 build (install.py, demos) carries it.
- **Doom side, generic.** `zscript/DoomerfallSwfMenu.zs` (`DDSwfMovie`) loads that lump and draws the SWF's tree with
  its own matrices, alpha and colour multipliers and frames (60 fps playheads per instance name), text fields with
  Doom's NewSmallFont ("$KEY" -> LANGUAGE `SKYUI_KEY`), and gives hit rectangles of named instances.
- **Tween menu.** `zscript/DoomerfallTweenMenu.zs`: what the SWF's ActionScript did. Open plays the SWF's
  `startExpand` frames (2-10) and the bottom bar slide; close (Tab/Escape) plays 11-19. `Selections_mc` frames by
  label for the highlight. Mouse hover highlights via the SWF's own `*InputRect` instances; click (on release), Enter,
  E, or the same direction twice opens. Up Character sheet, left Magic (spellbook), right Inventory, down Map.
  The level number on the bottom bar is Daggerfall's (`DD_SheetValue(DFB_SHEET_LEVEL)`); the date text and XP bar are
  hidden (no data). The choice runs the same command as the window's own control (`netevent df_character`,
  `df_spellbook`, `df_inventory`, new `df_map`), so the bridge opens the window exactly as the keys do.
- **Engine (bridge only, `dd_bridge.cpp`).** In a bridge session on a Daggerfall map, `togglemap` (Doom's Automap
  control, Tab) opens `DoomerfallTweenMenu` instead of Daggerfall's map (falls back to the map when the mod is not
  loaded). New `netevent df_map` opens Daggerfall's map directly (or Doom's automap on a regular map); the UI test id
  for the map now uses it. A key bound to togglemap also closes any window Doom opened, so Tab backs out of the window
  the menu opened. Non-bridge launches: unchanged (DD_BridgeToggleMap returns false without a session).
- New control "Open Map" in Doomerfall Controls, unbound by default. Manual: one line.

## Design calls (engineering, owner may revisit)

- Labels CHARACTER / MAGIC / INVENTORY / MAP (Skyrim's SKILLS/ITEMS renamed to the Daggerfall windows they open), in
  `LANGUAGE.txt`.
- Converting to native PNGs + data instead of playing the SWF: no Flash runtime in Doom; the same PNG+lump output can
  feed Daggerfall-side menus later (`skyrimify-ui`). ActionScript is not converted; each menu gets a ZScript class.
- Choosing opens the window at once (no close animation); Tab/Escape on the menu plays the 150 ms close animation.
- Closing a window opened from the menu returns to the game, not the menu (Skyrim does the same).

## Failed approaches / findings

- `Play` is a ZScript keyword (renamed to `PlayFrames`).
- Unnamed child sprites first read the root's playhead, so only named parts drew. Fixed (`InstanceFrame`).
- ZScript may run a console command only from a menu's event or draw call (DMenu::InMenu); not Ticker.
- Posted WM_KEYDOWN reaches Doom only while a menu is open (gameplay keys use raw input), and Doom's +logfile is
  written only at exit, so the paired test presses Tab through a test-only pk3 (`tools/tween_menu/testmod`, never
  shipped) and follows the bridge log, where the engine now logs `ui: tween menu opened`.
- Doom keeps running the Daggerfall clock while any Doom menu is open (same as the Escape menu); not changed.
