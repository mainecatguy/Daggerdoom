# Doom drops must be deterministic

Branch `agent/fixeddrops-20261124-232246`. Goal: the same place gives the same Doom drops and gun materials to every
character, and across save and load, for any mod, without editing mods, and stock outside Doomerfall sessions.

## Approach

Doom's drops (DropItem lists, a mod's drop helper actors such as DRLA's `RL...Drop`, `A_DropItem` chances,
`RandomSpawner` picks, death-state `A_Jump`s) all draw from Doom's shared gameplay random streams. Their state depends
on everything else that happened, so the same monster drops differently in every game. Seeding each mod's drop code is
impossible without editing mods, so the engine gives each loot roll its own random state instead:

1. `m_random.h`: `FRandom::GenRand32` draws from `*DD_RngOverride` while it is set (gameplay streams only; client
   `FCRandom` streams such as sounds are untouched). Null outside Doomerfall, so stock draws are unchanged.
2. `AActor` gets `ddLootRng` (the running state) and `ddLootId` (the first value; it names a drop). Both are saved, and
   written only when nonzero.
3. `DDLootScope` (`dd_lootrng.h`) sets the override to an actor's `ddLootRng` around: `CallDie`, every state action
   (`FState::CallAction`) and `CallPostBeginPlay`. It does nothing for actors without a loot state.
4. Seeds:
   - A monster with a Daggerfall id (`ddRecordId`) gets `ddLootRng` from that id when it starts dying (`DD_LootDied`).
     The id already holds the place (placement hash: map, block, marker, record) and pack member.
   - Anything spawned during a roll that is not a monster, missile or player (dropped items, drop helpers, spawners,
     gibs) gets its own state (`DD_LootInherit`, in `StaticSpawn`), from the owner's loot id, the child's class and how
     many of that class the owner has spawned. Not from the owner's stream position: the first version did that, and one
     Elite Former Human's drop ids changed after a load (see Failed approaches).
   - Encounter mooks (`SpawnMook`) and overworld seed monsters spawn under a state from their id, so a mod's random
     spawner standing in for them (DRLA's variant spawners) picks the same variant, and so the same drop table.
   - Map things on maps loaded in a bridge session spawn under a state from map name, thing index, type and spot, so a
     map-placed `RandomSpawner` (DRLA's `RLClipSpawner`, which can give a pistol) picks the same item every game.
   - `AActor::Revive` clears the state, so a raised monster's AI is stock again.
5. Living monsters, players and missiles never carry a loot state, so combat and AI randomness are unchanged. Odds and
   tables are unchanged; only which random numbers they read changes.

### Daggerfall side (gun material)

- New bridge kind `DFB_KIND_DOOM_ITEM_ID` (147, payload `dfb_item_take`): Doom sends the floor item's lasting id just
  before `DOOM_ITEM_TAKE`. Lasting id (`DD_LootItemId`): the treadmill id if it has one (map items: class + world spot),
  else `DYNAMIC_BIT | ddLootId` for a drop from a seeded roll, else none. The treadmill's `Park` now records a seeded drop
  under that same id instead of a session counter, so a drop picked up after leaving and returning has the same id.
- `DoomerfallDoomItems.OnTake` seeds the material roll with `LootSeed.Of(DoomFloorItem, class, id)` inside
  `LootSeed.Scope`. Without an id it rolls freely, as before. Daggerfall still owns the rule and the odds.
- Starter guns (Doom's new-game gun adopted by Daggerfall, and the plain-load pistol) are seeded from their class
  (`LootSeed.DoomStarterGun`), so every new character's starter gun has the same material at a given area level.
  The open question whether they should be fixed at Iron is unchanged; this only makes the current rule repeatable.

### Tiered ammo

`DoomerfallAmmo.zs` rolled a dropped ammo pickup's tier from where it spawned, which is where the monster happened to
die. It now uses the pickup's engine loot seed (`Actor.DD_LootSeed()`, new native) when it has one, so a dropped clip has
the same tier wherever the monster died. Pickups without a seed keep the old map-and-spot roll.

| Doom gun material at pickup (Daggerfall) | floor item's lasting id + class |
| Starter gun material (Daggerfall) | gun class |
| Daggerfall-rolled drops from slain Doom enemies | already seeded (`LootSeed`, run 20261123-233755) |

## Known gaps

- A corpse saved halfway through its death sequence restarts its per-class child count after the load, so a later child
  could share an earlier child's seed. Its own stream state is saved; only the child counts are not.
- The monster's own drop-list rolls (`A_NoBlocking`) still read its stream after whatever its death states drew first.
  If a mod's death branch depends on live state (a token given at spawn, a target), the draw count before the drop list
  can differ and change those rolls. Not seen in the test (classes always matched), but possible.
- Monsters without a Daggerfall id (session-only overworld monsters with dynamic ids, monsters a mod spawns mid-fight)
  are seeded only if they have an id; dynamic ids differ between games.
- Bridge layout hash changed (new constant), so old launchers, DLLs and test folders must be rebuilt.
- Drops land where the monster died, which still varies.

## Failed approaches

- First version derived each child's seed from one step of the owner's stream. In the load run one
  RLEliteHumanBattleRifle2's two drops got different ids (same classes), because its death drew a different count of
  numbers before spawning them. Fixed by keying children by owner id, class and per-class index.

## Play-test list

1. Two new characters: clear the three gunners at the Privateer's Hold entrance in each. Same guns and ammo drop, and a
   taken gun has the same material in both games.
2. Save before the fight, clear the entrance, note the drops and materials, load, clear again: the same.
3. Leave a dropped gun on the floor, leave the dungeon, come back, take it: same material as taking it at once would give.
4. Plain DOOM.WAD and DRLA without Daggerfall: drops still random between games, as stock.
