# Shop levels 2: shop shelves roll at the shop's level (run 20261127-103953)

Goal: everything a shop shelf rolls (weapon and armor material, magic items, modded weapons and armor) uses the
shop's level (card 01, `DoomerfallShopLevels`) instead of the map pixel's area level. Design:
`work/notes/20261124-124736-shop-levels.md`.

## Decisions (engineering calls)

- **Only one restock path exists.** `StockShopShelf` is called only from `ActivateLootContainer` (Doom's Use reaches
  it through `PlayerActivate` line ~969, the Doomerfall container entry) and from test files. So the one-line `using`
  in `PlayerActivate` covers every real restock. No other Doomerfall path restocks shelves (`DoomerfallItems` only
  restores saved shelf contents and `stockedDate`).
- **Lookup:** the provider finds the building's `BuildingSummary` in the current location's `BuildingDirectory`
  (`StreamingWorld.GetCurrentBuildingDirectory()`, the same call Doomerfall's Info path uses) by
  `BuildingDiscoveryData.buildingKey`, then `DoomerfallShopLevels.ForShop(directory.LocationData, summary)`.
- **Unknown shop -> 0 -> area level.** If the directory or summary is missing, or the shop table failed, the provider
  returns 0, `WorldLevel.Scope` does nothing, and the shelf rolls at the area level exactly as before. The log line
  says "(area level used)".
- **Shop ammo** runs inside the same scope (it is the last call of `StockShopShelf`), so `WorldLevel.Current` is the
  shop level there; its odds do not read it. One-line pointer left in `DoomerfallAmmoTiers.StockShop`.
- **Logging:** each restock writes one line to the bridge log file (`-dfbridgelog`): "shop restock: NAME (TYPE,
  quality Q) in REGION / TOWN at shop level N". Nothing reaches the screen.
- `-dfarealevel N` (the area level test override) does not override shop levels: they are a different table.
