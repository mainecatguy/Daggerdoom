# Shop levels 2: shop shelves roll at the shop's level (run 20261127-103953)

Goal: everything a shop shelf rolls (weapon and armor material, magic items, modded weapons and armor) uses the
shop's level (card 01, `DoomerfallShopLevels`) instead of the map pixel's area level. Design:
`work/notes/20261124-124736-shop-levels.md`.

## Plan

1. `WorldLevel.ShopProvider` + `WorldLevel.ForShop(building)`, as `DungeonProvider`/`ForDungeon`. Done.
2. One-line hook around `PlayerActivate.ActivateLootContainer`'s `StockShopShelf` call. Done.
3. Bridge sets the provider (`DoomerfallShopShelves.Level`), clears it on detach. Done.
4. Pointer in `DoomerfallAmmoTiers.StockShop`; its odds unchanged. Done.
5. Rate test `-dfshoplevelrates` (new file, attached from the existing shop stock test's `Attach`). Done.
6. Paired run into a real shop; log the restock level; compare with `shop_level.py`. Done (a general store: the test
   town has no other shop).
7. Demo folder, notes. Done.

## Decisions (engineering calls)

- **Only one restock path exists.** `StockShopShelf` is called only from `ActivateLootContainer` (Doom's Use reaches
  it through `PlayerActivate` line ~969, the Doomerfall container entry) and from test files. So the one-line `using`
  in `PlayerActivate` covers every real restock. No other Doomerfall path restocks shelves (`DoomerfallItems` only
  restores saved shelf contents and `stockedDate`).
- **Lookup:** the provider finds the building's `BuildingSummary` in the current location's `BuildingDirectory`
  (`StreamingWorld.GetCurrentBuildingDirectory()`, the same call Doomerfall's Info path uses) by
  `BuildingDiscoveryData.buildingKey`, then `DoomerfallShopLevels.ForShop(directory.LocationData, summary)`.
- **Unknown shop -> 0 -> area level.** If the directory or summary is missing, or the shop table failed, the provider
  returns 0, `WorldLevel.Scope` does nothing, and the shelf rolls at the area level exactly as before. The log line
  says "(area level used)".
- **Shop ammo** runs inside the same scope (it is the last call of `StockShopShelf`), so `WorldLevel.Current` is the
  shop level there; its odds do not read it. One-line pointer left in `DoomerfallAmmoTiers.StockShop`.
- **Logging:** each restock writes one line to the bridge log file (`-dfbridgelog`): "shop restock: NAME (TYPE,
  quality Q) in REGION / TOWN at shop level N". Nothing reaches the screen.
- `-dfarealevel N` (the area level test override) does not override shop levels: they are a different table.

## Findings

- **Shop shelves never used the approved material odds.** The approved odds
  (`work/notes/20261123-material-tier-proposal.md`) are applied only to enemy drops: `DoomerfallDrops.RollEnemy` sets
  `FormulaHelper.DoomerfallMaterialRoll` for the duration of the roll. `StockShopShelf` calls
  `FormulaHelper.RandomMaterial(level)` with no override, which is Daggerfall's classic curve: Daedric when
  `levelModifier + Random(0..255) >= 255`, with `levelModifier = 2 × (level − 10)` (×4 below 10). Per material roll
  that is 0% at level 4, 4.3% at 15, 6.6% at 18, 8.2% at 20 and 16.0% at 30, against 1 in 100 / 56 / 40 / 20 under the
  approved odds. The research notes' per-shelf table (12.8% / 29.1% / 50.0% for a weapon smith) assumed the approved
  odds, so it does not describe the game as it is. This run changes only the level, as the card says; the odds stay
  what they were (classic). **Question for the owner below.** If shelves should use the approved odds, the change is
  small: set `FormulaHelper.DoomerfallMaterialRoll = DoomerfallDrops.RollMaterial` inside the shop scope (note that
  `RollMaterial` reads the loot seed, so shop rolls would need their own seed or plain random).
- With the classic curve, the shop level now matters a lot: a level 30 weapon smith shelf has a Daedric item 90% of
  the time, a level 4 one never.
- The test town (Gothway Garden, group 7154) has only general stores, so the paired run uses a general store.
- This branch is behind `integration` (bridge schema `511cf051…` here vs `dd00ae67…` there), so the demo engines of
  other review folders do not attach to this Daggerfall Unity build. I built this branch's UZDoom, bridge DLL and
  launcher into `D:\dev\DoomDaggerfall-build\{uzdoom,bridge,launcher}-shoplvl` and its data with
  `install.make_data` into `D:\dev\DoomDaggerfall-build\shoplvl-data`.
