# Daggerfall's quest journal from Doom, with a hotkey (run 20261124-235038)

## Key choice: J, not L

Daggerfall's default for the journal (logbook) is **L** (`InputManager.cs:1027`). L clashes: DRLA Arsenal's
`keyconf.txt` has `defaultbind L drla_pda` (its PDA), and DRLA is part of the play set. So the journal uses **J**:

- free in Doom's default bindings (`UZDoom/wadsrc/static/engine/commonbinds.txt`, `defbinds.txt`), in every
  `defaultbind` of the extracted DRLA Arsenal, Monsters and DRLAX data (only Arsenal has any: L V B C M), and in
  Doomerfall's own keys (Q Info, I inventory, K travel, Tab map, E Use);
- easy to remember ("journal"), and next to K and I, where the other Daggerfall menus already are.

Daggerfall's separate Notebook key (N) gets no Doom key: the notebook is one of the journal's four tabs, and N is
the journal's own "next tab" shortcut inside the window. As with the other Doomerfall controls, J is bound by
`play.bat` on first launch (`scripts/play/install.py`) and can be rebound in Options > Customize Controls >
Doomerfall Controls ("Open Journal").

## What changed

- `bridge/doomerfall_bridge.h`: `DFB_UI_JOURNAL 9u` (context = Doom's `DFB_WORLD_*`). Generated files regenerated.
  **This changes the bridge layout hash**: old test folders need this branch's bridge DLL, launcher and uzdoom.exe.
- `UZDoom/src/dd_bridge.cpp`: `netevent df_journal` toggles the journal like `df_inventory` (opens, or closes any
  open Daggerfall menu), and the key bound to it also closes it from inside the menu (`UiCommandName`).
  Only active in a bridge session, like the other `df_*` events; without a session the event returns false.
- `mods/doomerfall`: "Open Journal" in Doomerfall Controls; `df_journal` is not logged as an unknown action.
- `DoomerfallUi.cs`: accepts `UI_JOURNAL` and posts Daggerfall's own `dfuiOpenQuestJournalWindow` (the journal opens
  on Active Quests, as in Daggerfall). Everything else is Daggerfall's stock `DaggerfallQuestJournalWindow`.
- Travel from the journal: clicking an active quest offers to find its place on the travel map, where the player can
  travel. Doom follows that travel only when it is outdoors (same rule as K, which says "You cannot travel from
  indoors."). Outdoors the journal's menu treats the travel map like K's (fast travel is followed). Indoors the travel
  map still opens to show the place, but starting a journey shows Daggerfall's message "You cannot travel from
  indoors." instead (`DoomerfallUi.RefuseJournalTravel`, a two-line hook in `DaggerfallTravelMapWindow.CreatePopUpWindow`).
  Without this, Daggerfall could travel while Doom stayed put. This is the existing rule applied to a new path, not a
  new design.

## Test

- `-dfjournaltest <file>` (`DoomerfallJournalTest.cs`, starts itself from the flag, no hook in game classes): after the
  game runs, starts two real quests (A0C00Y00, B0B00Y00) and adds three notes, a message and a finished quest entry;
  logs the top window and the journal's tab, page and count each time they change.
- `tools/journal/journal.py assemble | run | check`. Paired run, DRLA loaded, outside Privateer's Hold. Doom's
  `-dfuitest` opens the journal through the same command J is bound to (`netevent df_journal`; key presses posted
  to Doom's window do not reach Doom's game input, which is why the map keys test did the same); after that every
  press and click is a real window message through `DD_BridgeUiWndProc`.

## Play-test list

- Press J in town, in a building and in a dungeon: the journal opens with your quests; J, Escape and Exit close it.
- N or the bottom-left button cycles Active Quests, Finished Quests, Notebook, Messages; arrows and Up/Down page.
- In the Notebook tab, click the title to add a note and type it (typing goes through Doom).
- Outdoors, click an active quest: Yes shows the place on the travel map and you can travel there.
  Indoors, the same shows the place, but travelling says "You cannot travel from indoors."
- An existing play folder (with run\uzdoom.ini) does not get J bound automatically; bind "Open Journal" once in
  Doomerfall Controls.
