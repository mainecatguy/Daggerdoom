# Area level replaces player level everywhere (run 20261124-110837)

Branch `agent/arealevelall-20261124-110837`, from `integration` after the `ammotiers` merge (3805d1e).

## Plan

1. List every use of the player's level in Daggerfall Unity and sort it into world or character.
2. Add one small hook, `WorldLevel` (`Game/WorldLevel.cs`). `WorldLevel.Current` is the area level of where the
   player is in a bridge session, and the player's level otherwise, so normal Daggerfall Unity is unchanged.
3. Switch every world call site to `WorldLevel.Current`. Leave character uses alone.
4. Prove it in a paired session: the same place at player level 1 and at a high level gives the same loot, gold, and
   enemies, and a control roll with the provider off (classic behaviour) differs.

## Design

- `WorldLevel.CurrentPlaceProvider` and `WorldLevel.DungeonProvider` are set by `DoomerfallBridge` when the session
  attaches and cleared in `OnDestroy`. With no provider, `Current` returns `PlayerEntity.Level` exactly as before.
- Doomerfall's providers (`DoomerfallDrops.CurrentWorldLevel` / `DungeonWorldLevel`) use `DoomerfallAreaLevels`:
  the dungeon's level inside a dungeon, otherwise the terrain level of the map pixel (towns, houses, shops,
  wilderness), as the approved area level proposal defines. If the table cannot be built they return level 1, never
  the player's level. `-dfarealevel N` overrides both, as it does for drops.
- `WorldLevel.Scope` pins the level for a block of rolls. `DaggerfallDungeon.LayoutDungeon` builds a dungeon inside
  `WorldLevel.ForDungeon(location)`, because Daggerfall lays the dungeon out before the player counts as inside it.
  `DoomerfallDrops.RollEnemy` now uses a scope instead of temporarily overwriting `PlayerEntity.Level`.

## Every use of the player's level

### World: changed to the area level

| Call site | What it scales |
|---|---|
| `Game/Items/LootTables.cs` `GenerateRandomLoot` | Gold amount, random weapons and armor (material), creature and plant ingredient chances, magic items. Used by dungeon and building treasure piles and enemy loot. |
| `Internal/DaggerfallLoot.cs` `StockShopShelf` (5 uses) | Shop shelf weapons and armor material, magic items, modded weapons and armor material. |
| `Internal/DaggerfallLoot.cs` `StockHouseContainer` (3 uses) | House container magic items, weapons, armor. |
| `Game/UserInterfaceWindows/DaggerfallGuildServicePopupWindow.cs` magic item stock | Mages Guild "buy magic items" stock (shop stock). |
| `Game/Entities/EnemyEntity.cs` `SetEnemyCareer`, class enemy and custom class enemy | Class enemy level and max health, spell list, skills. |
| `Game/Entities/EnemyEntity.cs` city guard | City guards: area level + Daggerfall's 3 to 6. |
| `Game/Items/ItemHelper.cs` `AssignEnemyStartingEquipment` (2 uses) | Enemy equipment material, and the "no poisoned weapons at level 1" rule. |
| `Utility/RandomEncounters.cs` `ChooseRandomEnemy` | Random encounter table window (wilderness, town at night, dungeon spawns, rest interruptions). |
| `Utility/RDBLayout.cs` `ChooseRandomEnemyType` | Dungeon random enemy markers (classic selection). |
| `Internal/DaggerfallDungeon.cs` `LayoutDungeon` | Dungeon monster power (alternate selection) and, through the scope, everything rolled while the layout is built. |
| `Internal/DaggerfallAction.cs` `DrainHealth21`, `DrainHealth` | Dungeon trap and action damage. |
| `Game/EnemyAttack.cs` `ResetMeleeTimer` | Daggerfall enemies' melee attack rate. (Doom runs combat in a session, so this matters only to any Daggerfall enemy that still fights.) |
| `Doomerfall/DoomerfallDrops.cs` `RollEnemy` | Already used the area level by overwriting the player's level; now uses `WorldLevel.Scope`. |

Material rolls (`FormulaHelper.RandomMaterial` / `RandomArmorMaterial`, `ItemBuilder.CreateRandomWeapon` /
`CreateRandomArmor` / `CreateRandomMagicItem`) take the level as a parameter, so they follow their callers above.

| `FormulaHelper.cs:856, 920-1052, 1408, 1829`, `EnemyMotor.cs:1277` | Generic entity level in combat and spells. For the player it is the player's level; for an enemy it is the enemy's level, which is now area based. |

### Unclear: left unchanged and reported

- Player gender and race still pick armor fit and clothing in loot, shop shelves and enemy equipment
  (`LootTables`, `DaggerfallLoot`, `ItemHelper`). This is not level, so it is outside this goal, but it means two
  characters can see different (gender-fitted) armor in the same pile.
- The approved material odds (`DoomerfallDrops.RollMaterial`) still apply only to slain Doom enemies' drops. Shop
  shelves, house containers and treasure piles now use Daggerfall's classic material formula fed with the area level.
  Whether the approved odds should replace the classic formula everywhere is a question for the owner.

   Unity.exe -projectPath <worktree>/daggerfall-unity-master -buildTarget Win64 -executeMethod CliBuild.BuildWindows64
   -logFile <worktree>/daggerfall-unity-master/Logs/cli-build.log`. Result: `CliBuild result: Succeeded`.
2. `python tools/world_level/world_level.py assemble`: builds `D:\dev\DoomDaggerfall-loop\review\world-level` from
   `review\ammo-change` (UZDoom, launcher, bridge DLL and data from the merged ammotiers lane; the bridge header is
   unchanged) and this build of Daggerfall Unity.
3. `python tools/world_level/world_level.py run 1` and `run 25`: paired games, minimized, DRLA + Monsters + DRLAX on
   DOOM2, Doom in Privateer's Hold (`DDT07154`), Daggerfall with `-dfsynctest` and the new test-only
   `-dfworldleveltest N` (`DoomerfallWorldLevelTest.cs`, a one-line hook in `DoomerfallBridge.cs`). Logs in
   `review\world-level\run\level1-df.log` and `level25-df.log`.
4. `python tools/world_level/world_level.py compare 1 25`.

What the test does: it sets the player's level to N, then runs fixed-seed rolls through Daggerfall's own code, at the
current place (map pixel 109,158, area level 1) and inside `WorldLevel.ForDungeon` for Daggerfall city's dungeon
(area level 7). Per seed (4 seeds): treasure piles for loot keys A, K, N, P, T (`LootTables.GenerateRandomLoot`),
5 shop shelves at quality 20 (`StockShopShelf`), a house container (`StockHouseContainer`), class enemies (City Watch,
Mage, Warrior, Nightblade: level, max health, loot, equipment via `SetEnemyCareer`), random encounter picks
(`RandomEncounters.ChooseRandomEnemy`), dungeon marker picks (`RDBLayout.ChooseRandomEnemyType` at the dungeon's
level), and slain Doom enemy drops (`DoomerfallDrops.RollEnemy`). Then it repeats everything with the providers
switched off, which is exactly what normal Daggerfall Unity does, as a control.

Result:

```
A: worldleveltest: player level 1, map pixel 109,158, place level 1, dungeon 7
B: worldleveltest: player level 25, map pixel 109,158, place level 1, dungeon 7
area lines 182 182 hashes 8eff903a 8eff903a
control hashes e2f9f663 fd4065a2
area rolls: MATCH
control rolls (player level, as normal Daggerfall Unity): DIFFER (expected)
```

All 182 area lines are identical between a level 1 and a level 25 character: gold, items, materials, enemy types,
class enemy levels and health. Example: the City Watch in Daggerfall's dungeon is level 10 (area 7 + 3) with 103
health in both runs, and pile T/0 is `[Gold Pieces x287] [Iron Broadsword x1] [Leather Boots x1] [Round Shield x1]`
in both. The control differs, which shows the test is sensitive and that without a provider the code still uses the
player's level.

Normal Daggerfall Unity: with no provider, `WorldLevel.Current` returns `PlayerEntity.Level`, and
`WorldLevel.ForDungeon` is a no-op scope, so every changed call site computes exactly what it did before. The
control section above exercises that path. I did not launch a separate non-Doomerfall session.

Not covered: the real Doom-placed monsters and treasure in a converted dungeon at two player levels (those already
used the area level before this change, through `DoomerfallMonsters` and `DoomerfallDrops`), trap damage and enemy
melee timing (code review only), and the Mages Guild magic item window (code review only).

## Play-test list

1. With two characters of very different level, enter the same town shop (weapon smith, armorer, Mages Guild magic
   items). Shelves restock by date, so compare the kind of materials on offer, not exact items: they should feel the
   same for both characters.
2. In the same dungeon with both characters, compare treasure piles and enemy loot (gold amounts in particular).
3. Step on a dungeon damage trap with a high-level character in a low-level dungeon: the damage should be small.
4. City guards in a low-level region should be much weaker than in a high-level region, regardless of your level.
